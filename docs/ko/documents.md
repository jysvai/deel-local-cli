## 한글 문서와 엑셀

### 한글·워드·파워포인트 — 글로 읽습니다

`.hwpx` · `.docx` · `.pptx` 는 겉만 다르지 속은 전부 ZIP + XML 입니다(hwpx 는
한컴의 공개 규격 OWPML). 그래서 자체 zip 읽개와 xlsx 가 쓰던 작은 XML 읽기로
**의존성 0개 그대로** 풉니다. 문단은 차례대로, 표는 행마다 `이름 | 값` 꼴로,
발표 자료는 장별로 나옵니다.

이게 필요한 이유는 사고 하나로 요약됩니다 — hwp 를 정리해 달라고 했더니 Read 가
"바이너리" 로 실패하자 모델이 Write 로 새로 써서 원본이 죽을 뻔했습니다.
길 없는 거절은 모델을 우회로로 몹니다. 읽기가 되면 그 길 자체가 없어지고,
**문서를 주고 "이 스펙대로 만들어" 라고 시키는 일**이 비로소 됩니다.

고치기는 안 됩니다. 서식·그림·양식이 든 문서를 글로 왕복시키면 반드시 뭔가
잃습니다. 구형 `.hwp`(OLE)는 직접 못 읽는 대신 **한글에서 hwpx 로 저장하면
읽힌다**는 길을 같이 알려 주고, 이 PC 에 LibreOffice 가 있으면 그걸 빌려
읽어 봅니다(아래).

### Figma 시안 — `.fig` 를 짜임과 글로

「이 시안대로 만들어 줘」 하면서 `.fig` 를 건네는 일이 실제로 잦습니다. 그런데
그 파일은 여기서 끝났습니다 — 「이진 파일이라 못 읽습니다」. 그러면 사람이
화면을 캡처해서 다시 붙이거나, 글자를 하나씩 옮겨 적었습니다.

안에 있는 것은 그림만이 아닙니다. **틀 이름 · 글 · 크기 · 겹친 차례**가 다
글자로 들어 있습니다. 「로그인」 이라는 틀 밑에 「이메일」 「비밀번호」 라는
글상자가 있고 폭이 375 라는 것 — 코드를 짜는 데 필요한 것은 대부분 그겁니다.

```
◧ Read(로그인.fig)
  └ fig · 쪽 2개 · 도형 148개

## 로그인

- FRAME · 로그인 화면 375×812
  - TEXT · 제목 "다시 오신 것을 환영합니다"
  - FRAME · 입력칸 335×48
    - TEXT · 라벨 "이메일"
  - RECTANGLE · 밑줄 (숨김)
```

`deel doc2md 로그인.fig` 로 마크다운이 되고, 쪽마다 `## 쪽이름` 이 붙습니다.
쓰기는 없습니다 — 글로 왕복시킨 시안은 시안이 아닙니다.

**여기서도 새로 들이는 것이 없습니다.** `.fig` 는 zip 이고, 그 안
`canvas.fig` 는 Kiwi 라는 형식입니다. 보통 이런 이진 형식은 스키마를 따로
구해 와야 하고, 그러면 판이 올라갈 때마다 우리가 든 스키마가 낡습니다 —
낡은 스키마로 읽으면 **조용히 어긋난 값**이 나옵니다. 제일 나쁜 실패입니다.

Kiwi 는 **파일 첫 덩이가 그 파일을 읽는 법 자체**입니다. 정의 이름, 칸 이름,
칸 번호가 다 들어 있습니다. 그래서 우리가 아무 표도 안 들고 있어도 되고,
Figma 가 내일 칸을 하나 더 늘려도 그 파일이 제 손으로 알려 줍니다.

세 가지를 지킵니다.

- **안 내는 것을 먼저 말합니다** — 색 · 그림자 · 글꼴은 안 냅니다. 그것까지
  다 봤다고 여기고 답하면 안 되기 때문입니다.
- **모르는 칸 번호를 만나면 멈춥니다.** Kiwi 는 길이가 안 적혀 있어서 모르는
  칸을 건너뛸 수가 없습니다. 짐작으로 계속 읽으면 그 뒤가 전부 헛것이 됩니다 —
  반만 맞는 시안은 틀린 시안보다 나쁩니다.
- **남이 적어 놓은 개수로 우리 메모리를 정하지 않습니다.** 배열 개수가 남은
  바이트보다 크면 읽어 볼 것도 없이 거짓입니다.

요즘 `.fig` 는 zstd 로 눌려 있습니다. Node 가 zstd 를 들고 온 것은 **22.15**
부터고 이 프로그램의 바닥은 20 이라, 낮은 판에서는 못 풉니다. 그때 「깨진
파일입니다」 라고 하지 않습니다 — 파일은 멀쩡하고 여기 Node 가 못 푸는
것이며, 그 둘은 사람이 할 일이 완전히 다릅니다.

```
zstd 로 눌린 .fig 입니다. 이 Node 에는 zstd 가 없습니다 (지금 v20.11.0 ·
Node 22.15 부터 들어왔습니다).
  파일이 깨진 것이 아닙니다 — 여기서 못 푸는 것뿐입니다.
  고치는 법: Node 를 22.15 이상으로 올리면 그대로 읽힙니다.
```

### `deel doc2md` — 문서를 마크다운 한 장으로

같은 읽개를 쓰되 **나오는 모양**이 다릅니다. 표는 `| 이름 | 값 |` 꼴의 진짜
마크다운 표가 되고, 장·쪽은 `## 2장` `## 3쪽` 제목이 됩니다.

```bash
deel doc2md 보고서.pptx                 # 표준출력으로
deel doc2md 스펙.pdf --out 스펙.md      # 파일로
deel doc2md 명세.xlsx > 명세.md         # 파이프로 받아도 됩니다
```

왜 글이 아니라 마크다운이냐 — **읽는 쪽이 사람만이 아니기 때문**입니다.
마크다운 표는 모델이 "첫 줄이 머리글이고 셋째 칸이 비고" 라는 것을 그냥 압니다.
평평하게 이어 붙인 줄에서는 그걸 매번 다시 짐작해야 하고, 빈 칸이 하나 섞이면
거기서부터 어긋납니다. 같은 바이트로 더 많이 전하는 쪽이 마크다운입니다.

맡는 갈래는 직접 읽는 여섯 가지입니다 — `hwpx` · `docx` · `pptx` · `xlsx` · `pdf` · `fig`.
새로 들이는 것은 없습니다. 옛 형식(`.ppt`·`.doc`·`.xls`·`.hwp`)은 이 PC 에
LibreOffice 가 있을 때 `Read` 가 빌려 읽는 길 그대로입니다.

두 가지를 지킵니다.

- **못 읽은 쪽을 조용히 건너뛰지 않습니다.** 그 자리에 `> 이 쪽은 글로 못
  읽었습니다 — …` 를 남깁니다. 빈 쪽으로 넘기면 그 문서는 "그 쪽에 아무것도
  없는 문서" 가 되고, 모델은 그걸 근거로 "그런 내용 없습니다" 라고 답합니다.
- **칸이 열두 개를 넘으면 표로 안 그립니다.** 가로로 흐르는 벽이 되기 때문에
  CSV 울타리로 내리고 왜 그랬는지 적습니다. 조용히 모양을 바꾸면 표가 안 나온
  것이 파일 탓인지 우리 탓인지 알 길이 없습니다.

글은 표준출력으로, "몇 자에서 잘랐습니다" 같은 말은 표준오류로 나갑니다.
`> 보고서.md` 로 받아도 파일 안에 안 섞입니다.

### 못 읽는 형식은 이 PC 에 깔린 변환기를 빌립니다

`.ppt` · `.doc` · `.xls` · `.rtf` · `.odt` 처럼 우리가 직접 못 읽는 옛 형식이
사내 자료에는 제일 흔합니다. 이름만 `.pptx` 이고 속은 옛 `.ppt` 인 것도
흔합니다. 여태 그런 파일은 이렇게 끝났습니다.

```
◧ Read(보고서.ppt)
  └ 바이너리 파일입니다 — 텍스트로 읽을 수 없습니다
```

까닭도 길도 없는 거절이라 모델은 같은 파일을 또 열고, Bash 로 우회로를 찾다
울타리에 막힙니다. 그 왕복이 곧 토큰입니다. 그런데 정작 그 PC 에는
**LibreOffice 가 깔려 있는 경우가 많습니다** — 사람이 그 파일을 열어 보는 바로
그 프로그램입니다. `rg` 를 빌려 쓰는 것과 같은 원칙으로 그걸 빌립니다.

```
◧ Read(보고서.ppt)
  └ soffice 로 바꿔 읽음 · 148줄
```

- **아무것도 설치하지 않습니다.** 있으면 쓰고, 없으면 없다고 말하고 끝냅니다.
- 맥에서는 더 빠른 `textutil` 을 먼저 씁니다.
- `PATH` 에 없는 자리도 봅니다 — 맥 앱 꾸러미 안, 윈도우 `Program Files`.
- 바꾼 글은 **작업 폴더 안**(`.deel/tmp/`)에 떨구고 **읽는 그 자리에서 지웁니다**
  — 뽑은 글은 사람 문서의 알맹이라 사본이 남으면 그대로 커밋되거나 압축되어
  나갈 수 있습니다. 원본은 한 글자도 안 바뀝니다.
- 끄려면 `DEEL_CONVERT=off`.

변환기도 없으면 **없다고 못 박고 끝냅니다.** 무엇이라서 못 읽는지, 무엇이
없어서 못 바꾸는지, 사람이 무엇을 하면 되는지를 한 번에 말하고 「다시 열지
말라」고 적습니다. 다시 열어도 결과가 같은 것은 우리가 아는 사실입니다.

```
◧ Read(보고서.ppt)
  └ 보고서.ppt 은 deel 이 직접 못 읽는 형식입니다 (.ppt).
    이 PC 에 LibreOffice(soffice)가 없어서 바꿔 읽을 수도 없습니다.
    해결: 원래 프로그램에서 pptx 로 저장한 뒤 다시 주세요.
    **같은 파일을 다시 Read 하지 마세요. 결과는 같습니다.**
```

빌려 읽은 파일도 `Edit`·`Write` 로는 못 고칩니다. 글만 뽑아 본 것이라,
그 글을 되돌려 쓰면 원본 조판이 통째로 사라집니다.

### PDF — 쪽마다 글로, 못 읽은 쪽은 못 읽었다고

`.pdf` 도 `Read` 로 바로 읽힙니다. 속은 「사전 + 눌린 흐름」이고 그 압축이 거의
언제나 zlib 이라, **node 에 든 zlib 만으로** 풉니다. 새로 들이는 것은 없습니다.
고전 xref 표도, 요즘 쓰는 xref 흐름·객체 흐름(PDF 1.5+)도 읽습니다.

어려운 것은 압축이 아니라 **글자를 되찾는 일**입니다. PDF 안에 든 것은 글자가
아니라 글리프 번호입니다 — 「가」가 아니라 「이 글꼴의 1,283번째 그림」이 적혀
있습니다. 그래서 글꼴에 딸린 `/ToUnicode` 표로 번호를 글자로 되돌립니다.
한글 PDF 는 거의 전부 Identity-H(두 바이트 번호)라 이 표가 없으면 한 글자도
못 읽습니다.

```
--- 1쪽 ---
결제 한도는 1,000,000원입니다.
The quick brown fox jumps over the lazy dog.
--- 2쪽 ---
[이 쪽은 글로 못 읽었습니다 — 글이 없는 쪽입니다 (스캔한 사진일 수 있습니다 — OCR 이 필요합니다)]
```

**여기가 이 기능의 요점입니다.** PDF 는 애초에 글이 안 든 것이 흔합니다 —
스캔본, `/ToUnicode` 없는 글꼴, 암호. 그때 빈 글을 돌려주면 「그런 내용이 없는
문서」로 읽히고, 모델은 그걸 근거로 답합니다. 그래서 못 읽은 쪽은 **그 자리에**
왜 못 읽었는지 적고, 끝에 이렇게 묶습니다.

```
3쪽 중 2쪽을 글로 못 읽었습니다 (2 · 3쪽).
  · 글이 없는 쪽입니다 (스캔한 사진일 수 있습니다 — OCR 이 필요합니다)
  이 쪽들의 내용은 여기 없습니다 — 없는 것이 아니라 못 꺼낸 것입니다.
```

암호가 걸린 PDF 는 읽은 척하지 않고, 「뷰어에서 암호 없는 사본으로 저장하라」는
길을 줍니다. xref 나 `/Length` 가 틀린 파일(덧붙여 저장하다 어긋난 것 — 현장에
아주 많습니다)은 파일을 통째로 훑어서 살려 읽습니다.

고치기는 hwpx·엑셀과 같은 이유로 안 됩니다. PDF 는 「보이는 대로 인쇄하기」 위한
형식이라 글로 바꿨다가 되돌리면 조판이 통째로 사라집니다.

### 인코딩 — 읽은 그대로 되돌려 씁니다

사내 문서는 UTF-8 이 아닌 경우가 흔합니다. 윈도우 메모장이 오래 쓰던 완성형
(한국 CP949, 일본 CP932, 중국 GBK…) 으로 저장된 파일이 그대로 남아 있습니다.
그걸 UTF-8 로 읽으면 통째로 깨집니다. `한글` → `�ѱ�`

더 위험한 건 쓸 때입니다. 깨진 채로 읽고 UTF-8 로 저장하면 원본이 상합니다.
그래서 규칙이 하나입니다 — **읽은 인코딩으로 되돌려 씁니다.**

무엇으로 읽었는지는 **컴퓨터 설정이 아니라 파일 내용**을 보고 정합니다.
후보마다 엄격하게 해독해 보고, 나온 글이 그 인코딩으로 쓴 진짜 글처럼
보이는지 점수를 매깁니다. 그래서 우분투에서도, 미국 윈도우에서도, 한국
윈도우에서도 같은 CP949 문서가 같게 읽힙니다.

```
› Read 품의서.txt
└ 4줄 · CP949 (추정)
```

앞머리 표식이 없는 파일은 결국 **짐작**입니다. CP949 와 CP932 는 바이트 범위가
겹쳐서 짧은 파일일수록 자주 뒤집힙니다. 그래서 짐작한 것은 `(추정)` 이라고
적습니다 — 확정처럼 적어 두면 잘 읽힌 줄 알고 그 위에서 고치게 되고, 되돌려
쓰는 규칙 때문에 그때 원본이 상합니다. 표식이 있는 파일은 그냥 `UTF-8(BOM)`
처럼 적습니다.

그 인코딩에 **없는 글자**를 넣으려 하면 저장하지 않고 멈춥니다.

```
› Edit 품의서.txt   비고 → 비고 🚀
└ 이 파일은 CP949 로 되어 있는데, 그 인코딩에 없는 글자를 넣으려 합니다: 🚀
```

조용히 물음표로 바꿔 저장하는 것보다 안 쓰는 편이 낫기 때문입니다.
새로 만드는 파일은 UTF-8 입니다.

명령 출력도 마찬가지입니다. 윈도우 명령창은 UTF-8 이 아니라, `Bash` 결과를
utf8 로 받으면 한글이 깨집니다. 바이트로 받아서 풉니다.

**되돌리기 스냅샷도 바이트로 담습니다.** 예전에는 UTF-8 글자로 적었습니다.
그러면 CP949 파일을 되돌릴 때 `가나다`(`b0a1 b3aa b4d9`) 가 U+FFFD 여섯 개로
돌아옵니다 — **안전망이 원본 바이트를 없애 버리는 것입니다.** 지금은 UTF-8 로
되짚어 봐서 바이트가 그대로 살아나지 않는 파일만 base64 로 담고, 되돌릴 때
바이트 그대로 씁니다.

### 엑셀 — CSV 로 바꿔서 읽습니다

엑셀 파일은 글이 아니라 압축 꾸러미라, 보통은 "바이너리 파일입니다" 로 끝납니다.
사람이 손으로 CSV 로 내보내 붙여넣어야 했습니다. `Read` 가 알아서 합니다.

```
› Read 결재문서.xlsx
└ 시트 3개 · 128줄 · 직접 풀었습니다
```

- **의존성 0개** 그대로입니다. xlsx 는 사실 zip 이고 그 안은 XML 이라, Node 내장 `zlib` 만으로 풉니다.
- 시트가 여럿이면 전부 줍니다. 숨긴 시트도 줍니다 (숨김이라고 표시해서).
- 날짜는 숫자가 아니라 날짜로 보여줍니다. 서식을 읽어 판단합니다.
- 수식은 식이 아니라 **계산된 값**으로 줍니다. `#REF!` 같은 오류값은 지우지 않습니다.

**암호가 걸린 파일과 옛 `.xls`** 는 엑셀에게 맡깁니다. 그것만은 직접 풀 수 없습니다.
이때 암호를 물어봅니다. 엑셀이 없는 PC(맥·리눅스가 전부 여기입니다)에서는
LibreOffice 가 있으면 그걸 빌려 글로 읽어 봅니다 — 표가 아니라 글이지만,
아무것도 못 읽는 것보다는 낫습니다.

암호는 **아무 데도 남지 않습니다.**

- 설정 파일에 안 씁니다
- 세션 기록에 안 씁니다
- 감사기록에 안 씁니다
- 명령줄 인자로 안 넘깁니다 (작업 관리자에서 남의 명령줄이 보입니다)

나가는 길은 자식 프로세스의 표준입력 하나뿐이고, 그 사실을 검사로 못 박아 뒀습니다.
쓰고 나면 임시로 뽑은 내용까지 지웁니다.

> **엑셀 파일은 읽기만 됩니다.** `Edit`·`Write` 로 고치려 하면 막습니다.
> 서식·수식·차트가 든 파일을 CSV 로 왕복시키면 반드시 뭔가 잃기 때문입니다.
> 잃는 걸 알면서 쓰느니 안 쓰는 편이 낫습니다.
