## 추론 강도

<sub>전선 카드 · 캐시 표식 · 시킨 말에 맞춘 강도 · 컨텍스트 길이는 모델에서 긁어옵니다 · /out · 잘린 도구 호출 · 잠깐 막혔을 때</sub>

### 로컬 모델의 숨은 지연 — 프리픽스 캐시를 지킵니다

Ollama·llama.cpp 는 요청의 **앞부분이 지난 요청과 같을 때만** 계산을 재씁니다.
앞부분이 한 글자라도 다르면 거기서부터 끝까지 — 대화 전체까지 — 다시 계산합니다.
로컬에서 긴 대화가 갈수록 느려지는 숨은 이유가 대개 이것입니다. 오류가 아니라서
아무 데도 안 찍힙니다.

deel 은 말을 던질 때마다 알맞은 모드로 저절로 옮겨 가는데, 그 모드 지시문이
프롬프트 **앞쪽**에 있으면 모드가 바뀔 때마다 캐시가 통째로 깨집니다. 그래서
변하지 않는 것(규칙·폴더·프로젝트 지문·사용자 규칙·기억·스킬)을 앞에 굳히고,
매 턴 바뀔 수 있는 것(모드·핀)을 끝에 둡니다. 이 차례는 검사가 지킵니다
(`test/cache.test.js`) — 순서는 눈에 안 보여서, 검사가 없으면 다음 기능이
아무 데나 끼어듭니다.

Ollama 에는 `keep_alive: 60m` 도 같이 보냅니다. 기본값(5분)이면 사람이 잠깐
다른 창을 보다 돌아온 사이에 모델이 내려가고, 복귀 첫 마디에서 대화 전체를
다시 계산합니다. `DEEL_KEEP_ALIVE` 로 바꿀 수 있습니다. llama.cpp 를 직접 쓰면
서버 쪽 `--cache-reuse 256` 이 같은 효과를 냅니다.

### 전선 카드 — 이 모델이 이 주소에서 실제로 받는 것

같은 규격이라도 창구마다 받는 칸이 다릅니다. 그래서 세션을 열 때 **전선 카드**를
한 장 정하고 그 세션 내내 그 카드로 보냅니다. `/status` 와 `/think` 에 그 카드가
한 줄로 보입니다.

```
  wire       생각 adaptive · 눈금 low·medium·high·xhigh·max · 캐시 표식
```

| 칸 | 뜻 |
|---|---|
| 생각 | 생각을 켜는 방식 — `adaptive` · `budget_tokens` · `reasoning_effort` · `on/off` |
| 눈금 | 그 창구가 받는 강도 말 |
| 캐시 | 캐시를 누가 잡나 — `표식`(우리가 붙임) · `열쇠`(열쇠로 묶음) · `서버자동` · `없음` |

카드는 세 단계로 정해집니다. 이 프로그램이 컨텍스트 길이를 알아내는 방식과 같습니다.

1. **짐작** — 주소의 회사와 모델 이름의 판으로 첫 값을 고릅니다
2. **배움** — 서버가 `400` 으로 안 된다고 하면 그 문구에서 읽습니다
3. **남김** — 모델과 주소별로 집 파일에 적어 둡니다. 다음에 켤 때 그 값으로 시작합니다

배우는 순간에는 화면에 한 줄이 뜨고, 그 요청은 고친 카드로 다시 나갑니다.

```
  ⚙ 서버가 안 받는 칸이 있어 맞춰 다시 부릅니다 (생각형식)
```

**모르는 주소에는 아무것도 더 안 보냅니다.** 사내 게이트웨이는 모르는 칸 하나에
`400` 을 내는 곳이 흔합니다. 호환성을 넓힌다는 것이 「모르는 곳에 짐작으로 칸을
늘린다」 가 되면, 지금 잘 쓰고 있는 설치가 판올림 하나로 죽습니다. 그래서 회사를
못 알아본 주소에서는 나가는 몸이 예전과 **한 글자도 다르지 않습니다**
(`test/wire.test.js` 가 그것을 지킵니다).

#### 회사별 눈금

| 창구 | 받는 말 |
|---|---|
| Claude — Anthropic Messages 몸 (직통 · Bedrock mantle) | `low` `medium` `high` `xhigh` `max` |
| Claude — OpenAI 호환 몸 (Bedrock runtime) | `minimal` `low` `medium` `high` |
| OpenAI | `minimal` `low` `medium` `high` |
| Gemini | `none` `low` `medium` `high` |
| Azure | `low` `medium` `high` |
| Ollama | 참·거짓 |

**같은 회사라도 몸의 규격을 따릅니다.** 위 두 줄이 다른 이유입니다. `xhigh` 와
`max` 는 Anthropic Messages 몸으로 나갈 때만 씁니다 — OpenAI 호환 창구가 그
말을 받는지 문서에서 확인하지 못했고, 확인 못 한 말을 실어 보내면 그 턴이 `400`
입니다. 잘못 좁히면 손해가 「생각을 덜 한다」 로 끝나고, 잘못 넓히면 손해가
「그 턴이 죽는다」 입니다.

우리 눈금에 있는 말이 그 창구에 없으면 **있는 말 중 가장 가까운 아래쪽**으로
내립니다. `/think max` 를 걸어 두고 OpenAI 로 붙이면 `high` 가 나갑니다.
**올리지는 않습니다** — 사람이 `low` 를 골랐는데 우리가 `medium` 으로 올리면
그건 시킨 것과 다른 일이고, 요금도 사람이 안 정한 값으로 나갑니다.

### 캐시 표식 — 앞머리를 다시 안 보냅니다

프롬프트 캐시는 **앞에서부터 같은 만큼**만 잡힙니다. 그래서 어디까지 잡을지
표식으로 알려 줘야 하는데, 규격마다 그 방법이 다릅니다.

| 창구 | 방법 | 표식 없이 두면 |
|---|---|---|
| Anthropic 직통 | `cache_control` 표식 | 캐시가 **하나도** 안 잡힙니다 |
| Bedrock · Gemini · Azure | 서버가 알아서 | 정적 앞머리만 잡힙니다 |
| OpenAI 직통 | `prompt_cache_key` | 같은 대화인 줄 모릅니다 |

deel 은 표식을 받는 창구에 **두 자리**를 붙입니다.

- 시스템 프롬프트의 **굳은 부분 끝** — 도구 정의까지 같이 잡힙니다
- 대화의 **마지막 성한 블록** — 여기까지가 이번 요청에서 새로 굳는 자리입니다

대화가 스무 마디를 넘으면 중간에 **닻**을 하나 더 박습니다. 되돌아보기 창이 스무
자리라, 닻이 없으면 그 창을 벗어나는 순간 앞이 통째로 다시 나갑니다.

생각 블록과 빈 글에는 안 붙입니다. 생각 블록은 서명이 붙어 오는데 우리가 건드리면
그 턴이 통째로 거절되고, 빈 글에 붙인 표식은 서버가 안 받습니다. 표식 최소 크기
(Anthropic 1,024 · Bedrock 4,096) 아래면 붙여도 안 잡히므로 아예 안 붙입니다.

얼마나 맞고 있는지는 `/cost` 에서 봅니다.

```
  캐시       읽음 48,200 · 씀 6,100 · 적중 78%
```

**쓰기만 있고 읽기가 0 이면** 앞머리가 매번 새로 엮이는 중입니다. `/cost` 가
그 말을 같이 적어 줍니다.

답 토큰 중 **생각에 쓴 몫**도 같이 나옵니다. `/think` 를 높게 잡아 둔 대가가
숫자로 보이는 자리입니다.

```
  생각       12,400 토큰 · 답의 61%
```

이 값을 안 알려 주는 창구가 많습니다. 그때는 줄 자체가 안 나옵니다 — 모르는 것을
0 으로 적으면 「생각을 안 했다」 로 읽히고, 그건 우리가 모른다는 사실과 다릅니다.

### 시킨 말에 맞춰 강도를 고릅니다 — `/think auto`

`/think max` 를 걸어 두면 「안녕」 한 마디에도 최대 추론이 돌았습니다. 느리고,
비싸고, 그 사이 프리픽스도 계속 흔들렸습니다.

`auto` 를 켜면 정한 값이 **천장**이 됩니다. 가벼운 말은 낮은 강도로 빨리 돌아오고,
진짜 일은 천장까지 올라갑니다.

```
  /think auto        켜고 끄기
  /think             지금 값과 천장을 봅니다
```

| 시킨 말 | `/think max` 일 때 나가는 값 |
|---|---|
| `안녕` · `고마워` | `low` |
| `src/a.js 고쳐줘` | `max` |
| 앞에 대화가 쌓인 뒤의 `응` | `max` |

마지막 줄이 중요합니다. 짧은 말이라고 무조건 낮추지 않습니다 — 「응」 한 마디가
앞의 긴 이야기를 이어받는 자리일 수 있습니다.

**천장은 절대 안 넘습니다.** `/think low` 로 정해 둔 사람에게 `medium` 이 나가는
일은 없습니다.

밖으로 나가는 턴에서는 한 턴 안에서 강도를 **고정**합니다. 걸음마다 값이 흔들리면
그것이 곧 프리픽스가 흔들린다는 뜻이고, 프리픽스가 흔들리면 캐시가 매번 새로
엮입니다.

### 세션 이름

캐시를 잡아 주는 창구에 **이 대화가 아까 그 대화**라고 알려 줍니다. Anthropic
규격에서는 `metadata.user_id`, OpenAI 직통에서는 `prompt_cache_key` 와 `user` 로
나갑니다.

담는 것은 **대화 번호 하나뿐**입니다. 경로도, 주소도, 사용자 이름도, 열쇠도 안
들어갑니다. 대화 번호가 아닌 글이 오면 거르지 않고 **통째로 지문으로 바꿉니다** —
거르기는 남는 것이 무엇인지 안 보는 방식이라, 경로를 걸러도 사람 이름과 폴더
이름이 그대로 남습니다.

### 거절은 되밀지 않습니다

모델이 안전 판정으로 거절하면(`stop_reason: refusal`) 그 자리에서 멈춥니다.

거절한 답에는 대개 도구 호출이 없어서, 예전에는 「읽기만 하고 끝내려 한다」 로
읽고 한 번 더 밀었습니다. 밀어도 판정은 같으니 또 거절이고, 그게 걸음 수만큼
되풀이됐습니다. 한 번 거절당할 요청 하나가 열 번 나가고, 그 열 번이 분당 한도를
밀어 올려 그 다음 진짜 요청이 `429` 를 받습니다.

```
  ✗ 모델이 이 요청을 거절했습니다 — 되밀지 않고 여기서 멈춥니다
```

`deel run` 에서는 종료코드 **6** 으로 끝나고 `reason` 이 `refusal` 입니다.
`0` 으로 끝내면 뒤에 붙은 스크립트가 일이 된 줄 알고 다음 단계로 넘어갑니다.
오류(`1`)와도 갈라 둡니다 — 고칠 자리가 다릅니다. 오류는 연결이나 열쇠를 보는
일이고, 거절은 **시킨 말을 바꾸는 일**입니다.

### 할당량이 바닥나면 미리 기다립니다

서버가 응답 머리말로 남은 할당량과 회복 시각을 알려 주는 곳이 있습니다. 그 값이
0 이고 회복 시각을 아는 동안에는 **보내기 전에** 기다립니다.

```
  ⏸ 할당량이 바닥나서 12초 기다렸다 보냅니다
```

보내고 `429` 를 받아 물러나는 것과 결과는 같지만, 이쪽은 헛되이 나가는 요청이
하나 없습니다. 그 헛요청 하나하나가 다시 한도를 밀어 올리기 때문에 차이가 납니다.
1분보다 오래 기다려야 하거나 회복 시각을 모르면 그냥 보냅니다 — 모르는 것을
기다림으로 바꾸면 멀쩡한 요청이 멈춥니다.

### 컨텍스트 길이는 모델에서 긁어옵니다

이 숫자 하나가 프로그램 전체 크기를 정합니다. 한 번에 읽힐 수 있는 파일 수,
대화가 접히는 시점, 한 번에 쓸 수 있는 답 길이가 **전부 여기서 나옵니다.**

그래서 켤 때마다 서버에 물어봅니다. 저장된 값을 그대로 믿지 않습니다 —
같은 이름의 모델이라도 서버에서 몇 k 로 올렸는지가 그때그때 다르고,
그 차이는 화면에 안 뜨면 알 길이 없습니다. **그냥 조용히 작아집니다.**

```
 │ 모델    qwen3-coder  (640k 토큰)                        │
 ╰─────────────────────────────────────────────────────────╯
 ✓ 컨텍스트를 32,768 → 655,360 로 맞췄습니다 (LM Studio에서 읽음)
```

서버마다 이 숫자를 다른 이름, 다른 자리에 둡니다. 한 군데만 보지 않습니다.

| 서버 | 어디서 읽나 |
|---|---|
| LM Studio | `/api/v0/models` — `max_context_length` · `loaded_context_length` |
| llama.cpp | `/props` — `n_ctx` |
| vLLM | `/v1/models` — `max_model_len` |
| Ollama | `/api/show` — `<모델>.context_length` |
| 그 밖의 OpenAI 호환 | `/v1/models/<모델>` — `context_window` · `context_length` · `max_input_tokens` · `max_position_embeddings` (깊이 박혀 있어도 찾습니다) |

**모델 최대와 올려 둔 길이를 구분합니다.** LM Studio 는 655,360 까지 되는 모델을
8,192 로 올려 둘 수 있습니다. 그 상태에서 최대치를 믿고 보내면 서버가 거절합니다.
그래서 **실제로 쓸 값은 올려 둔 길이**로 잡고, 최대치는 따로 알려 줍니다.

```
 ⚠ 이 모델은 655,360 까지 됩니다 — 서버에서 더 올린 뒤 /ctx auto
```

| 명령 | 하는 일 |
|---|---|
| `/ctx` | 지금 값과 남은 자리 |
| `/ctx auto` | 서버에 다시 물어 모델에 맞춤 |
| `/ctx 655360` | 직접 지정 (`640k` · `128k` · `1m` 도 됩니다) |
| `/ctx 자세히` | 어디를 두드려서 어떤 값을 얻었는지 — 안 가져와질 때 원인을 봅니다 |
| `deel --ctx 655360` | 켤 때부터 이 값으로 (긁어오기를 건너뜁니다) |

`/ctx` 는 **얼마나 담나**를 정합니다. **얼마나 알아서 하나**는 `/grade` 입니다 —
다른 축이고, 위의 「걸린 모델에 맞춰 스스로 바뀝니다」 에 같이 적어 뒀습니다.

**`k` 는 1024 입니다.** 컨텍스트 길이는 전부 2의 거듭제곱이라 그래야 아귀가 맞습니다 —
655,360 은 `655k` 가 아니라 `640k`, 131,072 는 `131k` 가 아니라 `128k` 입니다.
화면에 뜨는 표기와 `/ctx` 가 받는 단위가 같아서, 보이는 대로 쳐도 같은 값이 됩니다.

### 한 번에 받을 답 길이 — `/out`

컨텍스트(담아 둘 수 있는 양)와 **출력 상한**(한 번에 낼 수 있는 양)은 다른 숫자입니다.
그 둘을 하나로 알면 큰 파일이 왜 안 만들어지는지 영영 알 수 없습니다 —
컨텍스트는 넉넉한데 답이 잘리기 때문입니다.

| 명령 | 하는 일 |
|---|---|
| `/out` | 지금 상한과 그 값이 **어디서 왔는지**(직접 정함 / 서버에서 알아냄 / 기본값) |
| `/out 32k` | 직접 지정 (`k` 는 1024). 프로필에 남아 다음에 켤 때도 그대로입니다 |
| `/out auto` | 직접 정한 값을 지우고 알아낸 값·기본값으로 |
| `deel --max-tokens 65536` | 켤 때부터 이 값으로 |

옛 이름 `/ctx out 32k` 도 그대로 받습니다.

**상한은 고정 숫자가 아닙니다.** 모델 컨텍스트와 지금 찬 양에서 매번 계산합니다 —
남은 자리의 몇 %를 이 단계에 내줄지가 배분입니다.

| 모델 | 첫 판단 | 이어가기 | 막혔을 때 | 잘린 뒤 다시 |
|---|---|---|---|---|
| 2k 로컬 | 819 | 716 | 921 | 1,638 |
| 8k 로컬 | 3,276 | 2,867 | 3,686 | 6,553 |
| 40k (qwen3) | 16,384 | 14,336 | 16,384 | 16,384 |
| 128k 게이트웨이 | 16,384 | 16,384 | 16,384 | 16,384 |
| 128k 인데 80% 참 | 10,485 | 9,174 | 11,796 | 16,384 |
| 640k 에 `/out 65536` | 65,536 | 65,536 | 65,536 | 65,536 |

컨텍스트가 차오르면 상한도 같이 줄어듭니다. 4k 모델에 4096 을 주면 입력 자리가 안 남기 때문입니다.

마지막 줄이 요점입니다. **아는 값이 있으면 16,384 는 비켜섭니다.**
한동안은 안 그랬습니다 — `Math.min(cap, max ?? 16384, 16384)` 의 세 번째 인자가
무조건 다시 조여서, 적어 둔 값은 **낮출 수만 있고 올릴 수 없었습니다.**
그런데 주석도 README 도 안내도 셋 다 "올릴 수 있다" 고 말했습니다.
문서에 적힌 탈출구가 막혀 있는 것이 가장 나쁩니다.

아끼다 대답이 잘리면 **상한을 풀어 자동으로 다시 부릅니다.** 이때 추론 강도도 한 칸
내립니다 — 생각 토큰이 같은 예산을 먼저 까먹기 때문에, 강도를 낮춰야 본문 자리가 실제로 늡니다.
잘린 채로 넘어가면 도구 호출이 반토막 나서 조용히 실패합니다.

**서버가 거절하면 그 문장에서 배웁니다.**

```
This model's maximum context length is 8192 tokens, however you requested 41003
```

이 숫자를 뽑아 즉시 맞추고 다시 부릅니다. 사용자는 실패를 안 봅니다.
규격을 몰라도 되므로 **처음 보는 서버에서도 통합니다.**

### 잘린 도구 호출

실제로 있었던 일입니다. 사용자가 대시보드를 만들어 달라고 했고, 모델은 HTML 문서를
통째로 `Write` 의 인자에 넣으려다 출력 한도에 걸렸습니다. 인자 JSON 이 중간에서
끊긴 채로 도착했습니다.

예전 코드는 그 읽히지 않는 JSON 을 조용히 `{_raw: "..."}` 로 바꿔 도구에 넘겼습니다.
도구는 `경로가 비었습니다` 라고 답했습니다 — **진짜 원인과 아무 상관 없는 말입니다.**
모델은 경로를 안 빠뜨렸으니 고칠 게 없다고 보고 똑같이 다시 시도했고, 또 잘렸습니다.

```
  ◆ Write(dashboard.html)
    └ 경로가 비었습니다        ← 아홉 번 똑같이

  ── 71초 · 도구 13회 · 컨텍스트가 차서 대화를 접음 · 파일은 안 생김
```

조용히 삼킨 값 하나가 그 전부를 만들었습니다. 지금은 이렇게 합니다.

| | 지금 |
|---|---|
| 안 읽히는 인자 | 삼키지 않고 **잘렸다고 표시**합니다. 도구에 넘기지 않습니다 |
| 모델에게 | 무슨 일이 났는지 그대로 말하고, 통째로 다시 보내지 말고 **뼈대만 먼저 만든 뒤 `Edit` 으로 나눠 이어 붙이라**고 알려 줍니다 |
| 잘린 내용 | 대화에 다시 넣지 않습니다 — 반쪽인 데다 컨텍스트만 먹습니다 |
| 잘림 판정 | 게이트웨이가 `finish_reason: "stop"` 이라고 해도 **인자가 깨진 것 자체를 잘린 증거로 봅니다.** 모델은 반쪽짜리 JSON 을 일부러 만들지 않습니다 |
| 같은 실패 3번 | 그 턴을 멈추고, 나눠서 시켜 보라고 말합니다 |

```
  ⊘ 같은 자리에서 헛돌고 있어 멈췄습니다.
    같은 도구 호출이 계속 잘립니다
    한 번에 만들 내용이 모델의 출력 한도보다 큽니다. 나눠서 시켜 보세요 —
    예: "뼈대만 먼저 만들어줘" → "표 부분 추가해줘" → "그래프 추가해줘"
```

**걸음 수 상한(`maxSteps`)으로는 이걸 못 막습니다.** 그건 '잘 되고 있는 긴 작업' 과
'헛도는 작업' 을 구분하지 못합니다. 여기서 세는 것은 걸음 수가 아니라
**같은 도구가 같은 이유로 실패한 횟수**입니다.

### 잠깐 막혔을 때 — 429 · 5xx · 끊김

사내 게이트웨이는 사람마다 할당량이 있어 `429` 를 자주 주고, 뒤에 붙은 모델이
재시작하면 `502`·`503` 이 몇 초 옵니다. 연결이 그냥 끊기기도 합니다. 이 셋은 몇 초 뒤
같은 요청을 다시 보내면 되는 것이라, 턴을 죽이지 않고 기다렸다 다시 부릅니다.

```
  ↻ 서버가 잠시 막았습니다 (HTTP 429) — 2초 뒤 다시 부릅니다 (1/3)
```

| | |
|---|---|
| 다시 부르는 것 | `408` `429` `500` `502` `503` `504` `529`, 그리고 머리말도 못 받고 끊긴 연결 |
| 안 부르는 것 | `400` `401` `403` `404` — 다시 불러 봐야 같습니다. 서버가 꺼진 것(연결 거부)과 시간 초과도 안 부릅니다 |
| 몇 번 | 세 번. 그 뒤에는 몇 번 불렀는지와 함께 사실대로 말합니다 |
| 얼마나 | 서버가 `Retry-After` 로 말하면 그것(60초까지). 없으면 1초 → 2초 → 4초, 30% 안에서 흔들어서 |
| 글이 흘러온 뒤에 끊기면 | 다시 안 부릅니다 — 반쯤 온 답이 두 벌이 되면 안 됩니다. 살려 쓰기가 받습니다 |
| 기다리는 중 Ctrl+C | 바로 멈춥니다 |

몇 번 다시 불렀는지는 `/cost` 에, `deel run --json` 에는 `usage.retries` 로 남습니다.
