# 늘려 쓰기

스킬 · 플러그인 · MCP · 이름 붙인 하위 작업 · 훅 · 에디터 안에서 쓰기(ACP)

---

## 스킬·플러그인

<sub>3단계로 나눠 올립니다 · 플러그인 받아 오기 · 안 넣은 것</sub>

### 3단계로 나눠 올립니다

전부 올리면 컨텍스트가 죽습니다.

| 단계 | 무엇을 | 비용 |
|---|---|---|
| 1 | 이름 + 설명 한 줄만 프롬프트에 | 40개 기준 약 1,800토큰 |
| 2 | 모델이 `Skill` 도구로 고른 것의 본문만 | 필요할 때 1개씩 |
| 3 | 본문이 가리키는 파일은 `Read` 로 | 그때 또 |

### 플러그인 받아 오기

```bash
# 온라인 기기에서
deel                                    # 대화 시작 후
/plugin install affaan-m/ECC            # git 이 있으면 clone, 없으면 tarball
/plugin pack 반입.zip                    # 실행 스크립트를 빼고 묶기

# 오프라인 기기에서 — 압축만 풀면 됩니다
unzip 반입.zip -d ~/.deel/plugins/
```

`/plugin pack` 은 `.js` `.sh` `.ps1` `.py` 같은 **실행 스크립트를 빼고** 담고,
안에 라이선스 표가 적힌 `사용안내.txt` 를 같이 넣습니다 — 그대로 반입 심사에 낼 수 있습니다.

### 안 넣은 것

| | 이유 |
|---|---|
| hooks | 실행 스크립트라 반입 심사에 걸리고, 자율 실행에 사고 경로를 늘립니다 |
| 서브에이전트 | 모델 호출이 배로 늘어 게이트웨이 할당량을 먹습니다 |
| MCP | 별도 프로토콜이라 그 자체로 하나의 프로젝트입니다 |

## 밖에서 도구 붙이기 (MCP)

<sub>다만 이건 남의 프로그램입니다</sub>

### 다만 이건 남의 프로그램입니다

이 프로젝트가 존재하는 이유가 '미승인 SW 반입 금지' 인데, MCP 를 아무렇게나 켜면
그 선을 우리 손으로 무너뜨리는 셈입니다. 그래서:

| | |
|---|---|
| **기본은 꺼져 있음** | `.deel/mcp.json` 에 직접 적어야만 뜹니다 |
| **`--offline` 이면 안 띄움** | 자식 프로세스가 어디로 나가는지 우리는 못 막습니다. **막을 수 없는 것을 막았다고 말하지 않습니다** |
| **작업 범위 밖** | MCP 서버는 우리 울타리를 안 지킵니다. `/mcp` 화면이 그렇다고 말합니다 |
| **감사기록에 남음** | 무엇을 띄웠고 무엇을 불렀는지 `.deel/audit.jsonl` 에 |
| **열쇠를 안 넘김** | 우리 환경변수를 통째로 안 넘깁니다 — `DEEL_*` 의 게이트웨이 열쇠가 남의 프로세스로 가면 어디로 가는지 알 수 없습니다 |
| **읽기 전용 모드엔 안 줌** | 이름이 '검색' 이어도 파일을 쓸 수 있습니다. 계획·설계 모드에서 '모르는 것' 을 쥐여 주면 그 약속이 약속이 아니게 됩니다 |
| **한 서버에 24개까지** | 스키마가 매 요청에 실립니다. 넘으면 자르고 **잘랐다고 말합니다** |

서버 하나가 죽거나·답이 없거나·헛소리를 해도 나머지는 그대로 씁니다.

### 두 번째부터는 안 띄웁니다

여태는 켜질 때 적힌 서버를 **전부** 띄웠습니다. 모델에게 넘길 도구 목록을 알아야
했으니까요. 그런데 그 목록은 **거의 안 바뀝니다** — 사내 위키 검색기의 도구 이름은
지난달에도 같았고 다음달에도 같을 것입니다. 그 변하지 않는 것을 알자고 매번 서버
네다섯 대를 띄우고, 악수를 두 번씩 하고, 사람은 그동안 빈 화면을 봅니다. 서버
넷이면 2초가 넘고, 그건 `deel` 을 칠 때마다입니다.

이제 목록을 `.deel/mcp-tools.json` 에 적어 둡니다. 다음부터는 **그 도구를 정말
부를 때** 띄웁니다. `/mcp` 가 ● 떠 있음 · ◐ 대기 · ○ 죽음 을 갈라 적습니다 —
대기를 죽음으로 뭉개면 사람은 없는 탈을 고치러 갑니다.

적어 둔 것이 진짜와 어긋나는 자리를 세 겹으로 막습니다.

| | |
|---|---|
| **지문이 다르면 안 씁니다** | 명령·인자·폴더·환경이 한 글자라도 바뀜으면 다른 서버입니다. 설정을 고치고 「왜 안 바뀌지」 를 겪는 일은 없습니다 |
| **일주일이 지나면 안 씁니다** | 도구가 늘어나는 서버도 있고, 영영 안 띄우면 그걸 영영 모릅니다 |
| **띄운 뒤에 맞춰 봅니다** | 다르면 그 자리에서 고쳐 적고, 부른 도구가 없어졌으면 **그렇다고 말합니다** — 「unknown tool」 한 줄로 둥글리지 않습니다 |

`DEEL_MCP_LAZY=off` 로 끕니다. 사내에서 「콠 때 다 뜼는지」 를 확인해야 하는 자리가
있고, 그때 끕 방법이 없으면 이 기능이 곳 걸림돌이 됩니다.
 안 뜬 것은
조용히 빠지지 않고 머리말에 이유가 뜹니다 — 조용히 빠지면 "왜 그 도구가 없지" 를
영영 알 수 없습니다.

## 이름 붙인 하위 작업

<sub>모드·모델·도구·지침을 파일 하나가 들고 있습니다</sub>

`Task` 는 이미 있습니다. 다만 **매번 처음부터 적어야** 합니다 — 무슨 모드로, 어느
모델에게, 무엇을 조심하며, 무엇이 끝나면 다 된 것인지. 팀에서 늘 같은 일을 시키는데도
그렇고, 그러면 매번 조금씩 다르게 적힙니다.

그 묶음에 이름을 붙여 파일 하나로 둡니다.

```json
// .deel/agents/리뷰어.json
{
  "설명": "고친 코드를 훑고 되돌릴 수 없는 것만 짚는다",
  "모드": "inspect",
  "도구": ["Read", "Grep", "Glob"],
  "걸음": 12,
  "지침": "먼저 무엇이 바뀌었는지 확인하고, 되돌릴 수 없는 것부터 본다. 취향은 적지 않는다."
}
```

그다음부터 모델이 할 일은 이것뿐입니다 —

```
Task({ agent: "리뷰어", purpose: "이번 diff 훑기", task: "…" })
```

파일 이름이 곧 에이전트 이름입니다. `.deel/agents/` (이 프로젝트)와
`~/.deel/agents/` (이 PC 전체)를 봅니다 — 이름이 겹치면 **가까운 쪽이 이깁니다.**
Claude Code 의 `.claude/agents/*.md` 앞머리 모양도 그대로 읽습니다. `/agents` 로
무엇이 정의돼 있는지 봅니다.

| 칸 | 뜻 |
|---|---|
| `설명` `description` | **필수.** 부모 모델이 고를 근거가 이 한 줄뿐입니다 |
| `모드` `mode` | `code` · `inspect` · `ask` … 안 적으면 `code` |
| `모델` `model` | 설정에 적어 둔 프로필 이름. 잔일을 작은 모델에게 |
| `도구` `tools` | 이 하위가 쓸 도구. **줄이기만 합니다** (아래) |
| `지침` `prompt` | 시킨 일보다 **앞에** 붙습니다 |
| `걸음` `maxSteps` | 걸음 수 상한 (최대 200) |

### 도구는 줄이기만 합니다

설계 모드는 「파일을 안 바꾼다」 는 약속이고, 사람은 그 약속을 믿고 `/architect` 를
켭니다. 정의 파일에 `"도구": ["Write"]` 한 줄을 적는 것으로 그 약속이 깨지면 안
됩니다 — 화면에는 여전히 설계 모드라고 뜬 채로 파일이 바뀝니다.

그래서 정의에 적은 이름 중 **지금 모드가 이미 주는 것만** 남깁니다. 모드가 안 주는
것을 적어 두면 그것만 빠지고, **빠졌다고 화면에 적습니다** — 조용히 빼면 사람은 제가
적은 도구가 도는 줄 알고, 하위가 그걸 안 했을 때 정의 파일이 아니라 모델을 의심합니다.

모드도 마찬가지로 **부모보다 셀 수 없습니다.** 읽기만 하는 모드에서 부른 하위는
정의에 `code` 라고 적혀 있어도 읽기 전용으로 내려갑니다.

### 무엇이 매 요청에 실리나

이름과 설명 한 줄뿐입니다. 지침 본문은 **고른 뒤에** 하위 프롬프트로 갑니다 — 여기
실으면 안 쓰는 에이전트의 지침까지 매 요청에 나갑니다. 스킬을 2단계로 올리는 것과
같은 셈법입니다.

없는 이름을 부르면 **조용히 그냥 돌지 않습니다.** 시킨 쪽은 「리뷰어가 본다」 고 알고
있는데 평범한 하위가 도는 셈이 되면, 그 어긋남은 결과를 읽어도 안 보입니다. 쓸 수
있는 이름을 적어 되돌려 줍니다.

끄려면 `DEEL_AGENTS=off`.

## 사내 규칙을 직접 걸기 (훅)

<sub>우리가 영영 모르는 것을 물어보는 자리</sub>

사내마다 지켜야 하는 것이 다릅니다. 어떤 팀은 `git push` 를 절대 못 하게 해야 하고,
어떤 팀은 파일을 고칠 때마다 사내 포맷터를 돌려야 하고, 어떤 팀은 사람이 친 말에
주민번호가 섞였는지를 먼저 봐야 합니다.

이걸 전부 프로그램 안에 넣을 수는 없습니다. 넣으면 팀마다 포크를 뜨게 되고, 포크를
뜨면 그 순간부터 우리가 고치는 것이 그 팀에 안 갑니다. 그래서 **자리만 내줍니다.**
무엇을 할지는 그 팀이 제 파일에 적습니다.

허락 규칙(`permissions`)과는 다른 축입니다. 규칙은 「이 무늬면 막는다」 는 표라서
우리가 아는 것만 잽니다. 훅은 아무 프로그램이나 부를 수 있어서, 사내 DLP 나 사내
승인 서버처럼 **우리가 영영 모르는 것**을 물어볼 수 있습니다.

```json
{
  "hooks": [
    { "때": "도구전", "도구": "Bash",       "명령": "python .deel/gate.py", "제한초": 10 },
    { "때": "도구후", "도구": "Write|Edit", "명령": "npx prettier --write --loglevel warn ." },
    { "때": "말전",                          "명령": "python .deel/dlp.py" }
  ]
}
```

`.deel/hooks.json` (이 프로젝트) 또는 `~/.deel/hooks.json` (이 PC 전체)에 적습니다.
Claude Code 의 `hooks` 설정 모양(`PreToolUse` · `matcher` · `{"type":"command"}`)도
그대로 받습니다 — 이미 그 파일을 갖고 있는 분에게 다시 적으라고 하면, 그분은 훅을
안 씁니다.

| 자리 | 언제 | 막을 수 있나 |
|---|---|---|
| `도구전` `PreToolUse` | 도구를 부르기 직전. 허락 규칙 뒤, 승인 물어보기 앞 | **예** |
| `말전` `UserPromptSubmit` | 사람이 친 말이 대화에 들어가기 **전** | **예** |
| `도구후` `PostToolUse` | 도구가 끝난 직후. 뱉은 글이 모델에게 갑니다 | 아니요 |
| `턴끝` `Stop` | 한 턴이 다 끝났을 때 | 아니요 |

주고받는 법은 하나뿐입니다. **넘길 것은 전부 stdin 으로 JSON 한 줄**이고
(`{"자리":"도구전","도구":"Bash","인자":{…}}`), 답은 **종료 코드**입니다.

| 코드 | 뜻 |
|---|---|
| `0` | 통과. 뱉은 글은 화면과 모델에게 갑니다 |
| `2` | **막습니다.** 뱉은 글이 그대로 까닭이 됩니다 |
| 그 밖 | 훅이 고장난 것으로 봅니다 — 막는 자리에서는 **막습니다** (아래) |

### 고장 나면 막습니다

문지기가 쓰러져 있으면 문은 잠긴 것이 아닙니다.

흔한 규격은 「2번으로 끝나면 막고, 나머지 실패는 지나간다」 입니다. 그러면 훅 파일에
오타 하나(`pythno check.py`)가 나는 순간 그 문은 조용히 열린 채로 남습니다 — 화면에는
여전히 「훅 3개」 라고 떠 있는 채로. 사내에 「걸어 뒀습니다」 라고 말해 놓고 실제로는
안 걸린 상태가 제일 나쁜 자리입니다.

그래서 **막는 자리의 훅은 고장 나면 막습니다.** 못 잰 것을 초록으로 안 세는 것과 같은
판단입니다. 지나가게 하려면 그 훅에 `"고장나면": "지나가기"` 라고 **적으셔야** 합니다 —
적힌 것만 지나갑니다.

### 이것도 남의 프로그램입니다

| | |
|---|---|
| **기본은 꺼져 있음** | `hooks.json` 에 직접 적어야만 돕니다 |
| **믿는 폴더에서만** | 프로젝트 파일은 `deel trust` 한 폴더에서만 읽습니다. 없으면 `git clone` 한 번이 곧 남의 명령이 내 PC 에서 도는 것이 됩니다 |
| **감사기록에 남음** | 무엇이 언제 돌았고 무엇을 막았는지. **통과시킨 것도** 남깁니다 — 「안 돌았다」 와 「돌았는데 통과시켰다」 는 다른 것입니다 |
| **모델 글은 명령줄에 안 감** | 도구 인자도 사람 말도 전부 stdin 입니다. 명령줄에 끼우면 그 자리가 곧 주입 구멍입니다 |
| **끌 수 있음** | `deel --no-hooks` (이번 판만) · `DEEL_HOOKS=off` (아예). 끄는 길이 안 보이는 안전 장치는 안전 장치가 아닙니다 |
| **작업 범위 밖** | 훅은 우리 울타리를 안 지킵니다. `/hooks` 화면이 그렇다고 말합니다 |
| **`--offline` 이어도 돕니다** | MCP 와 다른 점입니다. MCP 서버는 밖에서 받아 온 남의 프로그램이고, 훅은 **본인이 제 파일에 제 손으로 적은 명령**입니다 — `Bash` 도구를 안 막으면서 훅만 막으면 말이 안 맞습니다 |

승인을 훅이 대신하지 않습니다. 훅이 통과시켜도 `strict` 는 여전히 물어봅니다 —
허락은 **규칙 그리고 훅 그리고 사람**입니다.

무엇이 걸려 있는지는 `/hooks` 로, 왜 안 도는지는 `deel doctor` 로 봅니다. 제일 흔한
까닭이 믿는 폴더가 아니어서인데, 그건 어느 화면에서도 안 보이던 자리라 둘 다 그 말을
합니다.

## 에디터 안에서 쓰기 (ACP)

<sub>조용히 깨지는 자리들</sub>

이 프로토콜은 깨질 때 조용히 깨집니다. 에디터는 "에이전트가 응답하지 않습니다"
만 띄우고, 왜 그런지는 어디에도 안 남습니다. 그래서 다음 자리들을 검사로 못
박아 두었습니다 (`test/acp.test.js` — 진짜 프로세스를 띄우고 진짜 파이프로 잽니다).

| 자리 | 왜 |
|---|---|
| **표준출력에는 ACP 말고 아무것도** | 규격이 `MUST NOT` 이라 적은 것입니다. deel 안에는 화면에 적는 자리가 수십 군데인데, 그 중 하나만 이 모드에서 불려도 관이 깨집니다. 부르는 자리를 하나씩 막는 대신 **통로 자체를 바꿔 끼웠습니다** — 앞으로 새로 쓰는 코드까지 저절로 안전합니다. 적힌 글은 버리지 않고 표준오류로 보냅니다 |
| **한글이 덩이 경계에 걸칠 때** | 파이프는 글자가 아니라 바이트로 끊깁니다. 덩이마다 따로 디코딩하면 `안녕` 이 `안<?>하` 가 되는데 **JSON 은 그대로 파싱되므로 오류도 안 납니다.** 글자만 조용히 뭉개집니다 |
| **`id` 가 0 인 요청** | ACP 클라이언트는 0번부터 셉니다. `if (msg.id)` 로 보면 첫 `initialize` 를 알림으로 오해하고 답을 안 보냅니다 — 붙자마자 멈춥니다 |
| **취소가 도중에 닿는가** | 취소는 늘 무언가가 돌고 있는 중에 옵니다. 들어온 줄을 하나씩 기다렸다 처리하면 취소는 **영영 안 닿습니다** |
| **승인을 못 물어봤을 때** | 여기서 '그냥 실행' 을 고르고 싶어집니다 — 안 그러면 승인 창을 아직 안 만든 클라이언트에서 아무것도 안 도니까. 그런데 그건 "물어볼 수 없으면 마음대로 한다" 는 뜻입니다. **안 합니다** |
| **인증 방법을 안 적었을 때** | `initialize` 응답의 `authMethods` 를 비워 두면 에디터는 「이 에이전트는 인증이 필요 없다」 로 읽습니다. 그런데 deel 은 저장된 연결이 없으면 아무 일도 못 합니다 — 처음 붙인 사람은 대화를 열자마자 오류를 받고, **화면만 봐서는 이게 설정 문제인지 버그인지 모릅니다.** 규격에는 그 자리가 있습니다(Terminal Auth). 없는 것을 만드는 게 아니라 이미 있는 `deel setup` 을 **말하는** 일이었습니다 |
| **설정이 없을 때 내는 번호** | 위를 적어 놓고도 정작 설정이 없을 때 `-32602`(잘못된 인자)로 답하면 에디터는 「인증」 단추를 그릴 줄 모릅니다 — 그냥 빨간 글씨가 뜹니다. 규격이 그 자리에 정해 둔 번호는 **`-32000`(AuthRequired)** 입니다. 사람이 인자를 잘못 준 것이 아니라 **아직 설정을 안 한 것**이고, 그 둘은 에디터에서 하는 일이 다릅니다 |

### 껐다 켜도 어제 하던 얘기가 그대로

에디터를 닫았다 열면 **지난 대화가 그대로 열립니다.** 터미널에서 `--resume` 으로
되던 것이 에디터 안에서도 됩니다 — 무엇을 이미 확인했는지, 무엇을 하지 말라고
했는지를 처음부터 다시 말하지 않아도 됩니다.

대화는 터미널과 **같은 자리**(`.deel/sessions/`)에 남습니다. 그래서 에디터에서 하던
것을 터미널에서 `deel --resume <이름>` 으로 이어받는 것도 됩니다. 반대도 됩니다.

| 챙긴 자리 | 왜 |
|---|---|
| **세션 이름 = 파일 이름** | 에디터는 그 이름을 적어 뒀다가 **다음에 켤 때** 도로 들고 옵니다. `deel-1` 처럼 그 프로세스 안에서만 뜻이 있는 번호를 주면, 껐다 켠 순간 그 이름이 가리키는 것이 아무 데도 없습니다 |
| **걸음마다 적습니다** | 턴이 다 끝나고 한 번에 적으면, 도구를 열 번 돌린 뒤 에디터가 닫힌 순간 그 열 번이 통째로 사라집니다. 되살릴 때 제일 아쉬운 것이 바로 그 부분입니다 |
| **화면에 그릴 것과 모델에게 줄 것이 다릅니다** | 도구가 도는 중에 죽으면 부름만 적히고 답이 없습니다. 그대로 모델에게 보내면 **게이트웨이가 400 을 줍니다** — 되살리자마자 첫 마디에서 죽습니다. 그래서 모델에게는 손질한 것을 주고, **사람에게는 그 자리를 「끊겼습니다」로 보여 줍니다.** 어제 무엇을 하다 끊겼는지가 오늘 무엇을 시킬지를 정하기 때문입니다 |
| **못 박아 둔 것도 같이** | 안 되살리면 '접어도 요약해도 안 지워진다' 가 에디터를 닫았다 여는 한 번에 거짓이 됩니다 (`/pin`) |
| **되살린 것이 모델에게도 갑니다** | 화면에만 다시 그리고 모델에게 안 보내면, 사람은 이어서 얘기하는 줄 알고 "아까 그거 마저" 라고 합니다. 모델은 아무것도 모릅니다. **빈 대화를 여는 것보다 나쁩니다 — 사람이 속습니다.** 검사는 화면 글자가 아니라 게이트웨이가 받은 몸통으로 잽니다 |

**아직 안 하는 것도 적어 둡니다.**

| | |
|---|---|
| 그림·소리 붙임 | 로컬 모델 대부분이 못 읽습니다. 조용히 버리지 않고 "못 읽습니다" 라고 적어 모델에게 넘깁니다 |
| 에디터가 넘긴 MCP 서버 | 띄우지 않습니다. 그러면 **에디터 설정에 적힌 프로세스를 deel 이 대신 띄우는** 셈이 됩니다. 반입 심사에서 제일 먼저 묻는 것이 "이 도구가 무엇을 띄우는가" 인데, 그 답이 '에디터가 시키는 대로' 가 되면 안 됩니다. `.deel/mcp.json` 에 사람이 직접 적은 것만 띄웁니다 |

## 파이프라인에 넣기

### 답을 정해진 모양으로 — `deel run --output-schema`

`deel run` 은 글을 냅니다. 사람이 읽으면 그만이지만, 스크립트에 물리면
거기서부터 일이 시작됩니다.

```bash
deel run "이 계약서에서 계약 기간과 해지 조건을 뽑아 줘 계약.hwpx" | ???
```

뒤에 무엇을 붙일까요. 답이 매번 다른 모양으로 오니 `grep` 이나 `sed` 로
뜯어야 하고, 그 뜯는 코드는 모델이 다음번에 문장을 조금 다르게 쓰는 날
조용히 틀립니다. **조용히** 가 요점입니다 — 빈 값을 받은 스크립트는 오류를
안 내고 그냥 빈 값을 다음 단계로 넘깁니다.

모양을 미리 못 박으면 이 문제가 통째로 사라집니다.

```json
{
  "type": "object",
  "required": ["계약기간", "해지조건"],
  "properties": {
    "계약기간": { "type": "string" },
    "해지조건": { "type": "array", "items": { "type": "string" } },
    "위약금": { "type": ["number", "null"] }
  },
  "additionalProperties": false
}
```

```bash
deel run --output-schema 계약.schema.json "계약 기간과 해지 조건을 뽑아 줘 계약.hwpx" \
  | jq -r '.해지조건[]'
```

표준출력에는 **그 JSON 하나**만 나갑니다. 모델이 ```json 울타리를 두르거나
"네, 아래와 같습니다" 를 앞에 붙여도 걷어내고 냅니다 — 걷어냈다는 말은
표준오류에 적습니다. 조용히 걷어내면 시킨 말을 고칠 기회가 사라지니까요.

### 안 맞으면 어떻게 되나

| | |
|---|---|
| 한 번 더 시킵니다 | 무엇이 어떻게 안 맞았는지를 그대로 돌려주고 다시 적게 합니다. **한 번만** 입니다 — 두 번 세 번 되풀이하는 것은 모델이 못 하는 일을 억지로 시키는 꼴이고, 그 왕복은 사람이 냅니다 |
| 그래도 안 맞으면 **7** 로 끝냅니다 | 모양이 안 맞는 JSON 을 표준출력으로 흘려보내는 것이 여기서 할 수 있는 제일 나쁜 일입니다. 그건 이 기능이 없애려던 바로 그 상황입니다 |
| 표준출력은 **비웁니다** | `cmd \| jq` 처럼 쓴 자리에서는 앞 명령의 종료코드가 안 보입니다. 아무것도 안 주는 쪽이 낫습니다 — 무엇이 왔었는지는 표준오류에 이미 적혀 있습니다 |
| 스키마 파일이 잘못됐으면 **모델을 안 부릅니다** | 다 돌리고 나서 "스키마 파일이 없습니다" 라고 하면 모델을 부른 값을 통째로 버리는 셈입니다. 그리고 그건 대개 오타 하나짜리 실수입니다 |

`--json` 과 같이 쓰면 결과 덩이의 `schema` 칸에 들어갑니다 — `text` 를 다시
파싱할 필요가 없습니다.

### 안 재는 것은 안 잰다고 말합니다

JSON Schema 규격을 다 받지는 않습니다. `type` · `required` · `properties` ·
`items` · `enum` · `minimum` · `pattern` · `anyOf` 같은 것들을 재고,
목록에 없는 열쇠는 **본 척하지 않고 그냥 넘깁니다.** 대신 무엇을 안 봤는지
화면에 적습니다.

```
  ⚠ 스키마에서 안 재는 열쇠가 있습니다: format · deprecated
```

모르는 규칙을 아는 척 통과시키는 것이 모르는 채로 두는 것보다 나쁩니다 —
사람은 잰 줄 알고 지냅니다.

**`$ref` 로 바깥을 안 봅니다.** 규격은 `$ref` 에 주소를 적을 수 있고 검사기
대부분이 그걸 받아 옵니다. 우리는 안 받아 옵니다 — 스키마 파일 하나가
「나가는 주소는 사람이 정한 하나뿐」 을 깨뜨리는 길이 되면 안 됩니다.
바깥을 가리키는 스키마는 **읽는 자리에서 거절**하고, 같은 파일 안
(`#/$defs/...`)으로 바꾸라고 합니다.
