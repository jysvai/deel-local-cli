## 대화 중 명령

<sub>@파일 로 바로 붙이기 · /commit · 도중에 멈추기</sub>

### `@파일` 로 바로 붙이기

말 속에 `@` 뒤로 경로를 쓰면 그 파일을 말과 함께 바로 보냅니다.

```
❯ @src/a.js 이거 왜 느려?
  ◧ 붙임 src/a.js
```

모델이 `Read` 를 스스로 부르는 **왕복 한 번이 없어집니다.** 로컬 모델은 도구 호출이
약해서 그 한 번이 자주 헛돕니다 — 엉뚱한 경로를 부르거나, 아예 안 부르고 지어냅니다.
사람은 이미 어느 파일인지 아는데 모델더러 찾아보라고 시킬 이유가 없습니다.

어려운 것은 붙이는 일이 아니라 **아닌 것을 파일로 오해하지 않기** 입니다.
`@` 로 시작하는 것은 세상에 널렸습니다.

| 이렇게 쓰면 | 어떻게 되나 |
|---|---|
| `@src/a.js` | 붙습니다 — 실제로 있는 경로일 때만 |
| `hong@example.com` | 지목으로 안 봅니다. `@` 앞에 글자가 붙어 있으면 주소입니다 |
| `@media` · `@dataclass` · `@scope/pkg` | 그대로 둡니다 — 그런 경로가 없으니까 |
| `@src/` 처럼 폴더 | 안에 든 것을 목록으로 붙입니다 |
| `@"보고서 초안.txt"` | 띄어쓰기가 든 이름은 따옴표로 묶습니다 |
| 작업 범위 밖 | 안 붙이고, 왜 안 붙였는지 화면에 알립니다 |
| CP949 사내 문서 | 무엇으로 쓰였는지 알아보고 제대로 붙입니다 |

규칙은 하나입니다 — **실제로 있는 경로일 때만 붙입니다.** 없으면 아무 말 없이
글자 그대로 둡니다. 지목이 아니었을 테니 조용한 편이 맞습니다.

붙이는 양은 컨텍스트 길이의 **25%**(많아야 20,000토큰)까지입니다. 그보다 크면 앞부분만 붙이는데,
이때는 **'읽은 것' 으로 치지 않습니다.** 잘린 파일을 읽은 것으로 쳐 두면 모델이
안 본 자리를 그냥 고쳐 버립니다. 통째로 붙은 파일만 `Read` 를 건너뜁니다.

붙인 것은 화면에 반드시 알립니다. 사람이 안 보낸 글이 대화에 들어가 있는데
그걸 모르면, 컨텍스트가 왜 줄었는지도 알 수 없습니다.

### 화면 사진 보여 주기

`.png` · `.jpg` · `.gif` · `.webp` 는 글이 아니라 **그림으로** 보냅니다.
`Read shot.png` 도, `@shot.png` 도 같습니다.

```
❯ @오류화면.png 이거 왜 이래?
  ◧ 붙임 오류화면.png (그림 · 340KB)
```

붙어 있는 모델이 그림을 볼 수 있는지는 처음 붙일 때 **1×1 짜리 흰 점 하나**로
물어봐서 알아 둡니다 (`deel setup` 의 `그림 보기` 칸). 이름으로 짐작하지 않습니다 —
사내 게이트웨이는 `gpt-4o` 라는 이름 뒤에 무엇이든 걸어 둘 수 있고, 로컬에 받아 둔
모델은 이름이 제각각입니다.

**못 보는 모델에게는 바이트를 아예 안 보냅니다.** 보내 봐야 400 이 오거나, 더 나쁘게는
서버가 조용히 무시하고 답을 지어냅니다 — 그러면 사람은 모델이 화면을 봤다고 믿습니다.
대신 "이 모델은 그림을 못 봅니다" 한 줄로 끝냅니다.

| | |
|---|---|
| 한 장 한도 | 4MB. 넘으면 안 보내고, 얼마나 큰지 말해 줍니다. 줄여 주지는 않습니다 — 아무것도 안 깔고 도는 것이 이 도구의 규칙입니다 |
| 이름은 png 인데 속은 JPEG | 속을 보고 맞는 것으로 보냅니다. 이름만 믿고 보내면 게이트웨이가 400 을 줍니다 |
| 그림 주소를 받아 저장했더니 로그인 화면 HTML | 그림이 아니라고 말해 줍니다 |
| 창이 차오르면 | 오래된 그림부터 뺍니다 (최근 2장은 남깁니다). 사람이 쓴 말은 한 글자도 안 건드립니다 |

#### 캡처는 저장 안 해도 됩니다 — `/paste`

오류 화면 하나 물어보려고 **캡처 → 그림판 → 저장 → 경로 찾기** 를 거쳐야 했습니다.
그 네 걸음이 사람을 「그냥 말로 설명하자」로 되돌립니다. 캡처는 이미 클립보드에
있으니, 꺼내 오기만 하면 됩니다.

```
(Win+Shift+S 로 화면 캡처)

❯ /paste
  ◧ 클립보드에서 가져와 앉혔습니다 .deel/붙인그림/2026-03-04_05-06-07.png (182KB)

❯ @.deel/붙인그림/2026-03-04_05-06-07.png 이거 왜 이래?
```

`/paste` 는 그림을 `.deel/붙인그림/` 에 앉히고 `@경로` 한 줄로 바꿔 줍니다. 붙이는
일은 위의 `@` 길이 그대로 하므로, 예산 셈도 못 보는 모델 처리도 한 벌뿐입니다.
**어느 파일이 나가는지 경로를 보여 줍니다** — 안 보이면 엉뚱한 캡처가 나가도
알아차릴 자리가 없습니다.

새로 까는 것은 없습니다. 윈도우는 파워셸의 .NET 클립보드, 맥은 `osascript` 로
꺼냅니다 — 둘 다 그 운영체제에 원래 있는 것입니다. 리눅스는 `wl-paste` 나
`xclip` 이 필요한데, 없으면 **무엇을 깔면 되는지** 알려 줍니다.

세 가지를 갈라 말합니다. 「클립보드에 그림이 없다」(캡처를 다시 하면 됩니다) ·
「못 꺼냈다」(까닭과 길을 줍니다) · 「이 모델은 그림을 못 본다」(보내기 전에
말합니다). 뭉뚱그려 "안 됩니다" 로 내면 무엇을 고쳐야 할지 알 수 없습니다.

> `.deel/` 안에 두지만 **열쇠가 든 `config.json` 은 `@` 로도 안 붙습니다.**
> 붙인 그림을 이 폴더에 두면서 여기가 `@` 로 닿는 자리가 됐는데, `Read` 도구는
> 막고 있던 것을 `@` 는 안 막고 있었습니다. 도구는 막고 `@` 는 안 막으면 막은
> 것이 아닙니다. 지금은 둘 다 막습니다.

### `/commit` — 이번 대화가 바꾼 것만 남깁니다

일은 결국 git 을 거쳐야 남습니다. 그 마지막 한 걸음을 모델이 `Bash` 로
`git commit -m "…"` 를 쳐서 하면 세 군데서 샙니다 — 윈도우에서 따옴표가 깨져
메시지가 한 줄로 쪼그라들고, `git add -A` 가 옆 창에서 고치던 남의 파일까지
쓸어 담고, deel 이 이미 아는 증거(`/evidence`)가 한 글자도 안 들어갑니다.

```
❯ /commit
  담은 것 — 파일 2개
    · src/tools/ignore.js
    · test/ignore.test.js

  메시지
    feat: git 이 안 보는 것은 도구도 안 본다

    Glob 이 빌드 산출물을 그대로 훑어 답이 잘리고 있었다.

    검증: 2건 확인 · 0건 미확인
    Generated-by: deel 1.5.8 · qwen2.5-coder-7b

  ✓ 477b88b  feat: git 이 안 보는 것은 도구도 안 본다
     push 는 안 했습니다. 되돌리려면 git reset --soft HEAD~1
```

| 이렇게 치면 | 어떻게 되나 |
|---|---|
| `/commit` | 이번 대화가 건드린 파일만 담고 커밋합니다 |
| `/commit 전부` | 작업 폴더의 모든 변경을 담습니다 |
| `/commit 미리보기` | 메시지와 상태만 보여 주고 **안 찍습니다** |
| `/commit <제목>` | 제목은 그대로 쓰고 본문만 짓습니다 |

메시지는 지금 대화가 아니라 **담긴 diff 와 증거**를 보고 짓습니다. 대화를 통째로
보내면 모델이 제가 한 말을 근거로 제 커밋 메시지를 쓰게 되는데, 커밋에 실릴 것은
코드가 말하는 것이어야 합니다. 저장소의 최근 제목 열 개도 같이 보여 주므로,
그 저장소가 `feat:`·`fix:` 를 쓰면 따라 쓰고 안 쓰면 안 따라 씁니다.

고친 뒤에 아무것도 안 돌렸으면 메시지에 `검증: 0건 확인 · 1건 미확인` 이 적힙니다.
나중에 이 커밋을 읽는 사람에게 그때 무엇이 확인됐는지는 그 줄이 유일한 단서입니다.

**push 는 하지 않습니다.** 되돌릴 수 있는 자리(로컬 커밋)와 못 되돌리는 자리
(남이 보는 곳) 사이에는 사람이 한 번 있어야 합니다. 남이 먼저 담아 둔 것(index)도
말없이 풀지 않습니다 — 대신 "먼저 담겨 있던 것도 같이 실립니다" 라고 알립니다.

`전부` 는 **작업 폴더 전부**지 저장소 전부가 아닙니다. 큰 저장소의 하위 폴더에서 켰다면
그 폴더 밖은 안 담습니다 — 옆 팀 폴더가 이 커밋에 딸려 들어가면 그 내용이 커밋 메시지를
지으러 모델에게도 나갑니다.

`전부` 라고 해도 **`.deel/` 은 안 담습니다.** 거기에 게이트웨이 열쇠(`config.json`)와
감사기록이 있습니다. 한 번 커밋에 실린 열쇠는 되돌려도 이력에 남습니다. 이름이 다른
링크로 딸려 들어온 것도 담은 뒤에 실제 자리를 다시 보고 도로 뺍니다. 못 빼면 커밋을
아예 안 합니다.

커밋 메시지에서 **모델이 쓴 부분은 걸러서** 넣습니다. 터미널 제어문자(ESC)는 빼고 —
안 그러면 보이는 미리보기와 실제로 적히는 글이 다를 수 있고, 그 글자가 나중에 남의
`git log` 에서 다시 돕니다 — `Signed-off-by:` 같은 꼬리표도 지웁니다. 없는 사람의
서명이 이력에 남으면 그걸 세는 도구들이 진짜로 읽습니다.

`/commit` 은 저장소의 `pre-commit` · `commit-msg` 훅을 그대로 돌립니다(git 이 원래 그렇습니다).
남의 저장소에서 처음 쓸 때는 그 훅이 무엇을 하는지 한 번 보세요.

git 이 없거나, 저장소가 아니거나, 담을 것이 없으면 한 줄로 그렇게 말하고 끝납니다.

### 도중에 멈추기

모델이 엉뚱한 길로 가는 게 보이면 **Ctrl+C** 로 그 자리에서 끊습니다.

```
❯ 전체 테스트 다시 짜줘
  ◧ Read  test/smoke.js
  ◧ Read  test/loop.test.js
^C
  ⚠ 중단했습니다 (2단계까지)

❯ ▊
```

끊어도 대화는 성한 채로 남습니다 — 모델이 부르겠다고 한 도구가 있으면 그 자리에
`중단했습니다` 결과를 채워 짝을 맞춥니다. 짝이 깨진 대화는 다음 요청에서 게이트웨이가
400 으로 거절하기 때문에, 이걸 안 하면 세션 하나가 통째로 못 쓰게 됩니다.
돌던 도구는 끝까지 돌고, **아직 시작 안 한 것은 실행되지 않습니다.**

빈 줄에서 한 번 더 Ctrl+C 를 누르면 프로그램이 끝납니다.

### 멈추지 않고 방향만 틀기

Ctrl+C 는 **지금까지 한 것을 통째로 버립니다.** 그런데 대개 하고 싶은 말은
"다 버려라" 가 아니라 "그건 말고 저것부터" 입니다. 로컬 모델은 한 턴이 몇 분씩
가는데, 그동안 친 말이 턴이 끝날 때까지 기다리기만 하면 그 몇 분은 이미 틀린
길로 갑니다.

**일하는 도중에 그냥 치고 Enter 를 누르면 됩니다.**

```
❯ 전체 테스트 다시 짜줘
  ◧ Read  test/smoke.js
❯ 아, 그건 말고 실패한 것부터 봐줘
  ❯ 아, 그건 말고 실패한 것부터 봐줘  (도중에 낀 말 — 다음 걸음부터 반영됩니다)
  ◧ Read  test/loop.test.js
```

낀 말은 **다음에 모델을 부를 때** 같이 실려 나갑니다. 하던 일을 버리지 않고
방향만 틉니다. 지금 날아가고 있는 요청은 되돌릴 수 없으니 그 한 걸음은 끝까지
갑니다 — 그 다음 걸음부터 바뀝니다.

| | |
|---|---|
| 도구를 부르는 중이라면 | 도구 답이 다 붙은 **뒤에** 들어갑니다. 도구 부름과 그 답 사이에 사람 말이 끼면 대화 모양이 깨져 게이트웨이가 400 을 줍니다 |
| 슬래시 명령(`/mode`·`/undo`)을 쳤다면 | 턴 한가운데서 안 먹입니다. 설정과 파일을 건드리는 것이라, 무엇이 어느 설정으로 돌았는지가 흐려집니다. 큐에 그대로 뒀다가 턴이 끝나고 처리합니다 |
| 턴이 시작되기 **전에** 쳐 둔 말 | 원래대로 다음 턴이 됩니다. 끼어들기는 가던 길을 트는 것이지, 줄 서 있는 것을 당겨오는 것이 아닙니다 |
| 화면에 안 보이면 | 안 먹은 것입니다. 먹은 말은 반드시 위처럼 한 줄로 찍습니다 — 안 보여 주면 사람이 한 번 더 쳐서 같은 말이 두 번 나갑니다 |

발견된 스킬의 명령은 `/<플러그인>:<이름>` 으로 부르고 `$ARGUMENTS` 가 치환됩니다.

### 저절로 옮겨 가기 (종합 모드)

처음에는 **종합** 으로 시작합니다. 무슨 일이 올지 모르는 상태입니다.
한마디를 받을 때마다 그 말을 보고 알맞은 모드로 옮겨 간 다음 일합니다.

```
❯ 로그인이 왜 안 되지?

  ◉ 디버그 (debug)  말 속에 '왜 안 되', '왜 안' 가 있어서
  다르면 /code 처럼 직접 고르세요. 그때부터는 안 바뀝니다.
```

옮겨 가면 그 모드의 **절차·도구·추론 설정이 전부** 따라옵니다.
"디버그 모드입니다" 라고 이름만 붙는 게 아니라, 실제로 증상→재현→가설→증거 순서를
밟게 하고, 계획 모드에서는 `Write`·`Edit` 를 아예 안 줍니다.

| 이런 말이면 | 이 모드로 |
|---|---|
| 왜 안 돼 · 에러 · 실패 · 죽어요 · 원인 | ◉ 디버그 |
| 계획 · 순서 · 로드맵 · 먼저 잡자 | ☰ 계획 |
| 설계 · 구조를 어떻게 · 아키텍처 · 어떻게 나눌까 | ◈ 설계 |
| 뭐야? · 설명해줘 · 어떻게 동작해 · 차이가 뭐야 | ◇ 묻기 |
| 전체 · 전부 · 하나씩 · 끝까지 · 통일 | ❋ 총괄 |
| 고쳐줘 · 만들어줘 · 구현해줘 · 지워줘 | ◆ 코드 |

**애매하면 안 옮깁니다.** "음", "ㅇㅇ", "계속해줘", "아까 그거" 같은 말에는
종합 그대로 있습니다. 1등과 2등이 비슷할 때도 안 옮깁니다 —
잘못 옮겨서 읽기 전용 모드에 갇히면 사용자는 *왜* 막혔는지 모른 채 막힙니다.
그래서 읽기 전용 모드(계획·설계·묻기)는 문턱을 더 높게 뒀습니다.
"설명해주고 고쳐줘" 는 묻기가 아니라 코드로 갑니다.

옮겨 간 것은 **그 한마디에만** 붙습니다. 다음 말은 다시 처음부터 고릅니다.
상태줄에 `~` 가 붙으면 저절로 옮겨 간 것이고, 없으면 직접 고르신 것입니다.

```
◎ 종합        ← 대기 중
~◉ 디버그      ← 이번 한마디만 저절로
◉ 디버그       ← /debug 로 직접 고름. 저절로 안 바뀝니다
```

직접 고르면 그때부터 **고정** 됩니다. 다시 맡기려면 `/auto` 또는 `/work 종합`.

### 입력칸

터미널에서 그냥 켜면 **대화는 위로 흘러가고, 맨 아래에 입력 상자가 붙습니다.**
상자만 우리가 지우고 다시 그립니다 — 위쪽 대화는 손대지 않습니다.

```
  ❊ Grep(console.log)
    └ 3개 파일 · 11건
  ◈ Edit(src/runner.js)
    └ 1군데 +3-1
    - 12 console.log('시작', 이름)
    + 12 logger.info({ 단계: '시작', 이름 })

  ▌ 로그 호출을 logger 형식으로 통일했습니다. runner.js 한 군데입니다.

  ── 4.2초 · 도구 3회 · ↑3,900 ↓180

 ▏myproject · qwen2.5-coder:7b ▏ ▰▰▱▱▱▱▱▱ 22% ▏ ◎ 종합 · ◇ medium · ⏵⏵ 자동
 ╭─────────────────────────────────────────────────────────────────────────────╮
 │ ❯ 집계 함수도 줄여줘                                                        │
 ╰─────────────────────────────────────────────────────────────────────────────╯
```

터미널 스크롤·복사·`Ctrl+F` 찾기가 **그대로 됩니다.** 대화를 우리 칸에 가둬 두지
않기 때문입니다. 긴 글을 치면 상자가 알아서 여러 줄로 늘어납니다.

**저절로 꺼지는 자리가 있습니다.** 파이프·리다이렉트로 넘길 때, `CI` 가 켜져 있을 때,
`TERM=dumb` 일 때, 창이 40칸보다 좁을 때는 묻지 않고 상자를 안 그립니다.
`deel … | tee 기록.txt` 가 제어문자 덩어리가 되면 안 되기 때문입니다.
`--tui` 를 줘도 파이프면 안 켭니다. `--no-tui` 로 언제든 끌 수 있습니다.

줄 편집은 전부 Node 의 readline 이 그대로 맡습니다 — 한글 조합, 붙여넣기,
위아래 이력, Ctrl+A/E, 백스페이스. 우리는 readline 이 들고 있는 글을 상자 안에
**그리기만** 합니다. 직접 키를 받아 줄 편집을 짜기 시작하면 한글 입력기부터 깨집니다.

> **한 번 틀렸던 길** — 처음에는 터미널을 통째로 빌려(vim 처럼 딴 화면) 대화 칸·
> 파일 칸·할 일 칸을 나눠 그렸습니다. 보기에는 그럴듯했는데 **슬래시 명령이 전부
> 먹통**이 됐습니다. `commands.js` 를 비롯한 여섯 모듈이 화면 객체를 안 거치고
> 터미널에 바로 쓰는데, 매번 화면을 통째로 다시 그리니 그 글이 찍히자마자 덮여
> 사라졌던 것입니다. 명령이 안 도는 게 아니라 **결과가 안 보이는** 것이라 더
> 나빴습니다. 고치려면 터미널에 쓰는 자리를 전부 화면 객체로 꿰야 하는데, 지금
> 여섯 곳이고 앞으로 늘 것이며, 하나라도 빠뜨리면 같은 증상이 조용히 돌아옵니다.
> 그래서 반대로 갔습니다 — 대화는 그냥 흘려보내고 상자만 관리합니다.

### 여러 줄로 한 메시지 보내기

**줄 끝에 빈칸과 `` ` `` 를 붙이고 Enter** 를 치면 다음 줄로 넘어갑니다.
`` ` `` 없이 끝나는 줄에서 Enter 를 치면 그때 한 메시지로 묶여 나갑니다.

```
❯ 이 세 파일을 봐줘 `
   src/a.js `
   src/b.js
```

**이 방법은 어느 터미널에서나 됩니다.** 중간에 마음이 바뀌면 `Ctrl+C` 로 버립니다.

빈칸이 앞에 있어야 하는 이유는 `` read `config.json` `` 처럼 **인라인 코드로
끝나는 평범한 요청**과 가르기 위해서입니다. 그런 줄이 안 보내지고 갇히는 것이
1.5.0 의 결함이었습니다.

#### `Shift+Enter` 는 왜 안 되나

**터미널이 그 조합을 구분해서 보내 주지 않기 때문입니다.** `Shift+Enter` ·
`Ctrl+Enter` · `Command+Enter` 는 대부분의 터미널에서 그냥 Enter 와 **똑같은
바이트**(`\r`)로 나갑니다. 프로그램 쪽에서는 둘을 구분할 방법이 아예 없습니다 —
안 만든 것이 아니라 못 받는 것입니다.

`Alt+Enter`(맥은 `Option+Enter`)만 다릅니다. 이건 앞에 ESC 가 붙어서 나가므로
구분할 수 있고, deel 도 그것만 받습니다.

#### 맥에서 `Option+Enter` 가 안 먹을 때

macOS 터미널은 **기본값이 Option 을 Meta 로 안 보냅니다.** 그래서 아무 조합도
안 먹는 것처럼 보입니다. 한 번만 켜 주면 됩니다.

| 터미널 | 켜는 곳 |
|---|---|
| **Terminal.app** | 설정 → 프로파일 → 키보드 → **`Option을 Meta 키로 사용`** 체크 |
| **iTerm2** | Settings → Profiles → Keys → Left Option key → **`Esc+`** |
| **VS Code 터미널** | `terminal.integrated.macOptionIsMeta` 를 `true` 로 |
| **Warp · Ghostty · WezTerm** | 대개 기본으로 보냅니다 |

켜기 싫으면 위의 백틱 방법을 쓰면 됩니다. 그쪽이 설정 없이 어디서나 됩니다.

### 명령은 다 안 쳐도 됩니다

명령이 서른 개가 넘습니다. 다 외우고 있는 사람은 만든 사람뿐이고, 그마저도
`/mem…` 까지 치고 "이게 memory 였나 memo 였나" 하고 멈춥니다. 그때 할 수 있는
것이 `/help` 를 쳐서 서른 줄을 받아 눈으로 훑는 것뿐이면, 그건 명령이 아니라
시험입니다.

그래서 **치는 도중에 보여 줍니다.**

```
 ╭─────────────────────────────────────────────────────────────────────────────╮
 │ ❯ /mo                                                                       │
 ╰─────────────────────────────────────────────────────────────────────────────╯
   › /model [이름|list|models]   연결·모델 바꾸기 (이름 일부 · list · models)
     /mode <모드>                승인 정책 — 얼마나 물어보나
     /memory [지우기 <번호>|…]   대화가 끝나도 남는 기억 — 보기·지우기
```

`Tab` 을 누르면 채워집니다. 하나만 맞으면 끝까지, 여럿이면 **다 같이 가진
앞부분까지만** 채웁니다(`/mo` + Tab → `/mode`). 하나를 골라 박아 넣지 않는
것은, 사람이 원한 것이 아닐 때 지우는 수고가 더 들기 때문입니다. 인자를 받는
명령이면 빈칸까지 붙여 바로 이어 칠 수 있게 합니다.

앞에서 맞는 것을 먼저 보여 주고, **가운데 맞는 것도 뒤에 붙입니다** — 오타는
앞글자에서 제일 많이 나므로, `/emo` 라고 잘못 쳐도 `/memory` 가 나옵니다.
빈칸을 치는 순간(`/mode auto`) 목록은 접힙니다. 명령이 이미 정해졌기 때문입니다.

목록은 **상자 아래**에 붙습니다. 안에 넣으면 치던 글이 밀려 올라가서 무엇을
치고 있었는지가 안 보입니다.

> 위아래 화살표로 고르게 하지 않습니다. 그러면 **지난 입력 이력**(위 화살표)을
> 뺏어야 하는데, 그건 훨씬 자주 쓰는 기능입니다. 여기서 필요한 것은 고르는
> 것이 아니라 **알아보는 것**이고, 알아보고 나면 Tab 한 번이면 됩니다.
>
> `쉬움` 수준에서 감춰 둔 명령도 앞글자를 치면 나옵니다. 감춘 것은 '못 쓰는
> 것' 이 아닙니다 — `/recall` 을 아는 사람이 수준 설정 때문에 "그런 명령
> 없다" 는 화면을 보면 안 됩니다.

### 셸에서도 탭이 됩니다 — `deel completion`

위의 것은 대화 **안**에서 `/명령` 을 칠 때입니다. 대화를 **켜기 전에** 치는
`deel sbom` · `--effort` 같은 것은 도움말을 읽어야 알 수 있었습니다.

```
deel completion bash       > ~/.deel-completion.bash   # 그리고 .bashrc 에서 source
deel completion zsh        > ~/.deel-completion.zsh
deel completion powershell | Out-File -Encoding utf8 -Append $PROFILE
```

넣고 나면 이렇게 됩니다.

```
$ deel sb<TAB>
sbom

$ deel --mode <TAB>
auto  code  architect  ask  debug  plan  orchestrator

$ deel --think <TAB>
off  low  medium  high  max
```

`--mode` · `--think` · `--effort` 의 값 목록은 **코드에서 그대로 가져옵니다.**
손으로 베껴 적으면 언젠가 갈리는데, 완성이 없는 값을 알려 주는 것은 도움말이
틀린 것보다 나쁩니다 — 도움말은 안 읽으면 그만이지만 완성은 없는 것을 있다고
우깁니다. 같은 까닭으로 명령 목록이 실제 명령과 어긋나면 검사가 빨개집니다.

> **파워셸 스크립트만 영어입니다.** 윈도우에 기본으로 깔린 Windows PowerShell
> 5.1 은 BOM 없는 `.ps1` 을 UTF-8 이 아니라 그 PC 의 옛 코드페이지(CP949)로
> 읽습니다. 그러면 한글 두 바이트를 짝지어 먹다가 **닫는 따옴표까지 삼켜서**
> 스크립트가 통째로 문법 오류가 됩니다. 진짜 파워셸에 넣어 보고 알았습니다.

### 일하는 중에는 상자가 그대로 있습니다

로컬 모델은 느립니다. 한 걸음에 수십 초가 걸리는데 그 동안 화면 아래가 텅 비면
**멈춘 줄 알고 Ctrl+C 를 누르게 됩니다** — 다 되어 가던 일이 그렇게 날아갑니다.
그래서 테두리는 그대로 두고 안엣것만 바꿉니다.

```
  ◧ Read(집계.py)
    └ 6줄

 ▏myproject · qwen2.5-coder:7b ▏ ▰▱▱▱▱▱▱▱▱▱ 2% ▏ ◎ 종합 · ◇ medium · ⏵⏵ 자동 ▏ ↑3.8k ↓180
 ╭─────────────────────────────────────────────────────────────────────────────╮
 │ ⠹ 파일 들여다보는 중…                    12초 · 생각 1,240자 · Ctrl+C 중단 │
 ╰─────────────────────────────────────────────────────────────────────────────╯
```

문구는 **지금 진짜로 하는 일**을 따라갑니다. 재미로 넣은 것이 아닙니다 —
아무 말이나 돌려 대면 두 번째부터 아무도 안 읽고, 그때부터는 화면이 조용한 것과
같아집니다. 한 턴을 돌리면 이렇게 지나갑니다:

```
머리 굴리는 중  →  파일 들여다보는 중  →  코드 짜는 중  →  답 쓰는 중
```

| 하는 일 | 문구 |
|---|---|
| 생각 | 머리 굴리는 중 · 어떻게 할지 궁리하는 중 · 수 읽는 중 · 따져 보는 중 |
| `Read` `Grep` `Glob` | 파일 들여다보는 중 · 코드 훑는 중 · 어디 있나 뒤지는 중 · 단서 찾는 중 |
| `Write` `Edit` `Append` | 코드 짜는 중 · 고쳐 넣는 중 · 손보는 중 · 한 줄씩 옮기는 중 |
| `Bash` | 명령 돌리는 중 · 터미널 두드리는 중 · 결과 기다리는 중 |
| `WebFetch` | 문서 찾아보는 중 · 읽어 오는 중 |
| 답하는 중 | 답 쓰는 중 · 정리해서 말하는 중 |
| **45초가 넘으면** | 아직 하는 중 · 조금만 더 · 생각보다 오래 걸리는 중 |

### 왼쪽 그림도 같이 움직입니다

문구 옆에서 도는 것은 돌림표가 아니라 **지금 하는 일을 그린 작은 그림**입니다.

| 하는 일 | 한 바퀴 | 그림 |
|---|---|---|
| 생각 | `⠀⠶⠀` `⠰⣿⠆` `⢾⣿⡷` `⠰⣿⠆` | 부풀었다 줄어든다 |
| 읽기 | `⠉⠉⠉` `⠒⠒⠒` `⠤⠤⠤` `⣀⣀⣀` | 훑는 줄이 내려간다 |
| 쓰기 | `⡼⠭⠧` `⠼⡯⠧` `⠼⠿⡧` `⠼⡭⠧` | **노트북이 자판을 두드린다** |
| 명령 | `⠉⠀⠀` `⠉⠈⠀` `⠛⠊⠀` `⠿⠮⠄` | 결과가 한 줄씩 쌓인다 |
| 답 | `⠉⠀⠀` `⠛⠉⠀` `⠿⠛⠉` `⣿⠿⠛` | 글이 차오른다 |
| 웹 | `⣀⣀⣀` `⣤⣀⣀` `⣶⣤⣀` `⣿⣶⣤` | 신호 막대가 자란다 |
| 접기 | `⣿⣿⣿` `⣶⣶⣶` `⣤⣤⣤` `⣀⣀⣀` | 눌려서 한 줄로 모인다 |
| 45초 넘으면 | `⠶⠀⠀` `⠰⠆⠀` `⠀⠶⠀` `⠀⠰⠆` | 왔다 갔다 — '기다리는 중' |

점자만 씁니다. 점자 한 칸은 **가로 2 · 세로 4 점**이라 세 칸이면 6×4 격자가 되고,
어느 터미널에서나 정확히 한 칸입니다. 이모지나 `●` `▪` 는 동아시아 로캘에서 두 칸으로
잡히는 것이 섞여 있어 90ms마다 테두리가 어긋납니다.

그림이 안 나오거나 화면 읽기 프로그램을 쓰신다면 `DEEL_NO_MOTION=1` 로 끄면
예전처럼 한 칸짜리 돌림표만 돕니다.

#### 그림을 바꾸고 싶다면

**`/motion` 으로 고릅니다.** 치면 그 자리에서 바뀌고, 고른 것은 설정에 남아서
다음에도 그대로입니다. 그냥 `/motion` 만 치면 지금 뭐가 켜져 있는지 보여 줍니다.

```
/motion 기사     ⚔ 기사와 용
/motion 동물     🐢 거북이와 토끼
/motion 사무실   사람들이 일하는 방 (아래 참고)
/motion 끔       아무것도 안 돌림
/motion 기본     처음 그림으로
```

| 값 | 무엇이 나오나 |
|---|---|
| `기본` | 덩어리·막대·훑는 줄 — 무엇을 하는 중인지 말한다 |
| `기사` 또는 `knight` | **중세 기사.** 코드를 쓰는 동안 칼을 휘두르고, 읽는 동안 방패를 들고 나아갑니다 |
| `동물` 또는 `animal` | **픽셀 동물들.** 걷고, 뛰고, 기지개를 켭니다 |
| `사무실` 또는 `office` | 입력 상자 위에 열두 줄짜리 방 |
| `끔` 또는 `off` | 한 칸짜리 돌림표만 |

한 번만 다르게 보고 싶으면 환경변수도 그대로 됩니다. **환경변수가 설정을
이깁니다** — 그 상태에서 `/motion` 을 치면 그렇다고 알려 줍니다.

```bash
DEEL_MOTION=기사 deel
DEEL_OFFICE=1 deel
```

기사와 동물은 12×4 격자(점자 여섯 칸)를 씁니다 — 사람이나 짐승 모양은 6×4 에
넣으면 그냥 얼룩으로 보이기 때문입니다. 세로는 못 늘립니다. 작업 표시가 글자
한 줄 안에 들어가야 해서, 두 줄로 만들면 상자 높이와 커서 셈이 통째로 달라집니다.
그래서 **가로로 누운 옆모습**으로 그렸습니다.

45초가 넘어가면 기사는 **지쳐 쓰러졌다 다시 일어나고**, 동물은 **드러누워 잡니다.**
오래 걸리는 중이라는 것을 숨기지 않으면서, 화면은 계속 살아 있게 하려는 것입니다.

`DEEL_NO_MOTION=1` 은 테마보다 셉니다 — 점자가 안 나오는 자리에서는 테마가
소용없기 때문입니다. 모르는 이름을 주면 조용히 기본으로 갑니다.

### 사무실 — 지금 무슨 일이 도는지를 방 하나로

```
/motion 사무실
```

입력 상자 **위에** 열두 줄짜리 방이 붙습니다. 작업이 시작되면 그 자리에서
움직입니다 — 자리에 사람이 앉고, 자판을 두드리고, 서류를 보고, 오래 걸리면 존다.

**규칙이 하나 있습니다: 화면에 있는 것은 전부 진짜 숫자입니다.**
꾸미려고 놓은 것은 하나도 없습니다.

| 방 안의 것 | 무슨 값인가 |
|---|---|
| 방 안의 사람 수 | 지금 동시에 도는 일(읽기 도구 묶음 + 하위 작업) **+ 남은 할 일** |
| 밝은 화면 | 지금 도는 일 |
| 흐린 화면 | 맡았지만 아직 차례가 안 온 일 |
| 자세 | 자판(쓰기)·서류(읽기)·조는 중(45초 초과) |
| 방을 돌아다니는 사람 | 자리가 모자라 못 앉은 사람. 셋 이상이면 늘 하나는 일어나 있습니다 |
| 책상 위 머그 | 45초를 넘긴 자리 (조는 것과 같은 값) |
| 화이트보드 쪽지 | 할 일. 초록이 끝난 것, 노랑이 남은 것 |
| 서류함 서랍 | 읽은 파일 (일곱 개마다 한 칸) |
| 서버 불빛 | 모델을 부른 횟수 |
| 창밖 아침·낮·노을·밤 | 컨텍스트가 얼마나 찼나 (25% · 55% · 80% 에서 넘어갑니다) |
| 벽시계 바늘 | 이번 턴이 얼마나 걸렸나 (한 바퀴가 1분) |
| 책상 위 종이 | 고친 파일 (한 자리에 두 장까지) |

모르는 값은 **0 으로 둡니다.** 그럴듯한 것으로 채우지 않습니다 — 한 번 지어내기
시작하면 화면 전체를 못 믿게 되고, 그러면 이 열두 줄은 자리만 먹는 그림이 됩니다.

#### 안 켜지는 자리

- **화면이 28줄보다 낮을 때.** 사무실 12줄 + 상자 5줄이면 대화가 들어갈 자리가
  없습니다. 사무실을 보려고 도구를 못 쓰게 되는 것은 앞뒤가 바뀐 것입니다.
- **화면이 60칸보다 좁을 때.** 방은 늘 60칸을 씁니다. 더 좁게 그리면 책상과 사람이
  뭉개져서 방으로 안 보이고, 그렇다고 60칸을 그대로 내보내면 열두 줄이 스물네 줄로
  접힙니다. 상자는 열둘로 세고 커서를 올리니 어긋난 자리에 다음 판을 덮어써서
  화면이 지워집니다. 좁으면 그냥 안 보여 주는 편이 낫습니다.
- **화면 크기를 모를 때** (파이프로 넘길 때 등) — 모르는 채로 켜는 쪽이 손해가 큽니다.
- **`DEEL_NO_MOTION=1`** — 화면 읽기 프로그램을 쓰는 자리입니다.
- **256색이 안 되는 터미널** — 색 번호가 글에 그대로 새어 나옵니다.

사무실을 켜면 상자 안 그림(기사·동물)은 조용한 돌림표로 돌아갑니다. 둘 다 같은
것을 말하기 때문입니다 — 기사가 칼을 휘두르는 것도 '코드 쓰는 중', 사무실 사람이
자판을 두드리는 것도 '코드 쓰는 중'입니다. 바로 위아래에 붙여 놓고 같은 소리를
두 번 하면 시끄럽기만 합니다.

#### 무겁지 않은가

안 무겁습니다. 오히려 이걸 만들면서 상자가 **전보다 가벼워졌습니다.**

한 판을 통째로 보내면 9KB 가 넘는데, 판이 바뀔 때 실제로 달라지는 줄은 몇 안
됩니다(벽·창문·서류함·빈 책상은 그대로입니다). 그래서 상자가 바뀐 줄만
보내도록 고쳤고, 그 덕에 사무실을 안 켜는 사람도 같이 가벼워졌습니다.

얼마나 가벼워지는지는 **판이 바뀔 때 몇 줄이 실제로 달라지느냐**로 정해집니다.
조용한 방(혼자 도는 중)에서는 평균 **0.5줄**, 사람이 꽉 찬 방에서는 **4줄쯤**
입니다. 벽·창문·서류함·빈 책상은 안 바뀌고 사람이 있는 줄만 바뀌니, 사람이
늘면 그만큼 늘어납니다 — 그게 움직임의 값입니다. `test/office.test.js` 가 잽니다.

| | |
|---|---|
| 판마다 바뀌는 줄 (조용할 때) | 12줄 중 평균 **0.5줄** |
| 판마다 바뀌는 줄 (사람이 꽉 찰 때) | 12줄 중 평균 **4줄쯤** |
| 최악의 경우 (전부 바뀔 때) | 통째로 그리는 것과 **바이트가 같음** |

절대 수치(초당 몇 KB)는 안 적습니다. 터미널 폭·그때 무엇이 움직이는지·터미널
종류에 따라 몇 배씩 달라져서, 한 번 재서 적어 두면 그 다음부터는 그냥 틀린 숫자가
됩니다. 대신 코드가 늘 지키는 것만 적습니다 — **견주기는 통째로 그리는 것보다
바이트가 많아질 수 없습니다.** 다 바뀐 판에서는 두 방식이 같은 것을 내보내고,
덜 바뀐 판에서는 그만큼 덜 보냅니다.

같은 갈래 안에서도 4초마다 다른 문구로 넘어갑니다. 같은 글자가 30초 동안 그대로
있으면 그것도 멈춘 것처럼 보이기 때문입니다. 오른쪽에는 **걸린 시간**과, 모델이
추론 중이면 **지금까지 생각한 글자 수**가 같이 뜹니다 — 진짜로 늘어나는 숫자가
하나 있어야 '살아 있다' 가 표시가 아니라 사실이 됩니다.

### 무엇을 물어보고 무엇을 그냥 할지

내 파일이 **물어보고 바뀌는지, 안 물어보고 바뀌는지**는 흘깃 봐서 바로 알아야
하는 한 가지입니다. 상태줄 오른쪽에 늘 떠 있습니다.

| 표시 | 명령 | 무엇을 물어보나 |
|---|---|---|
| `⏵⏵ 자동 승인` | `/mode auto` | 안 묻고 고칩니다. 되돌리기(`/undo`)가 안전망입니다 |
| `⏵ 위험만 확인` | `/mode confirm` | 되돌릴 수 없는 명령만 물어봅니다. 파일은 안 묻고 고칩니다 |
| `⏸ 모두 확인` | `/mode strict` | 파일을 고치거나 명령을 돌리기 전에 매번 물어봅니다 |

`/mode` 만 치면 셋을 나란히 보여 주고 지금 것에 ● 를 찍습니다.
켤 때 머리말에도 사람 말로 한 줄 나옵니다 — 한 번 읽고 나면 그 다음부터는
글자만 봐도 압니다.

**`Shift+Tab` 으로 치지 않고 바꿉니다.** 누를 때마다 차례로 돌고, 무엇에서
무엇으로 갔는지 한 줄이 남습니다. 치던 글은 그대로 있습니다.

```
  ⏵ 위험만 확인  되돌릴 수 없는 명령만 물어봅니다. 파일은 안 묻고 고칩니다
  자동 승인 → 위험만 확인 · Shift+Tab 으로 계속 바꿉니다
```

차례는 **느슨한 쪽 → 조이는 쪽**입니다(자동 → 위험만 → 모두 → 자동). 잘못
눌러도 더 물어보게 될 뿐, 한 번에 '안 묻고 고침' 으로 떨어지지 않습니다.

> 이 자리는 원래 작업 모드(`종합`·`코드`…)가 쓰고 있었습니다. 바꾼 이유는
> **누가 더 자주 손대느냐**입니다. 작업 모드는 요청을 보고 저절로 옮겨 가지만,
> 승인 방식은 "이번 건은 좀 봐야겠다" 싶을 때 일하는 도중에 바꾸고 싶어집니다.
> 작업 모드는 `Ctrl+O` 로 옮겼고 `/work` 도 그대로 됩니다.

> 전에는 `auto` 라는 영문 한 낱말이었습니다. 옆에 `종합`·`medium·절약` 이 나란히
> 있으니 셋 다 그냥 '모드' 로 보였고, 그중 하나가 **묻지 않고 파일을 고친다**는
> 뜻이라는 것은 화면 어디에도 없었습니다.
>
> 자리가 모자랄 때 무엇을 접는지도 그래서 바꿨습니다. 사내 게이트웨이 모델 이름은
> `databricks-gpt-5-6-luna` 처럼 스물세 칸을 그냥 먹는데, 그것 하나 때문에 승인
> 방식이 화면에서 통째로 사라지고 있었습니다. 지금은 **모델 이름을 먼저 줄입니다** —
> 무엇으로 도는지는 이미 알지만, 내 파일이 안 물어보고 바뀌는지는 지금 봐야 압니다.
