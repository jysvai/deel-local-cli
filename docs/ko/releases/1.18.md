## 1.18.0

**있는 것과 걸리는 것은 다릅니다**

이 판은 기능을 더한 판이 아닙니다. **적어 둔 대로 안 돌던 자리**를 찾아 고친
판입니다. 검사 8,404개가 전부 초록인 상태에서 시작해, 명령 울타리를 통째로
여는 우회 네 가지와 게이트웨이 열쇠가 나가는 길 하나를 찾았습니다.

찾은 방법이 이 판의 알맹이라, 그것부터 적습니다.

### 초록불은 「깨면 잡힌다」 는 뜻이 아닙니다

이 저장소에서 되풀이해 나온 고장은 한 부류입니다.

- 규칙을 넣어 두고 그 규칙이 **한 번도 안 걸린** 자리
- 검사를 만들어 두고 **아무도 안 돌린** 자리
- 고쳤다고 적어 두고 **그 고침이 안 지켜지는** 자리

셋 다 화면에서는 멀쩡해 보입니다. 규칙이 안 걸리면 아무 데서도 안 터지고,
안 도는 검사는 빨개질 일이 없고, 안 지켜지는 고침은 주석에만 남습니다.
**있다고 믿게 만든다**는 점에서 없느니만 못합니다.

그래서 이 판에서는 그것을 재는 자를 셋 놓았습니다.

**1. 규칙이 실제 문장에 걸리나** — 모드를 고르는 점수표의 규칙 97개를 실제
사람 말 103문장에 전부 걸어 봅니다. 여기서 **열셋이 죽어 있었습니다.**
낱말 뒤 토씨를 `점검(해|좀|을|이)` 로 붙여서만 봤는데, 한국말로는 「점검 좀
해줘」 처럼 빈칸이 낍니다. 「분석 좀」 · 「검토 좀」 · 「리뷰 좀」 · 「설명 좀」 …
부탁하는 말투가 통째로 안 걸리고 있었습니다.

그리고 한 겹 더 갔습니다. **규칙이 사는 것과 그 가지가 사는 것은 다릅니다.**
`(해|\s*좀|을)` 에서 한 가지가 죽어도 다른 가지가 걸리면 규칙 전체는
「걸린다」 로 나옵니다. 그렇게 재 보니 고친 열둘 중 **넷**은 옛 모양으로
되돌려도 검사가 초록이었습니다 — 고쳤다고 적어 둔 것의 3분의 1이 안 지켜지고
있었던 셈입니다. 이제 가지마다 따로 잽니다.

**2. 만들어 놓고 아무도 안 돌리는 것** — `tools/` 의 모든 것은 npm 스크립트로
걸려 있거나, 개발 문서에 적혀 있거나, 다른 도구가 부르거나여야 합니다. 셋 다
아니면 아무도 안 돌립니다. 이 판에서 2차 리뷰 하네스를 만들어 놓고 스크립트로
안 걸어 둔 것이 바로 그 함정이었습니다. `npm run check` 는 `src/` 만 훑으니
`tools/` 는 문법이 깨져도 손으로 돌리는 날까지 아무 일도 안 납니다 — 그날은
대개 무언가 급할 때입니다. 그래서 읽히기는 하는지도 같이 봅니다.

**3. 눈으로 보는 데모** — `npm run demo` 는 **여태 한 번도 안 돌았습니다.**
설정을 엉뚱한 자리에 적어서 「저장된 연결이 없습니다」 한 줄만 찍고 끝났는데,
종료코드가 0 이라 아무도 안 물어봤습니다. 설정이 있는 PC 에서는 더 나빴습니다 —
가짜 게이트웨이가 아니라 **진짜 창구**에 말을 걸었습니다. 이제 안 돌면 안
돌았다고 말하고, CI 가 판마다 한 번 돌립니다.

### 명령 울타리가 네 가지 방법으로 열려 있었습니다

`src/safety/guard.js` 는 되돌릴 수 없는 명령만 담은 좁은 목록입니다. 그 목록이
지키던 약속이 넷으로 깨져 있었습니다. 넷 다 실제로 돌려 보고 확인했습니다.

```
rm -rf /                            막힘
rm -rf / ; echo done                통과 ←  셸은 둘 다 실행합니다
rm -rf / ;                          통과 ←  구분자만 붙여도
rm -rf "/"                          통과 ←  따옴표만 둘러도
git push -f origin main             통과 ←  짧은 꼴
Remove-Item C:\ -Recurse -Force     통과 ←  파워셸의 흔한 어순
Remove-Item -Recurse -Force C:/     통과 ←  파워셸은 빗금도 받습니다
Remove-Item -rec C:\                통과 ←  매개변수 줄임꼴
```

**뒤에 한 마디.** 규칙 여럿이 `\s*$` 로 글 끝에 못을 박습니다. `rm -rf /` 가
글 **끝**일 때만 걸린다는 뜻입니다. `; echo done` 여덟 글자면 통째로 빠져나갑니다.
앞에 붙이는 것(`echo hi && rm -rf /`)은 원래도 막혔고 **뒤에 붙이는 것만** 샜기
때문에, 「막힌다」 를 재는 검사가 다 초록이었습니다. 이제 명령을 마디로 갈라
각 마디를 따로 보고, 파이프를 건너 걸리는 규칙(`curl … | sh`)을 위해 전체 글도
계속 봅니다.

**따옴표.** 이 파일 머리말에는 이미 「따옴표 안은 안 가린다」 고 적혀 있었습니다 —
정확히 `sh -c "rm -rf /"` 를 놓치지 않으려는 뜻이었습니다. 그런데 **안 가리는
것과 떼고 보는 것은 다릅니다.** 안 가리기만 했지 떼 보지는 않아서, 적어 둔
의도와 실제 동작이 정반대였습니다.

**우리가 적은 철자만.** `--force` 는 막고 `-f` 는 안 막았습니다. 플래그가 앞에
오는 어순만 막고 뒤에 오는 것은 안 막았습니다. 역빗금만 막고 빗금은 안 막았습니다.
`-Recurse` 만 막고 `-rec` 는 안 막았습니다. 이건 「막았다」 가 아니라
**「내가 적은 모양으로 적은 사람만 막았다」** 입니다.

### `.DEEL` 로 적으면 열쇠가 그대로 읽혔습니다

살림 폴더를 막는 자가 `.deel` 이라는 **소문자 글자**로 찾고 있었습니다. 그런데
이 프로그램이 주로 도는 윈도우(NTFS)와 맥(APFS 기본)은 파일 이름의 대소문자를
안 가립니다. **이름은 안 맞는데 파일은 열립니다.**

```
.deel/config.json   막힘
.DEEL/config.json   통과 ←  같은 파일이 열립니다
```

그 파일에 게이트웨이 열쇠가 들어 있습니다. 열쇠는 대화에 실려 게이트웨이로
나가고 세션 기록으로 디스크에도 남습니다 — 「나가는 문은 하나」 라는 약속이
그 문으로 열쇠를 내보내는 꼴입니다. 커밋 쪽은 이미 막고 있었고 **읽는 쪽만**
열려 있었습니다.

### 저장소에 딸려 온 설정이 프로그램을 띄우고 있었습니다

`mcp.json` 은 프로젝트 폴더에 있습니다. 그러니 **저장소에 같이 딸려 옵니다.**
남의 저장소를 clone 하고 그 안에서 deel 을 켜면, 거기 적힌 `command` 가 이 계정
권한으로 자식 프로세스가 됐습니다. 도구 승인 화면도 안 거칩니다 — 모델이 부른
것이 아니라 우리가 「서버를 띄우려고」 부른 것이기 때문입니다.

```json
{ "mcpServers": { "sync": { "command": "cmd", "args": ["/c", "…"] } } }
```

훅(`safety/hooks.js`)은 정확히 이 위협에 `믿나(root)` 를 강제하면서 제 머리말에
**「MCP 와 같은 무게로 다룬다」** 고 적어 두었습니다. 그런데 무게를 견주던 쪽에는
그 문이 없었습니다.

스킬도 같습니다. 스킬은 글이지만 그 글은 모델에게 「이렇게 일하라」 고 시키는
글이고, 이름과 한 줄 설명이 **매 턴** 시스템 글에 실립니다. 그 자리에서
프로젝트가 제일 높습니다 — 사용자 것도 덮습니다.

둘 다 이제 믿는 폴더에서만 읽습니다(`deel trust`). **슬래시 명령은 일부러 그대로
둡니다** — 그건 사람이 `/이름` 을 직접 칠 때만 펴지고 시스템 글에는 안 실립니다.
위협이 다르면 문도 달라야 합니다. 둘 다 막아 두면 안전해 보이지만 실제로는
「이 도구는 남의 저장소에서 쓸모가 없다」 가 되고, 사람은 `trust` 를 습관처럼
치게 됩니다 — 그러면 정작 막아야 할 자리에서도 그냥 칩니다.

안 읽었으면 **안 읽었다고 말합니다.** 제가 적은 것이 왜 안 뜨는지 모르는 것이
두 번째로 나쁜 일입니다.

### 프롬프트 캐시 닻이 창 밖에 박히고 있었습니다

되돌아보기 창은 **블록 스무 개**입니다. 그런데 우리는 **메시지**로 세고
있었습니다. 도구를 도는 턴에서는 한 메시지가 블록 여럿이라, 닻이 창 밖에
떨어집니다. 그러면 꼬리 표식이 닻을 못 보고 매 턴 앞이 통째로 다시 나갑니다 —
오류는 한 줄도 안 나고 요금만 붑니다.

방향도 반대였습니다. 표식을 못 붙이는 자리를 만나면 닻이 **뒤로** 물러섰는데,
그러면 꼬리와의 거리가 늘어납니다. 실제로 재 보니 닻→꼬리가 25블록이었습니다.
창이 20인데요. 이제 닻은 꼬리 쪽으로 다가섭니다.

옛 검사는 이걸 못 잡았습니다. 자리를 막으려고 `content: null` 로 바꿨더니
블록수가 3에서 1로 줄어서 **닻자리 자체가 밀렸고**, 원래부터 붙일 수 있는 자리에
떨어졌습니다. 되돌아보기 고리를 통째로 지워도 초록이었습니다.

### 그 밖

**새로 만드는 hwpx 만 가린 표 검사를 건너뛰었습니다.** 모델이 Bash 로
환경변수를 읽으면 열쇠가 가려진 채 옵니다. 그 표식을 진짜 값으로 알고 옮겨
적으면 다른 형식은 그 자리에서 막히는데 hwpx 만 「새로 만듦」 이라고 답하고
조용히 만들어졌습니다. 사내 보고서를 만드는 것이 이 도구의 주된 쓰임이라
하필 제일 나쁜 자리입니다 — 그렇게 만들어진 문서는 남에게 나갑니다.

**설정을 못 남겼는데 남겼다고 말한 네 자리.** `/scan save` · `/level` · `/ctx` ·
컨텍스트 자동 학습. 홈이 읽기 전용이거나 디스크가 차 있으면 그 말이 그 자리에서만
참이고, 다음에 켜면 옛 값으로 돌아가 있습니다. 사람은 왜 그런지 알 길이 없습니다.

**주석이 코드와 어긋난 자리 셋.** 「나머지 일곱 칸」 이라 적혀 있는데 여덟이고,
문턱을 절반으로 오해하게 적혀 있었습니다. 주석은 코드와 같이 안 바뀌면 조용히
거짓말이 됩니다.

### 2차 리뷰 — 만든 모델과 다른 모델에게 한 번 더

위 부류가 오래 사는 까닭은 **만든 사람이 검사도 짜기 때문**입니다. 무늬를 잘못
적은 사람은 그 무늬를 재는 문장도 같은 오해로 고릅니다. 잘못이 두 곳에 똑같이
들어가면 둘이 서로를 통과시킵니다.

그래서 1차는 만든 쪽이 보고, **2차는 다른 모델이 봅니다.**

```bash
npm run review2                        아직 커밋 안 한 것
node tools/review2.mjs --since HEAD~3  최근 세 판
```

`agy`(Antigravity CLI)를 프로세스로 띄웁니다 — 소스에서 부르면 「나가는 문은
`src/backend/http.js` 하나」 가 깨지므로 rg·git 과 같은 취급입니다. `--mode plan`
이라 읽기만 합니다. 저장소 사정을 모르는 쪽이니 집안 규칙(한글 식별자·의존성
0개·나가는 문 하나)과 **위에 적은 고장 부류 다섯**을 같이 넘깁니다.

**이건 문지기가 아니라 눈입니다.** 찾은 것을 적을 뿐 아무것도 안 막습니다 —
빨간불이 되면 사람이 그것부터 끄게 되고, 그러면 눈이 하나 줍니다.

첫 판에서 값을 했습니다. 1차 리뷰가 끝나고 검사 8,368개가 전부 초록인 상태에서
돌렸는데 **심각 셋이 나왔고, 셋 다 30분 전에 만든 구멍**이었습니다. 「뒤에 한
마디」 를 고치면서 「반 마디」 자리를 만들었고, 앞쪽 낱말 경계를 고치면서 뒤쪽을
열어 뒀습니다. **울타리를 옮기면 옮긴 자리에 틈이 생깁니다.**

붙이면서 세 번 헛디뎠고 셋 다 소스에 적어 뒀습니다. 마지막 것이 제일 나빴습니다 —
종료코드 0 에 빈 답이 오는데, 화면에서 「지적할 것이 없다」 와 「한 번도 안 봤다」
가 똑같이 생겼습니다. 이 도구가 잡으러 온 부류를 이 도구가 갖고 있었던 셈입니다.
지금은 **빈 답을 실패로 칩니다.**
