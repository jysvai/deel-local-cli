## 2.2.6

**로컬 작업이 끊기지 않게 하고, 파일을 한 번에 읽고, 있는 파일을 찾습니다**

맥에서 실제로 쓰며 신고된 문제를 고치고, 로컬 모델로 일할 때 턴이 끝나는 자리와 경로 처리를 전부 다시 쟀습니다. 2.2.5 는 발행 전 검사에서 막혀 npm 에 나가지 않았고, 그 수정도 이 판에 들어 있습니다.

| 자리 | 전 | 이제 |
|---|---|---|
| 큰 파일 읽기(로컬) | 지시문이 "통째로 읽지 말고 찾은 자리 앞뒤만 읽어라"였고, 한 번에 창의 고정 몫만 실었습니다 | "통째로 한 번 읽고 바로 고쳐라"로 바꿨습니다. 남은 창에 들어가는 만큼 한 번에 싣습니다 |
| 지시문·도구 설명(로컬) | 아는 파일도 Outline → Grep 을 거치게 했고, 큰 일은 하위 작업으로 떼라고 했습니다. 하위 작업은 단일 슬롯 서버의 프롬프트 캐시를 밀어냅니다 | 어디 있는지 모를 때만 찾고 바로 읽게 했습니다. 사람이 시킬 때만 Task 를 씁니다. 처음부터 읽으면 다 들어가는 파일은 `limit` 을 줘도 통째로 줍니다. 파일을 안 고친 턴에는 Verify 를 시키지 않습니다. 영어 지시문에 한국어 줄이 섞이지 않습니다. Bash·Grep 결과도 남은 창을 보고 최대 세 배까지 싣습니다 |
| 읽은 것을 잃는 일(로컬) | 큰 결과가 들어오면 모델이 보기 전에 비워져 또 읽었습니다 | 압축 문턱 아래로만 싣고, 비울 때도 모델이 아직 못 본 결과는 남깁니다 |
| 같은 줄 반복(로컬) | 같은 인자 다섯 번이면 끊었습니다 | 이미 받은 줄을 또 읽는지로 봅니다. 새 줄을 읽으면 몇 번이든 안 끊습니다. 같은 줄만 12번 읽으면 두 번 더 일러 본 뒤 멈춥니다 |
| 파일 찾기 | 따옴표째 적은 경로, 작업 폴더 이름을 겹쳐 적은 경로, 터미널식 `\ ` 표기, `~/`, 한글 자모 모양이 다른 경로를 "없다"고 했습니다 | 있는 자리로 맞춥니다. 금지 규칙과 범위 검사는 맞춘 경로로 봅니다 |
| 못 찾았을 때 | "없음" 뿐이었습니다 | 다른 폴더의 같은 이름 파일을 알려 줍니다. `.gitignore` 에 가려진 파일도 이름은 알려 줍니다. `.deelignore` 는 그대로 지킵니다 |
| 서버 탈(로컬) | 답하다 끊기면 턴이 끝났고, 503 은 8초 뒤 포기했고, 빈 답 두 번이면 끝났고, 60초 침묵이면 끊었습니다 | 세 번 다시 묻고, 503 은 약 8분 기다리고, 재촉해서 다시 받고, 침묵 시한은 30분입니다 |
| 서버 재시작(로컬) | 응답하던 서버가 꺼지면 그 자리에서 턴이 끝났습니다 | 돌아오기를 약 8분까지 기다립니다. ESC 로 멈출 수 있습니다 |
| 끝까지 못 온 답(로컬) | 스트림이 멎거나 끝 표시 없이 닫히면 반쪽 글이 최종 답이 됐고, 안 닫힌 `<think>` 도 답으로 쳤습니다 | 버리고 다시 묻습니다. 닫힌 `<think>` 는 대화에 안 남깁니다 |
| 말만 하고 끝내기(로컬) | "이제 고치겠습니다" 로 끝나면 일을 안 한 채 턴이 끝났고, 없는 도구를 글로 부르면 그대로 끝났습니다 | 한 번 밀어 이어 가게 합니다. 글로 적은 잘못된 부름에는 쓸 수 있는 도구를 알려 줍니다 |
| 헛도는 실패(로컬) | 대상만 바꾼 실패는 300걸음까지 갔고, 같은 파일을 고치며 출력이 같은 시험을 돌리면 네 바퀴에 끊겼습니다 | 성공 없이 25번 연달아 실패하면 멈추고, 고치며 돌리는 시험은 끊지 않습니다 |
| 저장된 대화 | `/clear` 로 비운 대화가 `--continue` 로 되살아났고, `/compact` 는 저장 파일에 안 남았습니다 | 저장 파일도 같이 비우고 접습니다 |
| 헤매는 모델(로컬) | Edit 이 다른 글로 세 번 틀리면 끊었고, 창 8k 는 16걸음에서 끊었고, 고친 뒤 같은 `git commit` 도 막았습니다 | 다른 글로 고쳐 보는 것은 파일당 10번까지 봐 줍니다. 걸음 상한은 300(묻기 40, 설계 120)입니다. 파일을 고친 뒤에는 같은 명령을 다시 돌립니다. 헛돈다고 판정해도 두 번 더 일러 본 뒤 멈춥니다 |
| 입력창 | 둥근 따옴표가 든 글을 붙이고 치면 글자마다 상자가 쌓였습니다 | 그리는 동안 터미널의 자동 줄바꿈을 꺼서 어떤 글자가 넓게 그려져도 줄이 접히지 않습니다. 흔들리는 글자는 상자 안에서만 1칸 글자로 그립니다. 보내는 글은 그대로입니다 |
| 그림 붙이기 | `/paste` 만 됐습니다 | 맥·리눅스 터미널에서 Ctrl+V 로 커서 자리에 붙습니다. 맥에서 브라우저로 복사한 TIFF·JPEG 도 PNG 로 바꿔 붙입니다. 윈도 터미널은 `/paste` 를 씁니다 |
| 요청 모양(로컬) | 사람 말이 잇따르면 그대로 보냈습니다 | 한 말로 합쳐 보냅니다. 엄격한 챗 템플릿이 거절하는 모양입니다 |

**남은 것:** 맥의 실제 llama-server 와 실제 모델로는 재 보지 못했습니다. 위 수정은 가짜 서버로 재현해 확인했습니다.

## 2.2.5

**큰 파일을 읽는 길을 고쳤습니다**

이 판은 발행 전 검사에서 막혀 npm 에 나가지 않았습니다. 고친 내용은 2.2.6 에 들어 있습니다.

로컬 모델이 파일을 조각조각 읽기만 하고 고치지 않은 채 멈춘다는 신고가 왔습니다. 원인 셋을 고쳤습니다.

| 자리 | 전 | 이제 |
|---|---|---|
| 읽은 줄 수 | 화면에는 `357/1542줄` 인데 모델은 88줄만 받았습니다. 줄 중간에서 잘리고 어디까지 읽었는지 안내도 같이 잘렸습니다 | 줄 단위로 끊어서 화면과 실제가 같습니다. 바깥 연결도 같습니다 |
| 로컬 한 번 읽기 | 창 30k 에서 약 4,800자, 65k 에서 약 10,000자 | 약 14,300자, 30,000자입니다. 한 줄 50자 파일로 88줄 → 252줄, 183줄 → 524줄입니다 |
| 이어 읽기(로컬) | 어디서 이어야 할지 몰랐습니다 | `Next: offset=N` 과 뒤쪽 함수 지도(이름:줄)를 줍니다 |
| 읽기만 반복(로컬) | 같은 호출을 되풀이할 때만 잡았습니다 | 바뀐 것 없이 읽기만 하면 5걸음마다 고치라고 밉니다. 턴을 끊지는 않습니다. 고치는 모드에서만 겁니다 |
| 같은 읽기 반복(로컬) | 같은 인자로 세 번(되풀이 버릇이 잡힌 모델은 두 번)이면 턴을 끊었습니다 | 다섯 번까지 봐 줍니다. 결과를 다시 싣지 않아 자리를 거의 안 먹습니다 |
| 도구 결과 접기(로컬) | 접을 때마다 앞머리가 갈려 그 뒤를 다시 읽었습니다. 가짜 서버에서 요청 하나에 최대 약 44,000자였습니다 | 접지 않고 문턱에서 장부 압축 한 번으로 줄입니다. 같은 조건에서 걸음마다 약 12,000자로 일정합니다 |

**남은 것:** 맥의 실제 llama-server 에서는 재 보지 못했습니다. 모델이 재촉을 따라 고치는지는 실제 모델에서 확인해야 합니다.

## 2.2.4

**터미널이 로컬 모델의 몫을 덜어 줍니다**

컨텍스트가 금방 차고 웹챗보다 느리다는 신고가 왔습니다. 모델이 하던 일 가운데 터미널이 할 수 있는 것을 터미널로 옮겼습니다.

| 자리 | 전 | 이제 |
|---|---|---|
| 로컬 자동 압축 | 모델이 요약을 새로 썼습니다. 5 t/s 면 최대 약 4분이었습니다 | 터미널이 시킨 말·고친 파일·돌린 명령·오류를 옮겨 적습니다. 모델을 부르지 않습니다 |
| 압축 뒤 남기는 대화 | 창의 25% 까지 | 창의 8% 까지 한 번에 크게 자릅니다 |
| 접은 원문 | 컨텍스트에서 사라졌습니다 | brotli 로 압축해 `.deel/sessions/archive` 에 14일 보관하고 `Recall` 의 `id` 로 한 글자도 안 다르게 되찾습니다 |
| 로컬에 시키는 말 | 화면 말을 따랐습니다 | 영어로 시키고 답은 화면 말로 받습니다. Qwen3 토크나이저로 고정 프롬프트가 3,667 → 2,565토큰입니다. `/lang` 이나 `DEEL_PROMPT_LANG` 으로 바꿀 수 있습니다 |
| 명령 출력(로컬) | 앞에서부터 잘랐습니다 | 색깔 코드·진행률·연속 중복·많은 통과 줄을 빼고, 길면 앞 30%·뒤 70% 를 남깁니다. 오류 줄은 안 빼고, 잘린 원문은 `Recall` 의 `id` 로 되찾습니다 |
| 도구 호출(로컬) | 서버 판단에 맡겼습니다 | `parallel_tool_calls` 를 켭니다. 거절하는 서버는 배워서 끕니다 |
| 생각을 끈 Qwen3 | 서버의 생각 모드 값(temperature 1.0)으로 돌았습니다 | 생각 끔 권장값(0.7 · top_p 0.8)을 보냅니다 |
| 속도 숫자 | 터미널 시계로 쟀습니다 | llama-server 의 `timings` 를 씁니다. 웹 UI 와 같은 숫자입니다. `/cost` 에 캐시 재사용과 추측 적중을 적습니다 |
| 자가학습 | 명령과 모델 버릇 | 자주 고친 파일도 쌓아 다음 세션의 찾는 걸음을 줄입니다 |
| 화면(로컬) | 90ms 마다 그렸습니다 | 250ms 마다 그립니다 |

사람이 치는 `/compact` 와 바깥 연결의 압축은 전처럼 모델이 씁니다. 배포 때 전체 검사가 두 번 돌던 것을 한 번으로 줄였습니다.

**남은 것:** 맥의 실제 llama-server 에서는 재 보지 못했습니다. 검사는 가짜 서버로 했고, 토큰 수는 Qwen3-8B 토크나이저로 쟀습니다.

## 2.2.3

**로컬 모델이 압축만 하다 꽉 차던 것을 고쳤습니다**

요약을 거듭해도 결국 창이 차고, 로컬 모델은 웹챗보다 훨씬 느리다는 신고가 왔습니다.

| 자리 | 전 | 이제 |
|---|---|---|
| 요약 뒤 남기는 양 | 메시지 **개수**로 정해서, 큰 도구 결과가 남으면 요약하고도 80% 위였습니다 | 토큰으로 잽니다. 도구 호출 인자까지 세어 꼬리는 창의 25% 까지만 남깁니다 |
| 요약이 자리를 못 낼 때 | 1% 만 줄어도 성공으로 치고 걸음마다 다시 요약했습니다 | 요약 뒤 70% 위면 그 자리에서 비우고 이어 갑니다. 2걸음 안에는 요약을 다시 부르지 않습니다 |
| 요약이 쌓일 때 | 요약 위에 요약이 쌓였습니다 | 두 번 쌓인 뒤 또 차면 비웁니다 |
| 비우기 횟수 | 턴당 한 번이었습니다 | 간격으로 막습니다. 긴 턴에서 다시 찰 수 있고, 비운 바로 다음 걸음에 또 거절되면 오류로 끝냅니다 |
| 비울 때 옮기는 것 | 시킨 말 · 남은 할 일 · 손댄 파일 | 여기에 최신 요약까지 옮깁니다 |
| 로컬의 생각 | `/think off` 를 쳐도 OpenAI 꼴 서버에는 아무 칸도 안 나가 서버 기본값으로 생각했습니다 | 정하지 않으면 끕니다. `chat_template_kwargs: {"enable_thinking": false}` 를 보내고, `/think medium` 으로 다시 켭니다 |
| 로컬의 고정 프롬프트 | 창이 크면 클라우드와 같은 긴 판이었습니다 | 창과 상관없이 짧은 판입니다. 빈 폴더 · 65,536 창에서 6,676 → 4,282토큰, 스킬 목록은 12개 · 80자까지입니다 |
| 로컬의 문턱 | 창의 80% 까지 썼습니다 | 큰 창에서도 40,000토큰에서 요약합니다. 게이지 눈금도 같이 옮겼습니다 |

요약 입력에도 상한을 두었습니다(로컬 12% · 바깥 50%). 로컬에서는 요약할 때도 생각을 끕니다.

**남은 것:** 맥의 실제 llama-server 에서는 재 보지 못했습니다. 검사는 슬롯 하나를 흉내 낸 가짜 서버로 했습니다. `v2.2.2` 태그는 발행 전 검사에서 멈춰 npm 에 올라가지 않았고, 그 내용은 이 판에 모두 들어 있습니다.

주석 속 작업 회차 표지 618건과 안 쓰는 코드를 정리했고, 주석 비율이 높은 11개 파일의 고친 이력 문단을 줄였습니다. 이 11개 파일은 주석 말고는 한 글자도 안 바뀌었습니다.

## 2.2.1

**느린 로컬 모델에서 걸음마다 프롬프트를 처음부터 다시 읽던 것을 고쳤습니다**

24GB 맥에서 큰 모델을 SSD 로 돌리는 llama-server(슬롯 하나)에 붙이면 엄청 오래 걸리거나 안 된다는 신고가 왔습니다. 그
서버는 읽는 값이 큽니다 — 프롬프트 전체를 한 번 읽는 데 몇 분입니다. 그런데 deel 이 그 일을 스스로 자꾸 시키고 있었습니다.

| 자리 | 전 | 이제 |
|---|---|---|
| 생각 강도 | 로컬은 걸음마다(`medium → low → low`) · 낱말마다 · 모드마다 옮겼습니다. 강도 문구를 시킴말 맨 앞에 넣는 템플릿(Qwen3.8)에서는 그때마다 전체를 다시 읽었습니다 | 저절로 안 옮깁니다. `/think` 로 정한 값(없으면 기본)으로 갑니다 |
| 미리 읽기 · 턴 뒤 | 입력칸이 뜰 때마다 한 번 보내, 값 없이 캐시 끝을 흔들었습니다 | 처음 뜰 때 · 대화가 줄었을 때 · 모델을 바꿨을 때만 보냅니다 |
| 미리 읽기 · Enter | 돌던 것을 30초까지 기다렸습니다 | 3초까지만 기다리고 끊습니다. 읽은 데까지는 서버에 남아 진짜 요청이 잇습니다 |
| 미리 읽기 · 느린 서버 | 손을 뗄 때마다 보냈습니다 | 친 글 하나에 5초가 넘으면 친 글은 더 안 보냅니다. `/status` 가 그렇다고 말합니다 |
| 미리 읽기 · 꺼짐 | 모델을 올리는 동안의 503 이나 2분을 넘긴 읽기 두 번이면 「서버 거절」 로 꺼졌습니다 | 정말 안 받는다고 할 때(400 등)만 끕니다 |

## 2.2.0

**치는 동안 미리 읽힙니다 — 로컬 모델이 Enter 를 치자마자 답합니다**

로컬 모델에서 첫 글자가 나오기까지의 기다림은 대개 생각이 아니라 **읽기**였습니다. 첫 요청이 와야 서버가 모델을
올리고, 그다음 시킴말 · 도구 스키마 · 대화를 처음부터 읽었습니다. 이제 그 둘을 Enter 를 치기 **전에** 합니다.
보낼 것의 거의 전부를 이미 알기 때문입니다.

| 무엇 | 앞 | 뒤 |
|---|---|---|
| 켠 뒤 첫 말 | 첫 요청이 와야 서버가 모델을 디스크에서 올렸습니다(7B 도 몇 초, 30B 면 수십 초). 화면에는 「생각 중」 만 돌았습니다 | 입력칸이 뜨는 순간 모델을 올립니다. 실제로 쓸 `num_ctx` 그대로 올리므로 짧게 올렸다가 첫 말에 다시 올리는 일도 없습니다 |
| 치다가 손을 뗄 때(0.4초) | 아무 일도 없었습니다 | 그때까지 친 글까지 붙인 **진짜 요청과 같은 몸**을 답 한 토큰으로 막아 보냅니다. 서버의 프리픽스 캐시가 그 앞머리를 계산해 둡니다 |
| Enter | 시킴말 · 도구 · 대화 · 친 말을 처음부터 읽었습니다 — CPU · 작은 GPU 에서는 그것만 수십 초 | 이미 읽힌 앞머리를 이어받아 **남은 몇 글자만** 읽습니다. 미리 읽던 것이 아직 돌고 있으면 첫 부름이 그것을 기다립니다(30초까지 — 넘으면 끊고 갑니다). 안 기다리면 서버가 빈 자리에서 같은 앞머리를 한 번 더 읽습니다 |
| 어디서 켜지나 | — | 이 PC · 사내망 주소이고, 요금이 매겨진 모델이 아니고, Ollama 클라우드 모델(`…-cloud`)이 아닐 때 저절로. 127.0.0.1 에 선 프록시가 유료 모델로 넘기는 판도 요금표로 가립니다. 파이프 · `deel run` · 에디터(ACP)에서는 안 켭니다 |
| 끄고 켜기 | — | `DEEL_WARMUP=0` · 설정 `"warmup": false` 로 끄고, `DEEL_WARMUP=1` · `"warmup": true` 로 바깥에서도 켭니다. 잇달아 두 번 거절하는 서버면 그 연결에서는 스스로 끕니다 |
| 보이는 것 | — | 상태줄 모델 옆에 `↯ 읽는 중` → `↯ 미리 읽음`. `/status` 의 `미리 읽기` 줄이 켰는지 · 까닭 · 보낸 횟수 · 서버가 읽은 토큰 · 마지막에 걸린 시간을 적습니다 |

치는 동안 답까지 미리 짓지는 않습니다. 글자 하나마다 버려야 하고, 그동안 읽기에 쓸 GPU 를 붙듭니다. 게다가
이 프로그램의 답은 도구 부름이라 말을 다 치기 전에 파일을 고칠 수는 없습니다. 읽기는 버릴 것이 없습니다 —
먼저 친 앞부분은 그대로 재쓰입니다.

미리 보낸 몸이 Enter 뒤 첫 요청과 한 글자라도 다르면 캐시는 거기서 끊기고, 그건 오류가 아니라서 아무 데도 안
찍힙니다. 그래서 둘을 **같은 코드로** 짓고(도구 목록 · 첫 걸음 강도를 루프에서 꺼내 같이 씁니다 · 친 말이
옮겨 갈 모드까지), 진짜 루프를 가짜 Ollama · OpenAI 호환 서버에 붙여 두 몸을 바이트로 견줍니다
(`test/warm.test.js`). 진짜 터미널에서 쳐 두고 멈췄을 때 나가는지도 봅니다(`test/pty.test.js`, 맥 · 리눅스).
