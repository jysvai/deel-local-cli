## 1.6.3

**일이 되고 있는데 헛돈다고 끊던 자리**

1.6.2 를 맥에서 쓰다가 「폴더 정리 해줘」 한 마디에 나온 화면입니다.

```
⏺ Move  7개 옮김
☰ TodoWrite(3건)
⏺ Move  22개 옮김
☰ TodoWrite(3건)
⊘ 같은 자리에서 헛돌고 있어 멈췄습니다
```

파일 **스물아홉 개가 실제로 움직이는 중**이었습니다. 세 자리가 겹쳤습니다.

| | 1.6.2 | 1.6.3 |
|---|---|---|
| `Move` 로 22개를 한 번에 옮기면 | 턴이 아는 손댄 파일 **0개** | 22개 |
| 그래서 화면의 파일 목록 | 비어 있음 | 옮긴 것이 다 나옴 |
| 옮기는 동안 할 일 목록을 다시 쓰면 | 3번이면 턴이 죽음 | 안 죽음 (일이 되고 있으니까) |
| 똑같은 할 일 목록을 또 보내면 | 「3개 중 1개 완료」 (앞과 똑같음) | 「바뀐 것이 없습니다」 + 무엇을 할지 |
| 아무것도 안 하면서 되풀이하면 | 멈춤 | **그대로 멈춤** |

검사는 **5,264 → 5,278항목**입니다.

---

### 배열로 옮기면 무엇이 움직였는지가 사라졌습니다

`Move` 는 한 개씩 부를 때와 `moves` 배열로 부를 때가 있습니다. 배열 쪽에서
한 개짜리 결과의 「무엇이 바뀌었나」 를 **버리고 있었습니다.** 재 봤습니다.

```
22개를 옮긴 뒤 — 턴이 아는 「손댄 파일」 : 0개     ← 1.6.2
                                          22개    ← 1.6.3
한 개씩 옮길 때는 두 판 다 멀쩡합니다.
```

이 값은 여러 군데가 같이 봅니다 — 턴 끝의 파일 목록, `/commit`, 그리고
헛도는지 재는 자리. 그 자리들이 전부 「아무 일도 안 일어났다」 로 알고
있었습니다.

### 헛도는 것과 오래 걸리는 것은 다릅니다

같은 부름이 세 번이면 끊었습니다. 그 사이에 무슨 일이 있었는지는 안 봤습니다.
그래서 「옮기고 · 목록 갱신 · 옮기고 · 목록 갱신」 이 헛도는 것으로 보였습니다.

이제 **그 사이에 파일이 진짜로 바뀌었으면 되풀이 셈을 처음부터 다시 셉니다.**
아무것도 안 바뀐 채로 되풀이하는 것만 헛도는 것입니다.

끝없이 돌 수 있지 않냐면, 아닙니다. 손댄 파일은 서로 다른 것만 세므로 같은
자리를 맴돌면 안 늘어납니다. 늘어난다는 것은 매번 새 파일이 움직였다는 뜻이고,
그건 일이 되고 있는 것입니다. 걸음 수 상한도 마지막 울타리로 그대로 있습니다.

### 애초에 왜 같은 목록을 다시 보냈나

모델이 파일을 옮긴 뒤 끝난 줄을 `done` 으로 안 바꾸고 **글자 하나 안 틀린 같은
목록**을 보냈습니다. 그런데 받는 쪽이 그걸 성공으로 받고 앞과 똑같은 글을
돌려줬습니다. 모델 쪽에서는 갱신이 된 것이라, 다음 걸음에 또 보냅니다.

```
☰ TodoWrite → 3개 중 1개 완료                      ← 1.6.2 (앞과 글자까지 같음)

☰ TodoWrite → 3개 중 1개 완료                      ← 1.6.3
  이 목록은 앞에 보낸 것과 글자 하나까지 같습니다 — 바뀐 것이 없습니다.
  방금 끝낸 일이 있으면 그 줄을 done 으로 바꿔서 보내고,
  없으면 목록을 다시 보내지 말고 다음 일을 하세요.
```

오류로는 안 만듭니다 — 목록은 실제로 저장됐고, 틀린 것을 한 것도 아닙니다.

## 1.6.2

**「누르면 멈추고, 시킨 대로 하고, 안 끊긴다」**

쓰다가 걸린 다섯 가지를 받아서 고쳤습니다. ESC 가 안 먹고, 못 알아듣고 엉뚱한
것을 되묻고, 여러 가지를 시키면 몇 개가 조용히 빠지고, 붙여넣은 것이 화면에
안 보이고, 중간에 끊기면 거기서 끝나던 것들입니다.

| | 1.6.1 | 1.6.2 |
|---|---|---|
| Grep 이 도는 동안 ESC | **안 먹음** (그동안 키가 0번 배달됨) | 먹습니다 (14번 배달) |
| 멈추는 데 걸리는 시간 | 441ms | **6ms** |
| ESC 를 눌렀을 때 화면 | 그대로 (멈추는지 알 수 없음) | 그 자리에서 `멈추는 중` |
| 못 찾은 기억을 물었을 때 | 모델에게 **빈 글자**가 감 | 「없습니다」 라고 감 |
| 되묻기 | 「무엇을 할까요?」 를 두 번 | 이미 시킨 것은 못 묻습니다 |
| 「폴더 구조 개선해줘」 | 설계 모드 (파일 안 바꿈) | 코드 모드 (실제로 바꿈) |
| 다섯 가지를 시켰는데 셋만 하면 | 조용히 끝남 | `시킨 것 중 2가지가 안 다뤄졌습니다` |
| 40줄 붙여넣기 | 상자에 **마지막 한 줄만** 보임 | `[붙여넣기 #1 · 40줄 · 1.4KB]` |
| 걸음을 다 써서 끊기면 | 「다시 말씀하세요」 | `이어서 할까요? ⏎ 이어서` |

검사는 **5,024 → 5,264항목**(파일 94개 → 99개)입니다.

---

### ESC 가 안 먹던 진짜 까닭 — 그때 우리는 귀가 막혀 있었습니다

「esc 누르면 아직도 작업이 안 멈추는 이슈가 있어」

ESC 를 받는 코드는 멀쩡히 있었습니다. 그런데 **키가 배달되지 않았습니다.**

`Grep` 과 문서 변환은 남의 프로그램(`rg` · `soffice`)을 **동기로** 불렀습니다.
동기로 부르면 그 프로그램이 끝날 때까지 Node 가 아무 일도 못 합니다 — 키를
받는 일도 못 합니다. 재 봤습니다.

```
300ms 짜리 자식을 동기로 부르는 동안   → 419ms 동안 키가 한 번도 안 옴
207ms 짜리 Grep 이 도는 동안 (고치기 전) → 심장 소리 0번
207ms 짜리 Grep 이 도는 동안 (고친 뒤)   → 심장 소리 14번
```

세 겹으로 고쳤습니다. **첫째**, 자식 프로그램을 비동기로 부릅니다(`spawn.js`
하나로 모읍니다). **둘째**, 멈추라고 하면 돌던 자식도 같이 죽입니다 — 20초
짜리 변환이 걸려 있으면 안 죽이는 한 안 멈춥니다. 멈추는 데 걸리는 시간이
441ms 에서 6ms 로 줄었습니다.

**셋째**, 눌렀다는 것을 **그 자리에서** 보여 줍니다.

```
⠋ 생각하는 중…  esc 중단        ← 눌러도 그대로. 그래서 또 누른다
⠙ 멈추는 중…                    ← 1.6.2
```

제보의 절반은 진짜로 안 멈춘 것이었고, 나머지 절반이 이것이었습니다 — 멈추고는
있는데 그렇게 보이지 않았습니다. 그래서 또 누르고, 그러다 `Ctrl+C` 로 손이
가고, 두 번 누르면 대화가 닫힙니다.

### 못 알아듣고 엉뚱한 것을 되묻던 사슬

「deel 이 요청을 오해하고 엉뚱한 메뉴를 물어본다」

한 자리가 아니라 사슬이었습니다.

```
기억을 못 찾음 → 모델에게 빈 글자가 감 → 아무것도 모름
   → 그럴듯한 메뉴를 지어서 물음 → 무엇을 알아들었는지는 안 말함
```

`Recall` 이 못 찾으면 「요약」 칸에만 적고 **모델에게는 빈 글자**를 보냈습니다.
모델 쪽에서는 도구가 아무 말도 안 한 것과 같습니다. 이제 못 찾았으면 못
찾았다고 글로 보냅니다. 도구가 아무것도 안 돌려준 자리에는 「지어내지 말라」고
적어 보냅니다.

그리고 되물을 때는 **무엇을 알아들었는지 먼저 말하게** 했습니다.

```
› 어떤 방식으로 만들까요?                    ← 1.6.1
  1) …  2) …  3) …  4) …

  알아들은 것: 부문별 OCR 결과로 A4 2장짜리 PDF 를 부문마다 따로  ← 1.6.2
› 글씨체는 zip 안의 것을 쓸까요?
```

한 줄 더 쓰라는 것이 아닙니다. **잘못 알아들었으면 그 줄에서 티가 납니다.**

### 같은 물음을 되풀이하며 뺑뺑이 돌던 자리

맥에서 돌린 기록을 받았습니다. 사람은 「부문별로 PDF 만들어줘」 라고 한 번에 다
말했는데, deel 은 「어떤 방식으로 만들까요?」 를 네 갈래로 물었고, 답을 받고도
다음 턴에 거의 같은 물음을 또 물었습니다. 그 사이에 한 일은 다시 읽고 할 일
목록을 다시 쓴 것뿐이었습니다.

세 자리를 막았습니다.

* 손대라고 시킨 요청에 「무슨 일을 할까요」 를 되묻지 않습니다.
* 이번 턴에 이미 물은 것과 거의 같으면 막고, 받아 둔 답을 되돌려 줍니다.
* 한 턴에 두 번까지만 묻습니다.

얼마나 닮아야 같은 것으로 볼지는 찍지 않고 **쟀습니다.** 기록의 두 물음은
0.71·0.81, 같은 것을 놓고 갈래만 다른 물음은 0.27·0.38 이었습니다. 그 사이인
0.45 를 문턱으로 두고 그 수치를 검사에 박아 뒀습니다.

### 「고쳐줘」 라고 했는데 설계안만 오던 자리

「폴더 구조 개선해줘」 가 **설계 모드**로 갔습니다. 설계 모드는 파일을 안
바꿉니다. 그래서 사람은 고쳐 달라고 했는데 제안서를 받았습니다.

'구조' 라는 낱말만 보고 골랐기 때문입니다. 이제 **동사를 따로 봅니다** —
「개선해줘 · 고쳐줘 · 바꿔줘」 가 있으면 읽기만 하는 모드는 후보에서 뺍니다.
「설명해줘 · 검토만 해줘」 는 그대로 둡니다. 무엇을 뺐는지도 화면에 적습니다.

### 여러 가지를 시키면 몇 개가 조용히 빠지던 것

「요청사항이 다량일 경우 몇 번 까먹거나, 누락되거나 그런 이슈들이 생겨」

이제 턴이 끝날 때 **시킨 것과 한 것을 맞춰 봅니다.** 하나도 손대지 않은 항목이
있으면 먼저 모델에게 되돌려 보내고, 그래도 안 됐으면 사람에게 말합니다.

```
! 시킨 것 중 2가지가 안 다뤄졌습니다
   1. 글씨체는 zip 안에 있는 것으로
   2. 기존 A3_편집.html 은 건드리지 말 것
```

일부러 **덜 말하는 쪽**으로 맞췄습니다. 한 것을 안 했다고 하면 사람이 두 번
시키게 되고, 그건 안 하는 것보다 나쁩니다.

그리고 대화가 길어져 앞엣말을 접을 때, **이번에 시킨 말만은 원문 그대로**
남깁니다. 요약된 요청은 항목이 사라지기 딱 좋은 자리였습니다.

### 붙여넣은 것이 화면에 안 보이던 것

「붙여넣기 해도 창에 붙여넣기된 내용이 다 뜨는게 아니야 claude/codex 처럼
압축된 거 처럼 보이면 더 좋을거같아」

입력 상자는 여덟 줄까지만 보여 줍니다. 그런데 붙여넣은 앞줄들은 상자가 아예 안
그렸습니다 — 쌓아 뒀다가 보낼 때 이어 붙이기 때문입니다. 그래서 마흔 줄을
붙이면 상자에는 **마지막 한 줄**만 남았습니다.

```
 ❯ 40번째 줄 — 붙여넣기 시험                       ← 1.6.1

  [붙여넣기 #1 · 40줄 · 1.4KB] — 접어 뒀습니다.    ← 1.6.2
 ❯ [붙여넣기 #1 · 40줄 · 1.4KB] 이거 정리해줘
```

앞뒤에 무슨 말을 덧붙였는지가 그대로 보입니다. 크기는 글자 수가 아니라
**바이트**입니다 — 한글은 글자당 3바이트라, 글자로 세면 창에 무엇을 밀어 넣는지
감이 3분의 1로 어긋납니다.

접을지는 줄 수만 세지 않습니다. 한 줄이어도 폭보다 길면 상자 안에서 여러 줄로
접히기 때문에(로그 한 줄, 미니파이된 JSON 한 줄), 상자가 쓰는 것과 같은
셈법으로 세어 보고 넘칠 때만 접습니다. 세 줄짜리는 그냥 보입니다.

**접은 것은 보낼 때 글자 하나 안 틀리고 되돌아옵니다.** 줄바꿈도 탭도 이모지도
바이트 그대로입니다. 되돌릴 수 없는 접기는 접기가 아니라 잘라내기입니다.

### 걸음을 다 써서 끊긴 자리를 ⏎ 하나로 잇습니다

「중간에 끊기는 이슈가 생기는거 같은데 해당 문제점들이 극복되면 좋겠어」

한 턴에 도는 걸음 수에는 상한이 있습니다. 없앨 수 없는 안전장치입니다 — 그게
없으면 헛도는 턴이 컨텍스트를 다 먹을 때까지 안 멈춥니다. 그러니 고칠 것은
상한이 아니라 **거기서 길이 끊겼다는 것**이었습니다.

```
⚠ 도구 호출 16회에서 멈췄습니다. 이어서 하려면 다시 말씀하세요.   ← 1.6.1

⚠ 도구 호출 16회에서 멈췄습니다.
  안 끝난 것
    ☐ 둘째 부문 그래프 붙이기
    ☐ 셋째 부문 요약 쓰기
› 이어서 할까요? ⏎ 이어서 · n 그만                                ← 1.6.2
```

이을 말에는 남은 단계를 **글자 그대로 싣습니다.** 「아까 하던 것 이어서 해라」 는
가리키기만 하고 안 주는 말이라, 작은 모델은 그 '아까' 를 찾으러 지난 대화를
뒤지기 시작합니다. 이미 끝낸 것은 빼고 싣고, 다시 하지 말라고 못 박습니다.

### 여러 파일을 한 번에 고치는 것은 이미 됩니다

같이 물어보신 것이라 적어 둡니다. `Write` 는 `files`, `Edit` 는 `edits` 에
배열로 넣으면 한 번에 여러 파일을 다룹니다.

```
▶ Edit(4개 파일)
  └ 4군데 고쳤습니다.
      ✓ a.js (1군데)   ✓ b.js (1군데)   ✓ c.js (1군데)   ✓ d.js (1군데)
```

되돌리기는 **파일마다 따로** 떠 있어서, 넷 중 하나만 잘못돼도 나머지 셋을 안
날리고 되돌릴 수 있습니다. 하나가 실패해도 나머지는 갑니다 — 첫 실패에서
멈추면 왕복을 줄이려던 것이 도로 늡니다.

## 1.6.1

**헛도는 턴을 만들던 자리들**

1.6.0 을 맥에서 실제로 쓰다가 걸린 것들입니다. 사내 보고서(pptx·pdf)를 HTML 로
옮겨 달라는 평범한 부탁이 헛돌다 멈췄고, 그 화면을 처음부터 따라가 봤더니
**네 개의 버그가 아니라 하나의 사슬**이었습니다.

```
못 읽었다 → 우회로가 막혔다 → 실패에 길이 없었다 → 같은 문을 계속 두드렸다
                                                   → 컨텍스트만 타고 멈췄다
```

한 자리만 고치면 다음 자리에서 똑같이 막힙니다. 그래서 사슬을 통째로 끊었습니다.

| | 1.6.0 | 1.6.1 |
|---|---|---|
| `soffice … > /dev/null` | 「작업 범위 밖」으로 막힘 | 지나갑니다 (아무것도 저장 안 되는 자리) |
| `ls /usr/bin` | 막힘 — 무엇이 깔렸는지도 못 봄 | 봅니다 (프로그램이 사는 자리) |
| `.ppt` · `.doc` · `.xls` | 「바이너리 파일입니다」 | 깔린 LibreOffice 를 **빌려서 읽습니다** |
| 그것도 없으면 | 같은 말만 되풀이 | 까닭 + 할 일 + **「다시 열지 마세요」** |
| 32k 모델에서 1,425줄 파일 | 화면에 `1425줄` (실제로 간 건 384줄) | `384/1425줄 (일부만)` |
| 답이 천장에서 잘리면 | 아무 말 없음 | 얼마에서 잘렸는지 + `/out` |
| 11쪽을 다 못 읽은 PDF | **성공**으로 돌려줌 | 실패로. 까닭까지 |
| 「안녕」 한 마디 | 모델을 두 번 부름 (6.8초) | 한 번 |
| 그림 든 파일을 고치면 | **그림이 조용히 사라짐** | 막습니다 |

검사는 **4,932 → 5,024항목**(파일 92개 → 94개)입니다.

### 울타리가 자료 아닌 것까지 막고 있었습니다

```
▶ Bash(soffice --convert-to txt 보고서.pptx > /dev/null 2>&1)
  └ 막힘 — 작업 범위 밖입니다: /dev/null
▶ Bash(ls -l /usr/bin/strings)
  └ 막힘 — 작업 범위 밖입니다: /usr/bin/strings
```

`2>/dev/null` 은 셸 명령 절반이 달고 다닙니다. 그 한 조각 때문에 명령 전체가
거절됐습니다. 뒤엣것은 이 PC 에 무엇이 깔렸는지 보는 것인데, 그걸 못 보면
우회로 자체를 못 찾습니다.

이제 **아무것도 저장되지 않는 자리**(`/dev/null` 등)와 **프로그램이 사는 자리**
(`/usr/bin` · `/Applications` · `Program Files` 등)는 울타리를 안 묻습니다.
남의 홈 · `/etc` · `/var` · `/tmp` 는 그대로 막습니다. 중간 파일은
`.deel/tmp/` 에 쓰라고 모델에게 적어 줍니다.

### 못 읽는 옛 문서는 이 PC 의 변환기를 빌립니다

```
◧ Read(보고서.ppt)
  └ 바이너리 파일입니다 — 텍스트로 읽을 수 없습니다     ← 1.6.0

◧ Read(보고서.ppt)
  └ soffice 로 바꿔 읽음 · 148줄                        ← 1.6.1
```

정작 그 맥에는 LibreOffice 가 깔려 있었습니다 — 사람이 그 파일을 더블클릭해
열어 보는 바로 그 프로그램입니다. 1.6.0 에서 `rg` 를 빌려 쓴 것과 **같은
원칙**으로 그걸 빌립니다. **아무것도 설치하지 않습니다.** 맥에서는 더 빠른
`textutil` 을 먼저 쓰고, `PATH` 에 안 걸리는 자리(맥 앱 꾸러미 안, 윈도우
`Program Files`)도 봅니다. 끄려면 `DEEL_CONVERT=off`.

바꾼 글은 작업 폴더 안(`.deel/tmp/`)에 떨구고 **읽는 그 자리에서 지웁니다** —
그 글은 사람 문서의 알맹이라, 사본이 남으면 그대로 커밋되거나 압축되어 나갈
수 있습니다. 원본은 한 바이트도 안 바뀝니다.

[자세히 →](../documents.md#못-읽는-형식은-이-pc-에-깔린-변환기를-빌립니다)

### 안 되는 것은 확실히 안 된다고 말합니다

변환기도 없으면 이렇게 끝냅니다.

```
◧ Read(보고서.ppt)
  └ 보고서.ppt 은 deel 이 직접 못 읽는 형식입니다 (.ppt).
    이 PC 에 LibreOffice(soffice)가 없어서 바꿔 읽을 수도 없습니다.
    해결: 원래 프로그램에서 pptx 로 저장한 뒤 다시 주세요.
    **같은 파일을 다시 Read 하지 마세요. 결과는 같습니다.**
```

무엇이라서 못 읽는지, 무엇이 없어서 못 바꾸는지, 사람이 무엇을 하면 되는지를
한 번에 말합니다. 갈래마다 갈 길이 다릅니다 — `.doc` 이면 docx, `.xls` 면
xlsx, `.hwp` 면 hwpx. **길 없는 거절이 제일 비쌉니다.** 모델은 같은 파일을
다시 열고, 셸로 우회로를 찾다 막히고, 그 왕복이 전부 토큰입니다.

`.pptx` 처럼 우리가 읽을 줄 아는 형식이 안 읽히면 겉과 속을 견줘서 정체를
짚어 줍니다 — 「깨졌거나 다른 형식입니다」로 뭉뚱그리지 않습니다. 깨진 것이면
할 일이 없고 다른 형식이면 바꾸면 되는데, 그 둘은 완전히 다른 이야기입니다.

### Read 요약이 사실이 아니었습니다

파일의 **전체 줄 수**를 찍고 있었습니다. 모델에게 실제로 간 양이 아닙니다.

```
화면          ◧ Read(보고서.html)   1425줄
모델이 받은 것  384줄  (ctx 32k 기준)
```

잘렸다는 말은 모델에게 가는 본문에만 있었고 보는 사람에게는 없었습니다.
그래서 사람은 다 읽은 줄 알고 "왜 저걸 못 고치지" 를 되풀이합니다. 이제
`384/1425줄 (일부만)` 로 찍습니다.

### 답이 천장에서 잘려도 아무 말이 없었습니다

상한을 못 올리고 생각도 바닥이면 우리가 할 일은 없습니다. 그런데 그냥 조용히
끝냈습니다. 화면에는 중간에서 끊긴 답만 남습니다 — 사람 눈에는 모델이 게을러서
대충 답한 것으로 보이니 같은 것을 다시 시키고, 같은 자리에서 또 잘립니다.
이제 얼마에서 잘렸는지와 손댈 자리(`/out`)를 같이 말합니다.

### 못 읽은 PDF 를 성공으로 돌려주고 있었습니다

11쪽을 전부 못 읽고도 **성공**이었습니다. 그러면 되풀이 감지도, 배움도,
재시도 억제도 하나도 안 걸립니다. 이제 실패로 돌려주고, 못 읽은 까닭을 화면
요약에도 올립니다(`11쪽 못 읽음 (글꼴에 /ToUnicode 표 없음)`) — 스캔본이냐
글꼴 문제냐에 따라 사람이 할 일이 완전히 다르기 때문입니다.

### 인사 한 마디에 모델을 두 번 불렀습니다

```
❯ 안녕
  ▌ 안녕하세요! 무엇을 도와드릴까요?
  ↺ 읽기만 하고 끝내려고 해서 한 번 되밀었습니다
  ▌ 안녕하세요! 반갑습니다.
  ── 6.8초
```

되밀기는 「시킨 일을 안 하고 되돌려준」 자리를 잡으라고 만든 것인데, 인사에는
시킨 일이 없습니다. 시킨 것이 없으면 안 한 것도 없습니다. 인사에는 안 밉니다.
「안녕, README 정리해줘」처럼 뒤에 일이 붙으면 그대로 밉니다.

### 그리고 파일에서 그림이 조용히 사라지고 있었습니다

이번에 받은 것 중 제일 나쁜 자리입니다. 읽을 때 박힌 그림(base64)을 빼고 보여
주는데, 모델이 그 글을 손봐서 `Write` 로 덮어쓰면 **못 본 그림이 새 내용에
없습니다.**

```
◧ Read(보고서.html)   1425줄 · 그림 8.0MB 생략
◈ Write(보고서.html)  1420줄        ← 8MB 짜리 그림 일곱 개가 여기서 사라집니다
```

오류도 없고 화면도 멀쩡합니다. 파일을 열어 봐야 압니다. **안 보여 준 것에 대한
책임은 우리에게 있습니다** — 모델은 있는 줄 몰랐던 것을 지킬 수 없습니다.
이제 덮어쓰기 전에 그림 개수를 견주고, 줄어들면 막습니다.

### 0단계 — 아예 못 닿던 자리

#### 프록시 뒤에서 게이트웨이에 안 닿았습니다

문서에는 `HTTPS_PROXY` 를 지원한다고 적혀 있었습니다. 그런데 Node 24.19 에서
직접 재 봤더니 이랬습니다.

```
HTTP_PROXY=http://127.0.0.1:3128  deel
→ 프록시가 받은 요청: 0건        (그냥 직접 나갔습니다)
```

바깥으로 직접 못 나가는 망에서는 이게 「연결 실패」한 줄로만 보입니다. 왜 안
되는지는 아무 데도 안 나옵니다. 이제 deel 이 환경변수를 직접 읽고 `CONNECT` 로
터널을 뚫습니다. 프록시가 못 쓰는 것이면 **그렇다고 말합니다** — 조용히 직접
나가지 않습니다.

#### 서버가 잠깐 막으면 턴이 죽었습니다

사내 게이트웨이는 사람마다 초당 요청을 셉니다. `Task` 로 일을 쪼개면 그 수가
금방 붙습니다. 429 한 번에 하던 일이 통째로 끝났습니다. 이제 기다렸다 다시
부르고, 기다리는 동안 **왜 기다리는지 화면에 적습니다.**

---

### 1단계 — 매일 몇십 초씩 새던 자리

#### 윈도우에서 `ls` 를 `cmd` 에 던지고 있었습니다

모델은 `ls`·`cat`·`grep` 을 씁니다. 그런데 윈도우에서는 그게 `cmd.exe` 로
갔습니다. 로컬 모델은 한 번 왕복에 20~40초입니다 — 실패 한 번이 그만큼입니다.

이제 Git Bash 가 깔려 있으면 그리로 돌리고, 없으면 **어느 셸인지 모델에게
미리 말합니다.** 모르는 채로 틀리게 하는 것보다 아는 채로 맞게 하는 편이 쌉니다.

#### git 이 안 보는 것을 도구가 보고 있었습니다

`out/` · `.gradle/` · `coverage/` · 생성된 코드. 8k 창에 이런 것이 밀려들면
정작 볼 것이 안 남습니다. 이제 `.gitignore` 와 `.deelignore` 를 지킵니다.

#### `/commit` · 열쇠

일한 것이 밖으로 나가는 길은 결국 git 하나입니다. 그런데 여태 모델이 `Bash` 로
`git commit -m "…"` 를 쳐야 했고, 따옴표 하나에 메시지가 뭉개졌습니다. 이제
`/commit` 이 **이번 대화가 바꾼 것만** 담고 메시지를 diff 에서 씁니다.

열쇠는 NTFS 에서 아무 뜻도 없는 `chmod 600` 대신 이 PC 의 잠금장치에 맡깁니다
(윈도우 DPAPI · 맥 키체인). 반입 심사에서 제일 먼저 묻는 자리입니다.

### 3단계 — 큰 저장소·큰 문서

#### 5만 개짜리 저장소에서 Grep 이 「일치 없음」이라고 했습니다

이건 이번에 찾은 것 중 제일 나쁜 자리입니다. 폴더를 훑는 데 2만 개라는 상한이
있었는데, **상한에 걸렸다는 말을 아무 데도 안 했습니다.**

```
파일 5만 개 · 진짜 일치 100건

1.5.8   ❊ Grep(TODO)   → 일치 없음          ← 거짓말
1.6.0   ❊ Grep(TODO)   → 62건 (다 못 봄)
                          파일이 너무 많아 20,000개까지만 봤습니다 —
                          못 본 자리에 있는 것은 여기 안 나옵니다.
```

없다고 하면 사람은 그 말을 믿고 다른 데를 찾습니다. 그게 제일 비쌉니다.

그리고 `rg`(ripgrep)가 이미 깔려 있으면 **빌려 씁니다.** 아무것도 설치하지
않습니다 — 없으면 원래 방식으로 돕니다. 같은 파일을 보도록 확장자 목록을 한
군데서만 정해서, JS 로 돌 때와 `rg` 로 돌 때 결과가 달라지지 않게 했습니다.

#### PDF 를 쪽마다 글로 읽습니다

사양서는 대개 PDF 입니다. hwpx·docx·pptx 는 이미 읽고 있었는데 PDF 만 못
읽었습니다. 의존성 0개 그대로 붙였습니다 — xref·xref 스트림·ObjStm·
FlateDecode·PNG 예측자·`/ToUnicode`·Identity-H 까지.

진짜 크롬이 인쇄한 PDF 로 재면서 두 자리를 고쳤습니다.

```
크롬은 글자 하나에 명령 하나를 씁니다
  고치기 전:  결 제 를  누 르 면
  고친 뒤:    결제를 누르면          ← 펜이 어디 있었는지를 보고 붙입니다

글자 폭을 어림잡으면
  고치기 전:  jum ps over the la zy
  고친 뒤:    jumps over the lazy    ← 글꼴에 적힌 폭을 읽습니다
```

글이 아예 없는 쪽(그림만 있는 스캔본)은 **못 읽었다고 적습니다.** 조용히 빈 쪽을
주면 사람은 그 쪽이 비어 있는 줄 압니다.

#### `/review` · 할당량

바꾼 것을 **새 창에서** 한 번 더 봅니다 (`/review`). 쓴 사람이 못 보는 것을
잡으라고 만든 자리라, 대화 이력을 안 물려줍니다.

할당량은 429 를 맞고 나서야 아는 것이 아니라, 서버가 머리글로 알려 준 것을
받아 적어 `/cost` 와 상태줄에 미리 보여 줍니다.

### 4단계 — 손에 붙는 것

#### 일하는 도중에 그냥 치면 방향이 틀립니다

로컬 모델은 한 턴이 몇 분입니다. 그동안 「아, 그건 말고 저것부터」라고 쳐도
여태는 턴이 끝나야 나갔습니다. 할 수 있는 것은 Ctrl+C 로 **통째로 버리는 것**
뿐이었습니다.

```
❯ 전체 테스트 다시 짜줘
  ◧ Read  test/smoke.js
❯ 아, 그건 말고 실패한 것부터 봐줘
  ❯ 아, 그건 말고 실패한 것부터 봐줘  (도중에 낀 말 — 다음 걸음부터 반영됩니다)
```

하던 일을 안 버리고 방향만 틉니다. 도구 부름과 그 답 사이에는 안 끼웁니다 —
거기 끼면 대화 모양이 깨져서 게이트웨이가 400 을 줍니다.

#### 화면 캡처를 저장 안 해도 붙습니다

`/paste` 로 클립보드의 그림을 바로 넘깁니다. 파일로 저장했다가 `@` 로 붙이는
단계가 없어집니다.

이걸 만들다가 **열쇠가 새던 자리**를 하나 찾았습니다. `Read` 도구는
`.deel/config.json` 을 막고 있었는데, `@.deel/config.json` 으로 붙이면
그대로 딸려 갔습니다. 같은 문지기를 그 길에도 세웠습니다.

#### 에디터를 닫았다 열어도 어제 하던 얘기가 그대로

에디터(Zed·JetBrains·Neovim)에서 쓰면 창을 닫는 순간 대화가 사라졌습니다.
이제 그대로 열립니다. 대화가 **터미널과 같은 자리**에 남아서, 에디터에서 하던
것을 `deel --resume` 으로 이어받는 것도 됩니다.

도구가 도는 중에 죽은 자리는 「끊겼습니다」로 보여 줍니다. 어제 무엇을 하다
끊겼는지가 오늘 무엇을 시킬지를 정하기 때문입니다.

#### 그 밖에

`deel completion bash|zsh|powershell` 로 셸에서도 탭이 먹습니다. 화면 말에
일본어·중국어가 붙어서 넷이 됐습니다(한국어·영어·일본어·중국어).
