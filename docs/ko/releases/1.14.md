## 1.14.0

**적어 둔 것이 참인지 기계가 대신 봅니다**

이 판은 새 기능을 늘린 판이 아닙니다. 「이러이러하다」 고 적어 놓고 아무도 안
보고 있던 자리를 찾아 하나씩 기계에 물린 판입니다.

찾는 방법이 좀 달랐습니다. 서로 못 보는 검수자 여럿을 붙여 놓고, 나온 말마다
**반대쪽에서 뒤집어 보게** 했습니다. 스물다섯 건이 나와서 열 건이 남았습니다
— 열다섯 건은 근거를 대고 죽였습니다. 아래 여덟 개가 그 열 건에서 나온 일입니다.

---

### 하나. 접은 것을 「앞에서 봤잖아」 로 막고 있었습니다

자리가 모자라면 옛날에 읽어 둔 파일 내용을 한 줄짜리 자국으로 접습니다.
그러면서 「이미 읽었다」 는 표(파일 기억)는 같이 지우고 있었습니다.

그런데 표가 하나 더 있었습니다. **되풀이 표**입니다 — 같은 도구를 같은 인자로
불러 결과까지 같으면 다시 안 싣는 자리인데, 그 표는 「그 결과가 대화에 아직
있다」 를 전제로 삼습니다. 접기가 그 전제를 깹니다.

실제로 이렇게 됩니다.

```
Read(큰것.txt)        13,037자가 대화에 들어옴
  … 다섯 걸음 뒤, 자리가 차서 접힘 …
Read(큰것.txt)        76자짜리 쪽지: "앞에서 부른 Read 과 인자도 결과도 같습니다"
```

모델이 받은 것은 **대화 어디에도 없는 글을 가리키는 쪽지**입니다. 파일 내용은
영영 안 돌아오고, 고치라던 일은 그 자리에서 멈춥니다. 오류는 한 줄도 안 납니다.

접기·요약·비우기 세 자리에서 되풀이 표를 같이 버리게 했습니다
(`test/stuck.test.js` 의 `1.6-접힌뒤에는-되풀이가-아니다`).

### 둘. 셸이 쓴 파일은 `/undo` 가 몰랐습니다

되돌리기 스냅샷은 `isMutating(cmd)` 이 참일 때만 찍었습니다. 그런데
`echo x > a.js` · `sed -i` · `tee` · `git restore` 같은 것은 그 목록에 없습니다.
그래서 그 명령들이 고친 파일은 되돌릴 것이 없었고, 더 나쁜 것은 **다른 턴의
것이 대신 되돌아갔다**는 점입니다.

셸이 파일에 쓰는 무늬 열 가지를 따로 봅니다(`셸이파일에쓰나`). 새로 만들어지는
파일도 미리 찍습니다 — 없던 파일이 생기는 것도 되돌릴 일입니다.

### 셋. `.deel` 폴더를 통째로 지우는 것만 새고 있었습니다

`rm .deel/config.json` 은 막혔습니다. `rm -rf .deel/history` 도 막혔습니다.
그런데 `rm -rf .deel` 은 그냥 지나갔습니다 — 낱말에서 경로 후보를 뽑을 때
슬래시가 없는 것은 경로로 안 봤기 때문입니다.

「작업 폴더 정리해 줘」 한 마디에 `rm -rf build dist .deel` 이 나오는 것은
드문 일이 아닙니다. 그러면 되돌리기 이력과 감사 기록이 통째로 없어집니다 —
그 사실은 `/undo` 를 칠 때에야 드러납니다.

`.deel` 이라는 이름 자체를 경로로 보게 했고, 살림 폴더 통째로에는 따로 까닭을
답하게 했습니다(`test/guard.test.js` 의 `9-살림폴더-통째로`, 검사 113항목).

### 넷. ACP 문만 다른 물건을 주고 있었습니다

들어오는 문이 셋입니다 — 대화 화면(`repl.js`) · 배치(`oneshot.js`) ·
편집기(`acp/serve.js`). 셋이 같은 것을 줘야 하는데 ACP 문에만
`vision`(그림을 볼 수 있나)과 `열쇠받기`(토큰을 명령으로 받아 오기)가
빠져 있었습니다. 같은 모델인데 편집기로 들어오면 그림을 못 보고, 한 시간짜리
토큰을 쓰는 사내 게이트웨이에서는 편집기만 401 로 죽었습니다.

셋을 채우고, **다시 어긋나면 잡히게** 했습니다 — 세 문의 연결 정보 열쇠를
소스에서 긁어와 견주고, 셋 중 둘에만 있는 열쇠가 생기면 빨개집니다
(`test/doorparity.test.js`).

### 다섯. 화면에 적어 둔 종료코드 표에 한 칸이 빠져 있었습니다

`deel --help` 가 적어 주는 표에 `6 거절` 이 없었습니다. 배치 스크립트는 그
표를 보고 분기를 짭니다. 표와 프로그램을 소스에서 대조하는 검사를 넣었습니다
(`test/exitcode.test.js`).

### 여섯. `deel run /이름` 이 됩니다

`.claude/commands/배포점검.md` 를 만들어 두고 아침마다 손으로 `/배포점검` 을
치고 있었으면, 그걸 야간 잡에 옮기는 데 드는 일이 이것 하나입니다.

```bash
deel run /배포점검 서버3
```

여태는 `/배포점검` 이 **글자 그대로** 모델에게 갔습니다. 슬래시 낱말 하나를
받은 모델은 대개 "무슨 말인지 모르겠다" 고 답하고 그 턴은 **0 으로** 끝납니다
— 아무 일도 안 했는데 배치는 초록불입니다.

- 파일로 적어 둔 명령이면 본문을 펴서 시킵니다. `$ARGUMENTS` 도 채웁니다.
- 대화 화면 전용 이름(`/help` · `/undo` …)이면 그렇다고 말하고 **1** 로 끝냅니다.
- 아무것도 아니면 모르는 명령이라고 말하고 **1** 로 끝냅니다.

붙박이 이름을 **먼저** 봅니다. 차례를 뒤집으면 이 PC 에 `ralph-loop:help` 같은
플러그인 명령이 깔린 순간 `deel run /help` 만 딴 것을 부릅니다 — 같은 글자가
기계마다 다른 일을 하는 것이 제일 나쁩니다.

### 일곱. 커버리지 문턱이 아무것도 안 막고 있었습니다

`npm run coverage --min 90` 의 `--min` 은 **색깔을 칠하는 데만** 쓰였습니다.
90 을 주든 999 를 주든 종료코드는 같았습니다. README 와 문서는 「90%」 를 적어
두고 있었는데, 그 수를 지키는 자가 어디에도 없었습니다.

문턱을 종료코드에 물렸습니다.

문턱 값은 한 번 틀렸다가 고쳤습니다. 개발 PC(윈도우)에서 잰 90.6% 를 근거로
90 을 걸었는데, **이 관문이 도는 곳은 리눅스**고 거기서는 89.96% 입니다 —
윈도우 전용 길이 리눅스에서 안 밟히니 당연한 차이인데, 재는 곳과 거는 곳을
안 맞춘 것이 잘못이었습니다. 1.14.0 을 올린 뒤 CI 가 0.04점 차이로 빨개져서
알았습니다. 지금은 낮은 쪽에서 내림하고 한 점 더 뺀 **88** 입니다.

같은 자리에서 화면도 하나 고쳤습니다. 막대 옆에는 반올림한 `90%` 가 크게
적혀 있는데 바로 아래 줄이 「커버리지 90.0% 가 문턱 90% 아래입니다」 였습니다.
전체 비율만 소수 한 자리로 적습니다 — 관문이 보는 수와 화면에 적힌 수가
다르면 그 화면은 거짓말입니다.

### 여덟. 그래서 — 검사가 정말 지키는지 되잽니다

위 일곱 가지의 공통점은 **검사가 내내 초록이었다**는 것입니다. 초록불은
「아무도 안 깨졌다」 는 뜻이지 「깨면 잡힌다」 는 뜻이 아닙니다. 이 둘은 겉으로
구별이 안 되는데 값어치는 정반대입니다.

그래서 반대로 잽니다. 지켜야 할 줄을 **일부러 어긋내 놓고**, 짝지은 검사가
빨개지는지 봅니다.

```
$ npm run mutate

  어긋내기  (7개를 일부러 어긋내고 검사가 잡는지 봅니다)

  · 맨 test/guard.test.js → 초록 · 2.0초
  …
  ✓ .deel 이라는 이름만으로는 경로로 안 보게 만든다   test/guard.test.js 가 잡았습니다
  ✓ 접고 나서 되풀이 표를 안 지우게 만든다            test/stuck.test.js 가 잡았습니다
  ✓ 셸이 파일에 쓰는 것을 스냅샷 대상에서 뺀다        test/undo.test.js 가 잡았습니다
  …
  7개 잡음 · 0개 샜음
```

무엇을 어긋내는지와 「그러면 무슨 일이 나는지」 는 `test/mutants.json` 에
적혀 있습니다. 소스는 제자리에서 안 고칩니다 — 임시 폴더로 한 벌 베껴 놓고
거기서만 어긋냅니다. 도중에 죽어도 작업 트리에 어긋난 소스가 남지 않습니다.

어긋내기 **전에** 맨 검사가 초록인지 먼저 봅니다. 원래 빨간 검사는 무엇을
해도 빨개서 전부 잡은 것처럼 보이기 때문입니다.

CI 에서 `npm test` 뒤에 한 판 돕니다. 하나라도 새면 그 자리에서 실패합니다.

### 그 밖에

- 심사서에 박혀 있던 「123항목」 이 없어졌습니다. 어디서도 나온 적 없는
  수였습니다. 실측은 186항목(network 70 · web 56 · mcp 60)이고, 서류에는
  수 대신 **어디를 보면 되는지**를 적었습니다.
- 심사서에 「검사가 무엇을 지키는가」 절이 생겼습니다(한국어·영어 둘 다).
- README 의 검사 항목 표를 전부 다시 쟀습니다. `guard 24` 로 적혀 있던 것이
  실제로는 113 이었습니다. 스물한 줄이 낡아 있었습니다.
- 슬래시 명령 이름표를 `src/cmdnames.js` 로 뺐습니다. 배치 모드가 그 표를
  봐야 하는데, 그러자고 대화 화면 한 벌을 통째로 끌고 올 수는 없습니다.
- ROADMAP 의 T2-1 이 실제와 달랐습니다 — 전선 모양은 1.7.0 에 들어갔고,
  아직 안 된 것은 바깥 창구에 **실제로 닿아 본 적이 없다**는 것뿐입니다.

검사는 7,095항목입니다(1.13.1 은 7,046항목).
