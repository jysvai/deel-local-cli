## 1.19.1

**열두 번째 눈이 본 것, 그리고 오탐 열넷**

1.19.0 을 내고 나서 그 판에 든 커밋 넷을 2차 리뷰에 넣었습니다. 지적이 스물일곱
왔고 **하나씩 실행해 보니 열셋이 진짜**였습니다. 고친 것과, 안 고치기로 한 것과,
그 까닭을 같이 적습니다. 안 고친 쪽이 더 길어진 판입니다.

### 겹줄표와 괄호 — 갈래가 아니라 잣대가 구멍이었습니다

1.19.0 에서 `broken` 을 세 갈래에 맞췄는데, 잣대 자체에 구멍이 둘 남아 있었습니다.

```
Rewrite broken -- exit status 1   → 손대라는 말   CI 도구가 흔히 쓰는 겹줄표
Delete broken (old) files.        → 안 손댐       괄호로 곁말을 단 지시문
```

앞엣것은 홑줄표만 구분자로 봐서 샜고, 뒤엣것은 괄호를 통째로 구분자로 쳐서
**과하게 막았습니다.** 둘 다 어느 동사로 시작하든 똑같이 새고 똑같이 막혔습니다 —
지적은 「1·2번 갈래만 지킨다」 고 했는데, 재 보니 세 갈래 공통이었습니다.

괄호는 **끝나는 괄호**일 때만 로그입니다.

```
Change broken (2)            → 로그    괄호가 글 끝입니다
Build broken (exit 1)        → 로그
Delete broken (old) files.   → 지시문  뒤에 이름씨가 옵니다
```

### 리뷰 도구가 받아 온 쪽지를 그 자리에서 잃었습니다

이 판을 만드는 동안 도구를 실제로 쓰다가 셋을 겪었습니다. 셋 다 이 도구가
잡으러 만들어진 부류입니다.

**40분을 기다려 받은 답이 사라졌습니다.** `--out` 에 폴더를 줬더니 쪽지를 적는
자리에서 터졌는데, 그 자리가 모델을 부른 **뒤**입니다. 기다린 시간과 토큰을 다
쓰고 받아 온 답이 그대로 날아갑니다. 이번에 세 판을 그렇게 잃었습니다. 도움말이
「쪽지를 담을 **폴더**」 라고 적혀 있어서 폴더를 주게 만들고 있었습니다 — 받는
것은 파일 하나입니다. 이제 인자를 읽는 자리에서 봅니다, 비싼 일을 하기 전에.

**「쪼개서 보라」 는 말이 쓸 수 없는 말이었습니다.** 한 판이 출력 한도에 걸리면
도구가 `--files` 로 쪼개라고 일러 줍니다. 그런데 `--files` 는 언제나 안 올린
것만 봤고 `--since` 와 같이 쓰는 것은 아예 막혀 있었습니다. 커밋된 판에는 쓸 수가
없는 말이었습니다. 이제 같이 받습니다.

```bash
node tools/review2.mjs --since HEAD~4 --to HEAD~3 --files a.js
```

**값이 빠진 옵션을 세 가지 꼴로 놓쳤습니다.** 1.19.0 에서 「다음 칸이 아는
옵션이면 값이 없다」 로 적었는데 그 자리에 틈이 셋 남았습니다.

```
--since --unknown     오타 옵션이 값으로 먹혔습니다
--since ""            셸의 빈 변수가 값으로 먹혔습니다
--since -- a.js       POSIX 의 「옵션 끝」 표시가 값으로 먹혔습니다
```

셋 다 멈추는 대신 조용히 「안 올린 것 전부」 로 갔습니다 — 이 울타리가 막으려던
바로 그 자리입니다. 아는 옵션만 볼 것이 아니라 **값처럼 안 생겼나**를 봐야 합니다.

### 「1/4 에서 멈춘다」 는 내장만 있을 때는 안 멈췄습니다

1.19.0 에서 「재지도 않는 것을 주장하는 검사」 를 고쳤는데, 그 고침에 같은 탈이
남아 있었습니다.

```
내장 40 · 사용자 40 · 상한 40   →  내장 10   깎입니다
내장 40 ·  사용자 0 · 상한 40   →  내장 40   안 깎입니다
```

1/4 은 천장이 아니라 **자리를 다투는 쪽이 있을 때만 내장을 묶어 두는 빗장**입니다.
검사 이름은 천장인 것처럼 적혀 있었습니다. 그리고 이 자리 이름이 「몫과차례」 인데
**차례는 아무도 안 쟀습니다** — 자리표가 뒤집혀도 개수만 맞으면 초록이고, 1.19.0
에서 실제로 뒤집혀 있던 자리입니다.

### 안 고친 것들 — 그리고 왜

지적 스물일곱 중 열넷은 재현되지 않거나, 고치면 더 나빠지는 것이었습니다.
이 판에서는 그쪽이 더 값있는 기록입니다.

**「묶음 괄호가 없어 1·2번 갈래가 뚫린다」 — 세 판 연속 같은 주장입니다.**
10차·11차·12차가 모두 이것을 「심각」 으로 냈고 세 번 다 틀렸습니다.

```
update users set name = 42            막힙니다
build(target)                         막힙니다
Update available: 1.2.3               막힙니다
The user can delete applications.     막힙니다
```

**「전치사 잣대를 errors·crash 에도 넣어라」 — 넣으면 더 나빠집니다.**
얻는 것은 `Rewrite crash with exit code 1` 하나인데, 잃는 것이 이렇습니다.

```
Fix errors in route.js          Fix crash on startup.
Fix errors with the parser.     Remove errors from the log.
```

전부 흔한 지시문입니다. **울타리를 옮기면 옮긴 자리에 틈이 생깁니다** — 이번에는
옮기기 전에 재 보고 안 옮겼습니다.

**「`by` 를 전치사 목록에 넣어라」 — 같은 이유입니다.** `Delete broken by-products.`
와 `Update errors by hand.` 가 로그가 됩니다.

**「3번 갈래에 계획 울타리가 없다」 — 일부러 뺀 자리입니다.**
`Implement the plan we agreed on.` 은 계획을 **실행**하라는 말이고,
`Add a plan field to the schema.` 의 plan 은 딸린 이름씨입니다. 둘 다 코드가 맞습니다.

### 못 본 자리 하나

비밀 가리기 판(`src/safety/secrets.js`)은 **세 번 다 출력 한도에 걸려** 리뷰를
못 받았습니다. 우연이 아닙니다 — 그 파일의 무늬가 한 줄에 1,500자라 읽는 쪽 답이
길어집니다. 안 본 것을 봤다고 적지 않으려고 여기 적어 둡니다.

## 1.19.0

**한쪽을 맞히면 반대쪽이 틀렸습니다**

1.18.0 에서 「만든 모델 말고 다른 모델이 한 번 더 보는」 2차 리뷰를 붙였습니다.
이 판은 그것을 **열한 판** 돌리고, 그 사이에 이 도구를 실제 벤치마크 지시문으로
몰아 본 결과입니다. 고친 자리 쉰여덟인데 기능은 하나도 안 늘었습니다.

고친 것 대부분이 한 부류였습니다.

- 시킴말을 알아보게 넓히면 **로그와 물음**이 시킴말로 잡힙니다
- 로그를 걸러 내면 `Fix errors.` 같은 **진짜 시킴말**이 같이 빠집니다
- 비밀을 가리려고 넓히면 **비밀 아닌 것**이 가려지고, 좁히면 **진짜 열쇠**가 나갑니다

**울타리를 옮기면 옮긴 자리에 틈이 생깁니다.** 1.18 에서 한 번 적어 둔 말인데,
이 판에서 열한 번 더 겪었습니다. 그래서 이제 검사는 언제나 **양쪽을 같이** 잽니다 —
「걸려야 하는 것이 걸리나」 와 「안 걸려야 하는 것이 안 걸리나」 를 짝으로 둡니다.

### 3,577자짜리 지시문이 「원인부터 찾아라」 로 갔습니다

이 도구는 사람이 친 말을 읽고 모드를 고릅니다. 고치는 모드(code)와 읽기만 하는
모드(debug·ask·inspect·plan)가 하는 일이 아주 다르기 때문입니다. 1.18.0 을
실제 벤치마크 지시문으로 몰아 봤습니다.

```
「빈 작업 폴더에서 시작해 업무 요청·결재 웹 앱을 설계하고 구현하고
 검사까지 해라」  — 영어 3,577자

  →  디버그 모드 (원인부터 찾아라)
```

빈 폴더입니다. 찾을 원인이 없습니다.

까닭을 재 보니 낱말 두 개였고 둘 다 증상이 아니라 **요구사항 조건절**이었습니다.
그런데 그건 증상이었고 뿌리는 더 아래에 있었습니다. 영어 시킴말 열넷을 나란히
재 봤더니 **열 개가 code 표에서 0점**입니다.

```
  Fix errors.                        0점
  Could you please fix this?         0점
  Make a plan for this.              code (계획인데)
  Explain user.delete in detail.     code (설명해 달라는 말인데)
  Review this code.                  아무 모드도 아님
```

한국말은 여덟 판 동안 다듬었는데 영어는 첫머리 시킴말 몇 개로만 보고 있었습니다.
이 판에서 영어 쪽 점수표를 통째로 다시 짰습니다.

### 영어와 한국어가 서로 다른 프로그램이었습니다

한쪽을 고치면 다른 쪽이 뒤처지는 것이 세 번 되풀이됐습니다. 그래서 **같은 뜻의
짝 스물여섯**을 만들어 나란히 재는 검사를 뒀습니다.

```
  "이 코드 검토해 줘"      inspect        "Review this code."       (아무것도 아님)
  "이 코드 살펴봐 줘"      0점            "Inspect this code."      inspect
  "어떻게 돌리는 거야?"    0점            "The tests are failing."  debug
  "계획 세워 줘"           plan           "Make a plan for this."   code
```

왼쪽이 이기는 자리도 있고 오른쪽이 이기는 자리도 있었습니다. 어느 쪽이든
**같은 뜻이면 같은 모드로 가야 합니다.** 이제 짝이 어긋나면 검사가 빨개집니다.

### 붙여 넣은 글을 시키는 말로 읽었습니다

사람이 제일 많이 붙여 넣는 것은 지시문이 아니라 **로그와 코드**입니다. 붙여 넣을
법한 글 서른여덟 줄을 죽 재 봤더니 일곱이 시킴말로 읽혔고, 다섯이 한 모양이었습니다.

```
  fix: 값이 아닌 것을 가렸습니다        ← 이 저장소의 커밋 메시지입니다
  Change-Id: I8f2c1a
  delete from users where id = 1;
  update accounts set balance = 0 where id = 3
  Delete failed: permission denied
  Rewrite broken with exit code 1
  Update available: 1.2.3
```

시킴말로 읽히면 **읽기 전용 모드가 후보에서 통째로 빠집니다.** 「이 쿼리가 왜
이러냐」 고 물으려고 붙였는데 파일을 고치러 갑니다.

가르는 잣대를 낱말이 아니라 **뒤에 무엇이 이어지느냐**로 바꿨습니다.

```
  delete from users where id = 1;   → SQL   (from + 이름 + where)
  Delete from the list.             → 지시문 (뒤가 SQL 이 아닙니다)
  Delete the row from users.        → 지시문 (from 이 동사 뒤가 아닙니다)
  Modify broken.                    → 로그   (broken 은 그림씨입니다)
  Fix broken tests.                 → 지시문 (뒤에 이름씨가 옵니다)
```

### 비밀이 아닌 것을 가리고, 비밀은 내보냈습니다

가림이 하는 일은 **값**을 숨기는 것입니다. 그런데 값이 아닌 것을 가리고 있었습니다.

```
  const JWT_SECRET = process.env.JWT_SECRET;   → 가려짐  (참조인데)
  interface Cfg { API_KEY: string }            → 가려짐  (타입 이름인데)
  const API_KEY = config.apiKey;               → 가려짐  (참조인데)
  const API_KEY: string = "secret12345";       → 타입만 가려지고 비밀은 남음
```

마지막 줄이 제일 나쁩니다 — **줄은 망가지고 비밀은 그대로**입니다.

반대쪽으로 넓히자 이번엔 진짜 열쇠가 샜습니다.

```
  const API_KEY = "ENV-PROD-SECRET-KEY-12345";   → 안 가려짐
  {"API_KEY":"secret12345"}                      → 안 가려짐
  const API_KEY: () => string = "secret12345";   → 안 가려짐
  const API_KEY: string = ("secret12345");       → 안 가려짐
```

줄이 망가지는 것보다 이쪽이 훨씬 나쁩니다. 그 값은 그대로 모델에 실려 나갑니다.

두 번 헛디뎠고 둘 다 소스에 적어 뒀습니다. **타입처럼 생긴 글자를 목록으로
적는 쪽은 지는 싸움입니다** — 여덟 판 동안 목록을 넓혔는데 매번 밖의 꼴이
나왔습니다(둥근괄호 · 중괄호 · 화살표 · 세로줄 · 세미콜론). 지금은 목록 대신
**끝나는 자리**만 봅니다. 값이 어디서 끝나는지도 「뒤에 뭐가 오나」 가 아니라
따옴표 짝으로 봅니다.

### 남의 플러그인이 이 도구 자신을 목록에서 밀어냈습니다

빈 폴더에서 1.18.0 을 그대로 띄워 시스템 글을 재 봤습니다.

```
  시스템 글 9,399자
    └ 스킬 목록 6,700자 (71%) · 40개
        ├ 사용자 것        11개
        ├ 플러그인         29개  ← ~/.claude/plugins 캐시, deel 것도 아님
        └ deel 내장         0개
```

이 도구가 자기 방법론을 실으려고 만든 자리를, 남의 플러그인 300개가 밀어냈습니다.
자리표는 「프로젝트 > 사용자 > 내장 > 플러그인」 이라고 적혀 있었는데 실제로는
그 반대였습니다.

고치면서 또 반대쪽으로 넘어갔습니다 — 내장을 상한까지 **무조건 먼저** 떼어 두자
이번엔 프로젝트 스킬이 굶었습니다(상한 10 · 프로젝트 10 + 내장 7 → 프로젝트 3).
지금은 내장에 **상한의 1/4** 만 매어 두고 나머지는 자리표 순서대로 갑니다.

상한 값 자체도 세 가지가 어긋나 있었습니다.

```
  maxSkillsListed = -1        → 끝 하나만 빼고 다 (「하나도 안 싣기」 여야 합니다)
  maxSkillsListed = '10'      → 0개              (설정에서 오면 글자열입니다)
  maxSkillsListed = Infinity  → 0개
```

### 검사 파일은 못 찾고, 살림 파일은 검사로 알고 돌렸습니다

「이 프로젝트는 무엇으로 검사하나」 를 찾는 자입니다. 벤치마크가 만들 법한 프로젝트
모양 여덟 가지로 재 봤더니 하나가 빈손이었습니다 — 그리고 **이 저장소 자신이
그 모양**이었습니다.

```
  test/approval.test.js · test/roles.test.js 가 있고
  package.json 에 test 칸은 없는 프로젝트   →  찾은 것 0개
```

넓혔더니 이번엔 반대로 갔습니다. 앞쪽 갈래의 구분자에 점이 들어 있어서
**살림 파일이 검사로 잡혀 실제로 실행**됐습니다.

```
  check.config.js · test.min.js · qa.bundle.js · spec.d.ts · verify.config.mjs
```

앞에 붙는 이름과 뒤에 붙는 이름은 서로 다른 관례라 갈래를 나눴습니다. 낱말
하나짜리 단독 이름으로 받는 것은 `test` · `spec` 둘뿐입니다 — `check.js` ·
`bench.js` · `e2e.js` 는 아닙니다.

### 2차 리뷰를 열한 판 돌렸습니다 — 그 도구도 같은 병을 앓았습니다

1.18 에서 만든 2차 리뷰를 이 판에서 실제로 썼습니다. 열한 판에서 나온 지적을
**전부 손으로 재현해 보고** 진짜인 것만 고쳤습니다. 절반 남짓이 오탐이었습니다.
마지막 판에서도 「심각」 둘이 나왔는데 둘 다 재현되지 않았습니다 — 정규식 괄호가
일찍 닫혔다는 주장이었고, 열 문장을 넣어 보니 전부 멀쩡했습니다.

그 도구 자신이 이 판에서 잡으러 온 부류를 셋이나 갖고 있었습니다.

```
  node tools/review2.mjs --help     → 도움말 대신 진짜 리뷰가 40분 돌았습니다
  node tools/review2.mjs --since    → 조용히 「안 올린 것 전부」 가 됐습니다
  node tools/review2.mjs --to HEAD~2 → 화면에는 「안 올린 것」, 실제로는 딴 것
```

셋 다 **조용히 다른 것을 합니다.** 인자를 `indexOf` 로 하나씩 찾기만 해서 목록에
없는 말은 그냥 없는 것이 됐습니다. 이제 모르는 옵션과 **값이 빠진 옵션**에서
멈춥니다.

리뷰가 네 번 빈 손으로 돌아온 것도 찾은 게 없어서가 아니라 **출력 한도**에 걸려
다 못 적은 것이었습니다. 이제 범위를 좁혀 돌리고, 답이 잘리면 한 판 더 묻습니다.

### 그 밖

**모드를 못 골랐을 때 화면이 아무 말도 안 했습니다.** `route.js` 머리말에는
「왜 그렇게 봤는지 화면에 같이 뜬다」 고 적어 뒀는데, 정작 못 골랐을 때는
`if (골라진.mode)` 안에서만 찍고 있었습니다. 「일부러 안 골랐다」 를 사람이
알 길이 없었습니다.

**망이 끊긴 판을 40분짜리 재시도로 보냈습니다 — 또.** 「무엇이 잘렸나」 를
가르는 자리인데, 두 판에 걸쳐 두 번 샜습니다. `connection cut off by peer` 는
모델 답이 잘린 것이 아니라 망이 끊긴 것입니다. 그런데 「끼는 이름씨가 있으면」
으로 좁혔더니 `response cut off by peer` 처럼 **끼는 이름씨가 없는** 꼴이
남았습니다.

**초록이었지만 아무것도 안 재던 검사 열넷.** 조건이 안 서는 글로 재고 있던 것,
이름이 약속한 것보다 덜 재던 것, 개수만 세느라 나눔이 깨져도 초록이던 것.
전부 구현을 되돌려 **빨개지는 것을 보고 나서야** 초록으로 뒀습니다.

**주석이 코드와 반대로 적힌 자리 넷.** 「약자 목록에는 뒤가 없는 말만」 이라
적어 놓고 남긴 것은 전부 뒤가 이어지는 약자였고, 「등호 앞의 빈칸」 이라 적힌
잣대는 실제로 **값 앞의 빈칸**이었습니다. 주석은 코드와 같이 안 바뀌면 조용히
거짓말이 됩니다.
