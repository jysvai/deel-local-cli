## 1.10.0

**ESC 가 진짜로 멈추고, 자리가 다 차도 하던 일을 이어 갑니다**

제보받은 네 가지를 줄기로 잡았습니다. 넷 다 「기능이 없다」가 아니라
**「있다고 적어 뒀는데 그 자리에서만 없다」** 쪽이었습니다.

| 제보 | 실제로 무슨 일이었나 |
| --- | --- |
| ESC 를 눌러도 안 멈춘다 | 멈추라는 신호가 **세 자리에 아예 안 닿고 있었습니다** |
| 중간에 끊긴다 | 끊긴 자리에서 화면이 아무 말도 안 했습니다 |
| 요청을 몇 개씩 까먹는다 | 껐다 켜면 남은 할 일이 **빈 채로** 시작했습니다 |
| 컨텍스트가 차면 막힌다 | 자리를 배우고 **같은 대화를 그대로** 다시 보냈습니다 |

---

### ESC — 안 먹은 게 아니라 안 닿고 있었습니다

우리가 도는 동안은 이미 멈췄습니다. 안 멈추던 것은 **남이 답하기를 기다리는
자리**였습니다. 거기에는 시한만 있고 사람이 누른 키가 없었습니다.

```
                        전            후
  안 답하는 웹 서버     30초 기다림    0.14초
  안 답하는 MCP 도구    60초 기다림    0.12초
  뭘 고를지 물어보는 중  안 먹음        멈춤
```

화면에는 그 사이 내내 「멈추는 중…」 이 떠 있었습니다. 사람 눈에는 ESC 가
고장 난 것과 구별이 안 됩니다.

세 가지를 같이 지킵니다.

- **멈춤과 시한 초과를 다른 말로 적습니다.** 시한은 상대가 늦은 것이고
  멈춤은 우리가 그만둔 것입니다. 내가 누른 키가 남의 서버 잘못으로 찍히면 안 됩니다.
- **이미 멈춘 뒤에는 아예 안 나갑니다.** 멈춘 뒤에 남의 서버에 남기는
  발자국은 설명할 길이 없습니다.
- **줄 화면에서도 말합니다.** 터미널이 아닌 곳(CI·파이프)에서는 ESC 를 눌러도
  화면이 가만히 있었습니다.

---

### 자리가 다 차도 그 턴 안에서 이어 갑니다

전에는 이랬습니다. 자리가 모자라 서버가 거절 → 창 크기를 배우고 다시 부름 →
**같은 대화를 그대로 다시 보냄** → 또 거절 → 붉은 줄 하나 뜨고 턴이 죽습니다.
사람이 `/clear` 를 치고, 시킨 말을 처음부터 다시 치고, 붙였던 파일도 다시
붙여야 했습니다. 한 걸음도 못 나아간 채로.

지금은 스스로 살아납니다.

```
❯ 로그 형식 통일해줘
  ◱ 자리가 모자라 앞선 대화 17개를 비우고 이어갑니다 — 남은 할 일 2개
  비운 뒤에도 이어서 했습니다.
```

**사람이 다시 친 것은 0글자입니다.** 비울 때 시킨 말 원문·남은 할 일·이번 턴에
손댄 파일 이름은 그대로 들고 갑니다. 오류가 아니므로 종료코드도 0 입니다.

**한 턴에 한 번뿐입니다.** 비우고도 또 막히면 그때는 사실대로 오류입니다.
비우는 걸음은 걸음 수를 안 돌려주므로, 영영 도는 일은 구조적으로 없습니다.

접기·비우기를 **부른 뒤가 아니라 부르기 전에** 봅니다. 여태는 도구를 한 번
쓴 뒤에만 쟀기 때문에, 큰 것을 붙여 넣은 첫 마디는 잴 기회조차 없이 죽었습니다.

---

### 껐다 켜도 남은 할 일이 남아 있습니다

1.9.2 는 **한 대화 안에서** 접힘·줄임에 할 일이 사라지던 것을 막았습니다.
그런데 그 둘이 메모리에만 있어서, 창을 닫는 한 번에 그 보호가 통째로
없어졌습니다.

```
                            전          후
  주고받은 말                돌아옴      돌아옴
  못 박은 것                 돌아옴      돌아옴
  남은 할 일               ★ 빈 채로     돌아옴
  시킨 말 원문             ★ 빈 채로     돌아옴
```

**저장이 안 되고 있으면 그렇다고 말합니다.** 디스크가 차거나 홈이 읽기
전용이면 한 줄도 안 적히는데, 여태 화면은 아무 말이 없었습니다. 사람이
알아차리는 자리가 **다음 날 `--resume`** 이었습니다. 그때는 이미 대화가 없습니다.

```
⚠ 이 대화가 파일에 안 적히고 있습니다 (EACCES) — 12줄을 잃었습니다.
  지금 창을 닫으면 이어할 수 없습니다.
```

`/sessions` 화면은 전에는 무조건 「계속 저장되고 있습니다」 라고 약속했습니다.
이제 새고 있으면 그 자리에 경고를 대신 찍습니다.

### 번호를 고르면서 하고 싶은 말도 같이

물어보는 상자에서 전에는 번호를 치면 고른 것, 그 밖의 글은 **고른 것 없이**
자유 답이었습니다. 둘 다 하고 싶을 때 길이 없었습니다.

```
❯ 2 다만 .env 는 건드리지 마
  ▶ .env.example 만 추가 — 다만 .env 는 건드리지 마
```

`2:` `2,` `2 -` `2.` 다 됩니다. `1,3` 으로 여럿도 됩니다. 「3개만 해줘」 는
3번을 고른 것이 **아닙니다** — 수 뒤에 글자가 붙으면 수로 안 읽습니다.

계획 상자도 같습니다.

```
전:  이대로 진행할까요?  ⏎ 진행 · n 취소 · 그 밖엔 고칠 점
후:  이대로 진행할까요?  ⏎ 진행 · y 한마디 붙여 진행 · 3 그 단계에 한마디 · n 취소
```

`y 검사도 같이 넣어줘` 는 **계획을 다시 짜지 않고** 그 말을 얹어 진행합니다.
전에는 이렇게 치면 계획을 다시 짜러 가서 몇 분을 다시 기다렸습니다.

### 붙여넣기

일하는 중에 40줄을 붙이면 마지막 한 줄만 보였습니다. 사람은 한 줄만 들어간
줄 알고 다시 붙이고, 그러면 **진짜로 두 번** 들어갑니다.

```
전:  ❯ 40번째 줄 — …
후:  ❯ [붙여넣기 #1 · 40줄 · 1.6KB]
```

모델에게는 40줄이 바이트까지 그대로 갑니다. 표 낱말이 한국어로 박혀 있던 것도
고쳐서, 고른 말로 적힙니다 — `[pasted #1 · 3 lines · 5B]` · `[貼り付け #1 · 3行]` ·
`[粘贴 #1 · 3行]`. 말을 바꾼 뒤에도 앞서 찍어 둔 표를 알아봅니다.

### 회사마다 다른 창구를, 여덟 자리 전부 재 봤습니다

내장 도구 20개와 기능 32가지를 **여덟 환경**(로컬 · Ollama · OpenAI 직통 ·
Azure · Gemini · Claude 직통 · Bedrock 게이트웨이 · 사내 게이트웨이)에
하나씩 보내 봤습니다. 도구 20개는 어디로 보내도 한 글자도 안 깎입니다.
갈린 자리에서 **진짜 고장 다섯**이 나왔습니다.

| 어디서 | 전 | 후 |
| --- | --- | --- |
| Claude 직통 `deel setup` | **진단 8칸 전부 빨강** → 「도구 못 씀」 으로 저장됨 | 8칸 통과 |
| `/plan` (로컬·OpenAI·Gemini·Ollama) | 우리 눈금의 `max` 가 그대로 나가 **400** | 그 규격이 아는 제일 센 말로 |
| OpenAI 추론 모델 | 출력 상한의 옛 이름을 같이 보내 **첫 요청부터 400** | 새 이름만 |
| Claude 가 알려 준 한계 | 숫자를 **거꾸로 읽어** 프로필에 잘못 저장 → 계속 죽음 | 바로 읽음 |
| Claude · Bedrock 남은 할당량 | **항상 비어 있음** → 429 를 맞아야 앎 | 머리에서 읽음 |

첫 줄이 제일 나빴습니다. 진단이 Anthropic 규격을 몰라 첫 칸에서 400 이 나고,
그 결과가 `도구 못 씀 · 그림 못 봄` 으로 **프로필에 저장**됐습니다. 화면은
설정이 끝났다고 하는데 도구를 아예 안 쓰는 연결이 만들어집니다.

**Codex(`gpt-5-codex`)는 아직 못 붙습니다.** 그 계열은 다른 문(Responses API)
으로만 답하는데, 문을 하나 더 내려면 모델을 바꿀 때 규격이 안 바뀌는 것과
대화 접기가 조용히 멎는 것을 먼저 풀어야 합니다. 반쪽으로 넣으면
「된다고 화면이 말하는데 안 되는」 바로 그 고장이 됩니다. 대신 **왜 안 붙는지
한 줄로 말합니다** — 열쇠나 모델 이름을 의심하며 헤매지 않게.

### 보안 — 한 줄로 울타리를 넘던 자리

`cat .deel/config.json` 은 막고 있었습니다. 그런데 `cd` 를 한 번 거치면
파일 이름만 남아서 검사를 아예 안 했습니다.

```
type .deel\config.json            막힘
cd .deel && type config.json    ★ 통과
cd .deel; cat config.json       ★ 통과
cd .deel && del audit.jsonl     ★ 통과   ← 감사기록을 지우는 것도
```

이제 살림 폴더로 들어가는 것 자체를 막습니다. `pushd` · `Set-Location` ·
줄바꿈 · 셸을 한 겹 씌운 것까지 같이 막고, `cd src && cat x.js` 는 그대로
지나갑니다.

- **감사기록에 열쇠가 평문으로 적히던 것.** `curl -H "Authorization: Bearer …"`
  가 글자 그대로 남았습니다. 이 파일은 `deel audit` 로 심사 자료에 딸려 나갑니다.
- **작게 받아서 크게 푸는 묶음.** 압축 64MB 제한은 있는데 **푼 크기 제한이
  없었습니다.** 0으로 찬 4MB 가 4,098바이트로 줄어듭니다.
- **감사기록과 대화 파일도 본인만 읽게 잠급니다.** 설정 파일에만 걸려 있었습니다.
- **자식 셸이 게이트웨이 열쇠를 물려받던 것.** `env` 한 줄이면 열쇠가
  화면·대화기록·디스크로 갑니다. MCP 서버에는 이미 안 넘기고 있었습니다.
- **맥에서 검사가 사람의 진짜 열쇠를 덮어쓰던 것.** 키체인 이름이 하나로
  박혀 있어서, 맥에서 검사를 돌리면 실제 게이트웨이 열쇠가 검사값이 됐습니다.

### 끝날 때 남기지 않습니다

deel 을 끄고 작업 관리자를 열면 노드 프로세스가 하나씩 남아 있었습니다.
언어 서버와 MCP 서버는 우리가 띄운 남의 프로그램이라, 붙인 쪽이 안 닫고
끝나면 아무도 안 닫았습니다. 며칠 쓰면 눈에 띄게 느려집니다.

Ctrl+C 는 아이를 거둔 뒤, **그 신호를 맡은 손이 우리 것 하나뿐일 때만**
우리도 죽습니다. 남이 맡고 있으면 그쪽 마무리를 안 끊습니다.

### 그 밖에

- **탈이 나면 여기까지 흘러온 말이 통째로 사라지던 것.** 중단(ESC)은 남기는데
  오류는 안 남겼습니다. 반쯤 써 놓은 답을 잃습니다.
- **잘린 답이 `deel run` 과 에디터에서는 온전한 답인 척** 지나갔습니다.
- **끊긴 턴에서는 무엇이 빠졌는지 아무도 말해 주지 않았습니다.** 빠뜨린 것
  검사가 정상 종료에만 돌고, 정작 잘 빠뜨리는 자리에서는 안 돌았습니다.
- **규칙 파일(`DEEL.md`·`CLAUDE.md`)이 있는데 못 읽어도 「없음」** 이라고만
  했습니다. 사람은 규칙이 걸린 줄 알고 씁니다.
- **짐작한 인코딩을 사실처럼** 적었습니다. 이제 `CP949 (추정)` 로 적습니다.
- **설정을 못 남겨도 ✓ 만 찍던 아홉 자리.** 다시 켜면 되돌아가 있습니다.
- **일본어·중국어에 비어 있던 24 마디.** `/think` 화면이 표 틀만 번역돼 있고
  알맹이는 통째로 영어였습니다. 네 말 모두 419/419 입니다.
