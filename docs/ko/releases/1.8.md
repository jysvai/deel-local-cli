## 1.8.0

**한 시간짜리 토큰을 쓰는 사내 게이트웨이에서 하루를 보낼 수 있습니다**

1.7 까지는 열쇠를 적어 두는 것만 됐습니다. 사내 게이트웨이는 고정된 열쇠를
안 줍니다 — 한 시간짜리 토큰을 주고, 그것도 사내 로그인을 거쳐야 나옵니다.
그래서 실제로는 이렇게 됐습니다.

```
아침   포털에서 토큰 복사 → deel setup 에 붙여 넣기
점심   HTTP 401
그 뒤  다시 발급받으러 감 → 한 시간 뒤 같은 화면
```

제일 나쁜 것이 그 401 입니다. **「열쇠가 틀렸다」 와 「열쇠가 늙었다」 를
구별해 주지 않습니다.** 사람은 화면만 보고 열쇠를 다시 발급받으러 갑니다.

| | 1.7.0 | 1.8.0 |
|---|---|---|
| 한 시간짜리 토큰 | 만료될 때마다 손으로 다시 | 요청 직전에 받아 옵니다 |
| 401 을 맞으면 | 그대로 실패 | 새 열쇠로 **한 번만** 다시 부릅니다 |
| 지우고 다시 시작하려면 | 다시 설치 | `deel reset` |
| 영어로 켠 화면 | 62줄이 한국어로 나왔습니다 | 0줄 |

### 열쇠를 적어 두는 대신, 받아 오게 하기

열쇠 자리에 **열쇠를 얻는 방법**을 적습니다.

```json
"열쇠받기": {
  "명령": "az account get-access-token --resource api://ai-gw --query accessToken -o tsv",
  "수명": 3600
}
```

명령은 토큰 한 줄이나 `{"token": …, "expires_at": …, "headers": {…}}` 를 뱉으면
됩니다. 만료 1분 전부터 미리 새로 받습니다 — 보내는 순간에 살아 있던 토큰이
게이트웨이에 닿을 때 죽어 있으면, 그게 바로 그 401 이기 때문입니다.

지키는 선을 못 박아 뒀습니다.

| | |
|---|---|
| 경로는 직접 적습니다 | 찾아 주지 않습니다. `az` 가 PATH 에 있나 보고 알아서 부르면, 이 프로그램이 언제 무엇을 실행할지 모르게 됩니다 |
| 딴 프로세스로 띄웁니다 | `import` 하지 않습니다 — 우리 프로세스 안에서 돌면 그 코드가 다른 열쇠와 대화를 봅니다 |
| 한 판에 한 번 묻습니다 | 세 번 물으면 사람은 손이 가는 대로 누릅니다. 관리 정책이 준 명령은 안 묻습니다 |
| 봉인이면 안 부릅니다 | `--offline` 로 잠근 판에서 사내 포털에 나가면 약속을 깬 것입니다 |
| 파일에 안 적습니다 | 받은 토큰은 이 판이 도는 동안 메모리에만 있습니다 |
| 가립니다 | 토큰도, 같이 온 머리말 값도, 명령이 오류로 뱉은 글도 |

**배너가 섞인 출력은 거절합니다.** 사내 로그인 도구는 「Logged in as …」 를
찍고 그 다음 줄에 토큰을 찍습니다. 통째로 실으면 게이트웨이는 400 을 주고,
화면에서는 열쇠가 틀린 것과 구별이 안 됩니다. 무엇이 왔는지 첫 줄을 보여
주므로 `--query` 를 붙일 줄 알게 됩니다.

`/status` 의 `열쇠 보관` 줄에 「받아 옴 · 52분 남음」 이라고 적습니다.
보관이라고 안 적는 까닭은, 우리가 그 열쇠를 갖고 있지 않기 때문입니다.

자세한 것은 [설정 · 열쇠받기](../config.md)를 보세요.

### `deel reset` — 지우려고 다시 깔지 않게

설정·기억·대화·배운 것·플러그인을 갈래별로 지웁니다.

```bash
deel reset               # 무엇이 얼마나 있는지 보여만 줍니다
deel reset model         # 연결 설정만
deel reset memory        # 기억과 못 박아 둔 것
deel reset all           # 전부 (되돌리기·감사기록은 남습니다)
deel reset all --hard    # 그것까지
```

그냥 `deel reset` 은 아무것도 안 지웁니다. 무엇이 몇 개 있는지 보여만 줍니다 —
지우는 명령의 기본값이 지우는 것이면 안 됩니다.

`.deel/mcp.json` · `.deelignore` · `DEEL.md` 는 **어느 갈래로도 안 건드립니다.**
사람이 손으로 적은 것이라, 지워 주는 것이 도움이 되는 파일이 아닙니다.

맥에서는 키체인에 둔 열쇠도 같이 지웁니다. 윈도우는 설정 파일 안에 있어서
파일과 같이 지워집니다. 다른 PC 에서 넣은 것은 못 지운다고 그대로 말합니다.

### 영어로 켰는데 한국어가 나오던 예순두 줄

`/lang` 은 「영어 100%」 라고 답했습니다. 그런데 영어로 켜고 화면을 읽으면
한국어가 그대로 나오는 줄이 예순두 개였습니다.

```
/help 명령 목록   ESC 중단   Ctrl+C 중단·끝내기
첫 판단·medium 생각 중…
└ 1개 파일 · 1건 · rg      └ 5줄      └ 1군데 +1 −1
```

둘 다 맞는 말이었습니다. **표에 든 열쇠**는 다 채워져 있었고, 저 글들은 표에
들어간 적이 없었습니다. 세는 자리가 사람이 보는 것을 안 세고 있었던 것이고,
앞으로도 못 셉니다 — 없는 열쇠는 셀 수가 없습니다.

그래서 **켜서 읽는 검사**를 뒀습니다. 일곱 화면을 영어로 띄우고 한글이 한 자라도
나오면 빨개집니다. 소스를 훑는 방식으로는 못 잡습니다 — `└ 1개 파일 · 1건 · rg`
같은 글은 조각을 이어 그때그때 만들기 때문에 소스 어디에도 통째로 안 적혀
있습니다.

`1 files` 처럼 홑복수가 안 갈린 것과, 가운뎃점이 겹치거나 줄 끝에 남는 것도
같이 잡습니다. 그 둘은 한국어가 안 남았다는 점에서는 멀쩡한데, 사람 눈에는
안 옮긴 것만큼이나 대충 만든 것으로 보입니다.

`/tools` 스물한 줄은 한 자리 때문이었습니다. 영어 도구 설명표는 이미 있었는데,
**모델에게 줄 때만** 갈아 끼우고 화면은 원본을 찍고 있었습니다. 시키는 말과
보는 말은 다른 축입니다 — 영어로 시키고 한국어로 받는 조합이 실제로 쓰입니다.

같이 드러난 것으로, 규격 이름이 화면마다 달랐습니다. 켤 때 머리말은
「Ollama 규격」, `/status` 는 「Ollama 자체 규격」 이었습니다. 둘 다 맞는 말이라
아무도 안 고쳤습니다. 한 자리로 모았습니다.

### 사내 게이트웨이가 첫 한마디를 통째로 튕기던 것

도구 인자 이름에 한글이 섞여 있었습니다. Bedrock 은 인자 이름을
`^[a-zA-Z0-9_.-]{1,64}$` 로 검사해서, 한글 이름이 하나라도 있으면 그 요청을
통째로 거절합니다. 그리고 **처음 걸린 하나만** 말해 주므로, 고치면 다음 것이
나오고 또 고치면 그 다음이 나옵니다.

전부 영문으로 바꾸고, 옛 이름도 계속 받습니다. 그리고 검사를 뒀습니다 —
이름이 서버가 받아 주는 모양인지, `required` 가 진짜 있는 인자를 가리키는지,
설명서와 화면이 같은 이름을 부르는지. 그 검사가 만들자마자 진짜 버그를 하나
잡았습니다: `Task` 의 `required` 가 없는 인자를 가리키고 있었습니다.

터미널 그림은 손으로 안 그립니다. `tools/shot.mjs` 가 진짜로 `deel` 을 띄워
나온 것을 SVG 로 굳힙니다. 손으로 적은 그림은 화면이 바뀌어도 안 바뀌고,
실제로 이미 어긋나 있었습니다.
