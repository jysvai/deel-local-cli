## 2.1.7

**맥 기본 셸(zsh)에서 파일 이름 Tab 이 오류를 내던 것을 고쳤습니다**

2.1.6 에서 맥을 관문 CI 에 넣은 뒤, 맥에만 있는 코드 길을 진짜 맥에서 하나씩 돌려 봤습니다. 열린 포트 찾기 ·
`textutil` 로 .doc · .rtf · .docx · .odt 읽기 · 클립보드 그림 · 대소문자만 다른 import · `deel doctor` 는 그대로 맞게
돌았고, 아래 셋이 걸렸습니다.

| 무엇 | 앞 | 뒤 |
|---|---|---|
| zsh 에서 파일 · 폴더 자리에 Tab (`deel run my⇥` · `deel --root my⇥`) | `_deel_paths:11: bad substitution` 이 찍히고 후보가 하나도 안 나왔습니다. zsh 는 맥의 기본 셸입니다 | 빈칸 든 이름(`my dir`)까지 한 낱말로 들어갑니다. 진짜 맥 zsh 에서 Tab 을 쳐서 셸이 넘긴 낱말로 확인했습니다 |
| 12MB 넘는 화면 캡처 붙이기 (맥 · 리눅스) | 「osascript 를 못 불렀습니다: ENOBUFS」 — 도구가 고장 난 줄 압니다 | 「그림이 너무 큽니다 (한도 12MB 넘음) — 필요한 부분만 잘라서 다시 찍어 주세요」 |
| 자모로 풀린(NFD) 한글 프로필 이름 (맥 키체인) | 다시 잠글 때마다 키체인에 주인 없는 항목이 하나씩 남았습니다 | 같은 자리 하나에 넣습니다. 이미 넣어 둔 열쇠는 그대로 풀립니다 |

대소문자만 다른 폴더 이름(`MyProj` 를 믿고 `myproj` 로 열기)도 믿은 폴더로 보는지 맥에서 재 봤습니다 — 2.1.6 의
실제 자리 견주기로 이미 맞았고, 이제 관문 검사가 지킵니다. 이름이 이어지는 옆 폴더(`MyProjX`)로는 안 샙니다.

## 2.1.6

**맥에서 제대로 돌게 했습니다 — 키체인 열쇠 · `/tmp` 아래 폴더 믿기 · 파이프로 받는 긴 출력**

처음으로 진짜 맥(macOS 26 · Apple 칩)에서 전체 검사를 돌려, 맥에서만 나던 흠을 찾아 고쳤습니다. 이제 맥도 관문 CI 에
들어가 판마다 node 20 · 22 · 24 로 돕니다. 윈도 사용자에게 바뀌는 것은 없고, 리눅스는 마지막에서 두 번째 줄(파이프 출력)이
같이 고쳐졌습니다.

| 무엇 | 앞 | 뒤 |
|---|---|---|
| 긴 열쇠를 키체인에 넣기 | 약 3,000자를 넘으면 `security` 의 한 줄이 넘쳐 뒤 토막이 딴 명령으로 읽혔습니다 | 넣기 전에 길이를 재고, 넘으면 까닭을 말하고 안 넣습니다 |
| `DEEL_KEYCHAIN_NAME` 에 빈칸 · 줄바꿈 · 따옴표 | 명령 줄이 갈라져 엉뚱한 이름(`deel`)으로 들어가거나 못 잠갔습니다 | 거절하고, 그 환경변수 탓이라고 짚어 말합니다 |
| 키체인 앱에서 손으로 바꾼 값 | 깨진 글자를 열쇠로 보냈습니다 | 「`deel setup` 으로 다시 넣으세요」 |
| 잠긴 키체인 (SSH 로 들어온 맥에서 흔함) | 20초 뒤 `spawnSync security ETIMEDOUT` 한 줄 | 「잠겨 있을 수 있습니다 — `security unlock-keychain`」 |
| 열쇠를 바꾼 뒤 떠 있던 대화 (REPL · ACP) | 옛 열쇠를 계속 보냈습니다 | 새 열쇠를 씁니다 |
| `/tmp` · `/var` 아래 폴더 믿기 (맥은 이 둘이 `/private/…` 를 가리키는 링크) | 같은 폴더가 다른 글자로 와서, 믿은 폴더를 못 알아보고 프로젝트 설정을 통째로 버렸습니다. 집 폴더에서 켜면 제 설정을 「안 믿는 프로젝트 설정」 이라 했고, `deel reset` 은 한 파일을 두 번 셌습니다 | 실제 자리로 견줍니다. 지운 폴더도 링크 쪽 이름으로 믿음을 뺄 수 있습니다 |
| 받는 쪽이 늦게 읽는 파이프 (`deel sbom \| 느린명령`, 맥 · 리눅스) | 64KB 를 넘는 출력이 **0바이트**로 잘렸습니다 | 다 내보낸 뒤 끝냅니다 (최대 5초 기다림) |
| 셸 명령 속 끊긴 링크 (맥 뿌리의 `/.VolumeIcon.icns` 같은) | 디스크에 없는 이름으로 보고 작업 범위 검사를 건너뛰었습니다 | 무엇이든 놓여 있으면 경로로 보고 검사합니다 |

맥에서만 빨갛던 검사 열한 개는 대부분 검사가 맥을 몰랐던 탓이라 검사 쪽을 고쳤습니다 — bash 3.2 의 자동 완성, 애플 `unzip`
이 한글 이름을 `?` 로 찍는 것, 큰 출력 뒤 바로 끝내는 검사용 자식. 이 과정에서 ZIP 의 UTF-8 이름 표시가 한 번도 검사된
적이 없던 것도 찾아 이제 직접 잽니다.

코드 리뷰(Gemini)에서 받은 것 셋 — 지운 폴더의 믿음 빼기 · 설정 파일 **자체**가 링크인 경우 · 빈 열쇠. 셋 다 실행으로
확인하고 고쳤습니다. 키체인 고침은 진짜 맥에서 임시 키체인을 만들어 잠그고 · 넘치게 하고 · 손으로 바꾸고 · 잠근 채로
하나씩 재 봤습니다 (`security -i` 한 줄의 실제 끝은 4,096바이트, deel 의 한도는 그 안쪽 4,000).

## 2.1.5

**셸 명령이 작업 폴더 밖으로 새던 자리를 막았습니다 — `find .. -delete` 한 줄에 부모 폴더가 비었습니다**

기본(auto) 모드에서 셸 명령은 사람에게 묻지 않고 울타리(작업 범위 · 금지 목록)만 지납니다. 그런데 이 울타리는
**빗금이 든 경로**만 검사 대상으로 봤습니다. 그래서 부모 폴더 그 자체(`..`)와, 값을 알 수 있는 자리표(`$PWD` · `%CD%`)가
검사를 비켜 갔습니다. 모델이 실수한 한 줄로 작업 폴더의 부모를 통째로 지우거나 읽을 수 있었습니다. 급한 보안 수정이라
이 판에는 이것만 담았습니다.

| 입력 | 앞 | 뒤 |
|---|---|---|
| `find .. -delete` | 통과 — 작업 폴더의 부모가 통째로 지워졌습니다(버리는 폴더에서 재 봤습니다) | 작업 범위 밖이라 막음 |
| `rd /s /q ..` · `Remove-Item -Recurse ..` · `git -C .. clean -fdx` | 통과 — 부모를 지우는 명령이 검사 없이 셸로 갔습니다 | 막음 |
| `tar czf o.tgz ..` · `ls ..` | 통과 — 부모를 묶어 읽을 수 있었습니다(작업 폴더가 집 바로 밑이면 `~/.ssh` 까지) | 막음 |
| `rm -rf $PWD/../옆프로젝트` · `rd /s /q %CD%\..` · `"$(pwd -P)/../x"` · `$pwd.ProviderPath` | 「값을 모르는 자리표」 로 쳐서 범위 검사를 건너뜀 | 낱말 머리의 자리표를 지금 폴더로 풀어서 검사 |
| `rm -rf $OLDPWD` · `cd ~-/sub && …` | 통과 | 이전 폴더는 어디인지 모르므로 밖으로 봄(`~-` 와 같이). `cd ~-/sub` 는 이 명령 안에서 먼저 옮긴 적이 없을 때 |
| `cd - && rm -rf *` | 통과 | 이 명령 안에서 먼저 옮긴 적이 없으면 막음. `cd src && make && cd -` 는 그대로 돎 |
| `rd /s /q C:..` (윈도) | 통과 | 막음 |
| `ri -Recurse -Force C:\` · `del -Recurse ~` (파워셸의 다른 이름으로 드라이브 · 집 통째로) | 금지 목록은 지나감(범위 검사가 따로 막아 새지는 않았음) | 금지 목록도 막음 |

**바뀐 약속 하나.** `cd - && 명령` 은 여태 「직전 자리로 가는 것」 이라 보고 그대로 돌렸습니다. 그런데 deel 은 명령마다
셸을 새로 띄웁니다. 그래서 먼저 옮긴 적 없는 `cd -` 는 셸이 물려받은 이전 폴더로 가고, 그 자리는 deel 이 모릅니다
(`rm -rf ~-` 를 막는 것과 같은 까닭입니다). `cd -` 하나만 있는 명령과, 같은 명령 안에서 옮겼다가 돌아오는 것은 그대로
돕니다. `..` 가 낱말 하나로 든 평범한 글(`echo ..`)도 이제 막힙니다 — 드문 꼴이고, 막히면 모델이 다시 적습니다.

코드 리뷰(Gemini)에서 받은 것 넷 — `cd ~-/sub`(이전 폴더 **아래**) · 붙여 쓴 `cd..` 가 뒤에 오는 `..` 를 검사에서 빼 줌 ·
`$pwd.ProviderPath` · `$(pwd -P)`. 넷 다 실행으로 확인하고 고쳤습니다. 윈도에 더해 **맥(macOS 26 · Apple 칩)에서도**
진짜 Bash 도구로 지우는 명령을 돌려, 막히고 부모 폴더가 그대로인 것을 확인했습니다.

## 2.1.4

**열쇠를 안 넣고 브라우저로 로그인해서 붙습니다 — OpenRouter 하나로 Claude · GPT · Grok · Kimi**

「API 키도 좋은데, 링크 타고 계정으로 로그인하면 바로 쓰게」 가 오래 들은 말입니다. `deel setup` 의 3번이
그 길입니다. 바뀐 자리는 코딩 전에 설계를, 코딩 뒤에 코드를 다른 모델(Gemini)에게 보였고, 짚힌 것은 실행으로
가른 뒤 고쳤습니다.

| | 무엇 |
|---|---|
| **브라우저로 로그인** | `deel setup` → **3. 브라우저로 로그인 — OpenRouter**. 브라우저가 열리고, 로그인하면 그 계정에 `deel` 이름의 열쇠가 생깁니다. deel 이 받아서 붙여 넣은 열쇠와 똑같이 잠가 두고(윈도 DPAPI · 맥 키체인), 늘 하던 대로 붙어 보고 · 모델을 고르고 · 진단합니다. 열쇠 하나로 Claude · GPT · Grok · Kimi 를 다 쓰고, 쓴 만큼 그 계정에서 빠집니다 |
| **받는 법 — PKCE** | 무작위 검증자를 짓고 그 해시만 로그인 주소에 싣습니다. 로그인 쪽이 이 PC 의 `localhost` 로 코드를 돌려주면 코드 + 검증자를 한 번 보내 열쇠로 바꿉니다. 검증자는 브라우저·콜백 길로는 안 지나고 그 교환에만 실려서 코드를 가로채도 열쇠는 못 받고, 콜백 길은 판마다 새로 짓습니다. 우리가 직접 나가는 것은 그 교환 한 번이고 나가는 문 하나(`http.js`)를 지납니다 |
| **브라우저가 다른 기기에 있으면** | `deel setup --no-browser` — 링크를 아무 기기에서 열고, 로그인 뒤 화면에 뜬 코드(또는 주소째)를 붙여 넣습니다. SSH 로 들어왔거나 리눅스에 화면이 없으면 저절로 이쪽입니다 |
| **끝이 있습니다** | 5분 안에 안 돌아오면 끝내고 콜백 문을 닫습니다. 로그인 창에서 거절하고 돌아오면 바로 끝냅니다. 봉인(`--offline`)이면 로그인하러 나가지 않고 브라우저도 안 엽니다 |
| **OpenRouter 가 목록에** | 벤더 목록에 OpenRouter 가 생겼습니다. 열쇠가 있으면 붙여 넣고, 비우고 엔터하면 로그인으로 갑니다. 「열쇠만 있습니다」 는 `sk-or-` 를 알아봅니다 — 여태는 `sk-` 에 먼저 걸려 **OpenAI 로 보냈습니다** |
| **모델이 수백 개여도 고릅니다** | 모델을 앞 40개만 보여 줘서, 그 뒤 모델은 고를 길이 없었습니다. 40개가 넘으면 이름 일부로 좁히고(`claude` · `grok` · `kimi`), 목록 끝의 「직접 입력」 으로 아무 이름이나 넣습니다 |

Claude · Codex **구독** 로그인을 빌려 쓰지는 않습니다 — 그 로그인은 그 회사 도구용이라, 남의 도구가 쓰면
약관에 걸리거나 어느 날 막히고 사람은 까닭도 모른 채 못 쓰게 됩니다. OpenRouter 는 제 계정으로 열쇠를 내주는
로그인을 공식으로 엽니다.

### 고친 것

- **윈도에서 `&` 가 든 주소를 브라우저로 못 열었습니다.** `cmd /c start` 가 따옴표 밖의 `&` 를 명령 구분자로
  먹어 앞부분만 열리고 뒤는 명령으로 돌았습니다(미리보기 주소에는 `&` 가 없어 여태 몰랐습니다). 주소를
  따옴표로 싸서 그대로 넘기고, cmd 가 따옴표 안에서도 펼치는 `%이름%` 이 든 주소는 안 넘깁니다(주소는 화면에
  있습니다).

설계 검토에서 받은 것 셋 — `::1` 의 같은 포트를 남이 쥐고 있으면 포트를 다시 고름(안 그러면 `::1` 로 푼 브라우저가
코드를 남에게 넘깁니다) · `rundll32` 로 비켜 가는 대신 cmd 를 제대로 감쌈(사내 보안 정책이 `rundll32` 를 막는 일이
흔합니다) · 모델 검색이 하나도 안 맞을 때의 출구. 코드 리뷰에서 받은 것 넷 — cmd 의 `%` 펼치기 · 패딩(`=`) 붙은
코드와 `#code=` 주소 · 쪽이 다 나가기 전에 연결을 끊던 것 · 듣기 시작한 뒤의 서버 오류. 반증한 것 — 설정받기 순서
(봉인 판정은 순수 함수라 앞으로 옮겨도 같음) · 교환 뒤 연결 확인이 막힘(연결 확인은 제 주소를 엶) · 40개 이하 모델
목록(그대로) · 열쇠가 화면에 새는 길(없음).

| **MCP 자료 · 프롬프트** | 서버가 자료(resources)를 내면 `mcp__<서버>__read_resource` 로 읽고, 프롬프트는 `/mcp__<서버>__<이름> 인자…` 로 부릅니다(`deel run` 도). 빈칸이 든 인자는 따옴표로 묶고, 마지막 인자는 줄바꿈까지 그대로 받습니다 |

| **웹훅 주소가 그대로 나갔습니다** | Slack · Discord · Teams 웹훅과 Sentry DSN 은 주소 자체가 열쇠인데, 이름(`SLACK_WEBHOOK_URL`)에도 값의 꼴에도 그렇다는 표시가 없어 셸 환경 거르기와 출력 가리기를 둘 다 지나갔습니다. 모델이 `env` 한 줄만 쳐도 대화로 나갔습니다. 이제 **값의 꼴**로 알아보고 둘 다 막습니다. 무늬는 한 벌이라 한쪽에만 더해지는 일이 없습니다 |
| **strict 가 Jobs 끄기를 못 물은 꼴** | 끄는지를 `stop` 칸으로만 봐서, Jobs 도구가 받아 주는 `kill` · `끝내기` 로 보내면 strict 에서도 안 묻고 서버를 껐습니다. 이제 도구가 읽는 자로 가릅니다. `stop:"false"` 에 헛물음이 뜨던 것도 같이 없어졌습니다 |
| **EUC-KR 소스에서 Def · Refs** | Read · Edit 는 옛 인코딩을 알아보는데 Def · Refs 만 날 UTF-8 로 읽어, 한글 이름을 「그 줄에 없다」 로 못 찾았고 언어 서버에도 깨진 글을 보여 줬습니다 |
| **deel eval** | 과제 하나가 터지면(정답 복사의 권한·자리 부족) 평가 전체가 죽고 결과도 안 남았습니다 — 이제 그 과제만 실패로 셉니다. `--only` 로 일부만 돈 결과가 다음 전체 판의 「지난번」 이 되던 것, 일부만 도는 판끼리 겹치는 과제가 없는데 「지난번과 같습니다」 라던 것, `--only task-1` 이 `task-10` 까지 돌던 것, 결과 파일을 못 남겨도 말이 없던 것도 고쳤습니다 |

### 고친 것

- **완료 검사 설정이 말없이 잘렸습니다.** `checkTimeout` 은 600초, `checkRounds` 는 10 이 상한인데,
  넘게 적으면 조용히 줄여서 느린 통합 검사가 「시간 초과」 로 판수를 다 쓰고도 왜인지 안 나왔습니다.
  이제 첫 검사를 시작할 때 무엇을 얼마로 줄였는지 한 줄로 말합니다(대화 화면 · `deel run` · 에디터).
- **같은 내용으로 다시 쓰는 부름**은 승인 미리보기에 파일 이름 한 줄만 떠서, 무언가 바뀌는 줄 알고
  허락하게 됐습니다. 이제 「바뀌는 것 없음」 이라고 적습니다.
- **`deel run` 의 검사 실패 꼬리**가 끝 8줄을 먼저 자르고 빈 줄을 걸러, 원인 뒤에 빈 줄이 여럿이면
  원인이 화면에서 사라졌습니다. 대화 화면과 같은 차례(거르고 자르기)로 맞췄습니다.
- **점으로 시작하는 플러그인 이름**(`.hidden`)은 깔리기는 하는데 목록에서 영영 안 보였습니다. 이제
  폴더 이름으로 깝니다. 이 막이 전에 깔린 것은 폴더 이름으로 지울 수 있습니다.
- **상태줄이 그릴 때마다 대화 전체를 다시 셌습니다.** 일하는 동안 90ms 마다 모든 메시지를 글자 단위로
  훑었습니다 — 64만 토큰 창이면 초당 스무 번 넘게. 메시지는 제자리에서 안 고치고 새 것으로 갈아
  끼우므로, 한 번 센 메시지는 다시 안 셉니다.
- `deel eval` 의 탭 완성에 `--init` · `--only` · `--keep` · `--timeout` 이 빠져 있었습니다. 예제 과제 03 의
  정답 검사는 모델이 `src/` 밑에 폴더를 만들면 맞게 고쳐도 떨어졌고, 하위 폴더에 옛 이름이 남아도 통과했습니다.
- 문서: 작업 모드를 도는 키는 `Ctrl+O` 입니다(README 에 `Shift+Tab` 으로 잘못 적혀 있었습니다 —
  `Shift+Tab` 은 승인 방식). 확장 문서의 MCP 절에 깨진 글자와 끊긴 문장을 바로잡았습니다.
- 지금 입력으로는 안 닿지만 표가 바뀌면 터질 두 자리(중단 때 지어내는 도구 결과 번호 — 이제 이미 쓰인 번호를 건너뜁니다, 자동 모드
  고르기의 둘째 후보)는 코드로만 막았습니다 — 넘어질 곳을 검사에서 못 만듭니다.

짚혔지만 고치지 않은 것도 적어 둡니다. 서로게이트 글자(이모지 · 희귀 한자)를 토큰 둘로 세는 것은 실제
토큰 수에 더 가까워 그대로 둡니다. 2차 리뷰가 「심각」 으로 짚은 loop.js 의 선언 안 된 이름 셋은 모두
감싼 함수 안에 선언돼 있어 오판이었고, 고친 뒤의 2차 리뷰 스무 건 중 받아들인 것은 세 자리였습니다(나머지는
실행으로 반증 — 이미 막혀 있거나 설계대로).

## 2.1.0

**맡기면 멈추지 않고, 묻게 하면 diff 를 보여 줍니다 — 「다 됐다」 는 검사가 정합니다**

회사에 들여놓는 쪽의 검토에서 세 가지를 들었습니다. 「고치기 전에 미리 보여 주고 사람이 확인하는
절차가 기본으로 도나」, 「검증을 정적 검사에 기대면 한계가 있다 — 작업마다 골든셋이 필요하다」,
「루프를 더 다듬어야 한다」. 재 보니 셋 다 맞았습니다. 2.1.0 은 그 셋에 답합니다.

### 맡기는 모드와 묻는 모드

승인 모드는 원래 갈려 있었습니다 — `auto` 는 맡기는 모드, `strict` 는 묻는 모드. 그런데 양쪽 다
약속을 다 지키지 않고 있었습니다.

| | 무엇 |
|---|---|
| **auto 가 멈춰 서던 자리** | 도구 승인은 안 물었지만, 모델이 되묻거나(Ask) 「설계하고 만들어줘」 에 계획부터 내면 사람 답을 **끝없이** 기다렸습니다. 맡겨 두고 자리를 뜬 사람에게는 멈춘 것과 같습니다. 이제 auto 에서는 60초 안에 답이 없으면 알아서 진행합니다 — 되묻기는 스스로 판단하게 하고, 계획은 그대로 이어서 만듭니다. 시간은 설정의 `askWait`(`0` 이면 아예 안 물음). `confirm` · `strict` 는 여전히 시한 없이 기다립니다 |
| **strict 가 바꾸는 도구를 다 묻습니다** | 여태 Write·Edit·Bash 셋만 물었습니다. 바꾸는 도구 목록은 따로 여섯으로 적혀 있었는데 승인 관문만 옛 목록에 남아 있었습니다. 이제 Append·Move, 뒤에서 도는 명령 끝내기(Jobs stop), 붙여 둔 MCP 도구도 묻습니다. Jobs 로 출력을 **읽는** 것은 안 묻습니다 — 읽을 때마다 물으면 사람은 y 만 치게 됩니다 |
| **물을 곳이 없으면 거절** | 승인이 필요한데 부르는 쪽에 물을 곳(confirm)이 없으면 여태 **그대로 실행**했습니다. 「묻는다」 가 「물을 곳이 있으면 묻는다」 였던 것입니다. 이제 실행하지 않고, 모델에게 승인 없이 되는 방법을 고르라고 돌려줍니다 |
| **바뀔 내용(diff)을 먼저 보여 줍니다** | Write·Append·Edit 을 묻기 전에 대화창은 파일마다 바뀔 줄을 그리고, 편집기(ACP)는 승인 요청에 diff 를 실어 보냅니다. 미리보기는 실제로 쓸 때와 같은 셈(줄끝·들여쓰기 맞춤·여러 군데 고치기)으로 만들어서, 승인 창에서 본 것과 실제로 쓰인 것이 같습니다 |
| **미리보기가 안 여는 것** | deel 자신의 설정·열쇠, 모델이 아직 안 읽은 파일의 Edit, 작업 폴더 밖, 200만 자가 넘는 파일(여러 파일 중 하나라도 넘으면 통째로), 문서 파일(엑셀·워드·PDF·시안), 실제 도구가 거절할 가린 표 되돌리기는 미리보기에서 뺍니다. 실제 도구가 거절하는 자리를 미리보기가 대신 읽으면 도구는 안 돌았는데 읽기는 일어난 셈이라서입니다. 그런 호출은 예전처럼 한 줄로 묻습니다 |
| **관리 정책의 승인 바닥** | 관리 정책 파일(`policy.json`)에 `"approval": "strict"` 를 적으면 그 PC 에서는 그보다 느슨한 모드로 못 내립니다. `/mode`·Shift+Tab·`deel run --yes`·설정의 `allow`·편집기의 「앞으로 묻지 않기」 가 다 바닥에 막히고, 왜 막혔는지 화면에 적습니다. 모르는 값(오타)이나 안 읽히는 정책 파일은 strict 로 칩니다. `deel doctor` 에 한 줄로 나옵니다 |

바닥은 조이기만 합니다. 정책이 `confirm` 이면 `strict` 로 올리는 것은 되고, `auto` 로 내리는 것만
막힙니다. 정책 파일이 없는 PC 는 기본 `auto` 그대로입니다.

### 「다 됐다」 는 검사가 정합니다 — 완료 검사

턴이 끝나는 자리는 **모델이 도구를 안 부르고 말만 한 걸음** 하나였습니다. 「고쳤습니다」 한 줄이면
끝이었습니다. 확인할 길(Verify · 이 프로젝트의 검사 명령 찾기 · 증거 보고)은 있었지만 셋 다 권하거나
보여 주기만 했고, 안 돌리고 끝내도 막는 자리가 없었습니다.

| | 무엇 |
|---|---|
| **`check`** | 설정에 `"check": "npm test"` 를 적거나 `deel run --check` 로 주면, 모델이 무엇을 바꾸고 끝내려 할 때 deel 이 **직접** 그 명령을 돌립니다 |
| **실패하면 이어서 고침** | 실패 출력의 **끝**(무엇이 틀렸는지가 있는 자리)을 모델에게 돌려주고 이어서 고치게 합니다. 「검사를 고치거나 지워서 통과시키지 말라」 고 같이 적습니다. 기본 3판(`checkRounds`) |
| **끝내 실패면 실패로** | 판수를 다 쓰고도 빨가면 실패로 끝냅니다. `deel run` 은 새 종료코드 **8**, `--json` 에는 `check` 칸 |
| **같은 관문** | 검사 명령도 모델의 명령과 같은 관문을 지납니다 — 금지 규칙, 훅, 승인(`strict` 면 묻습니다), 위험 명령 차단. 설정에 적혀 있다고 건너뛰면 저장소 설정 한 줄이 strict 를 뚫습니다. 못 돌렸으면 통과로 치지 않고 「못 돌렸다」 고 적습니다 |
| **안 도는 때** | 아무것도 안 바꾼 턴 · 실패를 받고 아무것도 안 바꾼 채 끝내려는 턴 · 하위 작업. 명령을 **짐작해 돌리지 않습니다** — 정해 둔 것이 없으면 예전과 똑같습니다 |

### 얼마나 해내나 — 골든셋 (`deel eval`)

검사 1만 4천여 개는 가짜 게이트웨이로 「도구가 약속대로 도나」 를 잽니다. 「이 회사의 모델과 deel 이
실제 일을 몇 개 해내나」 는 한 번도 안 쟀습니다. 모델을 바꾸거나 deel 을 올릴 때 나아졌는지 나빠졌는지
말할 숫자가 없었습니다.

| | 무엇 |
|---|---|
| **과제 하나 = 폴더 하나** | `task.json`(시킬 말 · 정답 검사 명령) · `start/`(시작 파일) · `golden/`(정답 검사 파일) |
| **정답은 모델이 못 봅니다** | 과제마다 임시 폴더에 `start/` 를 깔고 `deel run` 을 돌린 **뒤에** `golden/` 을 넣고 채점합니다. 일하는 동안에는 폴더에 없어서 「검사를 보고 거기 맞춰 쓰는」 길이 없습니다 |
| **예제 다섯** | `deel eval --init` — 버그 고치기 · 기능 더하기 · 여러 파일 이름 바꾸기 · 빨간 검사 고치기(완료 검사 고리를 탑니다) · CRLF 줄끝 지키기. 여기에 사내 과제를 더합니다 |
| **되풀이와 견주기** | `--repeat` 로 여러 번 돌려 비율로 봅니다. 결과는 `golden/.results/` 에 남고 지난번보다 **나빠진 과제**를 짚습니다. 하나라도 떨어지면 종료코드 1 |
| **빼지 않습니다** | 모양이 틀린 `task.json`, `start/`·`golden/` 은 있는데 `task.json` 이 없는 폴더도 실패로 셉니다 — `--repeat` 수만큼. 조용히 빼면 스무 개 중 열아홉만 돌고 「다 통과」 가 됩니다 |
