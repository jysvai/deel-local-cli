## 2.1.3

**도구를 글로 부르는 모델도 일하고, `deel run` 은 이어 하고, 스크립트가 바꾼 것도 되돌아가고, MCP 는 주소로 붙습니다**

제품 기능을 한 판에 모았습니다. 로컬 모델이 흔히 막히는 자리(도구를 글로 부름 · 언어 서버 없음 · 큰 저장소)와
배치 · 편집기 밖에서 쓰는 자리(`deel run` 이어 하기 · 사건 흘리기 · MCP HTTP)가 중심입니다. 바뀐 자리는 다른
모델(Gemini)에게 한 번 더 보였고, 짚힌 것은 실행으로 가른 뒤 고쳤습니다.

| | 무엇 |
|---|---|
| **도구를 글로 부르는 모델** | 서버가 모델의 부름 꼴을 모르면 `tool_calls` 는 비고 답 글에 `<tool_call>{…}</tool_call>` · `<function=Read>` · `[TOOL_CALLS]` 같은 것이 실립니다. 여태는 「글로만 답했다」 로 턴을 끝냈습니다. 이제 **우리가 내준 도구 이름**으로 적힌 것만 건져 진짜 부름으로 돌립니다 — 건진 부름도 모드 · 승인 · 정책 바닥을 그대로 지납니다. 울타리 안 예시와 설명 사이에 낀 JSON 은 안 건집니다. 홑따옴표 · 끝 쉼표 · 따옴표 없는 열쇠처럼 **모양만 틀린** 인자 JSON 은 느슨하게 읽습니다(잘린 것은 안 읽습니다). `deel setup` · `deel diagnose` 의 도구 호출 진단이 이런 모델을 「도구를 글로 부릅니다」 경고로 적습니다 |
| **`deel run` 이 이어 합니다** | `--continue`(이 폴더의 가장 최근 대화) · `--resume <이름>` 으로 앞선 대화 · 못박은 것까지 이어 받습니다. 한 번 돈 것도 `.deel/sessions/` 에 남고 `--json` 결과에 `session` 이 실립니다. 결과에 **바뀐 파일 목록**(`files`)이 실리고, `--events <파일>` 은 도는 동안 사건을 한 줄에 하나씩 JSON 으로 흘립니다(글자 조각은 빼고, 긴 글은 잘라서). 사건 파일을 못 열면 일을 시작하기 전에 섭니다 |
| **스크립트가 바꾼 것도 `/undo`** | `npm run format` · `node 고치기.js` · `rm *.tmp` 처럼 이름이 명령줄에 없는 파일은 떠 둔 것이 없었습니다. git 저장소면 명령 **앞뒤**의 `git status` 를 견줘 정말 바뀐 파일의 앞 모습을 기록합니다 — 커밋된 그대로였으면 HEAD 에서(`git restore` 가 꺼내 줄 모습 그대로 — 줄 끝 변환까지), 고치던 중이었으면 명령 직전에 떠 둔 사본에서. `.git` 에는 아무것도 안 씁니다 |
| **언어 서버가 없어도 문법은 봅니다** | 고친 뒤 언어 서버가 말을 못 주면(없거나 데우는 중) `node --check` · JSON 읽기 · 중괄호 짝 · `py_compile` 만 싸게 봅니다. 머리에 「문법 검사」 라고 적어 언어 서버와 섞이지 않게 합니다 |
| **Outline 이 핵심 모듈부터** | 폴더 뼈대를 최근에 손댄 순서로만 실어서, 오래 안 건드린 핵심 모듈이 큰 저장소에서 제일 먼저 잘렸습니다. 이제 import · require · `from` 을 세어 **많이 불리는 파일부터** 싣고(지금 손대는 파일은 맨 앞 몇 자리를 지킵니다), 머리줄에 「N곳에서 불러 씀」 을 적습니다 |
| **MCP 가 주소로 붙습니다** | `"type": "http"` 와 `url` 로 streamable HTTP 서버에 붙습니다. 나가는 문은 모델 창구와 같은 하나이고, 적어 둔 주소는 물음이 도는 동안만 열었다 닫습니다. `--offline` 이면 이 컴퓨터 안(사내망 포함)만 붙습니다. `headers` 의 `${환경변수}` 를 펴고, 세션을 버린 서버에는 다시 인사합니다 |
| **MCP 자료 · 프롬프트** | 서버가 자료(resources)를 내면 `mcp__<서버>__read_resource` 로 읽고, 프롬프트는 `/mcp__<서버>__<이름> 인자…` 로 부릅니다(`deel run` 도). 빈칸이 든 인자는 따옴표로 묶고, 마지막 인자는 줄바꿈까지 그대로 받습니다 |
| **자동 모드가 일본어 · 중국어도** | 화면 말은 넷인데 모드 고르기는 한국어 · 영어만 알았습니다. 「直して」 · 「请帮我修复」 로 시키면 이제 고치는 모드로 가고, 「説明して」 · 「是什么」 는 묻기로 갑니다 |
| **생성 속도** | `/cost` 에 흘려받은 부름의 생성 속도(tok/s)를 적고, `deel run --json` 에 `genMs` · `tokPerSec` 가 실립니다. 못 쟀으면 안 적습니다 |

### 고친 것

- **`Verify` 가 깨진 `.js` 를 통과시켰습니다.** `package.json` 에 `"type"` 이 없는 자리의 `.js` 에 `export` 가 있으면
  node 의 모듈 감지 탓에 괄호가 안 닫혀도 `node --check` 가 0 으로 끝났습니다(node 24 에서 재 봤습니다). 그런 파일은
  모듈로 한 번 더 봅니다.
- **열쇠받기가 다른 프로필의 게이트웨이에 앞 토큰을 줬습니다.** 받아 둔 열쇠와 승인이 하나뿐이라, `/consult` 나
  모델을 고른 Task 가 제 열쇠받기 명령으로 열쇠를 청하면 앞 프로필의 토큰이 그대로 돌아왔고 그 명령은 묻지도
  않았습니다. 이제 명령마다 따로 들고 따로 묻습니다. 화면 글에서는 들고 있는 열쇠를 전부 가립니다.
- **열쇠받기 명령을 시한에 끊어도 deel 이 안 끝났습니다(윈도우).** 셸만 죽고 그 밑의 로그인 도구가 파이프를 물고
  남았습니다. 이제 나무째 거두고 파이프를 놓습니다.

2차 리뷰 일곱 판이 짚은 66건 중 24건을 받아 고쳤습니다 — 글 속 부름(안 닫힌 울타리 속 예시를 부름으로 읽음 ·
한 표 안의 부름 둘을 하나로 뭉침 · `01234` 가 `1234` 가 되는 칸 값), MCP HTTP(같이 나간 물음들이 세션 끝남을
만났을 때 · 번호 없는 오류 답 · OAuth 꼴 거절 글), 스크립트 되돌리기(git 에서 앞 모습을 못 꺼내면 「없던 파일」 로
적어 `/undo` 가 지울 자리), 프롬프트 인자(따옴표 · 줄바꿈), 사건 파일의 결과 줄, 모듈로 다시 보기. 확인하다가 둘을
더 찾았습니다 — core.autocrlf 저장소에서 `/undo` 가 CRLF 파일을 LF 로 되돌리던 것, 바뀐 파일마다 git 을 띄워
120개에 약 6.7초 걸리던 것(이제 약 0.3초). 나머지는 실행으로 반증했습니다 — 이미 막혀 있거나(믿는 폴더가 아닌
mcp.json · 값 없는 `--events` · 빈 `--resume`), 일부러 그렇게 둔 것(건진 부름도 승인 관문을 지남 · 오프라인은
네트워크 문지기와 같은 규칙)이거나, 잘못 읽은 것(porcelain 경로는 저장소 꼭대기 기준 · `rev-parse` 는 빈 줄을
찍음)이었습니다.

### 빨라진 것

- **`deel run` 이 대화 화면의 명령 전부를 읽었습니다.** 슬래시 명령 찾기 셋 때문에 `commands.js` 를 통째로 불렀습니다.
  찾는 규칙을 가벼운 `src/slash.js` 로 옮겨, 읽는 소스 파일이 133개에서 105개로 줄었습니다.

### 바꾸지 않은 것

- **WebFetch 의 DNS 리바인딩.** 2.1.2 와 같은 까닭입니다 — 나가는 문 하나 구조와 부딪힙니다.
- **MCP 의 인사 없는 새 판(2026-07-28).** 인사로 붙는 판(2025-11-25 까지)을 씁니다. 새 판만 받는 서버는 받는 판을
  적어 돌려주고, 그 말을 그대로 보여 줍니다.
- **옛 MCP HTTP+SSE 규격.** 받지 않고 까닭을 말합니다.

## 2.1.2

**confirm 이 MCP 도구도 묻고, 에디터 세션은 쌓이지 않고, `deel --version` 은 프로그램 전체를 읽지 않습니다**

2.1.1 에서 결정이 필요하다고 따로 둔 정책 셋에 작은 공백과 성능을 묶었습니다. 바뀐 자리는 다른
모델(Gemini)에게 한 번 더 보였고, 짚힌 것은 실행으로 가른 뒤 고쳤습니다.

| | 무엇 |
|---|---|
| **confirm 이 MCP 도구를 묻습니다** | confirm 은 「되돌릴 수 없는 것만 묻는다」 는 모드인데, 붙여 둔 MCP 도구는 안 물었습니다. MCP 서버가 한 일은 `/undo` 가 못 되돌립니다. 이제 묻습니다 — 서버가 도구에 「읽기만 한다」(`readOnlyHint`, `destructiveHint` 아님)고 적은 것만 빼고. strict 는 전처럼 다 묻습니다 |
| **에디터 세션이 쌓이기만 했습니다** | 에디터(ACP)는 대화마다 세션을 열고, deel 은 에디터가 켜져 있는 동안 삽니다. 연 세션을 내려놓는 자리가 없어 하루 종일 연 대화가 전부(대화 · 되돌리기 기록 · 감사기록 · 그 폴더의 MCP 서버) 메모리에 남았습니다. 이제 16개(`DEEL_ACP_MAX_SESSIONS`)를 넘으면 제일 오래 안 쓴 **쉬는** 세션을 내려놓고, 그 세션에 다시 말하거나 `session/load` 로 열면 파일에서 되살려 잇습니다. 에디터가 고른 작업 모드와 「앞으로 묻지 않기」 도 같이 돌아옵니다. 그 폴더의 마지막 세션이었으면 MCP 서버도 닫습니다 |
| **완료 검사 판수의 뜻** | `checkRounds` 는 검사를 **돌리는 횟수**입니다(고칠 기회는 하나 적습니다). 문서에는 「되돌려 보내는 횟수」 로 적혀 있었습니다. `0` · 음수 · 글 · `true` 처럼 못 쓰는 값은 말없이 기본값이 됐는데, 이제 상한에 걸려 줄일 때처럼 무엇을 무엇으로 썼는지 말합니다 |
| **deel eval 의 제한 시간과 견주기** | `--timeout 0` · `--timeout abc` 는 과제마다 deel 을 곧바로 죽여 전부 「시간 초과」 가 됐습니다 — 이제 사용법 틀림(64)입니다. task.json 의 `timeout` 이 `--timeout` 을 이긴다는 차례(pytest · jest 와 같습니다)를 문서와 머리줄에 적습니다. 지난번에 있던 과제가 없어지면 ⚠ 로 알리고, 처음 재는 과제는 따로 적고, 견주지 않은 과제가 있으면 「같습니다」 는 견준 과제만큼만 말합니다 |
| **과제마다 완료 검사** | task.json 에 `doneCheckRounds` · `doneCheckTimeout` 을 적을 수 있습니다. `deel run` 에 `--check-rounds` · `--check-timeout` 이 생겼고, eval 은 과제마다 그것으로 넘깁니다 |

### 빨라진 것

- **`deel --version` · `--help` 가 프로그램 전체를 읽었습니다.** 진입점이 모든 명령을 맨 위에서 불러와,
  판 번호 하나 찍는 데 파일 164개(4.4MB)를 읽었습니다. 이제 명령은 쓸 때 불러오고 시작 때 읽는 것은
  18개(471KB)입니다. `deel --version` 이 약 440ms 에서 약 290ms 로 줄었고, 판 번호는 설정을 읽기 전에 찍습니다.
- **되돌리기 이력을 턴마다 처음부터 읽었습니다.** 대화 화면은 턴이 끝날 때마다 되돌릴 턴 수를 세는데,
  고치기 전 원문을 통째로 담아 32MB 까지 자라는 이력 파일을 매번 처음부터 읽고 줄마다 풀었습니다. 이제
  덧붙은 꼬리만 읽습니다. 다른 탭이 파일을 다시 썼으면 알아보고 처음부터 셉니다.
- **상태줄이 90ms 마다 시스템 프롬프트를 다시 셌습니다.** 조각마다 센 토큰 수를 기억해, 한 번 그릴 때
  드는 셈이 0.23ms 에서 0.03ms 로 줄었습니다.

### 고친 것

- task.json 의 수 칸(`timeout` · `checkTimeout` · `doneCheckRounds` · `doneCheckTimeout`)이 `true` 를 1 로
  읽었습니다. 제한 시간 1초로 과제가 죽고, `--check-rounds true` 로 넘어가 `deel run` 이 사용법 틀림으로
  끝났습니다. 이제 수나 수를 적은 글만 받습니다.
- 처음 재는 과제가 떨어져도 견준 과제끼리 같으면 「지난번과 같습니다」 가 나와 그 실패가 묻혔습니다.
  `--only` 판도 고른 과제만 견주고 전체가 같다는 말로 읽혔습니다.
- 내려놓은 에디터 세션을 `session/load` 로 열면 작업 모드와 「앞으로 묻지 않기」 를 잃었습니다. 또
  「마지막으로 쓴 때」 를 시각으로 적어서, 한 밀리초 안에 쓴 두 세션은 같은 값이 되어 오래 안 쓴 세션
  대신 먼저 연 세션이 내려놓였습니다. 이제 늘 커지는 번호로 적습니다.

2차 리뷰가 짚은 열여섯 건 중 다섯 건을 받았습니다. 나머지는 실행으로 반증했습니다 — 이미 막혀 있거나
(값 없는 `--timeout` · `timeout: null` · 검증 안 된다던 task.json 의 `timeout`), 고치기 전과 같은
동작이고 부르는 쪽이 이미 잡는 것(이력을 읽는 사이 파일이 사라지는 경우)이었습니다.

### 바꾸지 않은 것

- **WebFetch 의 DNS 리바인딩.** 막으려면 IP 를 고정한 연결이 필요한데, 그러면 나가는 요청이 모두 한 문
  (`backend/http.js`)을 지나는 구조가 깨집니다. 그 구조가 deel 의 약속이라 넣지 않습니다.
- **Gemini 명시 캐시.** Gemini 2.5 부터는 암시 캐시가 저절로 돕니다. 명시 캐시는 cachedContents 를
  만들고 수명과 저장 요금을 챙겨야 하고, 요청에서 시스템 · 도구를 빼야 하는데 deel 은 단계마다 도구
  목록이 바뀝니다.
- **Glob 결과 · 언어 서버 시작 훑기 · 저장소 판별 캐시.** 재 보니 1만 파일 Glob 이 약 206ms, 언어 서버
  훑기가 보통 약 80ms 였습니다. 캐시가 낡을 위험보다 얻는 것이 작습니다.

**전체 검수에서 나온 것 — 한 칸 위를 물으면 열쇠가 보였고, 웹훅 주소는 그대로 나갔습니다**

2.1.0 을 낸 뒤 기능 전체를 영역 일곱(새 기능 · 에이전트 코어 · 백엔드 · 안전 · 도구 · 화면 ·
설계)으로 나눠 다시 훑었고, 2.1.0 에서 바뀐 자리는 다른 모델(Gemini)에게 한 번 더 보였습니다.
짚힌 것은 전부 실행으로 가른 뒤 고쳤습니다. 새 기능은 없습니다.

| | 무엇 |
|---|---|
| **한 칸 위를 물으면 열쇠가 보였습니다** | `deel config explain profiles.사내` 처럼 끝 칸 앞에서 멈추면 그 프로필이 JSON 째 그려졌고, 안의 `apiKey` · 인증서 `passphrase` 가 화면과 `--json` 에 평문으로 실렸습니다. 이제 객체·배열 안까지 같은 자로 가리고, 프록시·주소의 `사람:암호@` 도 doctor 와 같이 가립니다 |
| **웹훅 주소가 그대로 나갔습니다** | Slack · Discord · Teams 웹훅과 Sentry DSN 은 주소 자체가 열쇠인데, 이름(`SLACK_WEBHOOK_URL`)에도 값의 꼴에도 그렇다는 표시가 없어 셸 환경 거르기와 출력 가리기를 둘 다 지나갔습니다. 모델이 `env` 한 줄만 쳐도 대화로 나갔습니다. 이제 **값의 꼴**로 알아보고 둘 다 막습니다. 무늬는 한 벌이라 한쪽에만 더해지는 일이 없습니다 |
| **strict 가 Jobs 끄기를 못 물은 꼴** | 끄는지를 `stop` 칸으로만 봐서, Jobs 도구가 받아 주는 `kill` · `끝내기` 로 보내면 strict 에서도 안 묻고 서버를 껐습니다. 이제 도구가 읽는 자로 가릅니다. `stop:"false"` 에 헛물음이 뜨던 것도 같이 없어졌습니다 |
| **EUC-KR 소스에서 Def · Refs** | Read · Edit 는 옛 인코딩을 알아보는데 Def · Refs 만 날 UTF-8 로 읽어, 한글 이름을 「그 줄에 없다」 로 못 찾았고 언어 서버에도 깨진 글을 보여 줬습니다 |
| **deel eval** | 과제 하나가 터지면(정답 복사의 권한·자리 부족) 평가 전체가 죽고 결과도 안 남았습니다 — 이제 그 과제만 실패로 셉니다. `--only` 로 일부만 돈 결과가 다음 전체 판의 「지난번」 이 되던 것, 일부만 도는 판끼리 겹치는 과제가 없는데 「지난번과 같습니다」 라던 것, `--only task-1` 이 `task-10` 까지 돌던 것, 결과 파일을 못 남겨도 말이 없던 것도 고쳤습니다 |

### 고친 것

- **완료 검사 설정이 말없이 잘렸습니다.** `checkTimeout` 은 600초, `checkRounds` 는 10 이 상한인데,
  넘게 적으면 조용히 줄여서 느린 통합 검사가 「시간 초과」 로 판수를 다 쓰고도 왜인지 안 나왔습니다.
  이제 첫 검사를 시작할 때 무엇을 얼마로 줄였는지 한 줄로 말합니다(대화 화면 · `deel run` · 에디터).
- **같은 내용으로 다시 쓰는 부름**은 승인 미리보기에 파일 이름 한 줄만 떠서, 무언가 바뀌는 줄 알고
  허락하게 됐습니다. 이제 「바뀌는 것 없음」 이라고 적습니다.
- **`deel run` 의 검사 실패 꼬리**가 끝 8줄을 먼저 자르고 빈 줄을 걸러, 원인 뒤에 빈 줄이 여럿이면
  원인이 화면에서 사라졌습니다. 대화 화면과 같은 차례(거르고 자르기)로 맞췄습니다.
- **점으로 시작하는 플러그인 이름**(`.hidden`)은 깔리기는 하는데 목록에서 영영 안 보였습니다. 이제
  폴더 이름으로 깝니다. 이 막이 전에 깔린 것은 폴더 이름으로 지울 수 있습니다.
- **상태줄이 그릴 때마다 대화 전체를 다시 셌습니다.** 일하는 동안 90ms 마다 모든 메시지를 글자 단위로
  훑었습니다 — 64만 토큰 창이면 초당 스무 번 넘게. 메시지는 제자리에서 안 고치고 새 것으로 갈아
  끼우므로, 한 번 센 메시지는 다시 안 셉니다.
- `deel eval` 의 탭 완성에 `--init` · `--only` · `--keep` · `--timeout` 이 빠져 있었습니다. 예제 과제 03 의
  정답 검사는 모델이 `src/` 밑에 폴더를 만들면 맞게 고쳐도 떨어졌고, 하위 폴더에 옛 이름이 남아도 통과했습니다.
- 문서: 작업 모드를 도는 키는 `Ctrl+O` 입니다(README 에 `Shift+Tab` 으로 잘못 적혀 있었습니다 —
  `Shift+Tab` 은 승인 방식). 확장 문서의 MCP 절에 깨진 글자와 끊긴 문장을 바로잡았습니다.
- 지금 입력으로는 안 닿지만 표가 바뀌면 터질 두 자리(중단 때 지어내는 도구 결과 번호 — 이제 이미 쓰인 번호를 건너뜁니다, 자동 모드
  고르기의 둘째 후보)는 코드로만 막았습니다 — 넘어질 곳을 검사에서 못 만듭니다.

짚혔지만 고치지 않은 것도 적어 둡니다. 서로게이트 글자(이모지 · 희귀 한자)를 토큰 둘로 세는 것은 실제
토큰 수에 더 가까워 그대로 둡니다. 2차 리뷰가 「심각」 으로 짚은 loop.js 의 선언 안 된 이름 셋은 모두
감싼 함수 안에 선언돼 있어 오판이었고, 고친 뒤의 2차 리뷰 스무 건 중 받아들인 것은 세 자리였습니다(나머지는
실행으로 반증 — 이미 막혀 있거나 설계대로).

## 2.1.0

**맡기면 멈추지 않고, 묻게 하면 diff 를 보여 줍니다 — 「다 됐다」 는 검사가 정합니다**

회사에 들여놓는 쪽의 검토에서 세 가지를 들었습니다. 「고치기 전에 미리 보여 주고 사람이 확인하는
절차가 기본으로 도나」, 「검증을 정적 검사에 기대면 한계가 있다 — 작업마다 골든셋이 필요하다」,
「루프를 더 다듬어야 한다」. 재 보니 셋 다 맞았습니다. 2.1.0 은 그 셋에 답합니다.

### 맡기는 모드와 묻는 모드

승인 모드는 원래 갈려 있었습니다 — `auto` 는 맡기는 모드, `strict` 는 묻는 모드. 그런데 양쪽 다
약속을 다 지키지 않고 있었습니다.

| | 무엇 |
|---|---|
| **auto 가 멈춰 서던 자리** | 도구 승인은 안 물었지만, 모델이 되묻거나(Ask) 「설계하고 만들어줘」 에 계획부터 내면 사람 답을 **끝없이** 기다렸습니다. 맡겨 두고 자리를 뜬 사람에게는 멈춘 것과 같습니다. 이제 auto 에서는 60초 안에 답이 없으면 알아서 진행합니다 — 되묻기는 스스로 판단하게 하고, 계획은 그대로 이어서 만듭니다. 시간은 설정의 `askWait`(`0` 이면 아예 안 물음). `confirm` · `strict` 는 여전히 시한 없이 기다립니다 |
| **strict 가 바꾸는 도구를 다 묻습니다** | 여태 Write·Edit·Bash 셋만 물었습니다. 바꾸는 도구 목록은 따로 여섯으로 적혀 있었는데 승인 관문만 옛 목록에 남아 있었습니다. 이제 Append·Move, 뒤에서 도는 명령 끝내기(Jobs stop), 붙여 둔 MCP 도구도 묻습니다. Jobs 로 출력을 **읽는** 것은 안 묻습니다 — 읽을 때마다 물으면 사람은 y 만 치게 됩니다 |
| **물을 곳이 없으면 거절** | 승인이 필요한데 부르는 쪽에 물을 곳(confirm)이 없으면 여태 **그대로 실행**했습니다. 「묻는다」 가 「물을 곳이 있으면 묻는다」 였던 것입니다. 이제 실행하지 않고, 모델에게 승인 없이 되는 방법을 고르라고 돌려줍니다 |
| **바뀔 내용(diff)을 먼저 보여 줍니다** | Write·Append·Edit 을 묻기 전에 대화창은 파일마다 바뀔 줄을 그리고, 편집기(ACP)는 승인 요청에 diff 를 실어 보냅니다. 미리보기는 실제로 쓸 때와 같은 셈(줄끝·들여쓰기 맞춤·여러 군데 고치기)으로 만들어서, 승인 창에서 본 것과 실제로 쓰인 것이 같습니다 |
| **미리보기가 안 여는 것** | deel 자신의 설정·열쇠, 모델이 아직 안 읽은 파일의 Edit, 작업 폴더 밖, 200만 자가 넘는 파일(여러 파일 중 하나라도 넘으면 통째로), 문서 파일(엑셀·워드·PDF·시안), 실제 도구가 거절할 가린 표 되돌리기는 미리보기에서 뺍니다. 실제 도구가 거절하는 자리를 미리보기가 대신 읽으면 도구는 안 돌았는데 읽기는 일어난 셈이라서입니다. 그런 호출은 예전처럼 한 줄로 묻습니다 |
| **관리 정책의 승인 바닥** | 관리 정책 파일(`policy.json`)에 `"approval": "strict"` 를 적으면 그 PC 에서는 그보다 느슨한 모드로 못 내립니다. `/mode`·Shift+Tab·`deel run --yes`·설정의 `allow`·편집기의 「앞으로 묻지 않기」 가 다 바닥에 막히고, 왜 막혔는지 화면에 적습니다. 모르는 값(오타)이나 안 읽히는 정책 파일은 strict 로 칩니다. `deel doctor` 에 한 줄로 나옵니다 |

바닥은 조이기만 합니다. 정책이 `confirm` 이면 `strict` 로 올리는 것은 되고, `auto` 로 내리는 것만
막힙니다. 정책 파일이 없는 PC 는 기본 `auto` 그대로입니다.

### 「다 됐다」 는 검사가 정합니다 — 완료 검사

턴이 끝나는 자리는 **모델이 도구를 안 부르고 말만 한 걸음** 하나였습니다. 「고쳤습니다」 한 줄이면
끝이었습니다. 확인할 길(Verify · 이 프로젝트의 검사 명령 찾기 · 증거 보고)은 있었지만 셋 다 권하거나
보여 주기만 했고, 안 돌리고 끝내도 막는 자리가 없었습니다.

| | 무엇 |
|---|---|
| **`check`** | 설정에 `"check": "npm test"` 를 적거나 `deel run --check` 로 주면, 모델이 무엇을 바꾸고 끝내려 할 때 deel 이 **직접** 그 명령을 돌립니다 |
| **실패하면 이어서 고침** | 실패 출력의 **끝**(무엇이 틀렸는지가 있는 자리)을 모델에게 돌려주고 이어서 고치게 합니다. 「검사를 고치거나 지워서 통과시키지 말라」 고 같이 적습니다. 기본 3판(`checkRounds`) |
| **끝내 실패면 실패로** | 판수를 다 쓰고도 빨가면 실패로 끝냅니다. `deel run` 은 새 종료코드 **8**, `--json` 에는 `check` 칸 |
| **같은 관문** | 검사 명령도 모델의 명령과 같은 관문을 지납니다 — 금지 규칙, 훅, 승인(`strict` 면 묻습니다), 위험 명령 차단. 설정에 적혀 있다고 건너뛰면 저장소 설정 한 줄이 strict 를 뚫습니다. 못 돌렸으면 통과로 치지 않고 「못 돌렸다」 고 적습니다 |
| **안 도는 때** | 아무것도 안 바꾼 턴 · 실패를 받고 아무것도 안 바꾼 채 끝내려는 턴 · 하위 작업. 명령을 **짐작해 돌리지 않습니다** — 정해 둔 것이 없으면 예전과 똑같습니다 |

### 얼마나 해내나 — 골든셋 (`deel eval`)

검사 1만 4천여 개는 가짜 게이트웨이로 「도구가 약속대로 도나」 를 잽니다. 「이 회사의 모델과 deel 이
실제 일을 몇 개 해내나」 는 한 번도 안 쟀습니다. 모델을 바꾸거나 deel 을 올릴 때 나아졌는지 나빠졌는지
말할 숫자가 없었습니다.

| | 무엇 |
|---|---|
| **과제 하나 = 폴더 하나** | `task.json`(시킬 말 · 정답 검사 명령) · `start/`(시작 파일) · `golden/`(정답 검사 파일) |
| **정답은 모델이 못 봅니다** | 과제마다 임시 폴더에 `start/` 를 깔고 `deel run` 을 돌린 **뒤에** `golden/` 을 넣고 채점합니다. 일하는 동안에는 폴더에 없어서 「검사를 보고 거기 맞춰 쓰는」 길이 없습니다 |
| **예제 다섯** | `deel eval --init` — 버그 고치기 · 기능 더하기 · 여러 파일 이름 바꾸기 · 빨간 검사 고치기(완료 검사 고리를 탑니다) · CRLF 줄끝 지키기. 여기에 사내 과제를 더합니다 |
| **되풀이와 견주기** | `--repeat` 로 여러 번 돌려 비율로 봅니다. 결과는 `golden/.results/` 에 남고 지난번보다 **나빠진 과제**를 짚습니다. 하나라도 떨어지면 종료코드 1 |
| **빼지 않습니다** | 모양이 틀린 `task.json`, `start/`·`golden/` 은 있는데 `task.json` 이 없는 폴더도 실패로 셉니다 — `--repeat` 수만큼. 조용히 빼면 스무 개 중 열아홉만 돌고 「다 통과」 가 됩니다 |
