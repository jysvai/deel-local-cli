## 1.20.4

**붙임표 마디를 하나만 세고 있었습니다**

1.20.3 이 붙임표로 이은 이름(`github-token`)을 받게 했습니다. 그런데 마디를
**하나만** 봤습니다.

```
github-token: 'secret'            가림
aws-access-token: 'sk-12345678'   그대로 ← 평문으로 나갔습니다
my-aws-access-key: 'abcdef1234'   그대로
```

`aws-access-token` 은 클라우드 설정에서 예사로 쓰는 이름입니다. 마디가 몇이든
받습니다.

### 대소문자를 반만 가리고 있었습니다

붙임표·밑줄 뒤의 낱말을 소문자로만 봤습니다. 대문자 갈래에는 `PWD` 도 빠져
있었습니다.

```
db-pwd: 'secret1234'      가림
db-PWD: 'secret1234'      그대로 ← 같은 이름인데
auth_TOKEN: 'secret1234'  그대로
api_KEY: 'secret1234'     그대로
```

### 꾸밈표와 별표도 수식어입니다

1.20.3 이 몰래칸 앞의 수식어를 「글자와 빈칸」 으로 봤습니다. 그런데 꾸밈표
(`@inject`)와 별표(`*#gen()`)는 글자가 아닙니다.

```
class C { @inject #apiKey = config.apiKey; }    가려지고 있었습니다
```

설정 줄이라면 그 자리에 `:` 나 `=` 나 숫자가 있습니다 — 글자와 `@` · `*` 만
있을 수가 없습니다.

### 「길어서 잘렸다」 를 알리는 말은 하나가 아닙니다

2차 리뷰 도구가 `exceeded the output token limit` 만 알아봤습니다. 그런데 밑에
깔린 API 는 마침 까닭을 낱말로 줍니다.

```
finishReason: MAX_TOKENS      못 알아봤습니다
finish_reason: length         못 알아봤습니다
```

못 알아보면 **짧게 다시 묻지도 않고** 화면에는 쪼갤 수 없는 방법만 남습니다.
둘 다 알아봅니다. `length` 는 홀로 두면 넓어서(`content length`) 까닭을 적는
자리와 붙어 있을 때만 봅니다 — 망이 끊긴 판을 40분짜리 재시도로 보내면 안
되기 때문입니다.

### 눈금자가 한 일

이 판에서 이름 무늬를 크게 넓혔습니다. 넓히고 나서 눈금자를 돌렸더니 **78줄
전부, 10판 전부 그대로**였습니다 — 넓힌 자리 말고는 아무 데도 안 흔들렸다는
뜻입니다. 여태는 이걸 다음 판의 2차 리뷰에서야 알았습니다.

### 알고 치르는 값

`id-token: "write"` 처럼 액션 값에 따옴표를 두르면 가려집니다.
`github-token: "abc123"` 과 글자로 안 갈립니다. 검사로 못 박아 뒀습니다.

## 1.20.3

**울타리를 옮긴 자리가 어디까지 흔들렸는지 한 판에 보이게 했습니다**

앞 세 판이 전부 **그 앞 판이 낸 흠**을 고치는 판이었습니다. 무늬를 한 군데
손대면 손댄 자리만 바뀌지 않는데, 그걸 **다음 판의 2차 리뷰에서야** 알았습니다.

```
1.19.1  괄호 규칙을 좁혔다  → 넉 줄이 샜다
1.20.1  붙임표를 뺐다       → 밑줄까지 막혀 _password 가 안 잡혔다
1.20.1  「값 줄을 보라」    → 이름 줄을 잃었다
```

### 눈금자를 놨습니다

72줄짜리 뭉치와 여러 줄에 걸친 10판을 통째로 가려 보고, **가린 결과를 파일에
적어 둔 것과 글자 하나까지** 견줍니다. 어긋난 줄은 옛것·새것을 나란히 찍습니다.

```
$ node test/secrets-corpus.test.js
✓ 잰 줄 수가 같다                    적힌 것 95줄 · 잰 것 95줄
✓ 가린 결과가 적어 둔 것과 같다        72줄 · 0줄이 다릅니다
✓ 여러 줄 판도 적어 둔 것과 같다       10판 · 0줄이 다릅니다
```

무늬에서 `+` 를 `*` 로 한 글자 바꿔 봤습니다.

```
      56번째 줄
        적힌 것 "KEY: \"description\""
        잰 것   "KEY: «가림:환경변수»"
```

다시 적는 것은 손으로 합니다(`--기록`). **어긋난 줄마다 왜 달라졌는지 말할 수
있어야** 적는다는 뜻입니다.

### 붙임표로 이은 이름

1.20.2 가 `id-token: write`(깃허브 액션 문법)를 빼려고 붙임표를 통째로
막았습니다. 그랬더니 진짜 비밀 이름까지 같이 막혔습니다.

```
github-token: 'mysecretvalue123'    그대로 ← 평문으로 나갔습니다
```

이름으로는 안 갈립니다. **값으로 갈립니다** — 깃허브 액션의 값은 늘 맨
낱말(`write`·`read`)이고, 비밀은 따옴표에 싸여 옵니다. 붙임표 이름은
따옴표에 싸인 값일 때만 가립니다.

따옴표 없이 적은 붙임표 비밀은 여전히 샙니다. `id-token: write` 와 글자로
안 갈립니다 — 알고 치르는 값이고, 검사로 못 박아 뒀습니다. 모양을 아는
열쇠(`ghp_…`)는 그래도 잡힙니다.

### `_KEY` 와 몰래칸 수식어

`KEY` 를 「짝의 이름일 때가 많다」 며 뺐는데 `_KEY` 는 남아 있었습니다.
밑줄뿐인 앞머리는 앞머리가 아닙니다. 앞머리에 글자가 하나는 있어야 봅니다 —
`A_KEY` · `APIKEY` 는 그대로 봅니다.

몰래칸 선언은 `static #apiKey` 만 멀쩡했는데, 그건 `static` 이 **마침** 코드의
표시 목록에 있어서였습니다. 목록에 없는 낱말에서는 그대로 뭉갰습니다.

```
class C { accessor #apiKey = config.apiKey; }    가려지고 있었습니다
```

### 2차 리뷰 도구 — 두 판을 다 잃던 자리

19차 리뷰가 **두 판 다 답이 잘려** 아무것도 못 남겼습니다. 3.8KB 짜리 diff
하나였는데도 그랬습니다 — 들어간 것이 작아도 나오는 말이 길면 똑같이
버려집니다.

셋째 판까지 갑니다. **최대 3건 · 한 건 한 줄.** 한 건이라도 받는 것이 낫습니다.
그렇게 해서 이 판의 고침 셋을 받았습니다.

그리고 빈 손으로 왔을 때 하는 말을 고쳤습니다. 여태 「`--files` 로 쪼개서
보라」 고만 했는데, 이미 파일 하나를 준 판에서는 **쪼갤 것이 없습니다.**

```
✗ 2차 리뷰가 빈 채로 돌아왔습니다 (228초 · 한도 40m)
  답이 길어서 잘렸습니다 — 볼 것을 줄여야 합니다:
    · 판을 좁혀서 — --since <한 판 앞> --to <그 판> (지금은 HEAD~2..HEAD~1)
    · 파일이 이미 하나입니다. 그래도 잘리면 그 파일이 한 판에 보기엔 큽니다.
```

## 1.20.2

**앞 판이 막으려던 자리를 앞 판이 막고 있었습니다**

18차 리뷰가 여덟을 짚었고 다섯이 재현됐습니다. **그중 둘은 1.20.1 이 스스로
낸 것입니다.**

### 붙임표를 빼려던 울타리가 밑줄까지 막았습니다

1.20.1 이 `id-token: write` 를 빼려고 「앞이 붙임표나 낱말 글자면 안 된다」 는
울타리를 넣었습니다. 그런데 밑줄도 낱말 글자입니다.

```
_password = "mysecret1234"     그대로 ← 막으려던 것이 아닌데 막혔습니다
_token: abcdef123456           그대로
```

같은 판의 릴리스 노트에 **「`_apiKey` 도 본다」 고 적어 놓고** 정작 소문자
민 이름은 하나도 안 잡히고 있었습니다. 울타리를 「앞이 붙임표면 안 된다」
로만 좁혔습니다. 대소문자도 안 가립니다 — `id-TOKEN: write` 도 같이 빠집니다.

`X-API-KEY:` 처럼 붙임표로 이은 머리글은 따로 있는 `헤더` 갈래가 집습니다.
여기서 빠져도 안 샙니다.

### 값이 놓인 줄만 보게 고쳤더니 이름 줄을 잃었습니다

1.20.1 이 「짝이 여러 줄에 걸리면 **값이 놓인 줄**을 보라」 로 고쳤습니다.
그랬더니 반대쪽이 무너졌습니다.

```
const API_KEY =
  config.apiKey        ← 이름 줄에만 const 가 있어서 가려졌습니다

const opts = { apiKey:
  config.apiKey,       ← 값 줄에만 쉼표가 있어서 1.20.0 에서 가려졌습니다
};
```

한쪽만 보면 반대쪽이 뭉개집니다. **둘 다 봅니다** — 이름 줄이든 값 줄이든
하나라도 코드면 코드입니다.

### `KEY` 와 `OLDPWD`

1.20.1 이 소문자 `key` 를 뺀 까닭 그대로 대문자 `KEY` 도 뺐어야 했습니다.

```
const map = { KEY: "description" };   가려지고 있었습니다
OLDPWD: '/Users/work/project'         가려지고 있었습니다
```

`PWD` 를 「셸의 현재 폴더」 라고 뺐는데 `OLDPWD` 는 앞머리가 붙었다는 이유로
남아 있었습니다. 둘 다 폴더입니다. 이제 밑줄이 앞에 있어야 봅니다 — `DB_PWD`
는 그대로 봅니다. `KEY` 도 앞머리가 붙은 `API_KEY` · `A_KEY` 만 봅니다.

### 안 받은 셋

- `static #apiKey = …` 가 뭉개진다 — 재 보니 안 뭉개집니다. `static` ·
  `readonly` 는 이미 코드의 표시 목록에 있어서 그 줄이 코드로 읽힙니다.
- `#apiKey = get_api_key()` 를 파이썬 주석으로 봐야 한다 — 재 보니 애초에
  아무것도 안 가려집니다.
- `config?.#apiKey` 는 문법상 틀렸다 — 맞습니다. 틀린 코드를 이름씨로 봐도
  가림 결과가 달라지지 않습니다.

## 1.20.1

**`PASSWORD=` 는 한 번도 안 잡히고 있었습니다**

1.20.0 이 이름을 넓히자마자 17차 리뷰가 그 자리를 다시 짚었습니다. 열 가지 중
일곱이 재현됐고, 그중 하나가 **가장 흔한 이름을 통째로 놓치고 있었습니다.**

### 앞머리가 있어야 잡혔습니다

이름 무늬가 `API_KEY` 처럼 **앞에 무언가 붙은 것**만 봤습니다. 그런데 `.env` 에서
제일 흔한 이름이 바로 앞머리 없는 것들입니다.

```
API_KEY=sk-real-1234              가림
PASSWORD="prod_password_1234"     그대로 ← 평문으로 나갔습니다
SECRET=prod_secret_value_12       그대로
TOKEN: abcdef123456               그대로
A_KEY=abcdef123456                그대로 ← 앞머리가 짧아도 안 잡혔습니다
const _apiKey = 'sk-…';           그대로 ← 밑줄로 시작해도
```

`DB_PASSWORD` 는 잡히는데 `PASSWORD` 는 안 잡혔습니다. **앞머리를 요구한 것이
까닭이지 이름 목록이 모자란 것이 아니었습니다.**

### 민 이름으로 받을 때 뺀 셋

재 보고 뺐습니다. 이 저장소 파일 406개에 넣어 보니 이 둘이 걸려 나왔습니다.

```
PWD: '/work'        셸의 현재 폴더입니다. 암호가 아닙니다
id-token: write     깃허브 액션 문법입니다
```

- 소문자 `key` — `key: 값` 은 그냥 짝의 이름일 때가 너무 많습니다.
- `PWD` — 앞머리가 붙은 `DB_PWD` 는 그대로 봅니다.
- 붙임표로 이은 낱말 — 밑줄과 낙타등은 이름씨 관례고, 붙임표는 YAML 짝 이름
  관례입니다. `access_token` · `accessToken` 은 그대로 봅니다.

넓히고 나서 이 저장소에서 새로 가려진 줄은 **다섯**이고 전부 진짜 토큰입니다.

### 몰래칸 선언과 물음표 이음

`#` 을 주석으로만 알아서, 자바스크립트 몰래칸 선언 줄이 통째로 잘렸습니다.
잘린 자리에 코드의 표시가 없어 멀쩡한 선언이 가려졌습니다.

```
class C {
  #apiKey = config.apiKey;     ← 가려지고 있었습니다
}
const API_KEY = config?.apiKey;  ← 물음표 이음도 이름씨로 안 봤습니다
```

뒤에 이름씨 글자가 붙은 `#` 은 몰래칸으로 봅니다 — 점 뒤(`obj.#몰래칸`)든
줄머리든. 줄머리 `#` 을 안 잘라도 설정 줄은 안 상합니다. `# API_KEY: 값` 은
잘라도 안 잘라도 코드의 표시가 없어 어차피 가려집니다.

### 짝이 여러 줄에 걸리면 값이 놓인 줄을 봅니다

이름과 값이 다른 줄에 있으면 **이름 줄**만 보고 있었습니다. 값 줄의 쉼표를
못 보니 멀쩡한 객체 속성이 가려졌습니다.

```
const opts = {
  apiKey:
    config.apiKey,     ← 이 줄이 가려지고 있었습니다
};
```

### 안전망 문서에 가림 설명을 넣었습니다

네 판을 고치는 동안 정작 **무엇을 가리고 무엇을 못 가리는지 적힌 자리가
없었습니다.** `docs/ko/safety.md` 에 「모델로 나가기 전에 가립니다」 를 넣었습니다 —
아는 모양, 설정 줄과 코드 줄을 가르는 방법, 그리고 **못 가르는 자리 표**까지.

### 안 받은 셋

`tuple.0` 은 자바스크립트가 아닙니다. 틀 글자열 안의 따옴표는 재 보니 이미
맞게 셉니다. 무늬 안의 `[^\n]` 을 `[^\r\n]` 로 바꾸라는 것은, 줄을 떼는 자리에서
이미 `\r` 을 가르므로 같은 것을 두 군데 적는 셈입니다.

## 1.20.0

**대문자로 안 적은 열쇠는 그대로 나가고 있었습니다**

1.19.5 가 「따로 재 보고 내겠다」 고 적어 둔 자리입니다. 재 봤고, 냅니다.

### `.env` 만 대문자를 씁니다

비밀 이름을 여태 **대문자로만** 봤습니다. `.env` 는 대문자가 관례라 그것으로
됐는데, 코드와 JSON·YAML 설정은 아닙니다.

```
API_KEY=sk-진짜열쇠-1234        가림
apiKey: 'sk-진짜열쇠-1234'      그대로 ← 평문으로 나갔습니다
api_key: "prod.auth.secret"    그대로
accessToken: 'ya29.abcdefgh'   그대로
```

가운뎃줄 세 개가 설정 파일에서 제일 흔한 꼴입니다.

### 낱말 사이가 끊긴 이름만 봅니다

낙타등(`apiKey`)과 밑줄(`api_key`)로 이은 이름도 봅니다. 다만 **낱말 사이가
끊겨 있어야** 합니다 — `_key` 아니면 `Key`. 그냥 소문자 `key` 로 끝나는 것까지
받으면 이런 것들이 걸립니다.

```
monkey: 'brown-monkey'      안 가림 ✓
hotkey: 'ctrl+shift+s'      안 가림 ✓
turkey: 'roasted12'         안 가림 ✓
```

**재 보고 넓혔습니다.** 이 저장소 파일 348개에 넣어 보니 21줄이 새로 가려졌고
전부 진짜 열쇠였습니다(`apiKey: 'sk-…'` 꼴). 엉뚱하게 가려진 줄은 없었습니다.

치르는 값은 있습니다. `cacheKey` · `rowKey` 처럼 비밀이 아닌 낙타등 이름에
따옴표 값이 붙으면 같이 가려집니다 — 이름만으로는 `cacheKey` 와 `apiKey` 가
안 갈립니다. 줄이 뭉개지는 것이 비밀이 나가는 것보다 낫습니다. 검사로 못
박아 뒀습니다.

### 이름씨는 영문만이 아닙니다

점으로 이은 값이 「코드가 가리키는 이름」 인지 볼 때 영문자만 이름씨로 쳤습니다.
이 저장소 집안 스타일이 한글 이름씨라, **제 코드부터 뭉갰습니다.**

```
const API_KEY = 설정.비밀번호;      가림   ← 코드인데 뭉개졌습니다
const API_KEY = config.apiKey;     그대로
```

글자 갈래로 봅니다. 점 뒤의 `#` 도 이름씨의 한 조각으로 칩니다 —
`obj.#몰래칸` 은 자바스크립트입니다.

### 따옴표 안의 `#` 은 주석이 아닙니다

1.19.4 가 넣은 「줄 뒤 `#` 주석은 떼고 본다」 를 무늬 하나로 하면 둘 중 하나를
고르게 됩니다. 16차 리뷰가 양쪽을 다 짚었습니다.

```
API_KEY=prod.v1.secret#(운영)               빈칸을 요구하면 샙니다
msg = "a # b"; x.API_KEY = config.apiKey;   안 요구하면 뒤쪽 ; 이 잘려 뭉갭니다
```

따옴표를 세면서 걷습니다. **따옴표 밖**의 첫 `#` 부터가 주석입니다. 둘 다
맞습니다.

### `\r` 만 쓰는 글

줄바꿈을 `\n` 으로만 찾으면 `\r` 만 쓰는 글은 파일 통째가 한 줄이 되고,
저 아래 어딘가의 `;` 하나 때문에 그 줄이 코드로 뒤집혔습니다. 줄 끝을
`[\r\n]` 으로 봅니다.

### 안 받은 지적

16차 리뷰가 일곱을 짚었고 넷을 받았습니다. 못 받은 셋은 재 보고 물렸습니다.

- **`// API_KEY=prod.v1.secret` 이 샌다** — 맞습니다. 그런데 이 저장소가
  **`// API_KEY: config.api_key` 는 그대로 두라고** 못 박아 뒀습니다. 주석 안의
  한 줄이 비밀인지 코드인지는 글자로 안 갈립니다.
- **한 줄짜리 파일에서 다 샌다** — 그 한 줄이 실제로 코드입니다. 죄다 코드로
  보는 것이 맞습니다.
- **무늬 자체에 `\r?$` 를 넣어라** — 줄을 떼는 자리에서 이미 `\r` 을 가릅니다.
  같은 것을 두 군데 적으면 한쪽만 고쳐질 때가 더 위험합니다.
