## 1.20.12

**켠다고 적은 자물쇠가 아무것도 안 잠그고 있었습니다**

회사 PC 를 봉인하는 방법은 관리 정책 파일에 한 줄을 적는 것입니다.

```json
{ "offline": true }
```

`/mode` 는 「정책으로 오프라인이 켜져 있습니다 — 끌 수 없습니다」 라고 답했습니다.
그런데 `deel run` 은 그대로 바깥으로 나갔습니다.

```
deel run "안녕"

  앞   ✗ 주소를 찾을 수 없습니다 (DNS)          ← 정말로 나갔습니다
  뒤   ✗ 허용되지 않은 주소입니다: https://…
       오프라인 모드입니다 — 이 컴퓨터 밖으로는 나가지 않습니다
```

봉인을 켜는 길은 셋입니다 — `--offline` 깃발, 프로필의 `offline`, 관리 정책.
셋 중 하나를 고르는 자리가 이렇게 적혀 있었습니다.

```js
offline: !!(opts.offline ?? prof.offline ?? cfg?.offline)
```

`??` 는 `null`·`undefined` 에서만 다음 칸으로 넘어갑니다. 그런데 부르는 쪽이
깃발을 **언제나 `true`/`false` 로** 넘겼습니다. 첫 칸이 늘 `false` 로 차 있어서
뒤의 둘은 **한 번도 안 읽혔습니다.**

실패는 화면에 뜹니다. **안 걸린 자물쇠는 안 뜹니다.**

## 봉인이 안 걸리던 네 자리

| 어디 | 앞 | 뒤 |
|---|---|---|
| 대화 · `deel run` | 그대로 나감 | ⛊ 막힘 |
| 에디터(ACP) | 그대로 나감 | ⛊ 막힘 |
| 에디터의 MCP 서버 붙이기 | 봉인을 모르고 붙음 | ⛊ 막힘 |
| `deel diagnose` | 그대로 두드림 | `✗ 봉인되어 있어 이 주소는 안 두드립니다` |

사람이 제 손으로 `config.json` 에 적은 `"offline": true` 도 같이 살아났습니다.
봉인을 안 켠 판은 그대로 나갑니다 — 지나치게 막지 않습니다.

### 정책이 사람 설정 파일에 눌러앉았습니다

정책은 덮는 것이지 사람 파일을 고쳐 쓰는 것이 아닙니다. 그런데 한 번 저장하면
(`deel setup` · `/model` · `deel scan`) 정책 값이 그대로 박혔습니다.

| | 앞 | 뒤 |
|---|---|---|
| 내 `baseUrl` | 정책 주소로 **덮여 사라짐** | 내가 적은 그대로 |
| `offline` | `true` 가 박힘 | 안 적힘 |
| 정책의 금지 | 내 파일에 섞여 들어감 | 안 적힘 (내 금지는 그대로) |

관리자가 정책을 걷으면 그 값이 남아 있고, 그때 `deel config explain` 은
「이 PC 설정 = …」 이라며 **사람 본인을 범인으로 가리켰습니다.**

## 스위치가 뒤 낱말을 삼켰습니다

```
deel reset --hard all --yes

  앞   무엇을 지울지 같이 주세요        ← 아무것도 안 지우고 종료코드 0
  뒤   ✓ 연결·프로필 · 기억 · 대화 기록 … 되돌리기 스냅샷 · 감사기록까지
```

값을 안 받는 깃발 목록에 `hard` 가 빠져 있어서 `--hard` 가 뒤의 `all` 을 제
값으로 삼켰습니다. 사람이 손으로 칠 때는 갈래를 다시 물어 주니 잘 안 걸리고,
**스크립트에서만** 걸립니다. 그리고 스크립트는 0 을 보고 다음 줄로 갑니다.

### 휴대용 설치에서 플러그인만 집에 남았습니다

`DEEL_HOME` 은 USB·공유폴더에 통째로 넣어 쓰라고 있는 것입니다.

| | 앞 | 뒤 |
|---|---|---|
| 깔리는 자리 | `C:\Users\나\.deel\plugins` | `$DEEL_HOME/plugins` |
| `deel reset plugins` 가 보는 자리 | `$DEEL_HOME/plugins` | 같은 자리 |
| 그 결과 | 「플러그인 0개 · 이미 비어 있습니다」 · 종료코드 0 · **플러그인은 그대로 산다** | 정말 지웁니다 |

### 저장소 설정의 프로필이 이름으로만 붙었습니다

나머지 코드는 전부 `id` 로 도는데 겹치는 자리만 `name` 으로 맞췄습니다.

| 저장소 `.deel/config.json` | 앞 | 뒤 |
|---|---|---|
| `{id:'gw', model:'저장소모델'}` | **통째로 버려짐** (아무 말 없음) | 저장소 값이 먹음 |
| `{id:'gw', name:'우리팀', …}` | `gw` 가 **두 개**가 되고 집 것이 이김 | 하나 · 저장소 값이 먹음 |
| `{model:'…'}` (id·name 없음) | 조용히 사라짐 | 버리되 **말합니다** |

`deel config explain` 은 이 셋 모두에서 저장소 값이 이겼다고 그렸습니다 —
실제로 모델에 붙는 값은 집 것이었습니다.

## 못 읽은 것을 「없다」 로 적었습니다

```
/sessions

  앞   아직 없습니다. 지금 이 대화가 첫 번째입니다.
  뒤   ⚠ 20260101-120000        못 읽었습니다 — EISDIR
       ⚠ 여기 있는 대화를 하나도 못 열었습니다 — 이어할 수 없습니다.
```

권한이 막히거나 다른 프로그램이 잡고 있는 대화는 목록에서 통째로 빠졌습니다.
어제 한 일이 그대로 있는데 없다고 한 것입니다. `--continue` 도 못 읽는 것을
집어 **빈 대화**로 열렸습니다 — 사람은 어제 하던 것이 이어진 줄 압니다.

| 무엇 | 앞 | 뒤 |
|---|---|---|
| 셋 중 하나를 못 읽을 때 | 2개만 뜸 · 아무 말 없음 | 3개 다 뜸 · 못 읽었다고 적음 |
| 셋 다 못 읽을 때 | 「아직 없습니다」 | 셋 다 뜨고 이어할 수 없다고 말함 |
| `--continue` | 못 읽는 것을 집음 | 읽히는 것 중 최신 |
| `deel reset` 의 기억·대화 기록 | 못 읽어도 「0줄」 → 그대로 지움 | 「알 수 없음」 |
| `git diff` 를 못 읽을 때 | 「바뀐 내용이 없습니다」 | 「git 이 담긴 것을 못 읽었습니다 — …」 |

### 잠깐 막힌 것이 영영 사라졌습니다

디스크가 차거나 파일이 잠기면 남은 할 일이 안 적힙니다. 그런데 **적은 셈으로
표시**해 둬서, 다시 쓸 수 있게 된 뒤에도 그 값은 「안 바뀐 것」 이라 두 번 다시
안 적혔습니다.

| | 앞 | 뒤 |
|---|---|---|
| 막혔다 풀린 뒤 파일에 적힌 할 일 | `null` (영영 없음) | 막혀 있던 그것이 들어감 |

### 접다가 죽으면 대화가 통째로 없어질 수 있었습니다

대화를 jsonl 로 남기는 까닭이 「통째로 다시 쓰면 그 순간 파일이 깨진다」 인데,
정작 접을 때(압축)는 원본에 바로 덮어썼습니다. 이제 옆에 다 쓰고 **한 번에 갈아
끼웁니다** — 성한 쪽 아니면 성한 쪽입니다.

### 그 밖에 · 대화 저장

| 무엇 | 앞 | 뒤 |
|---|---|---|
| 대화가 1000개를 넘을 때 정리 | 0개 · 1005개 그대로 | 5개 정리 · 1000개 |
| 정리가 못 지운 것 | 지웠다고 셈 | 지운 것만 셈 |
| 「[급함] 로그인이 안 됩니다」 로 연 대화 | 목록에 `(빈 대화)` | 그 첫 마디 그대로 |
| `deel sessions --rm ../../남의것` | 지우고 「지웠습니다」 | 「대화 이름이 아닙니다」 |
| 이름이 다 차 있을 때 새 대화 | 파일 없이 시작 (「저장되고 있습니다」) | 자리를 찾아 적음 |
| 폴더를 못 만들었을 때 | 두 번 다시 안 만들어 봄 | 풀리면 그때부터 적음 |
| 윈도우에서 대화 파일 잠금 | `{모드: 0600}` 으로 적음 | 「못 잠갔습니다」 (NTFS 는 chmod 가 안 먹습니다) |

## 언어 서버가 준 답을 버리고 「없습니다」 라고 했습니다

`Refs` 는 이름 하나를 어디서 쓰는지 언어 서버에게 묻는 도구입니다.

```
Refs 셈하기

  앞   쓰는 자리가 없습니다. 정말 안 쓰는 것일 수도 있고…      ← 서버는 3곳을 줬습니다
  뒤   3곳
```

LSP 는 오가는 번호를 **양쪽이 따로** 셉니다. pyright·rust-analyzer 가 쓰는
관은 1번부터 세고, 우리도 1번부터 셉니다. 번호로 먼저 가르면 서버가 우리에게
묻는 말이 **우리 물음의 답으로 소비됩니다.** 답에는 `method` 가 없고 물음에는
있으니 그것으로 갈라야 하는데, 번호를 먼저 봤습니다.

모델은 「안 쓰는 함수」 라는 말을 믿고 그것을 지웁니다.

| 무엇 | 앞 | 뒤 |
|---|---|---|
| 번호가 겹칠 때 `Refs` | 없음 (서버는 3곳을 줌) | 3곳 |
| 그때 서버가 할 수 있는 일 | 빈 채로 **「준비됨」** | 제대로 읽음 |
| 그 사이 서버 | 제 물음의 답을 못 받아 멈춤 | 바로 답함 |

### 한 파일을 잇달아 고치면 옛 결과를 들었습니다

언어 서버는 잠깐 모았다가 진단을 냅니다. 그래서 1~2초 안에 두 번 고치면
**첫 판** 결과가 둘째 판 뒤에 도착합니다.

| | 앞 | 뒤 |
|---|---|---|
| 둘째 판(탈난 것)에 대해 받은 진단 | 0개 | 1개 |

진단이 0개면 화면에는 아무 말도 안 붙습니다. 이 프로그램에서 아무 말 없음은
**성하다** 는 뜻입니다 — 확인 안 한 것을 확인했다고 말한 셈입니다.

### 우리가 끈 것을 「서버가 스스로 끝났습니다」 라고 적었습니다

언어 서버는 5분 놀면 저절로 꺼집니다. 그런데 끈 뒤에 오는 종료 신호를 「무너진
것」 으로 읽어서, 멀쩡한 서버를 세션이 끝날 때까지 못 쓰게 만들었습니다.

| | 앞 | 뒤 |
|---|---|---|
| 끈 뒤 상태 | `서버가 스스로 끝났습니다 (코드 null)` | 아무 말 없음 |
| 다시 켜기 | 안 켜짐 | 켜짐 |
| 다시 켠 뒤 진단 | 영영 안 옴 | 옴 |

그 뒤 `Def`·`Refs` 는 「언어 서버가 이 자리에 없습니다」 라고 합니다 — 멀쩡히
깔려 있는데도요. 고친 뒤 진단은 조용해지고, 조용한 것은 성하다는 뜻입니다.

### 언어 서버가 죽는 찰나에 쓰면 deel 이 같이 죽었습니다

| | 앞 | 뒤 |
|---|---|---|
| 서버를 죽이고 곧바로 쓸 때 | **종료코드 1** — 하던 답이 통째로 날아감 | 그냥 넘어감 |
| 옛 서버가 남긴 바이트가 뒤늦게 올 때 | 새 서버의 통 경계가 어긋나 그 뒤 답이 전부 빈손 | 안 섞임 |

그 찰나에는 관이 아직 「쓸 수 있음」 이라 미리 하는 검사도, 감싸 둔 try/catch 도
못 막습니다. 오류가 한 박자 뒤에 튀어나오기 때문입니다.

## 답이 모델이 한 말과 다르게 그려졌습니다

모델이 코드를 한 줄에 다 적는 일이 있습니다.

````
```js console.log(1)```
## 다음 제목
**굵게**
````

````
  앞   ┌───────── js console.log(1)```
       │ ## 다음 제목
       │ **굵게**

  뒤   js console.log(1)
       ▍ 다음 제목
       굵게
````

여는 줄로 읽었으니 닫는 줄이 영영 안 옵니다. **그 뒤의 답 전체**가 코드
상자에 들어갑니다 — 제목도 굵기도 목록도 표도 다 사라지는데, 화면은
멀쩡한 코드 블록으로 보입니다.

반대 방향도 있었습니다. 마크다운 문서를 보여 주려고 백틱 넷으로 열고 그 안에
` ```js ` 를 적으면, 안쪽 울타리가 상자를 **일찍 닫았습니다.** 상자는 열자마자
닫힌 빈 상자가 되고 나머지 코드는 코드가 아닌 것으로 그려졌습니다.

### 별표가 소리 없이 사라졌습니다

| 모델이 한 말 | 앞 | 뒤 |
|---|---|---|
| `2 ** 3 ** 4 입니다` | `2  3  4 입니다` | 그대로 |
| `5 *x * y` | `5 x  y` | 그대로 |
| `*중요*입니다` | `*중요*입니다` (별표째로) | *중요*입니다 |
| `*주의*!` · `*참고*:` | 별표째로 | 기울임 |
| ` ``겹백틱`` ` | 바깥 백틱이 남음 | 안 남음 |

가운데 별표를 굵게로 먹으면 화면에서 별표가 **없어집니다.** 사람은 모델이
그렇게 말한 줄 압니다. 반대로 한국어는 조사가 바로 붙는데(`*중요*입니다`)

## 1.20.11

**안전망이 있다고 말하는데 없었습니다**

이번 판에서 고친 쉰두 자리 가운데 여덟은 한 갈래입니다. **되돌릴 수 있다고
화면이 말했는데, 실제로는 되돌릴 수 없던 것.**

```
rm 로고.png

  ⏺ Bash(rm 로고.png)
    ↩ 로고.png 는 떠 뒀습니다 — /undo 로 되돌아갑니다
```

그림·xlsx·zip·hwp 는 되돌리기가 **내용을 떠 두지 못하는** 갈래입니다. 그래서
`/undo` 는 그 파일을 아예 손대지 않습니다. 그런데 화면은 떠 뒀다고 말했습니다.
파일은 이미 없고, 사람은 안전망이 있다고 믿은 채 다음 일로 넘어갑니다.

이 프로그램에서 제일 나쁜 모양입니다. 실패는 화면에 뜹니다. **틀린 값은 안
뜹니다.**

## 되돌릴 수 있다고 말하던 자리 여덟

### `rm 로고.png` 는 되돌아가지 않습니다

| | 앞 | 뒤 |
|---|---|---|
| 화면 | `↩ 로고.png 는 떠 뒀습니다 — /undo 로 되돌아갑니다` | `⚠ 로고.png (바이너리) 는 못 떠 뒀습니다 — /undo 로 안 돌아옵니다` |
| 같은 명령의 글 파일 | 섞여서 한 줄 | `↩ 글.txt 는 떠 뒀습니다` 로 따로 |

### 대상이 스물넷을 넘으면 뒤엣것은 떠 두지도 않습니다

`sed -i 's/a/b/' f1.js … f40.js` 는 마흔 개를 고치는데 이력에는 앞 스물넷만
남습니다. 나머지 열여섯은 `/undo` 로 안 돌아오는데 화면에는 그 말이 없었습니다.
폴더 옮기기는 같은 자리에서 이미 말해 주고 있었습니다 — 여기만 안 했습니다.

### 아무것도 안 바꾼 턴이 `/undo` 한 번을 통째로 먹었습니다

CP949 사내 문서에 이모지를 넣으려다 거절당하면, 파일은 한 글자도 안 바뀌는데
되돌리기 이력에는 그 턴이 남았습니다.

```
앞   ① 진짜 고침    ② 이모지 → 거절(파일 안 바뀜)
     /undo → 「파일 1개를 되돌렸습니다」   ← ② 를 되돌린 것이다
     ①의 진짜 변경은 그대로 남는다

뒤   아무것도 안 바꾼 턴은 이력에 안 남는다
     /undo → ①이 되돌아간다
```

### 이력을 못 줄인 것을 「0개 버렸다」 와 같은 값으로 넘겼습니다

되돌리기 이력은 파일 원문을 담아서 금방 수십 MB 가 됩니다. 32MB 를 넘으면 오래된
턴부터 버리는데, 그 버리기가 실패하면(읽기 전용·디스크 참) 부르는 쪽은 실패와
「버릴 것이 없었다」 를 구별할 길이 없었습니다. 실패는 대개 이어지는 종류라
이력은 끝없이 자라는데 화면에는 영영 안 떴습니다.

### 이력을 줄이다 터지면 **고치던 파일이 그 오류를 뒤집어썼습니다**

이 일은 파일을 쓰기 **직전**에 돕니다. 그래서 이력을 읽다 막히면
`EACCES: …/edits.jsonl` 이 그대로 나갔습니다 — 고치려던 파일과 아무 상관 없는
줄입니다.

### 이력의 깨진 줄을 조용히 버렸습니다

이력 한 줄은 곧 한 파일의 원문입니다. 줄이 깨졌다는 것은 그 파일을 되돌릴 길이
사라졌다는 뜻인데, `/undo` 는 「파일 3개를 되돌렸습니다」 라고만 하고 넷째가 왜
안 왔는지는 아무 데도 안 남겼습니다.

### 되돌린 **뒤에** 쓰기가 실패하면 화면만 실패라고 했습니다

파일은 이미 되돌아가 있습니다. 그런데 그 턴이 이력에 그대로 남아서, 사람이
「실패했으니 다시」 하고 `/undo` 를 또 치면 **같은 턴**을 또 되돌립니다.

### 폴더를 옮기면 `.git` 이 새 자리에 남습니다

폴더 옮기기는 `renameSync` 라 전부 옮겨지는데, 되돌리기에 뜨는 것은 훑은 것뿐입니다.
`node_modules`·`.git`·`dist` 는 훑지 않으므로 `/undo` 를 누르면 **소스만 옛 자리로
돌아가고 `.git` 은 새 자리에 남습니다.** 갈라진 저장소가 되는데 화면은 초록이었습니다.

| | 앞 | 뒤 |
|---|---|---|
| 결과문 | `옮김: 서버 → apps/서버 (폴더 12개 파일)` | `(폴더 12개 파일 + 살림 폴더)` |
| 경고 | 없음 | `(.git · node_modules 도 같이 옮겨졌지만 되돌리기에는 안 떴습니다 — /undo 를 하면 이것들만 새 자리에 남습니다)` |

## 「없다」 와 「안 찾아봤다」 를 뭉개던 자리 넷

### 오타 난 폴더가 「찾은 파일 없음」 이 됐습니다

```
Glob(pattern:'**/*.tsx', path:'srcs')     ← src 의 오타

앞   찾은 파일 없음: **/*.tsx
     (한 군데도 안 찾아봤다. 모델은 「이 프로젝트에는 그런 것이 없습니다」 로 답을 맺는다)

뒤   그런 자리가 없습니다: srcs
     한 글자도 안 찾아봤습니다 — 「그런 파일이 없다」 가 아닙니다.
```

Grep 도 같습니다. 폴더 자리에 파일을 주면 그것도 말해 줍니다.

### 빠른 엔진(rg) 길이 잘라 놓고 잘랐다고 안 했습니다

8k 모델에서는 한 번에 여든 줄까지만 싣습니다. 삼백 개 파일이 걸려도 모델은 여든
줄을 받고 **그게 전부라고 믿습니다.** 「전부 고쳤습니다」 가 여기서 나옵니다.
자바스크립트 길과 Glob 은 이 경우를 이미 말해 주고 있었습니다.

## 찾아 놓고 안 주던 자리 둘

### `Recall` 이 찾아낸 대화를 모델에게 한 글자도 안 줬습니다

```
앞   ✓ 지난 대화 12건 중 8건            ← 모델이 받은 것은 이 한 줄뿐
뒤   같은 요약 + 여덟 건의 본문
```

못 찾은 갈래는 앞선 판에서 이미 고쳐 두고 **찾은 갈래**를 그대로 뒀습니다.
못 찾은 것보다 나쁩니다 — 찾았다고 들었는데 내용이 없으면 지어내기 딱 좋은
자리가 됩니다.

### 오류에 딸려 온 글을 버렸습니다

오류와 글이 같이 오는 자리가 셋입니다.

- 끊긴 명령이 죽기 직전에 뱉은 몇 줄
- 시간 초과로 끊긴 명령이 그때까지 찍은 것
- 여덟 개를 서로 다른 까닭으로 다 실패한 `Write`·`Edit` 의 줄별 사유

마지막이 제일 아픕니다. 결과에는 여덟 줄이 다 적혀 있는데 모델은 첫 줄 하나만
받고, 나머지 일곱은 왜 안 됐는지 모른 채 그대로 다시 보냅니다. 이제 오류가 첫
줄이고 글은 그 아래에 옵니다.

## 숫자가 사실이 아니던 자리 아홉

### 천 군데를 고치고 「1군데」 라고 했습니다

고친 군데 수를 **사람이 읽을 요약 글에서 정규식으로 되뽑고** 있었습니다.
그 글은 천 단위에 쉼표가 들어갑니다.

| 실제로 바뀐 곳 | 앞 | 뒤 |
|---|---|---|
| 1,200군데 | `1군데 고쳤습니다` | `1200군데 고쳤습니다` |

### 빈 파일에 한 줄을 붙이면 「전체 2줄」

0바이트 파일이 1줄로 세어졌습니다. `Append` 로 큰 파일을 만드는 것이 이 도구의
쓰임인데, 첫 줄부터 하나가 더 얹히고 그 값이 캐시로 남아 끝까지 따라갔습니다.

### `/context` 의 시스템 칸이 실제보다 작았습니다

시스템 글의 조각을 손으로 나열하다 셋을 빠뜨렸습니다 — 셸 안내, 작은 모델에
붙는 문단, 그리고 **사람이 못 박은 글**.

| | 앞 | 뒤 |
|---|---|---|
| 시스템 칸 | 1,607 | 1,704 |
| 긴 글을 못 박은 뒤 | 1,607 (그대로) | 1,902 |
| 8k 모델의 고정 몫 | `38%` | `42%` |

마지막 줄이 이 항목의 값입니다. 남은 자리가 그만큼 뻥튀기되고, 그 값으로 출력
상한이 잡히므로 **답이 조용히 잘리기 시작합니다.** 이제 진짜 시스템 글을 통째로
재고 따로 줄을 갖는 것만 뺍니다 — 앞으로 무엇이 더 붙어도 저절로 세어집니다.

### 「도구 결과 (파일 0개) 2,150토큰」

세는 것은 모든 도구 결과인데 적는 것은 읽은 **파일** 수였습니다. `Bash` 만 열 번
돌리면 「0개인데 2,150토큰」 이 뜹니다 — 무엇을 접어야 할지 보라고 만든 표가
거꾸로 가리켰습니다.

### 갈래를 바꾸면 쓴 돈이 줄었습니다

`/cost` 는 **지금 갈래** 것만 봤습니다. 갈래를 셋 굴리면 화면의 금액은 그중 하나
몫이고, 닫은 갈래가 태운 토큰은 **아예 사라졌습니다.** 갈래를 지운다고 청구서가
지워지지는 않습니다. 이제 `갈래 전부` 줄을 같이 적습니다.

### 옮긴 파일이 `/commit` 에서 빠졌습니다

파일 하나짜리 `Move` 와 hwpx `Write` 는 바뀐 **경로는 주는데 몇 줄인지는 안**
줍니다. 「몇 줄인지 모른다」 를 「안 바뀌었다」 로 뭉개고 있어서, 파일은 진짜로
옮겨졌는데 `/diff` 목록에 없고 상태줄 `✎` 에도 안 들고 **`/commit` 이 담는 목록
에도 없었습니다.** 커밋은 초록으로 끝나고 옮긴 파일만 안 담깁니다.

### 그 밖에

- 스킬 「전체」 수에 꺼 둔 스킬까지 세었습니다.
- 도구 정의 크기를 못 재면 0 으로 넘기고 **그 0 을 캐시에 굳혔습니다** — 그
  세션에서는 고쳐진 뒤에도 영영 0 입니다. 이제 못 쟀다고 `/status` 가 말합니다.
- 서버가 알려 준 값이 우리 추정과 너무 달라 **못 믿어서 버린 표본**을 세지도
  않았습니다. 「아직 한 번도 못 재 봤다」 와 「재 봤는데 세 배가 나왔다」 가
  화면에서 똑같아졌습니다.
- 보정 배수가 정확히 1.0 이면 「맞춰 본 추정」 이 「그냥 추정」 으로 적혔습니다.

## 다음 요청이 통째로 거절당하던 자리 둘

두 자리 다 **원인이 두 화면 전**이라 사람이 이어 붙일 수 없습니다.

### id 를 안 쓰는 서버(Ollama)의 이력을 이어받으면

짝지을 때는 순서로 봤는데 남길 것을 고를 때는 id 로만 걸렀습니다. id 가 없으니

### 한 번에 도구 둘을 부른 자리에서 대화를 접으면

결과도 두 줄인데 그 사이에서 끊겨 부름 둘에 결과 하나가 남았습니다. 접기가
**요약을 못 받아 물러설 때** 쓰는 길이라, 서버가 흔들릴 때 하필 여기서 대화가
죽습니다.

## 되돌린 뒤에도 남아 있던 것 셋

### 되돌린 일이 다음 접힘에서 되살아났습니다

시킨 말과 남은 할 일은 대화를 접거나 줄일 때 프롬프트에 다시 박히는 것들입니다.
`/undo` 로 되돌린 뒤에도 들고 있으면, **되돌린 그 일**이 첫 접힘에서 되살아나
붙습니다. 모델은 그걸 지금 시킨 것으로 알고 방금 되돌린 일을 다시 하러 갑니다.
`/clear` 는 같은 까닭으로 이미 비우고 있었습니다.

### 없어진 코드에 초록 확인 표시가 남았습니다

상태줄의 `✓5` 는 「돌려 봤고 아무 탈 없었다」 는 뜻입니다. 그 확인은 **그때 그
코드**를 확인한 것인데, `/clear` 로 비운 새 일의 화면에도 `/undo` 로 걷어낸
코드에도 그 초록이 그대로 서 있었습니다. 돈과 바뀐 파일은 안 지웁니다 — 돈은
실제로 썼고 파일은 실제로 바뀐 채입니다.

## 확장자만 그것인 파일을 만들던 자리 셋

없는 파일은 검사가 통째로 없었습니다.

| 부른 것 | 앞 | 뒤 |
|---|---|---|
| `Append('주간보고.hwpx', …)` | `새로 만듦: 주간보고.hwpx (+40줄)` — 한글에서 안 열림 | 거절하고 Write 로 만드는 길을 알려 줌 |
| `Write('로고.png', …)` | `새로 만듦: 로고.png (1줄)` | `로고.png 는 그림 파일 이름입니다 — 글로는 만들 수 없습니다` |
| `Write('어떤폴더', …)` | `EISDIR: illegal operation on a directory, read` | `폴더입니다: 어떤폴더. 파일 이름까지 적어 주세요.` |

## 스위치를 돌렸는데 아무 데도 안 이어져 있던 자리 넷

### `/motion 기사` 가 바꿨다고 말하고 아무것도 안 바꿉니다

`DEEL_NO_MOTION` 을 넣어 둔 자리에서는 무엇을 골라도 한 칸짜리 돌림표가 돕니다.
그건 맞습니다 — 그러라고 있는 환경변수입니다. 문제는 화면이 그 말을 안 한 것입니다.

```
DEEL_NO_MOTION=1 인 채로  /motion 기사

앞   ✓ 기사로 바꿨습니다. — 중세 기사가 칼을 휘두릅니다
        다음 판부터 바로 보입니다. 설정에도 남았습니다.     ← 안 보입니다

뒤   ✓ 기사로 바꿨습니다. — 중세 기사가 칼을 휘두릅니다
        ⚠ DEEL_NO_MOTION 이 켜져 있어 그림은 안 돕니다. 고른 것은 적어
          뒀고, 그 환경변수를 치우면 그때 살아납니다.
```

바로 그 위에서 「사무실을 켰는데 이 터미널이 작아서 안 뜬다」 는 굳이 말해 줍니다.
그 자리에 적어 둔 까닭이 **「켰다고 말해 놓고 안 보이면 그게 고장이다」** 인데,
똑같은 일이 환경변수로 일어날 때는 아무 말도 안 했습니다.

### 안 이기는 환경변수를 「이깁니다」 라고 적었습니다

```
DEEL_MOTION=cat        (오타이거나, 그런 이름이 있는 줄 알았거나)
설정 파일 = 동물

앞   ⚠ 환경변수(DEEL_MOTION·DEEL_OFFICE)가 켜져 있어 그쪽이 이깁니다.
        → 실제로 도는 것은 **동물**입니다. 환경변수는 그냥 무시됐습니다.

뒤   ⚠ DEEL_MOTION 에 적힌 "cat" — 모르는 이름이라 무시했습니다.
          설정에 고른 것이 그대로 쓰입니다.
```

앞엣말을 읽은 사람은 설정을 바꿔도 소용없다고 믿고 손을 뗍니다. 정작 이기고
있는 것은 그 설정입니다.

### `DEEL_NO_MOTION=0` 이 그림을 껐습니다

끄지 말라고 적은 값이 끕니다. 값을 안 읽고 **적혀 있기만 하면** 끄고 있었습니다.

바로 옆의 `DEEL_OFFICE` 는 값을 읽습니다 — `DEEL_OFFICE=0` 은 제대로 꺼집니다.
같은 `.env` 에 둘을 나란히 적으면 하나는 말을 듣고 하나는 반대로 갑니다.
이제 `0` · `false` · `off` · `no` · 빈 값은 「끄지 마라」 로 읽습니다.

### `--tui` 가 아무 데도 안 붙어 있었습니다

`deel --help` 와 자동완성이 「입력 상자를 켠다(force the input box on)」 라고
적어 둔 깃발입니다. 그런데 그 값을 보는 줄이 **켤지 말지를 다 정한 뒤**에
있었고, 그 다음 줄이 무조건 「켠다」 였습니다.

```
앞   if (좁은 창)  안 켠다
     if (CI)      안 켠다
     if (--tui)   켠다     ← 여기까지 왔으면 어차피 켜집니다
     켠다

뒤   if (파이프)   안 켠다   ← 그릴 데가 아예 없습니다. 이건 못 넘습니다
     if (--tui)   켠다     ← 나머지는 「대개 이럴 것」 이라는 짐작입니다
     if (CI)      안 켠다
     if (좁은 창)  안 켠다
     켠다
```

그래서 CI 값이 남아 있는 터미널이나 39칸짜리 창에서 `deel --tui` 를 치면
아무 말 없이 줄 화면이 떴습니다. 켜지는 자리에서는 어차피 켜지고, 안 켜지는
자리에서는 줘도 안 켜지는 — 있으나 마나 한 스위치였습니다.

## 그 밖에

- 하위 작업 구간에 세우는 세로줄(|)이 **빈 줄에서 끊겼습니다.** 도구가 하나
  뜰 때마다 그 앞에 빈 줄이 하나 들어가므로, 「여기부터 저기까지가 떼어 낸
  일」 을 한눈에 보여 주려던 줄이 도구마다 끊긴 점선이 됐습니다.
- 여러 개를 옮기다 하나가 범위 밖이면 **이미 옮겨진 파일이 결과에서 통째로
  사라졌습니다.** 디스크는 움직였는데 턴 끝 목록도 `/commit` 도 「아무 일도
  없었다」 로 알았습니다.
- ESC 로 끊으면 `rm -r dist` 가 이미 끝난 뒤여도 화면과 모델은 「중단했습니다」
  한 줄만 받았습니다. 되돌릴 수 있다는 사실까지 같이 사라졌습니다.
- Ctrl+C 로 끊은 명령이 죽기 직전에 뱉은 몇 줄을 버렸습니다. 그 몇 줄을 실으려고
  적어 둔 코드가 있었는데 **닿을 수 없는 줄**이었습니다.
- 「이건 다시 물어도 답이 같다」 는 표를 도구 열대여섯 자리가 달아 보내는데,
  저장소를 통틀어 **그 값을 읽는 자리가 한 곳도 없었습니다.** 주석은
  「되풀이 억제가 걸린다」 라고 적어 두었습니다.
- `Remember` 가 한 글자도 안 적고도 여느 성공과 똑같이 `✓` 로 보였습니다.
- 짐작한 인코딩을 사실처럼 적었습니다. 읽는 쪽은 「짐작」 을 붙이는데 **되돌려
  쓰는 쪽**이 더 단정했습니다.
- 이어 붙이기가 낡은 인코딩 캐시를 믿어, 남이 UTF-8 로 바꿔 둔 파일 꼬리에
  CP949 바이트를 붙이고 「이어 붙임 · CP949」 라고 답했습니다.
- 30MB 로그에 다섯 줄을 붙이자고 인코딩을 재느라 30MB 를 통째로 다시 읽었습니다.
- 일본어·중국어로 켜면 규칙 끝에 `**Answer in English.** The rules above are in
  Korean…` 이 붙었습니다. 화면은 일본어인데 모델은 영어로 답합니다.

## 1.20.10

**답하지 않았는데 답한 것이 되어 있었습니다**

이번 판에서 고친 스물일곱 자리 가운데 여섯은 한 갈래입니다. **사람이 한 글자도
치지 않았는데, 무언가가 대신 답해 놓은 것.** 그리고 그 답은 화면에 「✓」 로
남습니다.

```
echo "이 폴더 요약해줘" | deel

  ↗ 이 연결은 이 컴퓨터 밖으로 나갑니다.
     보낼 곳 api.example.invalid
  › 나가도 될까요? ⏎ 허락하고 기억 · n 그만 [y] 이 폴더 요약해줘
  허락을 적어 뒀습니다 — 이 프로필은 다음부터 안 묻습니다.
```

시킨 말이 물음의 **답으로 먹혔습니다.** 그래서 모델에게 가지도 않았고,
`online: true` 가 설정 파일에 박혀 그 프로필은 앞으로 영영 안 묻습니다.
이 프로그램이 파는 말이 하나인데(「모르고 나가는 것을 없앤다」) 그것이 파이프
하나로 조용히 꺼져 있었습니다.

---

## 답하지 않은 것을 답으로 읽던 자리 여섯

### 파이프로 켜면 시킨 말이 「나가도 될까요?」 의 답이 됐습니다

| | 전 | 후 |
|---|---|---|
| 화면 | `나가도 될까요? [y] 이 폴더 요약해줘` | `⚠ 파이프로 들어와 있어 물어볼 수가 없습니다` |
| 설정 파일 | `online: true` **영구 저장** | 손대지 않음 |
| 시킨 말 | 답으로 소모돼 모델에 **안 감** | — (나가지 않았으므로 애초에 안 보냄) |

빈 파이프여도 같았습니다. 입력이 끝난 것(EOF)과 사람이 Enter 를 친 것을 안
갈라서, `def` 값 `'y'` 가 답으로 잡혔습니다. 이제 물음마다 「입력이 끝나면
무엇으로 볼지」 를 따로 정합니다 — 이 물음에서는 **거절**입니다.

손으로 켠 판에서 Ctrl+D 를 눌러도 같은 일이 났습니다. 그쪽도 막았습니다.

### 물음이 뜨기 전에 쳐 둔 줄이 승인 답으로 먹혔습니다

일하는 동안 미리 쳐 두는 것은 이 프로그램이 권하는 사용법입니다. 그런데 그
줄이 30초 뒤에 뜬 「실행할까요?」 의 답으로 튀어나왔습니다.

```
전   ⏺ Edit(src/a.js)
     › 실행할까요? (y/n) [y]
     └ 거부됨                     ← 「다음은 테스트도 돌려줘」 가 답이 됐다
                                     그 지시는 큐에서 사라져 영영 안 갔다

후   물음이 뜬 **뒤에** 친 줄만 답으로 받습니다.
     먼저 쳐 둔 것은 그대로 두었다가 턴이 끝나고 처리합니다.
```

Ask 도구에서는 더 나빴습니다 — 「3번 파일도 고쳐줘」 의 앞머리 숫자를 **3번
선택지를 고른 답**으로 읽고, 사람이 고른 것과 똑같은 화면을 그렸습니다.

파이프로 답을 미리 넣는 길(`echo y | deel`)은 그대로 둡니다. 손으로 치는
자리가 없는 판에서는 그것이 유일한 답하는 길이기 때문입니다.

### 잘린 반쪽 계획에 「이대로 진행할까요?」 가 떴습니다

계획 승인 창은 「탈 없이 끝난 턴」 에만 떠야 합니다. 그런데 계획이 반만 나오는
대표 사건 넷이 그 판정에 안 잡혔습니다.

| 무슨 일이 났나 | 전 | 후 |
|---|---|---|
| 출력 상한에서 잘림 | `⚠ 답이 16,384 토큰에서 잘렸습니다` 뒤에 `┌ 계획 … ⏎ 그대로 진행` | 승인 창 없음 |
| 서버가 까닭 없이 멈춤 | 같음 | 승인 창 없음 |
| 걸음 수를 다 씀 | 같음 (게다가 「끊긴 자리에서 이어서」 물음이 아예 안 돌았습니다) | 「이어서 할까요?」 로 갑니다 |
| 모델이 거절 | 계획이 **아예 없는데** 승인 창 | 승인 창 없음 |

창 제목도 넷 다 「끝남」 이었습니다. 이제 「탈남」 입니다.

### 계획 상자가 지난 턴의 남은 할 일을 이번 계획인 척 그렸습니다

할 일 목록은 대화가 사는 동안 같이 삽니다. 비우는 자리가 없었습니다.

```
턴 A   로그인 작업이 걸음 상한에 걸려 안 끝난 할 일 둘이 남는다
턴 B   「결제 모듈 설계하고 만들어줘」 — 모델이 산문으로만 설계를 낸다

전     ┌ 계획
       1. 로그인 폼 만들기      ← 턴 A 의 것
       2. 세션 쿠키             ← 턴 A 의 것
       └ 2단계 · ⏎ 그대로 진행

후     이번 턴에 적은 계획이 없으면 「단계가 따로 적히지 않았습니다」
```

⏎ 를 누르면 그 옛 목록이 「방금 낸 계획」 이라는 이름표를 달고 모델에게
실려 나갔습니다.

### 할 일이 0개인데 「이어서 할까요?」 를 물었습니다

`남은할일 ?? []` 라, 빈 배열도 「이어갈 것이 있다」 로 읽혔습니다. ⏎ 한 번에
이어갈 자리가 없는 채로 모델을 한 판 더 불렀습니다.

### REPL 안에서 쓰면 안 된다고 적혀 있는 물음 함수를 쓰고 있었습니다

사내 로그인 명령을 띄울지 묻는 자리 하나가 옛 길로 남아 있었습니다. 그 파일이
스스로 「REPL 은 readline 이 stdin 을 쥐고 있어서 이걸 그대로 못 쓴다」 고 적어
둔 함수입니다. 셋이 한꺼번에 깨졌습니다.

- 친 `y` 가 readline 에도 들어가 나중에 다른 물음의 답이 됐습니다
- 끝나면서 raw 모드를 꺼서 그 뒤로 ESC·Shift+Tab 이 안 먹었습니다
- 그 자리에서 Ctrl+C 를 누르면 MCP·언어 서버·뒤에서 돌던 명령을 **하나도 안
  거두고** 죽었습니다

## 못 했는데 못 했다고 말하지 않던 자리 열둘

### 바깥 프로필을 처음 붙이면 늘 「서버가 안 알려줍니다」 였습니다

컨텍스트 길이를 서버에 물어보는 자리가 **허락을 받기 전**이었습니다. 우리
문지기가 막으니 언제나 실패했고, 화면에는 서버 탓이 적혔습니다.

```
전   ⚠ 컨텍스트를 서버가 안 알려줍니다 — 우선 32,768 으로 잡았습니다
     (서버는 이 물음을 받아 본 적도 없습니다. 그리고 허락한 뒤에도 다시
      안 물어봐서, 128k 모델을 그 판 내내 32,768 로 알고 씁니다)

후   허락을 받은 **뒤에** 물어봅니다.
     그래도 못 알아내면 까닭을 같이 적습니다 —
       · 이 주소로 나갈 허락이 아직 없어서 물어보지도 못했습니다
       · 서버가 응답은 했지만 길이를 안 알려 줍니다
       · 두드린 자리에서 아무 응답도 못 받았습니다
```

### `--resume` 이 못 읽은 대화를 아무 말 없이 새로 시작했습니다

```
deel --resume 없는대화아이디

전   (아무 줄도 없음 → 곧바로 머리말 → 그 아이디로 새 파일이 만들어짐)
후   ⚠ 없는대화아이디 — 그런 대화가 없거나 비어 있습니다.
       새 대화로 시작합니다. 이어할 것을 찾으려면 /sessions
```

권한이나 다른 프로그램 때문에 못 읽은 경우에는 그 까닭까지 적습니다.

### 허락을 거절하고 나가면 띄운 프로그램이 남았습니다

「나가도 될까요?」 에 `n` 을 치면 정리 블록을 통째로 건너뛰었습니다. MCP 서버는
그 시점에 이미 떠 있습니다 — deel 을 껐는데 남의 프로세스가 계속 돌았습니다.

### 훅이 막았을 때 왜 막았는지 안 보였습니다

화면은 `✗ 훅이 막았습니다 (dlp-check)` 한 줄이었습니다. 사내 정책이 진짜로 막은
것인지, 훅 파일이 없어져 못 돈 것인지 구별할 수 없었습니다. 뒤엣것은 사람이
고칠 수 있는 탈입니다. 이제 까닭을 네 줄까지 같이 적습니다.

### 못 확인한 것이 초록 ✓ 로 떴습니다

상태줄의 `✓` 는 「돌려 봤고 탈이 없다」 는 뜻입니다.

| 실제 | 전 | 후 |
|---|---|---|
| 확인 3 · 못 확인 0 | `✓3` (초록) | `✓3` (초록) |
| 확인 0 · **못 확인 5** | `✓0` (초록) | `✓0 ?5` (노랑) |
| 확인 1 · 탈 2 | `✓1 ✗2` (빨강) | `✓1 ✗2` (빨강) |

거부된 확인도 「돌았다」 로 세고 있었습니다. 이제 안 셉니다.

### 되돌리기 이력을 못 읽어도 옛 숫자가 그대로 떴습니다

상태줄의 `↩ 3` 은 안전망의 잔량입니다. 이력을 못 읽는 상태는 곧 `/undo` 도 못
하는 상태인데, 화면에는 되돌릴 것이 셋 남았다고 떠 있었습니다.

### 오래된 대화 정리 실패를 통째로 삼켰습니다

계속 실패하면 대화 폴더가 끝없이 커지는데 화면에는 영영 안 떴습니다.

### 되묻는 자리가 쌓아 둔 이어쓰기를 말없이 버렸습니다

줄 끝 백틱으로 세 줄을 쌓아 두었는데 그 사이 물음이 뜨면 통째로 사라졌습니다.
Ctrl+C 로 버릴 때는 「이어쓰던 것을 버렸습니다」 를 찍는데 이쪽만 조용했습니다.

### `/ctx`·`/out` 이 엉뚱한 연결에 값을 적었습니다

지금 붙어 있는 연결을 못 찾으면 **첫 번째 프로필**에 적고 「저장했습니다」 를
찍었습니다. 8k 서버 프로필에 655,360 이 박히면 다음에 켤 때 그 값을 믿고
시작해서, 긴 대화에서 서버가 거절합니다.

### 오프라인 잠금이 막은 것을 서버 탓으로 돌렸습니다

`/model` 로 목록을 물을 때, 우리 문지기가 막은 것과 서버가 목록을 안 주는 것이
같은 문장이었습니다. 셋으로 갈랐습니다.

### `/export`·`/evidence` 가 실패 까닭을 버렸습니다

「파일로 못 남겼습니다」 만 뜨면 디스크가 찼는지 폴더가 읽기 전용인지 알 길이
없습니다. 이제 `ENOTDIR`·`EACCES` 같은 까닭을 같이 적습니다.

### 슬래시 명령 하나가 대화를 통째로 끝냈습니다

`.deel` 이 읽기 전용이거나 디스크가 차 있으면 `/memory 어쩌구` 한 줄에 프로세스가
끝났습니다 — 오간 말도, 이어 갈 자리도 같이. 이제 한 줄 적고 대화를 잇습니다.

## 없는 이름을 있는 것으로 읽던 자리 여섯

자바스크립트에서는 모든 표가 `constructor` · `toString` · `valueOf` 를 물려받습니다.
그래서 `표[값]` 으로 「있나?」 를 물으면 **아무도 정한 적 없는 이름에 참**이 됩니다.

| 어디 | 전 | 후 |
|---|---|---|
| `/think 배분 constructor` | `✓ 배분 Object — undefined` 찍고 표 그리다 멈춤 | 배분 목록을 보여 줍니다 |
| `/think 배분 toString` | 그 자리에서 멈춤 | 같음 |
| `deel config explain constructor` | `오류 볼환경.filter is not a function` | `아무 데도 안 적혀 있습니다` |
| 관리 정책 화면 | 정책에 없는 칸이 「관리 정책에 적혀 있습니다」 로 한 줄 | 안 지어냅니다 |
| 모델이 `toString` 도구를 부름 | `t.run is not a function` | `모르는 도구: toString` |
| 도구 줄 글자 | `function Object() { [native code] }` | `⏺` |

앞엣것이 특히 나쁩니다 — **✓ 를 먼저 찍고** 멈춥니다. 사람은 배분을 바꿨다고
믿고, 그 판의 남은 턴이 전부 걸음 예산 계산에서 멈춥니다.

## 화면에 두 번 찍히거나 통째로 쏟아지던 자리 셋

### 줄 끝 백틱으로 이어 쓰면 앞줄이 두 번 찍혔습니다

```
전   ❯ 첫째 줄          ← 칠 때 한 번
     ❯ 첫째 줄          ← 보낼 때 또 한 번
        둘째 줄

후   ❯ 첫째 줄
        둘째 줄
```

### 일하는 중에 붙여넣은 것이 통째로 쏟아졌습니다

기다릴 때 보낸 것은 `[붙여넣기 #1 · 47줄 · 2.1KB]` 로 줄여 남기는데, 도구가 도는
사이에 미리 쳐 둔 것만 원문 그대로 화면에 떨어졌습니다. 터미널보다 넓은 줄이
접히면서 입력 상자의 줄 셈이 어긋나 위쪽 대화를 갉아먹기도 했습니다.

### 사무실에 앉은 하위 작업 수가 실제와 어긋났습니다

하위 작업이 도는 중에 턴이 터지면 세던 값이 안 내려가, 다음 턴의 첫 하위 작업이
둘로 뜨었습니다.

## 1.20.9

**안 보이는 것이 아니라 다른 것이 보이고 있었습니다**

이번 판에서 고친 마흔 자리는 거의 다 한 갈래입니다. **못 하는 것이 아니라,
다른 것을 해 놓고 아무 말도 안 하는 것.**

```
못 읽었다   [이 쪽은 글로 못 읽었습니다 — …]   ← 화면에 뜬다
다른 것     그럴듯한 글이 그냥 나온다            ← 뜰 자리가 없다
```

폼을 채워 저장한 PDF 에서 **채우기 전 값**을 읽었습니다. 컨텍스트를 비웠는데
사무실 하늘은 한밤이었습니다. 짐작한 창 크기가 잰 값처럼 적혔습니다. 미리 쳐 둔
글은 네 줄째부터 아무 데도 안 보였습니다. `/memory 지우기` 는 지우는 대신
`지우기` 라는 낱말을 기억에 적었습니다. 다섯 다 화면에는 아무 탈이 없어 보이는
자리입니다 — 넷은 ✓ 까지 붙어 있었습니다.

## PDF — 다른 것이 읽히던 자리 열셋

### 폼을 채워 저장한 PDF 에서 채우기 전 값을 읽었습니다

PDF 는 고칠 때 파일을 다시 쓰지 않습니다. **고친 객체를 뒤에 덧붙이고** 새
목차가 옛 목차를 가리킵니다. 폼을 채워 저장하거나, 주석을 달거나, 서명하면
실제로 이 꼴이 됩니다 — 옛 내용이 파일 안에 그대로 남아 있습니다.

그 목차를 최신 판부터 거슬러 읽으면서, 이미 정해진 자리를 **옛 판이 덮게** 두고
있었습니다.

```
읽은 것: OLD price 1000
참  값: NEW price 2000
```

지운 문장, 고친 금액, 채운 칸이 되살아납니다. 그리고 글은 멀쩡해 보입니다.

### 글 속에 「3 0 obj」 라고 적힌 문서

PDF 안에서 객체를 찾는 길은 셋입니다 — 파일을 통째로 훑기, 목차(xref) 읽기,
묶음 펼치기. 셋을 다 쓰는 것은 현장의 PDF 가 목차가 틀린 것이 흔해서입니다.

그런데 그 세 길에 각각 구멍이 있었습니다.

| 파일이 이렇게 생겼으면 | 무슨 일이 났나 |
|---|---|
| 머리가 `4 0`+줄바꿈+`obj` | 객체 자리가 한 칸 밀려, 목차까지 틀린 파일이 **통째로** 안 읽혔습니다 |
| 목차 한 줄이 19자 | 둘째 줄부터 어긋나 표를 전부 잃고, 딸린 trailer 까지 놓쳤습니다 |
| 본문에 `3 0 obj` 라는 글자 | 훑기가 그 자리를 객체로 잘못 짚고, 이를 바로잡을 목차는 위에서 잃었습니다 |

두 번째 줄의 값이 특히 비쌉니다. trailer 를 놓치면 **암호가 걸린 PDF 를 암호라고
말하지 못합니다** — 쓰레기 글이 나오거나 빈 글이 나옵니다.

「19자 줄도 맞춰 준다」 고 적힌 코드는 있었습니다. 그 줄은 공백을 만나면 그
자리에서 빠져나가도록 돼 있어서, 한 번도 맞춰 준 적이 없습니다.

### 「A」 대신 「䄀」

글꼴에 딸린 표는 글리프 번호를 유니코드로 되돌립니다. 그 목적지가 두
자리(`<41>`)로 적힌 파일이 있습니다 — 규격 위반이지만 실제로 있습니다.

```
<41>  →  '4100'  →  U+4100  →  「䄀」
바라던 것        →  U+0041  →  「A」
```

빈 자리를 뒤로 메우고 있었습니다. 위반을 만났을 때 없는 한자를 만들어 내는 것과
「A」 를 돌려주는 것 중 무엇이 나은지는 분명합니다.

### 대괄호 안의 글자 셋이 또 하나의 범위가 됐습니다

```
<0020> <0022> [<0041> <0042> <0043>]
                ↑ 이 셋이 다시 「범위」로 읽혔다
```

그래서 코드 0x41·0x42 에 「C」「D」 라는 **없는 매핑**이 생겼습니다. 한글 PDF 는
거의 전부 글리프 번호를 쓰므로, 0x41 은 실제로 어떤 글자입니다 — 그 글자가
엉뚱한 글자로 읽힙니다. 빠진 글자는 보이지만 틀린 글자는 안 보입니다.

### 그림 속 두 글자 때문에 쪽의 남은 글이 사라졌습니다

쪽 안에 박아 넣은 그림은 `BI … ID … EI` 로 싣습니다. 그림 자료는 눌린
바이트라, 그 안에 우연히 `EI` 두 글자가 들어 있을 수 있습니다.

그 자리에서 끊으면 그림 한가운데부터 낱말을 읽기 시작하고, 자료 속의 `(` 를
글자 시작으로 잘못 읽어 **그 쪽에 남은 글을 통째로 삼킵니다.**

```
읽은 것: before
참  값: before / after
```

그러면서 앞부분은 읽혔으니 「못 읽은 쪽」에도 안 들어갑니다.

### 한 줄이 낱말마다 쪼개졌습니다

한 줄 안에서 낱말 하나만 굵게 하려면 그 낱말만 따로 싣는 조판이 흔합니다.
그 끊는 자리를 줄바꿈으로 읽고 있었습니다.

```
Total          Total 1,000,000 won
1,000,000  →
won
```

줄이 바뀌었는지는 조판 덩이가 아니라 **세로로 움직였는지**가 말해 줍니다.

### 그 밖에

* 두 바이트 글꼴에 홀수 길이 글자열이 오면 마지막 한 바이트에 0 을 붙여
  **없는 글리프 번호**를 만들고 있었습니다. 그것이 표에 있으면 글에 없는
  글자가 끼어듭니다. 이제 못 읽은 것으로 세고, 그 쪽을 일부만 읽었다고 적습니다.
* 자원에 그림 칸이 **있기만 해도** 「스캔한 사진일 수 있습니다 — OCR 이
  필요합니다」 라고 적었습니다. 머리말 로고가 위쪽에 물려 있으면 정말 빈 쪽도
  그렇게 적혔습니다. 이제 그리기를 실제로 본 자리가 그것을 말합니다.
* `<0000>` 을 글자로 찍어 글에 NUL 을 섞고 있었습니다.
* 카탈로그를 되찾는 무늬가 속사전 하나에 막혔습니다. 자원을 쪽나무에 물려 둔
  한글 문서에서 이 길로 빠지면 글꼴을 같이 잃고, 화면에는 **「/ToUnicode 표가
  없습니다」** 라고 적혔습니다 — 표는 그대로 있었습니다.
* 이름 안의 `#` 뒤 한 자리만 16진수여도 받아들여, 뒤따라온 구분자까지 삼켰습니다.

## 화면 — 스스로를 갉아먹던 자리 열셋

### 좁은 창에서 화면이 스스로를 갉아먹고 있었습니다

입력 상자는 화면 맨 아래 몇 줄을 붙박아 두고 **그 자리에서만** 다시 그립니다.
위쪽 대화는 안 건드립니다. 그러려면 상자가 「나는 몇 줄짜리다」 를 정확히
알아야 합니다 — 그만큼 커서를 올려야 하니까요.

한 줄이라도 터미널보다 넓으면 그 셈이 무너집니다. 터미널은 그 줄을 두 줄로
접는데 상자는 한 줄로 세고, 그만큼 덜 올라갑니다. 키를 칠 때마다 **위쪽
대화가 한 줄씩 지워집니다.**

넓은 줄이 다섯 군데 있었습니다.

| 어디 | 얼마나 넓나 |
|---|---|
| 상태줄 | 창이 좁으면 덩이 하나가 그대로 넘칩니다 |
| 일하는 중 문구 | 하위 작업 목적·파일 경로가 그대로 들어옵니다 |
| `Enter 를 치면 지금 일이 끝난 뒤에 보냅니다` | 43칸 붙박이 |
| 상자 아래 도움말 | 길이를 정해 두지 않았습니다 |
| 할당량 경고 | 폭 80 에서 101칸 — 상자는 5줄로 세고 터미널은 7줄을 썼습니다 |

### 자르는 자를 고쳤더니 다섯 자리가 같이 나았습니다

넘치는 줄을 자르는 함수가 하나 있습니다. 그 함수가 **색 코드를 글자로 세고
있었습니다.**

색 코드는 화면에서 자리를 안 먹습니다. `\x1b[38;5;245m` 은 열두 글자지만 폭은
0 입니다. 그걸 한 칸씩 세면 두 가지가 한꺼번에 틀립니다.

```
상태줄(색 코드 66개)을 70칸에 맞추면

  옛:  ▏[38;5;245…          ← 보이는 글자 14칸 · 나머지는 색 코드가 먹었다
  새:  ▏⌂ Local · 1.20.8 · ⑂ main…   ← 70칸
```

그리고 자르는 자리가 색 코드 가운데면 `ESC [ 3 8 ; 5 ;` 라는 **명령 토막**이
화면에 남습니다. 터미널은 그걸 명령의 시작으로 보고 뒤따라오는 글자를 먹습니다.
색을 되돌리지 않고 끊으니 그 색이 **아래로 찍는 모든 줄에 번졌습니다.**

이제 색 코드는 통째로 넘기고 폭 0 으로 셉니다. 자른 자리에서 색이 켜져 있으면
되돌립니다.

### 미리 쳐 둔 글이 네 줄째부터 아무 데도 안 보였습니다

로컬 모델은 한 턴이 몇 분입니다. 그동안에도 글을 칠 수 있고, 실제로 받고
있습니다 — 화면에도 보여 줍니다. 세 줄까지만.

그런데 그 세 줄이 **앞에서 세 줄**이었습니다. 사람은 끝에서 치고 있는데
화면에는 처음 세 줄이 붙어 있으니, 네 줄째부터는 친 글자가 아무 데도
안 나타납니다. 커서는 셋째 줄 끝에 서 있습니다.

```
다섯 줄로 접힌 글을 치는 중

           옛 화면        새 화면
보이는 줄   1,2,3          3,4,5
방금 친 것  안 보임        보임
커서        3번째 줄 끝    5번째 줄 끝
가린 표시   없음(❯)        있음(…)
```

다 받고 있는데 키가 안 먹는 것처럼 보였습니다.

### 창 크기를 바꾸면 상자가 두 개가 됐습니다

폭이 바뀌면 터미널이 이미 제 손으로 줄을 다시 접어 놓습니다. 그래서 상자는
들고 있던 수를 다 버리고 **커서 자리에서 아래를 쓸어낸** 뒤 새로 그렸습니다.

커서는 상자 한가운데에 서 있습니다. 그 아래만 쓸어내면 **위쪽 절반이 그대로
남습니다** — 사무실·상태줄·윗테두리가 유령으로 붙어 있고, 새 상자가 그 아래
또 그려집니다. 그 유령은 대화와 함께 위로 밀려 올라가 영영 안 없어집니다.

흉내 화면에 그려서 셌습니다.

```
80 → 100 칸    옛: 윗테두리 2개    새: 1개
80 →  60 칸    옛: 유령 4줄        새: 2줄
```

이제 상자 맨 윗줄까지 올라가서 쓸어냅니다. **그보다 위로는 안 올라갑니다** —
거기는 대화입니다. (좁힐 때 두 줄이 남는 것은 터미널이 다시 접은 만큼입니다.
더 올라가면 대화를 지우게 되므로, 모자라는 쪽으로 잡습니다.)

### 45초가 넘으면 「아직 하는 중」에 붙박였습니다

오래 걸릴 때 문구를 갈아 주는 자리가 있습니다. 뜻은 「아까 하던 말을 계속
돌리면 붙박이처럼 보인다 — 아직 살아 있다는 신호를 줘라」 였습니다.

그 45초를 **턴이 시작된 때**부터 쟀습니다. 로컬 모델은 한 턴이 몇 분이라,
45초가 지난 다음부터는 파일을 읽든 코드를 짜든 명령을 돌리든 화면이 계속
'아직 하는 중' 만 돌았습니다. 이 문구가 스스로 붙박이가 된 것입니다.

```
                    옛 화면          새 화면
50초 → 쓰기 시작     아직 하는 중      코드 짜는 중
70초 → 명령 시작     아직 하는 중      명령 돌리는 중
130초 (명령 60초째)  아직 하는 중      아직 하는 중
```

갈래가 바뀐 때부터 셉니다. 걸린 시간은 그대로 턴 시작부터 셉니다.

### 사무실 하늘이 `/clear` 를 해도 안 밝아졌습니다

사무실 화면의 하늘은 컨텍스트가 얼마나 찼는지를 말합니다. 그런데 그 값을
**여태 쓴 토큰 총량**에서 뽑고 있었습니다. 창에 지금 얼마나 들어 있는지와는
다른 값입니다.

```
상태줄  ▰▰▱▱▱ 18%
하늘    한밤
```

`/clear` 로 창을 비워도 총량은 안 줄어드니 하늘은 그대로 밤이었습니다. 이제
상태줄이 읽는 그 값을 같이 읽습니다 — 한 가지 사실에 한 군데.

### 짐작한 숫자를 잰 것처럼 적고 있었습니다

두 자리에서 화면이 아는 것보다 더 말하고 있었습니다.

```
컨텍스트  5.5k/32k   ← 32k 는 서버가 알려 준 적이 없는, 우리가 짐작한 값
요금      $0.60      ← /cost 는 "못 잰 부름이 있다" 고 말하고 있었다
```

이제 잰 적이 없으면 `32k?`, 못 센 것이 있으면 `$0.60?` 라고 적습니다. 물음표
하나가 「이건 짐작이다」 를 말합니다.

### `--work` 오타가 가장 센 모드로 돌았습니다

`deel --work architcet` 처럼 한 글자만 틀리면, 모르는 이름이 조용히 무시되고
**아무 제한도 없는 기본 모드**로 돌았습니다. 파일을 고치고 명령을 돌릴 수 있는
그 모드입니다. 이제 시작하기 전에 이름을 확인하고, 틀리면 쓸 수 있는 이름을
보여 주고 멈춥니다.

같이 고친 것: 모드 이름에 `constructor` 나 `__proto__` 를 넣으면 하위 작업의
권한을 깎는 자리가 터졌습니다. 계획 모드가 사람만 칠 수 있는 명령을 모델에게
치라고 시키고 있었습니다. 좁은 창에서 쓰는 짧은 지시말이 세 모드에 아예
없었습니다 — 「원래 짧은 것들」 이라고 적혀 있었지만 그 중 하나는 761자였습니다.

## 명령 — 지우려는 말이 다른 일을 하던 자리 열넷

### 지우려고 친 명령이 하나를 더 적었습니다

`/memory 지우기` 는 번호를 안 붙이면 무늬에 안 걸리고 **「이걸 기억해라」** 로
떨어졌습니다. 그래서 `지우기` 라는 낱말이 기억 파일에 적히고, 화면에는
「기억했습니다」 가 떴습니다.

```
치신 것   /memory 지우기
화면      ✓ 기억했습니다 (2줄)
파일      1  사내 문서는 CP949 로 읽는다
          2  지우기            ← 이 줄이 매 요청마다 같이 나갑니다
```

`rm` · `잊어` · `forget` 도 같았습니다. 이제 번호를 물어보고 지울 것을 같이
보여 줍니다.

### 올리려고 친 명령이 가지고 있던 것을 내렸습니다

`/skills on 리뷰` 는 「리뷰에 걸리는 것만 올려라」 입니다. 한 개도 안 걸리면
**전부 내려간 다음** 성공 표시가 떴습니다.

```
✓ "리뷰" 에 걸리는 0개만 올립니다.
```

그다음 모델이 스킬을 못 쓰는 것을 보고 사람은 스킬이 깨진 줄 압니다. 이제 안
걸리면 아무것도 안 건드리고 안 걸린다고 말합니다.

### 화면이 알려 준 명령이 아닌데도 지웠습니다

`/learned 전선` — 화면이 알려 주는 명령은 `/learned 전선 지우기` 인데, 그
짧은 꼴만 쳐도 배운 것이 날아갔습니다. 「전선에서 뭘 배웠나 보자」 는 마음으로
치면 그것이 지우는 명령이었습니다.

`/undo 다섯` 도 같은 갈래입니다. 숫자를 못 읽으면 **말없이 한 턴**을 되돌렸습니다.
되돌리기는 파일을 실제로 되돌리는 명령이라, 잘못 읽은 수로 도는 값이 다른
명령보다 비쌉니다.

### 「바꿨습니다」 라고 하고 다음에 켜면 옛 모델이었습니다

`/model <서버에는 있지만 등록 안 된 모델>` 을 치면 새 프로필로 남깁니다.
그런데 그것을 **「지금 쓰는 것」 으로는 안 박았습니다.**

| 무엇 | 화면 | 참 |
|---|---|---|
| 바꾼 직후 | ✓ 모델을 llama-3-8b 로 바꿨습니다 | 맞습니다 |
| `/model list` | ● 가 옛 모델에 붙어 있습니다 | 설정의 `active` 가 안 바뀌었습니다 |
| 다음에 켤 때 | — | 옛 모델로 열립니다 |
| 그 사이 `/ctx 655360` | ✓ 프로필에 저장했습니다 | **엉뚱한 프로필**에 적힙니다 |

마지막 줄이 제일 비쌉니다. 8k 서버 프로필에 655,360 이 박히면, 다음에 켤 때
그 서버를 655,360 으로 믿고 시작합니다.

### 껐다고 하고 계속 울렸습니다

`/bell off` 는 설정 파일만 고쳤습니다. 울릴지 말지는 켤 때 한 번 읽어 둔 값이
정합니다. 그래서 그 세션 내내 계속 울렸습니다 — 화면은 「이 세션에도 바로
먹습니다」 라고 적으면서.

`/bell on` 은 더 나빴습니다. 그 자리에서 한 번 울려 **켜졌다는 증거까지** 보여
준 다음, 다음 턴부터 안 울렸습니다.

### 회사 창구로는 물어볼 수가 없었습니다

열쇠를 명령으로 받아 오는 프로필(SSO 토큰)이 있습니다. 그 프로필로 다른 모델에게
한 번 물어보거나(`/consult`) 하위 작업을 떼어 줄 때, **열쇠 받는 명령이 안
실렸습니다.**

```
/model 회사창구   →  됩니다
/consult 회사창구 →  401 만 돌아옵니다  ← 까닭이 화면에 없습니다
```

열쇠를 다시 받는 길도 같이 잠깁니다. 그림을 볼 수 있는지도 안 실려서, 볼 수 있는
모델에 하위 작업을 떼어 주면서 못 보는 것으로 쳤습니다.

### 모드 이름에 `constructor` 를 넣으면

앞 판에서 작업 모드의 같은 자리를 고쳤는데, 세 군데가 더 있었습니다. 표에서
이름을 찾을 때 **물려받은 열쇠**까지 걸립니다.

```
/mode constructor   승인 방식이 strict 도 confirm 도 아닌 값이 됩니다
                    → 아무것도 안 물어보는 상태 · 화면은 「엄격 → undefined」
/level constructor  그다음 명령 목록을 그리다 터집니다 — 대화가 끝납니다
/grade constructor  함수 하나를 급으로 삼고 「정했습니다」 를 찍습니다
```

### 오타를 조용히 넘기던 자리

`/work` 는 「그런 모드는 없습니다」 를 먼저 말합니다. 그런데 `/grade 크게` 나
`/think hgih` 는 오류 한 줄 없이 지금 상태 표를 띄웠습니다 — 사람은 정해진
줄로 읽고 그대로 씁니다.

`/think auto 켬` 은 반대로 먹었습니다. `켬` 이 켜는 말 목록에 없어서 **끄는**
명령이 됐고, 화면은 「껐습니다」 라고 적었습니다.

`/commit 전부 버그 수정` 은 둘 다 잃었습니다 — 폴더째 바뀐 파일이 빠지고,
`전부 버그 수정` 이 통째로 커밋 제목이 됐습니다.

## 1.20.8

**못 쟀다는 것을 안 된다고 적고 있었습니다**

연결을 처음 붙일 때 아홉 가지를 물어봅니다. 그 답이 그대로 프로필에 적히고,
그 뒤로 그 연결은 **적힌 대로만 삽니다.** 그래서 이 화면이 틀리면 프로그램이
반쪽이 됩니다.

그런데 세 자리에서 「우리가 못 쟀다」 를 「그 모델이 못 한다」 로 적고
있었습니다.

```
기본 대화   ✗  응답이 비어 있습니다 — 모델 이름을 확인하세요
그림 보기   ⚠  그림을 받긴 했는데 답이 비었습니다 — 안 보이는 것으로 칩니다
추론 강도   ⚠  차이 없음 (낮음 사고 0자/출력 0토큰 · 높음 사고 0자/출력 0토큰)
```

세 줄 다 주소·열쇠·모델 이름이 처음부터 맞은 판입니다.

| 무엇이 있었나 | 여태 적힌 것 | 진짜 |
|---|---|---|
| 사고를 글로 안 주는 추론 모델 | 모델 이름을 확인하세요 | 256토큰을 생각에 다 썼을 뿐 |
| 그림 물음이 32토큰 상한에 걸림 | 안 보이는 것으로 칩니다 | 서버는 그림을 받아 줬다 |
| usage 를 안 주는 게이트웨이 | 조절 차이 없음 | 잴 칸이 없었을 뿐 |

첫 줄이 제일 비쌉니다. 「기본 대화 ✗」 가 되면 **남은 여덟 줄이 전부 건너뛰기**
가 되고, 그 판정이 프로필에 `흘려받기·도구·JSON·생각·그림` **전부 안 됨**으로
남습니다. 사람은 맞는 모델 이름을 몇 번씩 다시 넣어 봅니다.

이제 손에 있는 증거를 봅니다 — **상한에 걸려 끝났나**, **생각 토큰을 썼나**.
그러면 넉넉히 한 번 더 묻습니다.

### 못 쟀을 때는 어느 쪽으로 틀리나

둘 중 하나는 틀릴 수밖에 없는 자리입니다. 틀리는 값이 다릅니다.

```
안 된다고 적으면   볼 수 있는 모델에 그림을 영영 안 보낸다.
                   되돌릴 길이 화면에 없다.
켠 채로 두면       못 하는 서버가 400 으로 말해 주고,
                   그 한 번으로 화면에 까닭이 뜬다.
```

되돌아올 수 있는 쪽으로 틀립니다.

### 우리가 자른 것을 남의 흠으로 적었습니다

도구 호출을 512토큰으로 물어봅니다. 인자 JSON 이 그 안에서 잘리면
**「인자가 부정확, 편집 신뢰성 작업이 더 필요합니다」** 가 보고서에 남았습니다.
모델은 경로를 제대로 쓰고 있었고, 그 원문은 우리 손에 그대로 있었습니다.

### 화면이 「지금 나가는 값 high」 라고 적고 아무것도 안 나갔습니다

`/think` 화면의 그 한 줄은 사람이 **정했다고 믿는 근거**입니다. 그런데 그 줄을
적는 자리가 「이 눈금을 실을 칸이 있나」 를 안 보고 있었습니다.

```
budget (Anthropic 옛 판)   눈금이 아니라 토큰 수가 나간다
think (ollama)             카드 눈금 표를 안 쓴다
생각 없음                  실을 칸이 아예 없다
```

이 세 전선에서 `/think high` 를 치면 화면은 받아 주고 전선에는 아무 눈금도
안 나갔습니다. **안 먹은 설정을 먹었다고 믿는 것이 안 먹은 것보다 나쁩니다.**

이제 몸을 만드는 세 갈래와 화면이 **같은 함수 하나**를 부릅니다 — 한쪽만
고치면 검사가 깨집니다.

### 끝에 빗금 하나를 붙여 적은 사람만 404 였습니다

```
https://…/v1      →  https://…/v1/chat/completions
https://…/v1/     →  https://…/v1//chat/completions   ← 404
```

`//` 는 게이트웨이마다 **다른 길**입니다. 그리고 그 404 는 화면에서 모델
이름을 잘못 적은 것과 구별이 안 됩니다. 물음표가 붙은 주소에서는 이미 빗금을
떼고 있었으니, 같은 주소를 물음표 있고 없고에 따라 다르게 다듬던 셈입니다.

### 배운 것과 짐작한 것이 화면에서 같아 보였습니다

400 을 맞으면 그 문구를 읽어 고치고 디스크에 남깁니다. 그건 **틀릴 수 있는
것**입니다. 그런데 화면은 짐작한 것과 배운 것을 똑같이 보여 줬습니다 —
「이 모델은 생각을 안 한다」 와 「3주 전 400 한 번을 우리가 그렇게 읽었다」 가
구별이 안 됐습니다.

이제 배운 자리를 적습니다.

```
생각 없음 · 캐시 열쇠 · 배움 생각·눈금
```

그리고 되돌릴 길이 **「쌓아 둔 것 전부 비우기」 하나**였습니다. 그러면 몇 주
걸려 쌓은 명령 겪음과 토큰 보정까지 같이 날아갑니다 — 그게 아까워서 사람은
안 비우고, 안 비우니 꺼진 기능을 그냥 안고 씁니다.

```
/learned 전선 지우기      전선에서 배운 것만 비웁니다
```

`/learned` 화면에 전선 줄도 같이 띄웁니다. 쌓인 것 중 제일 크게 작용하는
것인데 그 화면에 아예 안 떴습니다.

### 적어 둔 MCP 서버가 화면 어디에도 안 떴습니다

`mcp.json` 에 다른 도구의 설정을 그대로 붙여넣는 것이 제일 흔한 시작입니다.
거기에는 `"type": "sse"` 나 `url` 만 있는 항목이 섞여 있습니다.

그것을 **말없이 버렸습니다.** 켤 때 뜨는 줄도 `/mcp` 목록도 붙은 것만 세우니,
사람 쪽에서는 목록이 완전해 보입니다. 이 파일이 스스로 「안 뜬 것은 안 떴다고
말한다 — 조용히 빠지면 왜 그 도구가 없지 를 영영 알 수 없다」 고 적어 둔
자리입니다.

### 설정을 안 고쳤는데 매번 서버 하나가 떴습니다

도구 목록을 적어 두고 다음부터는 안 띄웁니다(서버 넷이면 기동이 2초 넘습니다).
그런데 적어 두는 자리가 파일을 **통째로 새로** 썼습니다.

```
1판  가 는 대기 · 나 를 새로 띄움  →  가 의 메모가 날아간다
2판  가 를 띄움 · 나 는 대기       →  나 의 메모가 날아간다
3판  …
```

그 뒤로 **매번 한 대가 반드시 즉시 뜹니다.** 화면에는 ● 하나 ◐ 하나가 떠서,
설정을 안 고쳤는데 왜 매번 남의 프로세스가 뜨는지 알 길이 없습니다.

### 「다르면 그 자리에서 고쳐 적고」 가 없었습니다

정말 띄운 뒤에 목록을 맞춰 봅니다. 다르면 그 사실을 들고 화면이 말합니다.
그런데 **고쳐 적지 않았습니다.** 그래서 옛 목록이 매 실행마다 다시 모델에게
나갔습니다 — 지문이 같고 이레가 안 지났으니 다음 판도 같은 옛것을 씁니다.

그리고 맞춰보기가 **이름만** 봤습니다. 제일 조용한 어긋남은 이름이 그대로인
쪽입니다 — `wiki_search` 가 필수 인자를 하나 더 받기 시작하면, 모델은 그 인자
없이 부르고 서버가 기본값으로 넘어가는 구현이면 **그럴듯한 엉뚱한 결과**가
돌아옵니다. 400 이 나는 것보다 나쁩니다.

### 끝냈다고 목록에 남겨 두고 볼 길을 끊었습니다

죽이라고 시켰는데 안 죽은 프로세스는 목록에 남깁니다 — 「다시 시킬 수 있어야
한다」 는 것이 그 까닭입니다. 그런데 남기기 전에 **파이프를 이미 끊고**
있었습니다. 목록에는 `도는중` 으로 뜨는데 그놈이 뱉는 말은 다시는 안 들어오고,
자식은 다음 쓰기에서 EPIPE 를 맞습니다.

### 끄라고 시켰는데 조용히 읽기만 했습니다

```
Jobs({ job: 1, action: "stop" })
```

`action` 은 우리가 받는 이름이 아닙니다. 그런데 **아는 것과 모르는 것이
섞이면** 그냥 `action` 을 버리고 출력만 읽어 **성공으로** 돌려줬습니다.
끄라고 시킨 모델은 껐다고 여기고 넘어가는데 서버는 그대로 돕니다.

이제 버린 이름을 적어 보냅니다 — 뜻이 거기 있었으면 다음 걸음에서 고쳐 부릅니다.

### 안 버렸는데 앞이 잘렸다고 했습니다

출력이 256KB 를 넘으면 앞을 버립니다. 그런데 버리는 되풀이가 조각이 **둘
이상**일 때만 돌았습니다. 큰 조각이 하나 들어오면 아무것도 안 버리고 「앞이
잘렸습니다」 를 답니다. 모델은 없는 앞을 찾으러 처음부터 다시 읽습니다.

### 인자 없는 도구가 흘려받을 때만 깨졌습니다

인자 자리에 공백 한 칸이 오면 — 한 번에 받으면 「인자 없음」 이고, 흘려받으면
**깨진 부름**이었습니다. 같은 모델, 같은 도구인데 흘려받나 아니냐로 갈렸습니다.

### 할 일 목록이 도구를 둘 부른 판에서만 접혔습니다

대화가 차오르면 오래된 도구 결과를 접습니다. 접힘 문구는 「필요하면 다시
읽으세요」 인데, **할 일 목록은 다시 읽을 파일이 없습니다** — 접는 순간 남은
항목이 어디에도 없어집니다. 그래서 마지막 목록 하나는 안 접기로 해 뒀습니다.

그런데 그 지킴 판정이 **한 메시지의 첫 결과 이름만** 봤습니다. 모델이 한 턴에
`Read` 와 `TodoWrite` 를 같이 부르면 — 흔한 조합입니다 — 그 규격은 결과 둘을
한 메시지에 싣고, 이름이 `Read` 로 잡혀 목록이 지킴에서 빠집니다.

「긴 작업일수록 뒤로 갈수록 시킨 것을 빠뜨린다」 로 제보받은 것의 남은 몫이
여기였습니다.

### 3만 토큰을 아낄 수 있는데도 기다렸습니다

접기는 값이 드는 일입니다. 이력 가운데 글을 바꿔치면 그 자리부터 뒤가 전부 새
글이 되고, 캐시가 거기서 끊깁니다. 그래서 「모아서 한 번에」 로 해 뒀습니다.

그런데 막는 자가 **개수**뿐이라, 아낄 것이 3만 토큰이어도 넷이 안 모이면
기다렸습니다. 미루면 그 다음 안전망은 80% 요약 압축이고, 그쪽은 대화를 통째로
요약으로 갈아 치우는 **훨씬 비싼** 일입니다 — 개수를 기다리다 더 큰 것을
치르는 셈입니다.

이제 값으로 판단합니다.

```
아끼는 것 > 접은 뒤 다시 보낼 것   →  지금 접는다
그 반대                            →  여태처럼 모은다
```

### 「최근 두 장만 남긴다」 면서 넉 장을 남겼습니다

그림은 사람 말 자리에 실려서 따로 뺍니다. 그런데 **장수가 아니라 메시지 수**로
세고 있었습니다.

```
석 장 실린 덩이 + 한 장 실린 덩이   자리가 둘이라 한 장도 안 뺀다
                                     (남는 것은 넉 장, 정해 둔 것은 둘)
```

몇 MB 짜리 사진 셋이 그대로 남습니다. 이제 장수로 셉니다 — 다만 사람이 한 번에
붙인 덩이는 쪼개지 않고, 마지막 덩이는 몇 장이든 남깁니다(방금 보여 준 사진을
그 자리에서 없애면 그 턴이 헛턴입니다).

뺀 장수도 틀리게 돌려주고 있었습니다 — 넉 장을 뺐는데 「1장」 이었습니다.

### 첫 턴부터 「값이 튑니다」 라고 겁줬습니다

접을 때 캐시를 다시 쓰면 값과 지연이 한 번 튑니다. 그래서 그 줄을 화면에
띄웁니다. 그런데 그 판단을 **결정용 함수**로 하고 있었습니다 — 그 함수는 모르는
쪽을 「캐시가 있다」 로 기울이므로(덜 잃는 쪽이라 맞습니다), 캐시가 아예 없는
창구의 첫 턴에도 늘 참이었습니다. 잃을 캐시가 없는데 겁을 준 셈입니다.

결정은 기울여도 되지만 **화면은 아는 것만 적습니다.**

### 물러선 뒤 `/context` 가 없는 파일을 세고 있었습니다

요약을 못 받으면 그냥 줄이는 쪽으로 물러섭니다. 그 자리에서 파일 기억은
비우는데 **읽은 파일 수는 안 내렸습니다.** `/context` 가 그 수로 「도구 결과
N개」 를 적으니, 대화에 없는 파일까지 세어 보여 줬습니다.

### 그 밖에

* 프록시 뒤 `CONNECT` 200 뒤의 빈 답 — 도구 없는 빈 답이 `content: null` 로
  이력에 들어가 다음 요청부터 그 대화가 거절되던 자리를 막았습니다.
* Anthropic 흘려받기가 「usage 를 받았다」 는 표를 안 남겨, 제일 먼저 오는
  소식을 잠잠한지 보는 자가 못 세던 자리.
* 명령이 없어 안 뜬 일감의 종료코드가 `null` 로 덮여 「시그널로 죽었다」 와
  구별이 안 되던 자리.
* `Jobs({ job: "abc" })` 의 오류가 `(받은 것: undefined)` 라고 적던 자리.

## 1.20.7

**서버가 말해 준 것과 반대를 배우고 있었습니다**

이 프로그램은 게이트웨이가 400 으로 거절하면 그 문구를 읽어 **무엇을 보내면
안 되는지 배우고, 배운 것을 디스크에 남깁니다.** 그래야 다음부터 안 틀립니다.

그런데 OpenAI 가 o1·GPT-5 계열에 실제로 내는 문구는 두 이름을 **한 줄에
같이** 적습니다.

```
Unsupported parameter: 'max_tokens' is not supported with this model.
Use 'max_completion_tokens' instead.
```

「`max_completion_tokens` 라는 낱말이 보인다」 는 이유로 **옛 이름으로
갈아타라**고 읽었습니다. 서버가 말한 것과 정반대입니다. 그리고 그 값이
디스크에 남습니다 — 그 창구는 그때부터 **매 턴 400** 이고, 배움 파일을
지우기 전에는 안 낫습니다.

| 서버가 준 문구 | 여태 배운 것 | 이제 배우는 것 |
|---|---|---|
| `'max_tokens' … Use 'max_completion_tokens' instead` | 옛 이름 ✗ | 새 이름 |
| `'max_completion_tokens' … Use 'max_tokens' instead` | 옛 이름 | 옛 이름 |
| `max_tokens … must be used instead` | 옛 이름 ✗ | 새 이름 |

이제 **서버가 쓰라고 한 이름**을 그대로 따릅니다.

### 할당량 이야기를 칸 이야기로 읽었습니다

```
Adaptive rate limit exceeded: request not allowed
```

할당량이 찼다는 말입니다. 그런데 `adaptive` 와 `not allowed` 가 같이 있어서
**「생각 형식을 안 받는구나」** 로 배우고 남겼습니다. 멀쩡한 설정이 꺼진 채
굳습니다.

거절 문구인지만 보지 않고 **칸을 두고 하는 말인지**까지 봅니다. 그리고
Anthropic 전용 형식을 OpenAI 규격 창구에 배우지 않습니다.

### 헤더 이름 하나가 대화 이름을 껐습니다

```
Unrecognized request argument supplied: user-agent
```

`user_agent`(밑줄)는 막아 뒀는데 **`user-agent`(붙임표)는 안 막혀** 있었습니다.
붙임표는 낱말 글자가 아니라 낱말 경계가 걸립니다. 걸리면 「이 창구는 대화
이름을 안 받는구나」 로 배우고 디스크에 남깁니다 — 되던 기능이 그 창구에서
영영 꺼지고, 되돌릴 길이 화면에 안 보입니다.

### 모델 크기 표기를 세대로 읽었습니다

`custom-gpt-50b-chat` 의 `50b` 는 판 번호가 아니라 매개수인데 `gpt-5` 로
읽었습니다. 추론 모델로 보고 `reasoning_effort` 를 실어 보내면 그 턴이
400 입니다. 같은 파일의 다른 갈래는 이미 제대로 보고 있었습니다 — **한
파일 안 두 갈래가 같은 이름을 두고 서로 다르게 판정**하고 있었습니다.

### Claude 에 없는 눈금을 하나 얹었습니다

Bedrock 의 OpenAI 호환 창구에서, 넓게 잡으면 죽는다고 주석까지 적어 놓고
**`minimal` 을 되레 하나 더 얹고** 있었습니다. `minimal` 은 OpenAI 전용
눈금이라 Claude 에 실어 보내면 그 턴이 400 입니다.

### 생각 세기가 조용히 안 나갔습니다

생각 형식을 하나 배우면 딸린 칸도 따라 맞춥니다. 그런데 그 딸린 맞춤이
**「서버가 안 받는다고 했다」 는 표까지 같이** 달았습니다. 그래서 처음
한 번 배운 순간 그 표가 달리고, 그 뒤로는 눈금을 실을 칸이 영영 안 켜집니다.
화면에는 눈금이 그대로 떠 있는데 전선에는 안 나갔습니다.

서버가 직접 거절한 것과 우리가 딸려 맞춘 것을 갈라 셉니다.

### 「생각 없음」인데 눈금 넷을 광고했습니다

`gpt-4o` 전선이 **「생각 없음 · 눈금 minimal·low·medium·high」** 로 떴습니다.
읽는 사람은 눈금을 고를 수 있다고 믿지만 나가는 칸이 아예 없습니다.

### 프록시 뒤에서 답을 찍고도 안 끝났습니다

프록시가 `CONNECT` 에 200 만 주고 입을 다무는 자리(뒷단이 죽은 프록시·
들여다보는 프록시)에서 **터널 소켓이 남았습니다.** 중단은 제때 들어 화면은
멈추는데, 프로세스가 안 끝납니다.

### 프록시를 켠 사람만 영어 원문을 받았습니다

열쇠에 한글·줄바꿈이 섞이면 한국어 안내가 뜹니다. 그런데 프록시를 켜면
다른 길로 나가고, 그 길의 오류 말투를 안 알아봐서 **안내 대신 영어 원문**이
떴습니다. 같은 열쇠, 같은 실수인데 프록시가 있고 없고에 따라 답이 갈렸습니다.

### 쓸 수 있는 인증을 두고 담당자를 찾아가게 했습니다

사내 프록시는 흔히 여러 방식을 한꺼번에 내밉니다.

```
Proxy-Authenticate: Negotiate, Basic realm="corp"
```

앞엣것만 보고 **「이 방식은 지원하지 않습니다 — 담당자에게 문의하세요」** 로
끝냈습니다. 바로 옆에 쓸 수 있는 Basic 이 열려 있는데도 그랬습니다. 이제
`user:pw@` 를 넣을 자리를 알려 주고, Negotiate 는 못 한다고 따로 짚습니다.

### 모델 이름 하나가 진짜 원인을 가렸습니다

게이트웨이가 오류 문장 끝에 모델 이름을 붙여 주는 자리가 있습니다.

```
Unrecognized request argument supplied: stream_options
(Received Model Group=qwen3-235b-a22b-thinking-2507)
```

「`thinking` 이 보인다」 는 이유로 **생각을 껐습니다.** 그러면 두 가지가 같이
일어납니다 — 진짜 원인인 `stream_options` 는 안 껐으니 **같은 400 이 매 턴
다시** 뜨고(화면에는 「배웠습니다」 가 뜹니다), 그러면서 멀쩡한 생각 기능이
딸려 죽어 디스크에 남습니다.

이름을 적어 주는 토막을 먼저 잘라내고, 제일 헐거운 갈래를 맨 뒤로 옮겼습니다.

### 「제일 값진 문장」이 제일 흔한 창구에서 한 번도 안 걸렸습니다

서버가 **받는 값을 세어 주는** 문장은 짐작을 사실로 갈아탈 수 있는 유일한
문장입니다. 그런데 그 갈래가 문장 앞에 칸 이름이 적혀 있어야 걸렸고, 실제
말투가 목록에 없었습니다.

```
Invalid value: 'minimal'. Supported values are: 'none', 'low', 'medium', and 'high'.
```

이 문장이 아래로 굴러떨어져 **「칸을 안 받는다」** 가 됐습니다 — 생각이 통째로
꺼졌습니다. 이제 칸 이름 대신 **세어 준 값이 눈금 말인지**를 봅니다.

### 값 하나가 틀린 것으로 기능을 통째로 껐습니다

받는 말이 둘뿐인 모델(`low`·`high`)에 `medium` 을 보내면 서버는 **값 하나**를
거절합니다. 그걸 「그 칸을 안 받는다」 로 읽어 생각형식을 끄고, 딸린 자리가
눈금까지 비우고, 그게 디스크에 남았습니다. 그 모델에서 `/think` 는 그날부터
아무 일도 안 했습니다.

## 1.20.6

**2차 리뷰가 판을 조용히 잃고 있었습니다**

다른 모델에게 한 번 더 보이는 도구입니다. 빈 손으로 돌아오면 더 짧게 다시
묻게 돼 있는데, **다시 묻는 자리가 까닭을 거의 못 알아봤습니다.**

```
{finish_reason: 'length'}                     알아봄
{error: '…', finish_reason: 'length'}         못 알아봄  ← 자리가 둘만 돼도
{status: 'MAX_TOKENS'}                        못 알아봄
{error: {message: '…token limit'}}            못 알아봄  ← 객체로 오면
{error: 'context_length_exceeded'}            못 알아봄  ← 오픈AI 오류 이름
'a tool required the read_file permission'    못 알아봄  ← 도구가 막힌 판
```

못 알아보면 다시 묻지도 않고 화면에는 「빈 채로 돌아왔습니다」 만 뜹니다.
사람은 그걸 **모델이 지적할 것을 못 찾았다**로 읽습니다.

### 까닭을 이어 붙인 다음에 재고 있었습니다

자리가 여럿이면 한 줄로 이어 붙여 놓고 무늬를 맞췄습니다. 그러면 `^…$`
같은 무늬가 **옆 칸까지 껴안아서**, 자리가 하나 늘 때마다 새로 샙니다.
무늬를 세 번 고쳤는데 세 번 다 옆에서 다시 샜습니다.

이어 붙이길 그만뒀습니다. 칸을 쪼갠 채로 칸마다 잽니다.

### 도구가 막힌 판도 다시 묻습니다

여태는 **길이로 죽은 판만** 다시 물었습니다. 도구가 거절당해 멈춘 판은
「다시 물어도 같은 자리에 막힌다」 고 보고 한 번 부르고 버렸습니다.

재 보니 아니었습니다. 같은 것을 다섯 번 돌리면 길이초과 한 번, 도구거절
한 번이 납니다 — **판마다 나는 것이 아니라 흔들리는 것**이라, 다시 부르면
그만큼 삽니다. 다시 묻는 말도 까닭에 맞춥니다.

### 새로 만든 파일은 리뷰를 한 번도 안 거쳤습니다

`git diff` 는 아직 add 안 한 파일을 한 줄도 안 보여 줍니다. **새 파일이야말로
새 실수가 사는 자리**인데, 거기만 통째로 비어 있었습니다.

### 잘린 답은 빈 답이 아닙니다

답이 왔는데 상태가 나쁜 판을 버리면서 「빈 채로 돌아왔습니다」 라고 적었습니다.
잘린 채로도 발견이 몇 건 들어 있습니다. 이제 잘렸다고 말하고 받은 것은
보여 줍니다.

### 성공률을 재는 자를 넣었습니다

`npm run review2눈금` — 같은 것을 같은 설정으로 N 번 돌려 성공률과 실패
갈래를 냅니다. 여태 한 판씩만 돌려 보고 까닭을 짐작했는데, **재 보니 짐작이
틀렸습니다.** 「세 판을 내리 잃었으니 이 판은 크다」 고 본 것이 실은 3/5
성공이었고, 세 판 연속 실패는 6% 짜리 불운이었습니다.

## 1.20.5

**`aws_access_token` 이 안 잡히고 있었습니다**

1.20.4 가 「마디가 몇이든 받는다」 고 했는데, **붙임표 마디만** 셌습니다.

aws_access_token: 'abcdef123456'    그대로 ← 평문으로 나갔습니다
custom_auth_token: 'abcdef123456'   그대로
```

밑줄로 이은 여러 마디는 **파이썬·테라폼에서 제일 흔한 꼴**입니다. 붙임표든
밑줄이든 마디로 셉니다. 붙임표 뒤 파스칼케이스(`aws-access-Token`)도 같이
빠져 있었습니다.

### 까닭이 글이 아니라 속성으로 올 때

2차 리뷰 도구가 끝맺음의 `error` 한 자리만 봤습니다. 그런데 밑에 깔린 것이

```
{ error: 'finishReason: MAX_TOKENS' }   알아봤습니다
{ finishReason: 'MAX_TOKENS' }          못 알아봤습니다   제미나이
{ finish_reason: 'length' }             못 알아봤습니다   오픈AI 꼴
{ done_reason: 'length' }               못 알아봤습니다   오라마
```

까닭이 적히는 자리를 다 봅니다. **끝맺음을 통째로 글자로 만들지는 않습니다** —
거기엔 모델이 쓴 답도 들어 있어서, 답에 `MAX_TOKENS` 라고 적힌 판을 잘린
것으로 오해합니다. 그 자리도 검사로 못 박아 뒀습니다.

  발견입니다. 다시 물으면 이미 받은 것을 버리게 됩니다.
- **`api-Key:` 가 샌다** — 재 보니 앞자리 `헤더` 갈래가 집습니다.
- **인자 붙은 꾸밈표(`@inject('service')`)가 뭉갠다** — 재 보니 안 뭉갭니다.
  잘린 자리에 괄호가 남아 그 줄이 코드로 읽힙니다.

`A_KEY` · `APIKEY` 는 그대로 봅니다.

몰래칸 선언은 `static #apiKey` 만 멀쩡했는데, 그건 `static` 이 **마침** 코드의

```
class C { accessor #apiKey = config.apiKey; }    가려지고 있었습니다

일곱이 재현됐고, 그중 하나가 **가장 흔한 이름을 통째로 놓치고 있었습니다.**

### 앞머리가 있어야 잡혔습니다

이름 무늬가 `API_KEY` 처럼 **앞에 무언가 붙은 것**만 봤습니다. 그런데 `.env` 에서
제일 흔한 이름이 바로 앞머리 없는 것들입니다.

```
API_KEY=sk-real-1234              가림
PASSWORD="prod_password_1234"     그대로 ← 평문으로 나갔습니다
SECRET=prod_secret_value_12       그대로
TOKEN: abcdef123456               그대로
A_KEY=abcdef123456                그대로 ← 앞머리가 짧아도 안 잡혔습니다
const _apiKey = 'sk-…';           그대로 ← 밑줄로 시작해도
```

`DB_PASSWORD` 는 잡히는데 `PASSWORD` 는 안 잡혔습니다. **앞머리를 요구한 것이
까닭이지 이름 목록이 모자란 것이 아니었습니다.**

### 민 이름으로 받을 때 뺀 셋

재 보고 뺐습니다. 이 저장소 파일 406개에 넣어 보니 이 둘이 걸려 나왔습니다.

```
PWD: '/work'        셸의 현재 폴더입니다. 암호가 아닙니다
id-token: write     깃허브 액션 문법입니다
```

- 소문자 `key` — `key: 값` 은 그냥 짝의 이름일 때가 너무 많습니다.
- `PWD` — 앞머리가 붙은 `DB_PWD` 는 그대로 봅니다.
- 붙임표로 이은 낱말 — 밑줄과 낙타등은 이름씨 관례고, 붙임표는 YAML 짝 이름
  관례입니다. `access_token` · `accessToken` 은 그대로 봅니다.

넓히고 나서 이 저장소에서 새로 가려진 줄은 **다섯**이고 전부 진짜 토큰입니다.

### 몰래칸 선언과 물음표 이음

`#` 을 주석으로만 알아서, 자바스크립트 몰래칸 선언 줄이 통째로 잘렸습니다.
잘린 자리에 코드의 표시가 없어 멀쩡한 선언이 가려졌습니다.

```
class C {
  #apiKey = config.apiKey;     ← 가려지고 있었습니다
}
const API_KEY = config?.apiKey;  ← 물음표 이음도 이름씨로 안 봤습니다
```

뒤에 이름씨 글자가 붙은 `#` 은 몰래칸으로 봅니다 — 점 뒤(`obj.#몰래칸`)든
줄머리든. 줄머리 `#` 을 안 잘라도 설정 줄은 안 상합니다. `# API_KEY: 값` 은
잘라도 안 잘라도 코드의 표시가 없어 어차피 가려집니다.

### 짝이 여러 줄에 걸리면 값이 놓인 줄을 봅니다

이름과 값이 다른 줄에 있으면 **이름 줄**만 보고 있었습니다. 값 줄의 쉼표를
못 보니 멀쩡한 객체 속성이 가려졌습니다.

```
const opts = {
  apiKey:
    config.apiKey,     ← 이 줄이 가려지고 있었습니다
};
```

### 안전망 문서에 가림 설명을 넣었습니다

네 판을 고치는 동안 정작 **무엇을 가리고 무엇을 못 가리는지 적힌 자리가
없었습니다.** `docs/ko/safety.md` 에 「모델로 나가기 전에 가립니다」 를 넣었습니다 —
아는 모양, 설정 줄과 코드 줄을 가르는 방법, 그리고 **못 가르는 자리 표**까지.

### 안 받은 셋

`tuple.0` 은 자바스크립트가 아닙니다. 틀 글자열 안의 따옴표는 재 보니 이미
맞게 셉니다. 무늬 안의 `[^\n]` 을 `[^\r\n]` 로 바꾸라는 것은, 줄을 떼는 자리에서
이미 `\r` 을 가르므로 같은 것을 두 군데 적는 셈입니다.

## 1.20.0

**대문자로 안 적은 열쇠는 그대로 나가고 있었습니다**

1.19.5 가 「따로 재 보고 내겠다」 고 적어 둔 자리입니다. 재 봤고, 냅니다.

### `.env` 만 대문자를 씁니다

비밀 이름을 여태 **대문자로만** 봤습니다. `.env` 는 대문자가 관례라 그것으로
됐는데, 코드와 JSON·YAML 설정은 아닙니다.

```
API_KEY=sk-진짜열쇠-1234        가림
apiKey: 'sk-진짜열쇠-1234'      그대로 ← 평문으로 나갔습니다
api_key: "prod.auth.secret"    그대로
accessToken: 'ya29.abcdefgh'   그대로
```

가운뎃줄 세 개가 설정 파일에서 제일 흔한 꼴입니다.

### 낱말 사이가 끊긴 이름만 봅니다

낙타등(`apiKey`)과 밑줄(`api_key`)로 이은 이름도 봅니다. 다만 **낱말 사이가
끊겨 있어야** 합니다 — `_key` 아니면 `Key`. 그냥 소문자 `key` 로 끝나는 것까지
받으면 이런 것들이 걸립니다.

```
monkey: 'brown-monkey'      안 가림 ✓
hotkey: 'ctrl+shift+s'      안 가림 ✓
turkey: 'roasted12'         안 가림 ✓
```

**재 보고 넓혔습니다.** 이 저장소 파일 348개에 넣어 보니 21줄이 새로 가려졌고
전부 진짜 열쇠였습니다(`apiKey: 'sk-…'` 꼴). 엉뚱하게 가려진 줄은 없었습니다.

치르는 값은 있습니다. `cacheKey` · `rowKey` 처럼 비밀이 아닌 낙타등 이름에
따옴표 값이 붙으면 같이 가려집니다 — 이름만으로는 `cacheKey` 와 `apiKey` 가
안 갈립니다. 줄이 뭉개지는 것이 비밀이 나가는 것보다 낫습니다. 검사로 못
박아 뒀습니다.

### 이름씨는 영문만이 아닙니다

점으로 이은 값이 「코드가 가리키는 이름」 인지 볼 때 영문자만 이름씨로 쳤습니다.
이 저장소 집안 스타일이 한글 이름씨라, **제 코드부터 뭉갰습니다.**

```
const API_KEY = 설정.비밀번호;      가림   ← 코드인데 뭉개졌습니다
const API_KEY = config.apiKey;     그대로
```

글자 갈래로 봅니다. 점 뒤의 `#` 도 이름씨의 한 조각으로 칩니다 —
`obj.#몰래칸` 은 자바스크립트입니다.

### 따옴표 안의 `#` 은 주석이 아닙니다

1.19.4 가 넣은 「줄 뒤 `#` 주석은 떼고 본다」 를 무늬 하나로 하면 둘 중 하나를
고르게 됩니다. 16차 리뷰가 양쪽을 다 짚었습니다.

```
API_KEY=prod.v1.secret#(운영)               빈칸을 요구하면 샙니다
msg = "a # b"; x.API_KEY = config.apiKey;   안 요구하면 뒤쪽 ; 이 잘려 뭉갭니다
```

따옴표를 세면서 걷습니다. **따옴표 밖**의 첫 `#` 부터가 주석입니다. 둘 다
맞습니다.

### `\r` 만 쓰는 글

줄바꿈을 `\n` 으로만 찾으면 `\r` 만 쓰는 글은 파일 통째가 한 줄이 되고,
저 아래 어딘가의 `;` 하나 때문에 그 줄이 코드로 뒤집혔습니다. 줄 끝을
`[\r\n]` 으로 봅니다.

### 안 받은 지적

16차 리뷰가 일곱을 짚었고 넷을 받았습니다. 못 받은 셋은 재 보고 물렸습니다.

- **`// API_KEY=prod.v1.secret` 이 샌다** — 맞습니다. 그런데 이 저장소가
  **`// API_KEY: config.api_key` 는 그대로 두라고** 못 박아 뒀습니다. 주석 안의
  한 줄이 비밀인지 코드인지는 글자로 안 갈립니다.
- **한 줄짜리 파일에서 다 샌다** — 그 한 줄이 실제로 코드입니다. 죄다 코드로
  보는 것이 맞습니다.
- **무늬 자체에 `\r?$` 를 넣어라** — 줄을 떼는 자리에서 이미 `\r` 을 가릅니다.
  같은 것을 두 군데 적으면 한쪽만 고쳐질 때가 더 위험합니다.
