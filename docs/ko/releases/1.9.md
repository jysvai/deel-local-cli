## 1.9.2

**막고 있다고 적어 둔 것들이 실제로는 안 막고 있었습니다**

보안 점검을 한 바퀴 돌렸습니다. 나온 것 중 제일 나빴던 모양은 「고장」이
아니라 **「고장인데 초록」** 이었습니다. 막는 줄을 통째로 지워 봐도 6,110건이
전부 통과하는 자리가 여럿이었습니다.

| 막는다고 적어 둔 것 | 그 줄을 지웠을 때 |
| --- | --- |
| 작업 폴더 밖은 안 만진다 (링크 탈출) | 6,110건 전부 초록 |
| 사내망·`file://` 로 되돌리는 주소는 안 따라간다 | 6,110건 전부 초록 |
| 잘라 읽은 것은 「일부다」라고 알린다 | 6,110건 전부 초록 |
| `Authorization` 값은 가린다 | 71건 전부 초록 |
| 플러그인 묶음은 폴더 밖에 파일을 못 쓴다 | **실제로 못 막고 있었습니다** |

마지막 줄은 검사 문제가 아니라 구멍이었습니다. 남이 만든 플러그인 묶음에
`../../../..` 로 시작하는 이름이 하나 있으면 플러그인 폴더 **밖에** 파일을
씁니다. 받는 쪽이 없는 폴더까지 만들어 가며 나갑니다. 이제 하나라도 밖을
가리키면 묶음째 거절합니다 — 나머지를 깔아 줄 까닭이 없습니다.

`Authorization` 쪽은 왜 안 걸렸는지가 분명했습니다. 재던 예제 값이 둘 다
JWT 라, 헤더 규칙이 죽어도 JWT 규칙이 대신 가려 줬습니다. 그런데 사내
게이트웨이가 주는 Bearer 값은 대개 JWT 가 아닙니다 — **헤더 규칙이 유일한
그물인 자리가 바로 거기**입니다.

**「대화를 잘 기억 못 한다」의 큰 몫을 찾았습니다**

네 가지를 시키고 파일을 열 번 읽은 대화를 만들어 접어 봤습니다. 접기 한 번에
남은 할 일이 통째로 사라집니다.

```
                        고치기 전     고친 뒤
  시킨 말 4번 항목       살아남음     살아남음
  할 일 (3번 미완)     ★ 사라짐       살아남음
  물러선 길의 시킨 말  ★ 안 실림      실림
```

까닭은 접힘 문구에 그대로 적혀 있었습니다 — 「필요하면 다시 읽으세요」.
파일이면 맞는 말입니다. 그런데 **할 일 목록은 다시 읽을 파일이 없습니다.**
접는 순간 남은 항목이 어디에도 없어집니다.

그리고 시킨 말을 못 박는 코드가 **접기가 성공한 길에만** 있었습니다. 정작
자주 밟히는 길은 요약을 못 받아 물러선 쪽인데, 그쪽은 맨 앞 2개만 남깁니다.
세 번째 턴에서 네 가지를 시켰다면 그 네 가지가 통째로 사라집니다.

이제 접든 줄이든 **같은 것**을 박습니다 — 시킨 말 원문과 아직 안 끝난 할 일.
끝난 것은 안 싣습니다. 이 쪽지가 답할 질문은 「무엇이 남았나」 하나입니다.

**화면이 사실대로 말합니다**

- **옮기다 원본만 못 지운 것을 실패라고 했습니다.** 드라이브가 다르면
  복사하고 원본을 지우는데, 그 둘이 한 덩이로 묶여 있었습니다. 원본 폴더의
  파일 하나를 편집기가 잡고 있으면 「못 옮겼습니다」가 뜹니다. 사람은 실패로
  알고 다시 옮기고, **두 벌이 된 걸 아무도 모릅니다.**
- **서버가 끝났다는 말 없이 멈춰도 다 온 답으로 셌습니다.** 중계 프록시가
  몸통을 자르고 연결을 곱게 닫으면 끊긴 티가 안 납니다. 이제 그렇다고
  말합니다 — 상한 얘기가 아니니 `/out` 을 권하지도 않습니다.
- **감사기록을 못 적어도 조용했습니다.** 그러면 `/증거` 가 「아직 바꾸거나
  돌린 것이 없습니다」를 띄웁니다. 안 한 것을 말하라고 만든 화면이 안 한
  것처럼 보이게 하던 자리입니다.
- 끊었을 때 **유닉스에서만** 「중단됨」이 여전히 거짓이었습니다.
- `/undo` 가 못 되돌린 파일까지 세어서 「2개를 되돌렸습니다」라고 했습니다.
- 도구 이름 지문이 4개만 서로 달랐습니다(5,825개가 되어야 할 자리).

검사는 6,061건에서 **6,149건**이 됐습니다. 늘어난 88건은 전부 **변이를 심어
빨개지는 것을 확인한 것**입니다 — 통과 건수만 늘리는 줄은 오히려 둘 지웠습니다.

## 1.9.1

**한글 이름을 쓴 MCP 도구가 모델 눈에 전부 같아 보였습니다**

1.9.0 이 회사 규격에 안 맞는 도구 이름을 고쳐 보내기 시작했습니다. 그런데
못 쓰는 글자를 **글자마다** 밑줄로 바꿨습니다.

```
mcp__사내문서__검색    →  mcp__________
mcp__사내문서__열기    →  mcp__________
mcp__사내문서__지우기  →  mcp___________
```

겹치는 것은 뒤에 번호를 붙여 면했지만, **모델이 보는 이름은 여전히 구별이
안 됐습니다.** 「검색해 줘」 라고 했는데 지우기가 불릴 수 있고, 그건 오류도
안 납니다 — 이 기능이 없애려던 바로 그 고장입니다.

이제 덩어리째 밑줄 하나로 줄이고 지문을 붙입니다. 읽히지는 않아도 서로
다르고, 목록 차례가 바뀌어도 같은 이름이 나옵니다. 무엇을 하는 도구인지는
설명이 그대로 지고 갑니다(`[사내문서] 검색`) — 이름이 못 읽히는 자리에서
뜻을 지는 것은 설명 쪽입니다.

```
mcp__사내문서__검색    →  mcp_0144c0
mcp__사내문서__열기    →  mcp_00mk0u
mcp__사내문서__지우기  →  mcp_01s4l9
```

1.9.0 과 그 밖의 차이는 없습니다.

## 1.9.0

**화면이 읽히고, 회사 API 가 제 말을 알아듣습니다**

1.8 까지 화면에서 제일 안 읽히던 것이 **표**였습니다. 모델은 마크다운 표로
답하는데, 화면에는 작대기가 그대로 나왔습니다.

```
| 파일 | 검사 | 실패 |
|---|---:|---:|
| toolfit.test.js | 49 | 0 |
```

결과 보고를 표로 받는 일이 제일 잦은데, 그 자리가 제일 안 읽혔습니다.

그리고 회사 API 를 직접 붙였을 때 **조절한 것이 실제로는 안 실리는** 자리가
둘 있었습니다. 추론 강도와 도구 규격입니다. 둘 다 화면에는 조절됐다고 뜨는데
전선에는 아무것도 안 실렸습니다 — 아무 일도 안 하는 것보다 나쁩니다. 사람은
조절했다고 믿기 때문입니다.

| | 1.8.0 | 1.9.0 |
|---|---|---|
| 모델이 표로 답하면 | 작대기가 그대로 | 상자로 그립니다 |
| Claude 직통에서 `/think high` | 요청에 아무것도 안 실림 | `thinking` 예산으로 실립니다 |
| Gemini 에 MCP 도구를 주면 | 스키마 하나에 400 | 보내기 직전에 규격에 맞춥니다 |
| 여러 줄 붙여넣기 | 맨 끝 줄만 보임 | 붙인 것이 다 보입니다 |
| 같은 파일을 다시 읽으면 | 통째로 다시 실림 | 바뀐 자리만 |
| `/lang en` 으로 `deel audit` | 한글 서류 | 영어 서류 |

### 표를 표로 그립니다

가름줄의 `:` 을 그대로 지킵니다 — 숫자 칸은 오른쪽으로 섭니다.

```
┌──────────────────┬──────┬──────┬───────────┐
│ 파일             │ 검사 │ 실패 │ 걸린 시간 │
├──────────────────┼──────┼──────┼───────────┤
│ toolfit.test.js  │   49 │    0 │     0.1초 │
├──────────────────┼──────┼──────┼───────────┤
│ packlang.test.js │   36 │    0 │     1.9초 │
└──────────────────┴──────┴──────┴───────────┘
```

한 줄씩 흘려보내면서는 칸을 못 맞춥니다 — 아랫줄이 얼마나 넓을지 모르는 채로
윗줄을 이미 찍어 버리기 때문입니다. 그래서 표가 시작되면 **표가 끝날 때까지
들고 있다가** 한꺼번에 그립니다. 다만 들고 있는 동안 화면이 멈춘 것처럼 보이면
안 되므로, 표가 아닌 것으로 판명되면 바로 흘려보냅니다.

좁은 창에서는 칸이 접힙니다. 접혀도 상자는 안 어긋납니다.

### Claude·Bedrock 에서 추론 강도가 실제로 걸립니다

OpenAI 호환 쪽은 `reasoning_effort: 'high'` 처럼 **말**로 줍니다. Anthropic
규격은 **토큰 수**로 줍니다.

```json
"thinking": { "type": "enabled", "budget_tokens": 6144 }
```

이 자리가 비어 있었습니다. `anthropic몸()` 이 강도를 인자로 받아 놓고 한 번도
안 썼습니다. 그래서 Claude 를 직접 붙이면 상태줄에는 `◇ medium` 이 뜨는데
요청에는 아무것도 안 실렸습니다.

지키는 선이 둘입니다. 둘 다 어기면 요청이 통째로 튕깁니다.

- 최소 1,024. 그보다 작으면 서버가 거절합니다.
- `max_tokens` 보다 작아야 합니다. 생각도 그 예산에서 나갑니다.

그래서 답이 설 자리를 남겨 두고 깎고, 그러고도 1,024 이 안 되면 **생각을 아예
안 켭니다.** 켤 수 없는 자리에서 켜면 그 턴이 죽습니다.

### 회사마다 다른 도구 규격을 보내기 직전에 맞춥니다

도구 목록을 만드는 자리는 어디로 보낼지 모릅니다. 같은 목록이 로컬
llama.cpp 로도 가고 Anthropic 으로도 갑니다. 그래서 **보내는 자리**에서
한 번 다듬습니다.

| 어디로 | 무엇을 |
|---|---|
| Gemini | OpenAPI 부분집합 밖의 열쇠를 뺍니다 (`$schema` · `$ref` · `oneOf` · `additionalProperties` · 모르는 `format`) |
| Anthropic · Bedrock | 인자가 객체가 아니면 객체로 만듭니다 |
| 모두 | 이름을 `[a-zA-Z0-9_-]{1,64}` 로 맞추고, 답이 오면 **원래 이름으로 되돌립니다** |
| 그 밖 | 아무것도 안 건드립니다 |

어디로 가는지는 **주소의 호스트**로만 압니다. 모델 이름으로 짐작하지 않습니다 —
LiteLLM 같은 사내 게이트웨이 뒤에 Claude 가 있어도 우리가 말을 거는 상대는
게이트웨이이고, 그쪽이 제 나름대로 이미 다듬어서 넘깁니다. 모르는 주소면
아무것도 안 건드립니다. 이 프로그램이 제일 많이 서는 자리가 바로 거기입니다.

우리 도구 20개는 어느 회사로 보내도 한 글자도 안 바뀝니다. 실제로 걸리는 것은
**MCP 서버가 준 스키마**입니다 — 남이 만든 스키마에는 `$ref` 와
`additionalProperties` 가 흔하고, 그 하나가 그 턴을 통째로 죽입니다.

이름을 고쳐 보내면 모델은 고친 이름으로 부릅니다. 그대로 위로 올리면 도구가
조용히 안 불립니다 — 오류도 안 나는, 제일 알아내기 어려운 고장입니다. 그래서
다듬은 자리에서 되돌림 표를 같이 들고 있다가 답이 오면 되돌립니다.

### 읽은 파일을 들고 있다가 바뀐 만큼만 싣습니다

고치고 확인하러 다시 읽는 것이 제일 흔한 걸음입니다. 그때마다 파일이 통째로
다시 실렸습니다.

```
읽기 → 고치기 → 다시 읽기      같은 400줄이 두 번 실린다
```

이제 앞에서 읽은 것과 견주어 **바뀐 자리만** 싣습니다. 지키는 선이 셋입니다.

- 줄 번호는 **지금 파일의 번호**로 적습니다. 모델은 이 번호로 Edit 을 겁니다.
- **잘라 읽은 것은 기억하지 않습니다.** 조각을 「그대로입니다」 라고 하면
  모델은 안 본 데를 봤다고 여깁니다.
- 요약해서 접은 뒤에는 **통째로 다시 싣습니다.** 접힌 뒤에는 앞엣것이 대화에
  없습니다.

줄여서 이득이 없으면 안 줄입니다 — 짧은 파일이나 반쯤 갈아엎은 파일은 통째로
싣는 쪽이 짧고 읽기도 쉽습니다.

이제 이름에 크기가 없으면 **서버가 알려 준 창 길이**를 봅니다. 짐작한 것은

### `/lang en` 이면 산출물도 영어로 나옵니다

`deel audit`·`deel sbom`·`deel pack` 은 대화를 안 거칩니다. 그래서 말을 정할
기회가 아예 없었고, **언제나 한국어**로 나왔습니다. 영어로 쓰던 사람이 심사에
낼 서류를 뽑으면 한글 문서가 나왔다는 뜻입니다. 그 서류는 낼 수가 없습니다.

이름까지 같이 옮깁니다. 안이 영어인데 이름이 `반입심사서.txt` 면 받은 사람은
열기 전에 무엇인지 모르고, 메일에 첨부하면 이름이 깨져서 옵니다.

| 한국어 | 영어 |
|---|---|
| `반입심사서.txt` | `import-review.txt` |
| `심사명세.json` | `audit-spec.json` |
| `읽어주세요.txt` | `READ-ME-FIRST.txt` |
| `deel-반입.zip` | `deel-import.zip` |

`sbom.cdx.json` 은 이름이 규격이라 두 말에서 같습니다.

설정 파일도 영어 이름으로 적을 수 있습니다. 설정은 **사람이 손으로 적는 것**
이라, 한글 자판이 없는 사람이 못 적는 이름 하나에 기능이 통째로 막히면 안 됩니다.

```json
"authCommand": { "command": "az account get-access-token …", "ttl": 3600 }
"pricing": { "claude-opus-4-6": { "input": 0, "output": 0, "asOf": "2026-09-01" } }
```

`/think` 화면도 영어로 나옵니다. 여태 이 화면은 통째로 한국어였습니다 —
표의 틀만 영어고 알맹이가 한국어면 아무것도 안 읽힙니다.

### 「중단됨」 이라고 했으면 진짜 멈춥니다

`Bash` 를 그냥 부르면 제한 시간이 지날 때 끊습니다. 그런데 윈도우에서는
**끊긴 것이 화면뿐이었습니다.**

```
Bash(npm run dev)  →  시간 초과로 중단됨 (120000ms)
실제로는           →  서버가 살아서 3000 포트를 물고 있다
```

Node 의 시간 제한은 바로 아래 자식(`cmd.exe`)에게만 시그널을 보냅니다.
손자는 안 건드립니다. 그러면 무엇이 포트를 물고 있는지 알 길이 없는,
이 프로그램이 없애려던 바로 그 상태가 됩니다.

이제 **cmd 가 살아 있는 동안** 나무를 끊습니다. 뿌리가 죽은 뒤에는
`taskkill /pid` 가 「프로세스를 못 찾았습니다」 로 끝나서 다시 부를 수조차
없기 때문에, 순서가 전부입니다.

같은 자리를 하나 더 고쳤습니다. 컴퓨터가 바쁘면 `taskkill` 이 상한에 걸려
잘리는데, 그것을 「이미 죽었다」 와 똑같이 넘기고 있었습니다. 이제 갈라 보고,
다 못 훑었으면 뿌리를 살려 둔 채 다시 훑습니다 — 검사 한 판마다 세 개씩
남던 프로세스가 0 개가 됐습니다.
