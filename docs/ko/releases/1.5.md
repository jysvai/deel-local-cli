## 1.5.8

**5MB 문서를 919줄 중 8줄만 보고 있었습니다**

사내 업무용 HTML 문서를 로컬 모델로 고치라고 시킨 화면입니다.

```
❉ Outline(*.html)      1개 파일 · 22곳
◧ Read(…문서.html)   919줄       ← 열한 번
❊ Grep(제목|쪽나누기|page-break…)   6건

▶ Bash(그림을 빼고 읽으려는 짧은 스크립트)
  └ 막힘 — 작업 범위 밖입니다

⏺ Ask → "이 HTML 에서 어떤 내용을 수정할까요?"
▶ 하위 작업 … 완료  135.9초
```

같은 파일을 열한 번 읽고, 명령이 막히고, 마지막에는 사람에게 되물었습니다.
「roo code 는 같은 로컬 모델로 요구사항 확인해서 바로 조치해 주는데」 —
맞는 지적이었고, 원인은 두 개였습니다.

#### 1. 그 파일은 919줄인데 5MB 였습니다

사내 업무용 HTML 은 그림을 파일 안에 base64 로 박아 넣습니다. 줄
수는 멀쩡한데 **한 줄이 메가바이트**입니다. 도구 결과 상한은 30,000자니까,
실제로 이렇게 됩니다 — 같은 모양으로 만들어 재 봤습니다.

```
919줄 문서 · 8.1MB
→ 모델이 보는 것: 8줄. 그중 99%가 base64.
```

**여덟 줄.** 그러니 열한 번을 읽어도 문서가 어떻게 생겼는지 알 수가 없습니다.
그러고 나서 모델이 한 짓을 보면 딱합니다 — **base64 를 지우는 스크립트를 직접
써서 돌렸습니다.** 그래야 읽힌다는 것을 스스로 알아낸 것입니다. 그런데 그
스크립트마저 막혔습니다(아래 2번). 남은 길이 없으니 되물을 수밖에 없었습니다.

이제 읽을 때 그림 자리를 빼고 보여 줍니다.

```
918   <img src="../data:image/png;base64,…(1.1MB 생략)…">

[박힌 그림 7개(8.0MB)를 빼고 보여 줍니다. 파일은 그대로입니다 —
 생략 표시가 든 줄을 Edit 의 old_string 으로 그대로 쓰면 안 맞습니다.]
```

같은 파일로 다시 재면:

```
8줄 / 919줄   →   614줄 / 919줄
8.1MB         →   44KB
```

**파일은 한 글자도 안 바뀝니다.** 실어 보내는 값만 줄입니다. 그림이 아닌 줄은
한 글자도 안 건드리고, 그림 줄 자체도 그 자리에 남습니다 — 어디에 무엇이
있었는지가 있어야 고칠 수 있습니다. 작은 아이콘(200자 미만)은 그대로 둡니다.

#### 2. 정규식을 경로로 읽고 명령을 막았습니다

```
▶ Bash(자바스크립트가 든 짧은 명령)
  └ 막힘 — 작업 범위 밖입니다: /[\s\S]*?/g     ← 정규식입니다
  └ 막힘 — 작업 범위 밖입니다: /div        ← 여는\/닫는 태그입니다
```

울타리는 명령줄에서 경로처럼 보이는 낱말을 뽑아 범위 밖인지 봅니다. 그런데
거기 오는 것은 셸 명령줄인데 모델은 그 안에 **자바스크립트를 통째로** 넣습니다.
그러면 코드 안의 슬래시가 전부 경로가 됩니다. 앞엣것은 정규식 리터럴이고
뒤엣것은 `</div>` 가 잘려 온 것입니다. 파일과 아무 상관이 없는데 **명령
전체**가 거절됐습니다.

모델은 왜 막혔는지 모르니 따옴표만 바꿔 대여섯 번을 다시 했습니다. 한 요청이
몇 분씩 늘어난 큰 몫이 이것이었습니다.

이제 코드 조각은 경로로 안 읽습니다 — 따옴표가 섞인 낱말, `/` 로 시작하면서
정규식 메타문자가 든 낱말, 빗금만 남은 조각(`/`), 디스크에 없는 한 마디짜리
(`/div`). 넘기는 기준을 좁게 잡았습니다: **실수로 밖을 건드리는 경로는
`/Users/남/것` 처럼 평범하게 생겼지 정규식을 달고 오지 않습니다.** 글로브는
일부러 안 넘깁니다 — `rm /Users/남/*` 은 진짜 경로이고 계속 걸려야 합니다.

밖으로 나가는 것은 그대로 막힙니다. 검사로 못 박아 두었습니다.

#### 붙여넣으면 앞부분이 화면에서 사라졌습니다

「복사하면 왜 뒷부분은 사라지고 앞부분만 나와?」

보낸 값은 멀쩡했습니다. **화면에 남는 것**이 틀렸습니다 — 보낼 때 찍는 것이
마지막 줄뿐이었습니다. 앞줄들은 쌓아 두었다가 이어 붙이는데, 붙여넣기는 쌓는
동안 일부러 안 찍기 때문입니다(스무 줄이 주르륵 지나가지 않게). 그래서 세 줄을
붙이면 화면에는 셋째 줄만 남았고, 사람은 앞부분이 안 갔다고 생각하고 다시
붙여넣었습니다.

이제 보낸 것을 보낸 그대로 남깁니다. 화면에 남는 것과 모델에게 가는 것이 같아야
나중에 스크롤을 올려서 무엇을 시켰는지 알아볼 수 있습니다.

#### 값

검사는 **3,869항목**입니다. 이번 것들은 전부 「그렇게 적혀 있나」가 아니라
**얼마나 보이나**를 잽니다 — 그림이 박힌 919줄 문서에서 모델이 보는 줄 수를
세고, 화면에 찍힌 그 명령을 그대로 넣어 안 막히는지 봅니다. 고치기 전으로
되돌려 놓고 검사가 실제로 빨개지는 것도 확인했습니다.

## 1.5.7

**맥에서 한글 폴더를 쓰면 제 파일이 전부 「범위 밖」이었습니다**

1.5.6 을 쓰신 분이 이런 화면을 보내 주셨습니다.

```
❉ Outline(**/*)
  └ 20개 파일 · 801곳 · 못 읽음 17개

◧ Read(…/자료_ᄎ…)      ← ᄎ  (자모가 따로)
◧ Read(…/자료_챗…)      ← 챗 (한 글자)

❉ Outline(**/*.py)
  └ 작업 범위 밖입니다: /Users/me/.Trash/Archive 오후 3.05.41
```

같은 파일 이름이 **두 가지 모양**으로 찍혀 있고, 뿌리 폴더 자신을 가리키는데도
「범위 밖」이라고 합니다.

#### 무슨 일이었나

맥은 파일 이름을 **자모 분리형(NFD)** 으로 저장합니다. `챗` 이 디스크에는
`ᄎ + ᅢ + ᆺ` 세 글자로 들어가 있습니다. 반면 모델이 글로 쓰는 한글은 합쳐진
모양(NFC)입니다. 눈에는 똑같은데 **문자열로는 다릅니다.**

```
'오후'.length            → 2   (NFC, 모델이 쓴 것)
'오후'.normalize('NFD')  → 4   (맥이 준 것)
```

울타리는 이 둘을 글자로만 견줬습니다. 그래서 한글이 든 폴더에서 deel 을 켜면
**제 작업 폴더 안의 파일이 범위 밖으로 튕겼습니다.** 어느 모양으로 오느냐에
따라 갈려서, 같은 호출이 한 번은 되고 한 번은 안 됐습니다.

그러면 이렇게 됩니다 — 도구가 절반쯤 실패하니 모델은 파일을 못 보고, 못 본
채로는 할 수 있는 일이 없으니 결국 「무엇을 도와드릴까요」로 끝납니다.
지난 판에서 「말을 안 듣는다」고 하신 것의 상당 부분이 이것이었습니다.
모델 잘못이 아니라 **도구가 자기 폴더를 못 열고 있었습니다.**

이제 **견줄 때만** 한 모양으로 맞춥니다. 돌려주는 경로는 원래 것 그대로
둡니다 — 리눅스 파일시스템은 바이트를 그대로 보므로 두 모양이 **다른 파일**이고,
거기서 바꿔 버리면 멀쩡한 파일을 못 찾게 됩니다. 울타리는 그대로입니다:
폴더 밖도, `..` 로 올라가는 것도 여전히 막힙니다.

사내 폴더 이름은 한글이 흔합니다. 여기가 깨지면 그 사람은 프로그램 전체를
못 씁니다.

#### 붙여넣으면 줄마다 한 번씩 물어봤습니다

「줄 이어진 거 복사해서 넣으면 각각 한 줄씩 프롬프트 입력되어서 괜히 과다하게
된다」 — 맞습니다.

터미널은 붙여넣기를 그냥 **타자로** 흘려보냅니다. 줄바꿈마다 readline 이
줄 하나를 완성하므로, 스무 줄을 붙이면 **스무 번 물어본 것**이 됩니다.
한 덩이로 보내려던 글이 스무 조각으로 쪼개지고 요청도 스무 번 나갑니다.
느린 로컬 모델에서는 이게 몇 분입니다.

이제 붙여넣기를 한 덩이로 받습니다.

```
❯ (세 줄을 붙여넣으면)
  3줄을 붙여넣었습니다 — Enter 로 한 번에 보냅니다
```

터미널에게 붙여넣기를 표로 감싸 달라고 하고(`bracketed paste`), 그 표 안의
줄바꿈은 **사람이 Enter 를 친 것이 아니므로** 안 보냅니다. 쌓아 두었다가
사람이 진짜 Enter 를 칠 때 한 덩이로 나갑니다. 쌓는 자리는 줄 끝 백틱이
쓰던 것과 같습니다.

표를 안 보내는 터미널에서는 예전 그대로 돕니다 — 나빠지는 것은 없습니다.

#### ESC 로 멈춥니다

「ESC 누르면 중간에 대화를 멈추게 해줘. Ctrl+Z 하니까 대화 자체를 꺼버려서」

멈추는 길이 `Ctrl+C` 뿐이었는데, 그건 **한 번 더 누르면 프로그램을 끝냅니다.**
급히 멈추려고 두 번 누르면 대화가 통째로 닫힙니다. (`Ctrl+Z` 는 더 나쁩니다 —
셸이 프로세스를 재워서 대화가 끊깁니다.)

`ESC` 는 **멈추기만** 합니다. 끝내지 않고, 치던 글도 안 건드립니다. 도는 중이
아닐 때는 아무 일도 안 합니다. 그래서 마음 놓고 누를 수 있습니다.

#### 스물일곱 개를 읽고 「무엇을 도와드릴까요」로 끝났습니다

이게 이번 판에서 제일 큰 것입니다.

```
❯ 문서 정리해줘

  ☰ TodoWrite(3건)
    ▶ 문서 파일과 실행 구조를 확인한다
    ☐ README 와 PDF 안내 문서를 정리한다
    ☐ 정리된 문서의 링크·내용을 검토한다
  ◧ Read × 스물일곱
  ▌ 무엇을 도와드릴까요? 프로젝트 구조와 실행 방식은 확인했습니다.

  ── 30.9초 · 도구 27회
```

오류가 하나도 없습니다. 걸음 수 상한에도 안 닿았습니다. 그런데 시킨 일은
시작도 안 됐고 바뀐 파일은 없습니다. 다시 「정리해줘」라고 하면 스물일곱 개를
또 읽습니다 — 조사한 것이 매번 버려집니다.

여태 있던 안전장치로는 이 자리가 안 잡힙니다. 걸음 수 상한은 「잘 되고 있는
긴 작업」과 구분을 못 하고, 되풀이 감지는 같은 호출만 봅니다. 모델은 오류
없이, 정중하게, 제 일을 사람에게 되돌려주고 끝낸 것입니다.

이제 **한 번 되밉니다.**

```
  ↺ 읽기만 하고 끝내려고 해서 한 번 되밀었습니다
  ✎ Edit(README.md)
```

세 가지가 다 맞을 때만입니다 — 이번 턴에 바꾼 파일이 하나도 없고, 파일을
바꿀 수 있는 모드이고, 되묻는 말로 끝냈거나 남은 할 일이 있는데 답이 한
줄일 때. 설계·묻기 모드는 안 바꾸는 것이 정상이라 안 밉니다. 다 고쳐 놓고
「더 필요한 것 있으면 말씀해 주세요」로 맺는 것도 안 밉니다.

**한 번뿐입니다.** 밀었는데도 또 물으면 그건 진짜 막힌 것이니, 그 말을
그대로 보여 드립니다. 두 번 밀면 못 하는 일을 두고 실랑이가 됩니다.

#### 되묻기가 이미 하신 말을 되물었습니다

1.5.6 에서 넣은 `Ask` 가 이렇게 나왔습니다.

```
❯ 파일 정리 좀 해주고 파일구조도 각 역할에 맞게 나눠줘
  ⏺ Ask → "1 문서·레거시 파일을 역할별 폴더로 정리하고…"
```

물어볼 것이 아니라 그냥 할 일이었습니다. 되묻기를 넣은 것이 오히려 턴을
잡아먹은 셈입니다. 규칙에 두 줄을 더했습니다 — **이미 시킨 것을 다시 묻지
마라**, 그리고 **도구가 자꾸 실패하면 몇 개가 막혔는지 말해라.** 실패를 삼킨
채 「무엇을 도와드릴까요」로 끝내면 사람은 왜 안 됐는지 영영 모릅니다.

#### 줄바꿈이 상자 안에서 됩니다

Option+Enter 는 되긴 됐습니다. 그런데 이렇게 됐습니다.

```
 ❯ 첫째 줄
   … 다음 줄. 그냥 Enter 로 보냅니다
 ╭────────────────────╮
 │ ❯                  │
 ╰────────────────────╯
```

친 줄이 상자 **위로** 올라가 버립니다. 이미 찍힌 글자라 백스페이스가 안
닿고, 보낼 글이 두 군데로 쪼개져 있어 고칠 수도 없습니다. 「한 번에 보낼
거면 위로 올릴 이유가 뭐냐」 — 맞는 말입니다.

이제 상자가 늘어납니다.

```
 ╭────────────────────╮
 │ ❯ 첫째 줄          │
 │   둘째 줄          │
 ╰────────────────────╯
```

못 하고 있던 이유는 readline 의 이력이었습니다. `rl.line` 에 `\n` 을 넣고
Enter 를 치면 이력이 그 줄을 `\n` 에서 쪼개 거꾸로 쌓고 `\r` 로 도로 붙입니다.
이번에 다시 재 봤습니다(node 24.19).

```
rl.line = 'a\nb'   →  'line' 이 주는 값: "b\ra"
historySize: 0     →  "a\nb"
```

이력을 끌 수는 없습니다 — 위 화살표로 지난 입력을 부르는 것이 훨씬 자주
쓰입니다. 그래서 줄바꿈을 `\n` 이 아닌 **글자 하나로** 들고 있다가, 화면에
그리기 직전과 보내기 직전에만 진짜 줄바꿈으로 폅니다. 이력에게는 그냥 평범한
글자라 쪼갤 거리가 없습니다.

줄 끝 백틱으로 잇는 길은 그대로입니다 — Option+Enter 를 안 보내는 터미널이
아직 있습니다. 어느 키를 보내는지는 `/keys` 로 볼 수 있습니다.

#### 화면 떨림

한 판을 한 번의 `write` 로 보내도 터미널은 받는 대로 그립니다. 그래서 열두
줄이 같이 바뀌는 판에서는 고쳐 그리는 중간 모습이 눈에 들어옵니다 — 잔상과
찢김으로 보입니다.

이제 판 앞뒤에 「다 받은 뒤에 한 번에 보여 달라」는 표를 붙입니다. iTerm2 ·
WezTerm · kitty · Windows Terminal · Ghostty 에서 떨림이 사라집니다. 모르는
터미널은 그냥 무시하므로 잃는 것은 없습니다.

**맥 기본 터미널은 이걸 모릅니다.** 그리고 거기서 사무실이 갈라져 보이는
것도 저희가 못 고칩니다 — 기본 터미널은 줄 간격이 1.0 보다 넓어서 칸과 칸
사이에 빈 띠가 남습니다. 색이 꽉 차야 할 자리에 가로줄이 그어지는 것이 그
모습입니다. 그래서 `/motion 사무실` 을 거기서 켜면 고치는 자리를 알려 드립니다 —
터미널 › 설정 › 프로파일 › 텍스트 › 글꼴 「변경」 › 행간 1.0. iTerm2 가 멀쩡한
것도 같은 이유입니다(거기는 기본이 1.0).

#### 값

고정 몫이 8k 창에서 **3,107 → 3,146** 이 됐습니다(규칙 세 줄). 울타리는
3,150 에서 3,200 으로 옮겼습니다 — 8토큰만 남겨 두면 다음에 낱말 하나만
고쳐도 빨개져서, 울타리가 일을 하는 게 아니라 방해가 됩니다. 되밀기는 규칙이
아니라 **장치**라서 매 요청에 실리는 값이 한 글자도 안 늘었습니다.

검사는 **3,848항목**입니다. 붙여넣기와 줄바꿈은 진짜 deel 을 띄워 터미널이
보내는 바이트를 그대로 흘려 넣고, 모델에게 **몇 번 갔는지**와 상자에 **몇
줄로 그려졌는지**를 셉니다 — 소스에 그렇게 적혀 있나가 아니라요. 예전 방식을
되돌려 놓고 검사가 실제로 빨개지는 것도 확인했습니다.

## 1.5.6

**시킨 일에 맞는 도구가 없었습니다**

한 판에 몰려 나온 여섯 가지입니다. 겉으로는 따로 보이는데, 큰 것 셋은
원인이 같습니다 — **시키는 일에 맞는 길이 아예 없었던 것**이지 모델이
말을 안 들은 게 아니었습니다.

#### 1. 「파일 구조 바꿔 줘」 가 계속 헛돌던 진짜 이유

도구 목록을 다시 세어 봤습니다.

```
Read Write Append Edit Glob Grep Skill Bash WebFetch
Recall Remember TodoWrite Verify Outline Task Jobs Def Refs
```

**파일을 옮기는 도구가 없었습니다.** 그러니 구조를 바꾸는 길은 `Bash mv`
하나뿐이었는데,

- `mv` 는 위험 명령으로 잡혀 있어(`src/safety/guard.js`) 승인 방식에 따라
  **파일 하나 옮길 때마다** 물었습니다. 스무 개면 스무 번입니다.
- Bash 로 옮긴 것은 **되돌리기에 안 잡힙니다.** `/undo` 를 눌러도 구조가
  안 돌아옵니다.

`Move` 를 넣었습니다.

```
Move(moves: [
  { from: "utils.py",  to: "src/core/utils.py" },
  { from: "models.py", to: "src/core/models.py" },
  { from: "ui",        to: "src/view" },
])
```

한 번에 여러 개, 폴더째도 됩니다. 없는 폴더는 만들어 줍니다.

되돌리기가 이 도구의 어려운 부분이었습니다. 되돌리기는 **내용을 떠 놓는**
방식이라, 옮기기를 얹으려면 떠난 자리와 닿을 자리를 **둘 다** 떠야 합니다.
하나만 뜨면 되돌린 뒤 파일이 두 군데 있거나 **한 군데도 없습니다.** 안전망이
파일을 잃는 자리라, 검사 35개 중 여덟이 여기에 붙어 있습니다.

고치다가 되돌리기 자체의 구멍도 하나 나왔습니다. 폴더째 옮긴 뒤 되돌리면
파일을 담을 폴더가 이미 없어서 `writeFileSync` 가 죽고, **되돌릴 내용을
손에 쥔 채로 못 넣고 있었습니다.** 이제 자리를 다시 만들어 줍니다.

막는 것도 못 박았습니다:

| 이럴 때 | 어떻게 |
|---|---|
| 닿을 자리에 이미 있다 | **거절합니다.** 조용히 덮어쓰면 그 파일이 그 자리에서 없어집니다 (`overwrite: true` 로 넘길 수 있습니다) |
| 폴더를 제 안으로 (`mv a a/b`) | 거절합니다. 셸에서도 잘 나는 사고고, 그대로 두면 폴더가 통째로 사라집니다 |
| 작업 폴더 밖으로 | 거절합니다 |
| 여러 개 중 하나가 막혔다 | 나머지는 옮기고 **막힌 것을 결과에 다 적습니다.** 절반만 옮겨진 것을 모르고 지나가는 것이 제일 나쁩니다 |

#### 2. 「수행할 구체적인 작업 요청이 없습니다」

큰 폴더를 「역할에 맞게 구조 바꾸고 env 만들어 줘」라고 시켰더니, 파일을
스무 개쯤 읽고 나서 저 한 줄을 적고 멈췄습니다.

요청은 분명히 있었습니다. 대화 어디에서 사라진 것인지 실제로 재 봤습니다 —
줄이기(`trim`) 세 번, 도구 결과 접기, 나누기를 모두 돌려도 **맨 처음 요청은
그대로 남았습니다.** 목표가 없어진 게 아니었습니다.

모델이 **물어볼 길이 없었던 것**입니다. 갈림길에 섰는데 되물을 방법이 글밖에
없으니 글로 적었고, 글로 적는 순간 턴이 끝났습니다. 사람이 답해도 앞에서 읽은
스무 개는 이미 끝난 턴에 있어서 처음부터 다시 읽습니다.

되묻기를 **도구로** 만들었습니다.

```
  ┌ 물어봅니다
  │ 구조를 어디까지 바꿀까요?
  │
  │ 1 표준 패키지 구조로 전부 재배치
  │ 2 파일 이동은 최소화하고 .env.example 만 추가
  └ 숫자로 고르거나, 그냥 쳐서 답하세요
```

숫자 하나면 끝나고, 답은 **도구 결과로 돌아와 하던 자리에서 이어집니다.**
숫자로 골라도 모델에게는 「2」가 아니라 **그 줄의 글**이 갑니다.

- **모든 모드에서** 물을 수 있습니다. 갈림길은 모드를 안 가립니다.
- 물어볼 사람이 없는 자리(`-p` 한 방 실행 · 파이프 · 하위 작업)에서는
  **안 막히고** 「스스로 판단하고 무엇을 가정했는지 적어라」로 돌아옵니다.
  안 끝나는 것은 틀린 답보다 나쁩니다.
- 도구만 있으면 안 씁니다. 기본 규칙에 「되묻는 것은 도구로도 못 알아낼
  때뿐」이라고 못 박혀 있었는데 **나머지 반쪽이 없었습니다** — 정말 물어야 할
  때 어떻게 물으라는 말이요. 네 판(긴·짧은 × 한국어·영어) 모두에 넣었습니다.

#### 3. 계획을 승인했는데 지난 대화를 뒤지기 시작했습니다

계획이 뜨고 엔터를 눌렀는데, 일을 시작하는 대신 `Recall` 로 지난 대화를 세 번
뒤지고 세 번 못 찾고 끝났습니다.

승인 뒤에 보내던 말이 이랬습니다 — 「**위 계획**을 승인받았다. **적어 둔 단계**를
하나씩 끝내라」. 사람 눈에는 계획이 바로 위에 있으니 말이 됩니다. 그런데 모델에게
이건 **가리키기만 하고 안 주는 말**입니다. 그래서 「적어 둔」 것을 찾으러 나섰고,
찾으러 나선 곳이 지난 대화였습니다.

이제 계획을 **글자 그대로 실어 보냅니다.** 두 번 적는 토큰이 아까워서 안 주고
있었는데, 아낀 것보다 헛도는 값이 훨씬 컸습니다.

#### 4. 창 크기를 바꾸면 사무실이 다다다 늘어났습니다

크기가 지난번과 다르면 상자는 들고 있던 값을 다 버리고 **지금 자리에서 새로**
그렸습니다. 옛 폭에서 센 값으로 커서를 올리면 대화가 지워지기 때문인데,
「낡은 상자가 한 번 위에 남지만 스크롤 자국일 뿐」이라는 셈이었습니다.

**한 번이 아니었습니다.** 창을 마우스로 끌면 터미널은 한 칸마다 새 크기를
알려 줍니다. 끌면서 쉰 번이 오면 상자를 쉰 벌 찍고 하나도 안 지웁니다.
세로로 늘릴 때 특히 심했습니다 — 28줄을 넘는 순간 사무실 열두 줄이 통째로
더 붙기 때문입니다.

나눠서 다룹니다. **접힘은 폭이 정하므로, 폭이 그대로면 들고 있던 수도 맞습니다.**

| 무엇이 바뀌었나 | 어떻게 |
|---|---|
| 높이만 | 평소처럼 **줄 단위로 제대로 지우고** 다시 그립니다 |
| 폭이 | 옛 수는 못 믿으니 **커서 아래를 쓸어냅니다.** 상자는 늘 맨 아래라 그 아래엔 아무것도 없고, 위로는 안 올라가니 대화를 안 건드립니다 |

#### 5. 영어로 시키고 한국어로 받기

여태 말이 하나였습니다. `/lang en` 을 켜면 화면도, 모델에게 주는 글도, 답하는
말도 한꺼번에 영어가 됐습니다. 그래서 「영어로 시키고 한국어로 받기」가 아예
안 됐는데, 그게 실제로 쓸모가 있습니다 — 한글은 글자당 약 1토큰이고 영문은
약 3.6자당 1토큰이라 **값이 눅고**, 작은 모델이 영어 지시를 더 잘 따릅니다.

두 축으로 갈랐습니다.

```
/lang ko en      화면은 한국어, 시키는 말만 영어    ← 답은 한국어로 옵니다
/lang ko auto    다시 하나로
```

8k 창에서 재면 고정 몫이 **3,109 → 2,408 토큰, 23% 줄어듭니다.** 규칙 글도
모드 설명도 도구 설명도 다 영어로 가는데, **답하는 말만 따로 못 박습니다** —
안 박으면 영어 규칙 안의 "Answer the user in English" 가 그대로 먹어서, 값을
아끼려다 못 읽는 답을 받습니다.

#### 6. 줄바꿈 — 되는 자리와 안 되는 자리가 갈려 있었습니다

맥에서 줄바꿈이 안 된다는 말을 몇 판째 듣고도 못 고쳤습니다. 고칠 데를 못
찾은 게 아니라 **무슨 일이 나는지를 몰랐습니다.**

그러다 진짜 결함을 하나 찾았습니다. 백틱 이어쓰기가 **입력을 기다리는
동안에만** 먹었습니다. deel 이 일하는 도중에 미리 쳐 두면 백틱이 그냥 글자로
나갔습니다 — 첫 줄이 백틱을 단 채 혼자 보내지고, 다음 줄은 따로 또 보내집니다.
사람 눈에는 그냥 **줄바꿈이 안 먹는 것**입니다. 미리 치는 것은 원래 일하는
중에 하는 짓이라, 오히려 이쪽이 더 흔한 자리입니다. 고쳤습니다.

그리고 짐작을 그만두려고 `/keys` 를 넣었습니다.

```
/keys
  ┌ 키 확인
  │ 아무 키나 눌러 보세요. 이 터미널이 실제로 보낸 바이트를 그대로 보여 줍니다.
  └ 끝내려면 Ctrl+C 또는 q

  · return     "\e\r"        meta
```

눌러 본 것을 놓고 **이 터미널에서 되는 길**을 알려 줍니다. Enter 를 눌렀는데
`meta` 가 한 번도 안 붙으면 그 터미널은 Option 을 ESC 로 안 보내는 것이고,
그 자리에서는 아무리 눌러도 안 됩니다 — 그때는 백틱 쪽과 터미널 설정을
같이 알려 줍니다. 문서에 「설정을 바꾸세요」라고만 적어 두는 것은 고친 것이
아니었습니다.

#### 그 밖에

- 켤 때 맨 아래에 **별 부탁 한 줄**이 붙습니다. 회색 한 줄이고, 파이프·CI
  기록에는 안 나갑니다 — 거기 섞인 부탁은 그냥 잡음입니다.
- **만들어 놓고 안 돌리는 검사**를 막는 검사를 넣었습니다. `test/run.mjs` 는
  파일을 손으로 적은 목록으로 돌리는데, 새 검사를 목록에 안 넣으면 조용히 한
  번도 안 돌아갑니다. 실제로 그랬습니다 — 되묻기 검사 18항목이 만들어진 채로
  목록에 없어서, 전체 검사는 초록인데 그 18항목은 아무것도 안 지키고 있었습니다.
  안 돌아가는 검사는 없느니만 못합니다. 없으면 없는 줄이라도 아는데, 있으면
  지켜지고 있다고 **믿게** 됩니다.

#### 값

도구가 둘 늘면 **매 요청마다** 스키마가 그만큼 나갑니다. 8k 모델 기준 고정
몫이 **2,764 → 3,107 토큰**으로 343 늘었습니다(창의 34% → 38%). 재 보면
`Ask` 가 134, `Move` 가 193 입니다.

먼저 줄일 수 있는 것을 줄였습니다 — 설명은 **앞에 중요한 것부터** 놓았고
(좁은 창에서는 뒤에서부터 문장째로 잘립니다), `question`·`from`·`to` 는
이름만 봐도 아는 인자라 좁은 창에서 설명을 뺐습니다.

그러고도 남는 343 은 **울타리를 옮겨서** 받았습니다(`test/compact.test.js`).
둘 다 없으면 8k 모델이 못 하게 되는 일이 생깁니다 — 갈림길에서 글로 묻고 턴을
끝내거나(그 창에서 여태 읽은 것이 통째로 버려집니다), 구조를 바꾸려고 `Bash mv`
를 파일마다 부르거나(되돌리기에 안 잡힙니다). 343 을 아끼려고 창 하나를 통째로
잃는 셈이라, 작은 창일수록 오히려 밑지는 거래입니다.

`/lang ko en` 을 쓰면 그 343 이 도로 사라지고도 남습니다.

울타리는 여전히 빡빡합니다(43토큰 남음). 다음에 무엇을 더하든 거기서 한 번 더
멈추게 하려고 그렇게 뒀습니다.

검사는 **3,785항목**입니다.

## 1.5.5

**계획을 세우면 방이 찹니다 — 저마다 다른 박자로**

「사람은 1명으로 고정이냐, 계획이 있어도 한 명만 나온다」는 말을 들었습니다.
고정이 아니라 **버그였습니다.**

#### 1. 사무실에 사람이 늘 한 명뿐이었습니다

무엇을 시키든 자리 하나만 찼습니다. 계획을 세워 할 일이 다섯이어도 그랬습니다.

자리를 「지금 도는 일」로만 셌기 때문입니다. 그 수는 사실상 늘 하나입니다 —
deel 은 한 번에 하나씩 하고, 하위 작업도 앞의 것이 끝나야 다음이 갑니다.
그래서 계획 다섯 개는 화이트보드 쪽지로만 있고 **방은 텅 비어 있었습니다.**

이제 방에 앉는 사람은 이렇습니다:

| 누구 | 무슨 값 |
|---|---|
| 밝은 화면 앞에 앉아 자판을 두드리는 사람 | 지금 도는 일 |
| 흐린 화면 앞에 앉아 있는 사람 | 맡았지만 아직 차례가 안 온 일 (남은 할 일) |
| 방을 돌아다니는 사람 | 자리가 모자라 못 앉은 사람 |

**동시에 도는 것도 제대로 셉니다.** 진짜로 한꺼번에 도는 것은 읽기 도구
묶음입니다 — 파일 셋을 같이 읽는 그것이요. 그 개수는 화면에 「3개를 함께
돌립니다」로 이미 찍히고 있었는데, 방만 그 값을 안 보고 있었습니다. 자세도
지어내지 않습니다: 묶여 도는 것은 읽기 전용뿐이라(Read·Glob·Grep·Skill·WebFetch)
저 자리는 전부 읽는 중인 게 맞습니다. 반면 하위 작업이 무엇을 하는지는 여기까지
안 올라오므로 그 자리는 '대기' 로 둡니다.

한 번 잘못 갔던 길도 적어 둡니다. 처음에는 기다리는 사람의 **화면을 아예 꺼**
뒀습니다. 「다섯이 동시에 도는 것처럼 보이면 거짓말」이라는 이유였는데, 결과는
꺼진 모니터 앞에 넷이 굳어 앉아 있는 방이었습니다. 정직하려다 이 화면을 켠
이유를 죽인 셈입니다. 그래서 **흐린 화면**으로 바꿨습니다 — 구분은 남기고
방은 살립니다.

#### 2. 다들 저마다 다른 박자로 움직입니다

예전에는 온 방이 시계 하나를 같이 봤습니다. 그래서 세 사람이 **한 몸처럼**
동시에 자판을 두드렸습니다 — 사람 셋이 아니라 톱니 셋으로 보입니다.

이제 자리 번호만큼 박자를 밀어 둡니다. 차례를 기다리는 사람은 더 느리게
움직입니다 — 바쁜 사람과 한가한 사람이 같은 박자면 누가 바쁜지 안 보이니까요.

그리고 **셋 이상이면 하나는 일어나 있습니다.** 다 앉아만 있으면 사무실이
아니라 독서실입니다. 사람 수는 그대로고, 그중 하나가 자리에 없을 뿐입니다.
지금 도는 일을 맡은 사람은 늘 자리에 있습니다 — 일하는 중인 사람이 방을
돌아다니면 그게 거짓말이라서요.

판이 바뀔 때 실제로 달라지는 줄은 조용한 방 **0.5줄** · 사람이 꽉 찬 방
**4줄쯤**입니다(12줄 중). 사람 하나가 1픽셀 움직이면 그 자리 세 줄이 통째로
다시 나가기 때문입니다 — 그게 움직임의 값입니다. 숨길 것이 아니라 재서
적어 둘 값이라 검사에도 넣었습니다.

## 1.5.4

**방에 하루가 흐릅니다**

방이 너무 단출했습니다. 창밖은 대낮 아니면 밤 둘뿐이라 컨텍스트 5% 와 50% 가
같은 그림이었고, 벽에는 아무것도 없었습니다.

#### 1. 창밖이 대낮 아니면 밤, 둘뿐이었습니다

창밖이 낮/밤 둘뿐이었습니다. 그래서 컨텍스트 5% 와 50% 가 **똑같은 대낮**
이었습니다 — 열두 줄을 먹으면서 아무 말도 안 하고 있었던 셈입니다.

이제 넷입니다. **아침 → 낮 → 노을 → 밤**, 25% · 55% · 80% 에서 넘어갑니다.
해가 동쪽에서 낮게 떠 한낮에 높이 오고, 서쪽으로 기울었다가 달로 바뀝니다.
노을이 들면 슬슬 접을 때고, 밤이면 이미 늦은 것입니다 — 숫자를 안 읽고
곁눈으로 봐도 그게 보입니다. 방 안 벽과 바닥도 같이 저뭅니다(사람과 책상은
안 어둡게 합니다. 자리를 읽는 것이 이 방을 켠 이유라서요).

같이 들어온 것들:

- **벽시계** — 이번 턴이 얼마나 걸렸나. 한 바퀴가 1분이라, 두 바퀴째면
  「오래 걸리는 중이구나」가 숫자를 세기 전에 옵니다. 창을 놓고 남는 자리가
  있을 때만 겁니다 — 시계 때문에 창이 하나 줄면 그건 손해입니다.
- **식은 커피** — 45초를 넘긴 자리에 놓입니다. 조는 것과 **같은 값**을 한 번 더
  다르게 보인 것입니다. 자는 자세는 화면 뒤로 반쯤 숨어서 좁은 터미널에서는
  조는지 비었는지 헷갈렸는데, 머그는 안 숨습니다.
- **책상 위 종이가 한 자리에 두 장까지** — 전에는 자리마다 한 장이라 다섯
  자리짜리 방에서 다섯 장이 상한이었습니다. 여섯 개를 고치나 스무 개를
  고치나 같은 그림이었습니다.
- **흐르는 구름과 깜빡이는 별** — 이 둘만은 숫자가 아닙니다. 방이 멈춰 있지
  않다는 것만 말합니다. 그래서 아주 느리게 둡니다. 빨리 움직이면 눈이 그쪽으로
  끌려가서, 정작 읽어야 할 자리·쪽지·불빛을 안 보게 됩니다.

「화면에 있는 것은 전부 진짜 숫자」라는 규칙은 그대로입니다. 늘어난 것도 전부
어딘가에서 온 값이고, 모르는 것은 여전히 0 으로 둡니다.

판이 바뀔 때 실제로 달라지는 줄은 12줄 중 평균 0.4줄에서 **0.5줄쯤**으로
늘었습니다. 구름과 별이 움직이는 값입니다.

#### 2. 화면이 둘인데 견주는 자리가 없었습니다

사무실 자리를 고치면서 상자 화면에만 메서드를 하나 달았더니, `--no-tui` 로 도는 계획
승인 흐름이 **통째로 끊겼습니다.** 문법 검사도 통과하고 상자 검사도 통과했습니다 —
두 화면이 같은 말을 알아듣는지 보는 자리가 없었기 때문입니다.

이제 검사가 봅니다. 상자 화면에만 있고 줄 화면에 없는 메서드가 하나라도
생기면 거기서 멈춥니다.

## 1.5.3

**맥에서 써 본 사람이 걸린 것들을 고칩니다**

터진 것은 하나도 없습니다. 전부 **「되는 줄 알았는데 안 되더라」** 쪽입니다 —
안 터지고, 검사도 안 잡고, 화면에서만 어긋나서 오래 남는 종류입니다.

앞의 셋은 맥에서 써 본 사람이 걸린 것이고, 넷째는 그걸 고치다 드러난 것입니다.

#### 1. 맥에서 `Shift+Enter`·`Ctrl+Enter`·`Cmd+Enter` 로 줄바꿈이 안 됐습니다

**앞으로도 안 됩니다.** 못 고치는 것이라 그 이유를 적습니다.

터미널이 프로그램에 보내는 것은 「어느 키를 눌렀나」가 아니라 **바이트**입니다.
그런데 이 셋은 그냥 Enter 와 **바이트가 똑같습니다** — 셋 다 `\r` 한 글자입니다.
프로그램 쪽에서는 구별할 방법이 없습니다. 맥이든 윈도든 리눅스든 같습니다.

`Alt+Enter`(맥에서는 `Option+Enter`)만 다릅니다. 이것은 앞에 `\x1b` 가 붙어서
`\x1b\r` 로 오기 때문에 구별이 됩니다. 그런데 **맥 터미널들은 기본값에서
Option 을 그렇게 안 보냅니다.** Option 을 글자 조합용(´ø∑)으로 쓰기 때문입니다.

그래서 이번 판은:

- 어디서나 되는 길인 **``` ` ```(백틱) 방식을 안내문 맨 앞으로** 옮겼습니다.
  줄 끝에 빈칸+`` ` `` 를 붙이고 Enter 를 치면 다음 줄로 넘어갑니다. 터미널
  설정과 무관하게 됩니다.
- 문서(`docs/ko/interface.md`)에 **Option 을 Meta 로 보내게 하는 설정**을
  터미널별로 적었습니다 — Terminal.app, iTerm2, VS Code. Warp·Ghostty·WezTerm
  은 대개 이미 됩니다.

#### 2. 답이 흘러나오는 동안 사무실이 사라졌습니다

계획표가 뜨거나 모델이 말을 시작하면 아래쪽 사무실 그림이 없어지고, 그 답이
끝날 때까지 안 돌아왔습니다.

글을 한 조각 붙일 때마다 상자를 지우기만 하고 **다시 그리지를 않았습니다.**
답이 30초 동안 흘러나오면 30초 내내 사무실이 없는 셈이었습니다.

이제 한 줄이 끝날 때마다 상자를 다시 그립니다. 답이 흘러나오는 내내 아래에서
사람들이 계속 움직입니다.

한계도 적어 둡니다: **아주 긴 한 줄이 글자 단위로 흘러나오는 동안**에는 여전히
잠깐 안 보입니다. 줄이 끝나야 돌아옵니다. 이걸 완전히 없애려면 터미널의
스크롤 영역(DECSTBM)을 잡아야 하는데, 그러면 위로 밀려난 대화가 스크롤백에
안 남습니다. deel 이 「대화는 터미널에 그냥 흘려보낸다」를 지키는 쪽을
골랐습니다.

#### 3. 기사·동물 버전을 어떻게 켜는지 알 수 없었습니다

환경변수 두 개(`DEEL_MOTION`, `DEEL_OFFICE`)였습니다. 이름을 둘 다 외워야 하고,
바꾸려면 터미널을 껐다 켜야 했습니다. 재미로 넣은 것을 켜는 데 그만한 품이
들면 아무도 안 켭니다.

명령 하나로 합쳤습니다.

```
/motion            지금 뭐가 켜져 있나 + 고를 수 있는 것
/motion 기사        ⚔ 기사와 용
/motion 동물        🐢 거북이와 토끼
/motion 사무실      사람들이 일하는 사무실 (넓은 터미널에서만)
/motion 끔          아무것도 안 돌림
/motion 기본        점 돌림표
```

고르면 **그 자리에서 바뀝니다.** 껐다 켤 필요가 없고, 고른 것은 설정에
남아서 다음에도 그대로입니다.

환경변수도 그대로 삽니다. 한 번만 다르게 보고 싶을 때 쓰라고 남겼고,
**환경변수가 설정을 이깁니다.** 그 상태에서 `/motion` 을 치면 「지금은
환경변수가 이기는 중」이라고 알려 줍니다. 그리고 `/motion` 은 사람이 넣어 둔
`DEEL_NO_MOTION` 을 **지우지 않습니다** — 껐다고 믿는 자리에서 그림이 도는
것이 제일 나쁜 결과라서요.

사무실은 터미널이 좁으면(28줄 미만 또는 60칸 미만) 안 켜집니다. 그럴 때
`/motion 사무실` 을 치면 지금 크기와 필요한 크기를 알려 줍니다.

#### 4. 덤 — 화면 한국어의 조사가 값을 따라갑니다

`/motion` 을 만들다가 「기사 **으로** 바꿨습니다」가 나왔습니다. 값이 그때그때
달라지는 자리에 조사를 글에 박아 둔 탓입니다. 안 터지고, 검사도 안 잡고,
화면에서만 어색해서 오래 남는 종류입니다.

이제 화면 말이 값의 받침을 보고 조사를 고릅니다 — 기사**로** · 기본**으로** ·
동물**로**(ㄹ 받침) · 끔**으로**. 같은 자리에 있던 `/lang` 과 상태줄 곁말도
같이 고쳐졌습니다. 목록 정렬도 글자 수가 아니라 **화면 칸 수**로 맞춥니다 —
한글은 한 글자가 두 칸이라 「사무실」 줄만 밀려 있었습니다.

## 1.5.2

**적대적 리뷰가 남긴 나머지를 전부 정리했습니다**

1.5.1 은 화면을 부수는 것 셋만 급히 뺐습니다. 이번에는 같은 리뷰(Claude ·
codex · agy)가 잡아 둔 나머지를 다 처리합니다. **화면이 거짓말하던 자리**가
대부분입니다 — 안 깨지지만 없는 것을 있다고 하거나, 있는 것을 안 보여 주던
자리들입니다.

#### 1. 문서에 있던 「45초 뒤 존다」가 한 번도 일어난 적이 없었습니다

오래 걸리는 일이면 방 안 사람이 엎드려 존다고 적어 뒀는데, **그 코드에
닿는 길이 없었습니다.** 조는 자세를 고르는 조건이 `일감.갈래 === '느긋'`
인데, 넘어오는 갈래는 `생각`·`답`·`하위`·`접기`·도구이름뿐이라 `느긋` 이
될 수가 없었습니다. 상자 안 돌림표는 자기 자리에서 따로 재고 있었고요.

이제 방이 직접 시계를 봅니다. 45초가 넘으면 실제로 엎드립니다.

부끄러운 것은 검사가 이걸 가려 주고 있었다는 점입니다 — 손으로 만든
`{갈래:'느긋'}` 를 넣어서 통과시키고 있었습니다. 실제로 일어날 수 없는
입력으로 검사를 통과시키면, 그 검사는 아무것도 안 지킵니다.

#### 2. 256색 관문이 죽은 코드였고, `NO_COLOR` 를 무시했습니다

「256색이 안 되는 터미널에서는 안 켭니다」라고 적어 뒀는데, 그 판단이
`TERM !== 'dumb'` 하나였습니다. 그런데 **상자 자체가 이미 `dumb` 를
거부합니다.** 상자 안에서는 늘 참이라 있으나 마나 한 관문이었고, 16색짜리
콘솔에서도 사무실이 켜졌습니다.

그리고 `NO_COLOR=1` 을 아예 안 봤습니다. 색을 끈 사람에게 색이 전부인
화면을 그리고 있었습니다.

이제 **확실할 때만** 켭니다. 모르면 안 켭니다 — 못 켜면 사무실이 안 보일
뿐이지만, 잘못 켜면 색 번호가 글자로 쏟아집니다.

#### 3. 이모지가 반으로 쪼개졌습니다

```
접어쓰기("a😀", 2)  →  ["a\ud83d", "\ude00"]
```

글자를 한 칸씩 세다 보니 😀 처럼 두 칸을 쓰는 글자 **한가운데서** 줄이
접혔습니다. 화면에는 물음표 두 개로 찍히고, 그 뒤로 폭 계산도 어긋납니다.

이제 눈에 보이는 한 덩이를 통째로 떼어 옵니다. 살색 조절(👍🏽)이나 ZWJ 로
이어붙인 것(👨‍👩‍👧)도 안 쪼개집니다.

#### 4. 자가 치유가 시간이 아니라 **타수**로 세고 있었습니다

바뀐 줄만 보내는 방식은 화면이 제가 아는 그대로라고 믿습니다. 그래서 4초에
한 번은 통째로 덮어써서 저절로 낫게 해 뒀는데 — **판 45번**으로 세고
있었습니다.

일이 도는 동안에는 90ms마다 그리니 그게 4초가 맞습니다. 그런데 **놀고 있을
때는 키를 칠 때만 그립니다.** 그때는 4초가 아니라 '45타' 였고, 가만히 두면
깨진 화면이 영영 안 나았습니다. 이제 시계로 셉니다.

#### 5. 창 크기를 바꾸면 화면이 어긋났습니다

창 크기 변화를 보는 자리가 아예 없었습니다. 폭이 바뀌는 순간 터미널은 제 손으로
줄을 다시 접는데, 상자는 옛 폭에서 센 줄 수로 커서를 올립니다 — 엉뚱한 자리에
덮어써서 대화가 지워집니다. 줄 수가 우연히 달라질 때까지 아무도 안 고쳐 줬습니다.

이제 그릴 때마다 지난번 크기와 견주고, 다르면 들고 있던 것을 버립니다.
`resize` 이벤트를 안 쓴 것은 일부러입니다 — 상자마다 리스너를 걸면 걷을 자리가
필요하고(안 걷으면 EventEmitter 경고가 뜹니다), 이벤트가 안 오는 환경도 있습니다.
어차피 손해를 보는 순간은 **다음에 그릴 때**라, 그 자리에서 견주면 충분합니다.

창을 줄인 직후 한 번은 낡은 상자가 위에 남을 수 있습니다. 그건 스크롤로 지나가는
자국일 뿐입니다 — **어디 있는지 모르는 줄을 짐작해서 덮어쓰는 것보다, 안 건드리고
새로 그리는 편이 낫습니다.**

#### 6. 화면이 낮으면 붙박이가 화면 밖으로 넘쳤습니다

사무실을 켜는 기준 28줄은 '사무실 12 + 상자 5' 로 잡은 값인데, 상자는 그것보다
커질 수 있습니다. 긴 글이 여덟 줄로 접히고 추천 목록에 경고까지 붙으면 서른두
줄입니다.

기준을 34로 올리는 길도 있었지만 그러면 평소 멀쩡히 쓰던 분들이 사무실을
잃습니다. 그래서 **그 판만** 사무실을 뺍니다. 자리가 나면 저절로 돌아옵니다.

#### 7. 방 안 숫자가 조용히 포화했습니다

- **할 일**: 쪽지가 다섯 장뿐이라 「열 개 다 끝남」과 「열 개 끝나고 하나 남음」이
  똑같이 초록 다섯 장이었습니다. 남은 일이 화면에서 사라졌습니다. 이제 남은 일이
  하나라도 있으면 노란 쪽지 한 장은 반드시 남깁니다.
- **모델 호출**: 여섯 번과 백 번이 똑같이 다 켜진 불이었습니다. 다 차면 끝 불이
  넘침 색으로 바뀝니다.
- **일하는 자리**: 좁은 화면에서 둘이 도는 것과 셋이 도는 것이 같은 그림이었습니다.
  이제 마지막 자리에 넘침 표시가 붙습니다.

#### 8. 하위 작업 자리가 부모의 자세를 흉내 냈습니다

이 화면의 규칙은 **전부 진짜 숫자**입니다. 그런데 하위 작업 자리에 부모의
자세를 그대로 복사해 놨습니다 — 부모가 자판을 두드리면, 파일을 읽고 있던
하위까지 자판을 두드렸습니다. 자리 수는 진짜인데 자세는 지어낸 것이었습니다.

하위가 지금 무엇을 하는지는 여기까지 안 올라옵니다. 그래서 이제 '대기' 로
앉힙니다. 모르는 것을 그럴듯하게 채우느니 모른다고 두는 편이 낫습니다.

#### 9. `--no-tui` 에서 안 되는 조작법을 알려 줬습니다

머리말이 `Shift+Tab` 과 `Alt+Enter`·백틱 줄바꿈을 안내하는데, 셋 다 상자
안에서만 도는 것입니다. 줄 화면·파이프·CI 에서는 **안 되는 것을 알려 주고**
있었습니다. 이제 상자를 쓸 때만 나옵니다.

#### 10. 재현 안 되는 성능 수치를 뺐습니다

「10 KB/초 → 1.6 KB/초, CPU 0.09%」 라고 적어 뒀는데, 다시 재니 그 숫자가
안 나왔습니다. 터미널 폭과 그때 무엇이 움직이는지에 따라 몇 배씩 달라집니다.

절대 수치를 지우고, 코드가 늘 지키는 것만 남겼습니다 — 판마다 바뀌는 줄은
열둘 중 평균 0.4줄이고, **다 바뀌는 최악의 판에서도 통째로 그리는 것과
바이트가 같습니다.** 견주기가 손해를 볼 자리는 없습니다.

#### 11. 검사를 이음매에서 잽니다

여태 사무실은 따로 떼어 놓고만 쟀습니다. 그래서 1.5.0 의 치명 결함(60칸을
50칸 터미널에 그리기)이 검사를 그냥 통과했습니다 — 그 줄이 **상자에 얹혔을
때** 어떻게 되는지를 아무도 안 봤기 때문입니다.

이제 `프레임()` 을 거쳐서 잽니다. 그리고 상자 검사의 「지운 뒤에도 안 깨진다」도
고쳤습니다. 시작부터 쌓인 출력에서 테두리를 찾고 있어서, 지금 화면에서 테두리가
통째로 사라져도 통과하던 절이었습니다. 이제 자가 치유가 도는 그 단계의 출력에서
직접 봅니다.

## 1.5.1

**1.5.0 이 넣은 것 두 개가 망가진 채 나갔습니다. 그것을 고칩니다**

1.5.0 을 내보낸 뒤 적대적 리뷰를 세 개(Claude · codex · agy) 돌렸습니다.
셋 다 같은 코드를 의심했는데 원인은 셋 다 못 짚었습니다. 검사가 하나도
없었기 때문입니다 — 화면에 **그려지는 모습**만 보면 둘 다 멀쩡했습니다.

#### 1. `Alt+Enter` 로 쓴 여러 줄이 뒤집혀서 갔습니다

`안녕` → Alt+Enter → `반가워` 를 치면 모델이 받는 값은 `반가워\r안녕`
이었습니다. 세 줄이면 완전히 역순이 됩니다.

> 나중에 안 것을 덧붙입니다: 이 뒤집힘은 **Node 24 이상에서만** 납니다.
> Node 20·22 에서는 그대로 갔습니다. 그래도 고친 것은 맞습니다 — deel 은
> Node 20 이상을 받으므로, 어느 판에서 도느냐에 따라 줄 순서가 달라지면
> 안 됩니다.

상자 안에 그려지는 글은 내내 맞았습니다. 어긋난 곳은 보내는 순간이었습니다 —
`rl.line` 안에 넣어 둔 개행을 readline 의 history 가 쪼개서 거꾸로 쌓고
`\r` 로 다시 붙여 돌려줬습니다.

고친 방법은 개행을 `rl.line` 밖에서만 다루는 것입니다. 줄 끝 백틱이 이미
그렇게 하고 있었으므로 `Alt+Enter` 도 같은 자리를 쓰게 했습니다.

#### 2. 줄 끝 백틱이 평범한 요청을 삼켰습니다

```
read `config.json`     보내지지 않고 이어쓰기 모드에 갇힘
echo `date`            닫는 백틱이 뜯김
이 파일 고쳐줘 `a.js`     보내지지 않음
```

백틱 하나로 끝나기만 하면 이어쓰기로 봤습니다. 그런데 코딩 도구에서
인라인 코드로 끝나는 줄은 아주 흔합니다. 사람 눈에는 **Enter 가 안 먹는
것**으로 보였습니다.

이제 **백틱 앞이 빈칸이고, 그 줄에 백틱이 그것 하나뿐일 때만** 이어쓰기로
봅니다. 인라인 코드는 백틱이 둘이라 안 걸립니다.

그리고 **Ctrl+C 로 이어쓰기를 버릴 수 있게** 했습니다. 전에는 취소할 길이
아예 없어서, 표를 붙여 놓고 마음이 바뀌면 다음에 치는 것이 무엇이든 앞줄에
붙어 나갔습니다 — `/help` 같은 명령까지 앞줄에 붙는 순간 `/` 로 시작하지
않게 되어 명령으로 안 읽히고 모델에게 넘어갔습니다.

#### 3. 사무실이 좁은 터미널에서 화면을 지웠습니다

방은 늘 60칸을 씁니다. 그런데 켤지 말지를 정할 때 **줄 수만 보고 칸 수는
안 봤습니다.** 50칸 터미널에서 켜면 열두 줄이 스물네 줄로 접히는데 상자는
열둘로 세고 그만큼만 커서를 올립니다. 어긋난 자리에 다음 판을 덮어쓰니,
50×40 에서 200판을 돌리면 테두리도 대화도 남지 않았습니다.

이제 **60칸보다 좁으면 안 켭니다.** 화면 크기를 모를 때도 안 켭니다.

부끄러운 것은 검사가 이 넘침을 *정상*이라고 통과시키고 있었다는 점입니다 —
「아주 좁아도 안 터진다」는 이름으로요. 그 검사를 뒤집어서, 이제는 어떤 줄도
터미널보다 넓지 않다는 것을 잽니다.

#### 4. 없던 검사를 넣었습니다

이 결함들이 리뷰 셋을 다 통과한 이유가 검사가 없어서였습니다. `newline.test.js`
를 새로 뒀습니다. **그려지는 모습이 아니라 보내지는 값**을 잽니다. 예전 방식이
왜 틀렸는지도 함께 못 박아 뒀습니다 — 누가 `rl.line` 에 개행을 다시 넣으면
그 자리에서 걸립니다.

## 1.5.0

**줄바꿈이 생겼고, 화면이 재미있어졌고, 그러면서 오히려 가벼워졌습니다**

#### 1. 줄바꿈 — `Alt+Enter`, 또는 줄 끝에 `` ` ``

여러 줄을 한 메시지로 보낼 방법이 없었습니다. Shift+Enter · Ctrl+Enter 를
눌러도 그냥 보내집니다. 사람 잘못이 아니라 정말로 그런 코드가 없었습니다.

왜 Shift+Enter 로 못 하는지 바이트를 직접 흘려보내 확인했습니다 — 터미널
대부분이 그걸 **평범한 Enter 와 똑같은 바이트**(`\r`)로 보내고, readline 이
우리보다 먼저 그 바이트를 받아 줄을 끝내 버립니다. 가로챌 기회 자체가
없습니다. ESC 로 시작하는 조합(Alt/Option+Enter)만 다릅니다 — readline 이
ESC 뒤를 기다리는 사이 우리가 먼저 봅니다.

터미널이 Alt+Enter 도 안 보내 주면 줄 끝에 `` ` `` 를 붙이고 Enter 를 치면
됩니다. 어디서나 됩니다. 백슬래시가 아니라 백틱인 것은 일부러입니다 —
윈도우 경로 끝이 흔히 `\` 라서, 경로를 붙여넣기만 해도 이어 치는 것으로
잘못 읽힙니다. 백틱 **하나**로 끝날 때만이고, ` ``` ` 로 끝나는 마크다운
코드 울타리는 그대로 둡니다.

#### 2. 일하는 그림에 테마 — 중세 기사와 픽셀 동물들

```bash
DEEL_MOTION=기사    # knight
DEEL_MOTION=동물    # animal
```

코드를 쓰는 동안 기사가 칼을 휘두릅니다. 읽을 때는 방패를 앞세워 나아가고,
45초가 넘어가면 **지쳐 쓰러졌다 다시 일어납니다.** 동물은 걷고 뛰고 기지개를
켜다가, 오래 걸리면 드러누워 잡니다.

오래 걸릴 때 진행 중인 척하면 곧 끝날 것처럼 보여 오히려 답답하고, 가만히
있으면 멈춘 줄 압니다. 쓰러지는 편이 둘 다 아닙니다.

기본 그림은 한 글자도 안 건드렸습니다. 안 고르면 지금까지와 똑같습니다.

#### 3. 사무실 — 지금 무슨 일이 도는지를 방 하나로

```bash
DEEL_OFFICE=1 deel
```

입력 상자 위에 열두 줄짜리 방이 붙고, 일이 시작되면 그 자리에서 움직입니다.
자리에 사람이 앉고, 자판을 두드리고, 서류를 보고, 오래 걸리면 존다.

**화면에 있는 것은 전부 진짜 숫자입니다.** 자리에 앉은 사람은 지금 도는 일
(부모 1 + 하위 작업 수), 화이트보드 쪽지는 할 일, 서류함 서랍은 읽은 파일,
서버 불빛은 모델 호출 횟수, 창밖 낮/밤은 컨텍스트가 얼마나 찼나입니다.
모르는 값은 0 으로 둡니다 — 한 번 지어내면 화면 전체를 못 믿게 됩니다.

기본은 꺼져 있고, 화면이 28줄보다 낮으면 안 켜집니다(사무실 12줄 + 상자
5줄이면 대화가 들어갈 자리가 없습니다). 켜면 상자 안 기사·동물은 조용한
돌림표로 돌아갑니다 — 둘 다 같은 것을 말하는데 위아래에 붙여 놓으면 같은
소리를 두 번 하는 셈입니다.

#### 4. 그러면서 상자가 6배 가벼워졌습니다

사무실을 얹기 전에 쟀더니, 열두 줄을 90ms 마다 통째로 보내면 초당 104KB
였습니다. 그런데 판이 바뀔 때 **실제로 달라지는 것은 열두 줄 중 한 줄**
이었습니다 — 벽·창문·서류함·빈 책상은 그대로입니다.

그래서 상자가 줄마다 견줘서 바뀐 것만 보내게 고쳤습니다. **사무실을 안 켜는
분도 같이 가벼워졌습니다.**

판마다 실제로 달라지는 줄은 **열둘 중 평균 0.4줄**입니다. 다 바뀌는 최악의
판에서도 통째로 그리는 것과 바이트가 같으니, 견주기가 손해를 볼 자리는 없습니다.

> 여기에 초당 몇 KB 라고 적었던 표는 1.5.1 에서 뺐습니다. 터미널 폭과 그때
> 무엇이 움직이는지에 따라 몇 배씩 달라져서, 다시 재면 그 숫자가 안 나왔습니다.

견주기는 '화면이 내가 아는 그대로다' 를 믿으므로, 통째로 그리던 시절의
자가 치유를 잃습니다. 그래서 4초에 한 번은 통째로 그립니다.

#### 5. 같은 코드가 한 번은 통과하고 한 번은 실패하던 검사

상자 검사가 진짜 deel 을 띄워 놓고 화면을 읽는데, 언제 읽을지를 **시간으로**
정해 뒀습니다(1800ms 자고 일어나서 읽기). 바쁜 컴퓨터에서는 그 안에 못
켜지고, 빈 화면을 읽고 죄다 틀렸다고 합니다. 같은 코드로 15번 돌리면 3번이
그렇게 죽었습니다.

시간이 아니라 **일어난 일**을 기다리게 고쳤습니다 — 켜졌다는 신호, 답이
나온 것, 바라는 글이 상자에 뜬 것. 15회 중 3회 실패에서 0회가 됐고, 빨리
되면 빨리 넘어가므로 평소에는 오히려 더 빠릅니다.
