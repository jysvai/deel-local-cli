## 1.10.0

**ESC actually stops, and a full context carries on instead of dying**

Four reports drove this release. None of them was a missing feature. Every one
was **something the code claimed to do, and did — except in one place.**

| The report | What was actually happening |
| --- | --- |
| ESC doesn't stop anything | The stop signal **never reached three places** |
| It cuts off mid-way | At the cut-off point the screen said nothing at all |
| It forgets items from a long request | After a restart the outstanding work came back **empty** |
| A full context blocks everything | It learned the limit and re-sent **the same transcript** |

---

### ESC — it was not ignored, it never arrived

While *we* are running, it already stopped. What did not stop was **waiting for
somebody else to answer.** Those places had a timeout and nothing else.

```
                          before        after
  A web server that hangs   30s wait     0.14s
  An MCP tool that hangs    60s wait     0.12s
  While asking you to pick  no effect    stops
```

The screen said "stopping…" the whole time. From where you sit that is
indistinguishable from a broken key.

Three things hold together here.

- **Stopping and timing out are written differently.** A timeout is the other
  side being slow; stopping is us giving up. The key you pressed must not be
  recorded as somebody else's server failing.
- **After the stop, nothing goes out.** A footprint left on someone else's
  server *after* you stopped cannot be explained to anyone.
- **The line screen says it too.** Outside a terminal (CI, a pipe) pressing ESC
  used to leave the screen perfectly still.

---

### A full context now recovers inside the same turn

It used to go: no room, the server rejects → learn the window size, call again →
**re-send the very same transcript** → rejected again → one red line, turn dead.
You then typed `/clear`, retyped the whole request, and re-pasted your files.
Having moved not one step forward.

Now it recovers on its own.

```
❯ make the log format consistent
  ◱ Out of room — cleared 17 earlier messages and carried on · 2 items left
  Carried on after clearing.
```

**You retype nothing.** The verbatim request, the unfinished items, and the
files touched this turn are carried across. It is not an error, so the exit code
stays 0.

**Once per turn.** If it fills up again after clearing, that is a real error and
is reported as one. The clearing step does not consume a step from the budget,
so there is no way for it to spin forever.

Folding and clearing are now checked **before** the call, not after. Until now
the check only ran after a tool step, so the first message of a turn — the one
with a large paste in it — died before it could ever be measured.

---

### Restarting keeps the work that is left

1.9.2 stopped the outstanding work from disappearing **inside** a conversation
when it folded or trimmed. But both lived only in memory, so closing the window
removed that protection in one stroke.

```
                              before      after
  the messages                 restored    restored
  pinned items                 restored    restored
  outstanding work           ★ empty       restored
  the verbatim request       ★ empty       restored
```

**And if it cannot save, it says so.** A full disk or a read-only home means not
one line is written, and the screen used to say nothing. The place you found out
was **`--resume` the next day** — by which point the conversation is gone.

```
⚠ This conversation is not being written to disk (EACCES) — 12 lines lost.
  Close this window now and it cannot be resumed.
```

The `/sessions` screen used to promise "still being saved" unconditionally. When
it is leaking, that line is now a warning instead.

---

### Pick a number *and* say something

In the question box, a number picked an option and anything else was a free-form
answer with no option chosen. There was no way to do both.

```
❯ 2 but leave .env alone
  ▶ add only .env.example — but leave .env alone
```

`2:` `2,` `2 -` `2.` all work, and `1,3` picks several. "3 items only" does
**not** select option 3 — a number with letters attached is not read as a number.

The plan box works the same way.

```
before:  Go ahead with this?  ⏎ go · n cancel · anything else = what to change
after:   Go ahead with this?  ⏎ go · y + a note · 3 + a note on that step · n cancel
```

`y also add tests` goes ahead **with the note attached, without re-planning.**
Typing that before sent it back to re-plan, costing you minutes of waiting again.

### Pasting

Paste 40 lines while it is working and only the last line showed. You assume one
line went in, paste again — and now it really is in twice.

```
before:  ❯ line 40 — …
after:   ❯ [pasted #1 · 40 lines · 1.6KB]
```

The model still receives all 40 lines byte for byte. The chip's wording was
hardcoded Korean; it now follows the language you chose — `[pasted #1 · 3 lines · 5B]`,
`[貼り付け #1 · 3行]`, `[粘贴 #1 · 3行]`. Chips printed before a language change
are still recognised afterwards.

---

### Every vendor's endpoint, measured in all eight positions

All 20 built-in tools and 32 features were sent to **eight environments** —
local, Ollama, OpenAI direct, Azure, Gemini, Claude direct, a Bedrock gateway,
and a corporate gateway. The 20 tools survive every one of them untouched.
Where behaviour diverged, **five real faults** turned up.

| Where | Before | After |
| --- | --- | --- |
| `deel setup` on Claude direct | **all 8 probes red** → saved as "no tools" | all 8 pass |
| `/plan` (local · OpenAI · Gemini · Ollama) | our `max` went on the wire → **400** | mapped to the strongest word that wire knows |
| OpenAI reasoning models | the old output-limit key was sent too → **400 on the first request** | new key only |
| A limit Claude told us | the numbers were read **backwards** and saved to the profile → dies every time | read correctly |
| Claude · Bedrock quota left | **always empty** → you learn at the 429 | read from the headers |

The first row was the worst. The probe did not know the Anthropic shape, so the
first check returned 400 and the result — `tools: false, vision: false` — was
**written into the profile.** The screen says setup succeeded while building a
connection that never uses tools.

**Codex (`gpt-5-codex`) still does not connect.** That family answers only
through a different door (the Responses API), and adding that door requires
first fixing that the shape is not re-decided when you switch models, and that
transcript folding would stop silently. Half of it would produce exactly the
fault this project exists to prevent — a screen that says it works. So instead
it **says in one line why it will not connect**, rather than leaving you to
suspect your key or the model name.

### Security — one word stepped over the fence

`cat .deel/config.json` was blocked. Put a `cd` in front and only a bare
filename is left, which was never checked at all.

```
type .deel\config.json            blocked
cd .deel && type config.json    ★ allowed
cd .deel; cat config.json       ★ allowed
cd .deel && del audit.jsonl     ★ allowed   ← deleting the audit log, too
```

Entering the housekeeping folder is now itself the violation. `pushd`,
`Set-Location`, a newline, and a wrapped shell are all covered, while
`cd src && cat x.js` passes exactly as before.

- **Keys were written to the audit log in clear.** `curl -H "Authorization: Bearer …"`
  was stored verbatim — and that file ships with `deel audit` as review material.
- **A small archive that expands enormously.** The 64MB cap was on the
  *compressed* size; there was no cap on the output. 4MB of zeros compresses to
  4,098 bytes.
- **The audit log and session files are now owner-only,** like the config file
  already was.
- **Child shells inherited the gateway key.** One `env` puts it on the screen,
  in the transcript, and on disk. MCP servers were already scrubbed.
- **On macOS the test overwrote your real key.** The keychain entry name was
  fixed, so running the suite on a Mac replaced the real gateway key.

---

### Nothing is left behind on exit

Close deel, open the task manager, and a node process was still there. Language
servers and MCP servers are other people's programs that we started, so if
whoever attached them exits without closing them, nobody does. After a few days
it is noticeably slower.

On Ctrl+C the children are collected first, and we exit **only when ours is the
single handler** for that signal — if something else owns it, its shutdown is
left alone.

---

### Also

- **A failure threw away everything streamed so far.** Aborting kept it; an
  error did not, losing a half-written answer.
- **A truncated answer passed as a complete one** in `deel run` and in the editor.
- **A turn that was cut short never said what it missed.** The missing-item check
  ran only on the normal exit, never where items actually go missing.
- **A rule file that exists but cannot be read** was reported as "no rules", so
  you believe rules are in effect when they are not.
- **A guessed encoding was stated as fact.** It now reads `CP949 (guess)`.
- **Nine settings printed ✓ without saving.** Restart and they are back.
- **24 phrases missing from Japanese and Chinese.** The `/think` screen had a
  translated frame around entirely English contents. All four are now 419/419.

---

### Tests

6,149 → **6,629 checks**. Every one of the 480 added was confirmed by mutation.
Five wall-clock windows were converted to ratios and four source-text greps were
replaced by assertions on **the body actually sent** — both changes tighten what
is measured rather than relax it.

Zero failures in all three environments.
