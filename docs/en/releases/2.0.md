## 2.0.0

**Every fence we said was there, checked for whether it actually holds**

We stopped 1.20.14 on its way out (it was never published — "before" in the tables below is 1.20.13) and went back over every feature. Claude read it
first along ten lines of inquiry; Gemini then read it a second time — **read only**.
Every point either of them raised was settled by running it, and only the true ones
were fixed. Each fix got a failing test first.

After that we kept hunting. Agents, one per area, built real commands · files · server
responses · archives and threw them at deel; whatever turned up was fixed under the same
rules (confirm by running it · failing test first). We shipped only once a round found nothing new.

The major version is for one reason: **a lot of what the docs and the screen promised
did not actually happen.** Fixing that changes some behavior. Start with this table.

Last of all, codex (gpt-5.6-sol) read it a third time — **read only**.
Everything all three eyes raised was settled by running it.

## Part 1 · What changed

### What behaves differently

| What | 1.20.13 | 2.0.0 |
|---|---|---|
| `offline` · `active` in a project config (`.deel/config.json`) | overrode the home config | only the narrowing side wins — a repository cannot switch offline off |
| Tools from a connected MCP server | listed, but calling one returned "unknown tool" in every mode | actually run in modes that list them; ask · plan don't list them and refuse a call by name |
| Locking the undo and audit files on Windows | recorded as locked `0600` | recorded as not lockable on Windows |
| Korean file names shipped to npm | 11 | English names ([below](#file-names-shipped-to-npm)) |
| A usage mistake (unknown flag · flag with no value · misspelled mode) | exit code 2 — the same number as the step limit | **64** · suggests the nearest flag |
| Unknown flags · words after `--` | swallowed as the prompt or silently ignored | stops · words after `--` are the prompt |
| An approval mode in the wrong case (`--mode Strict`) or unknown | passed through — approvals were off | stops |
| `deel trust` in the home folder · a drive root | trusted every repository below it | refused |
| `mode` in the home config | ignored by `deel run` | followed by run · chat · acp (a flag still wins) |
| A `--root` that doesn't exist, in chat · acp | created and used | stops (exit 1) |
| An allow rule (`Write(*.md)`) against several arguments | allowed without asking if any one matched | all must match |
| Model answers · tool lines · diffs · todos · the status bar · approval prompts on screen | terminal control sequences went straight through | stripped (our own colors kept) |
| A plugin archive with a file and folder of the same name · names differing only in case | raw error mid-extract · one file silently lost | refused before extracting |
| An unknown command · a single-dash flag (`-x`) · `--json=yes` · `--root ""` | exit 1, or silently taken as the prompt · the current folder | stops with 64 |
| Environment variables a hook receives | the whole environment (`*_API_KEY` · `*_TOKEN` included) | secret-looking names removed, as for the Bash tool — keep some with `셸환경.남길것` in the home config |
| Claude Code style hook decisions (`permissionDecision: deny` · `decision: block` · `continue: false`) | passed when the exit code was 0 | block |
| `.deel/memory.md` in an untrusted folder | loaded into the system prompt every turn | only when it is exactly what deel on this PC wrote (hand edits after `deel trust`) |
| `.deel/agents` in an untrusted folder | loaded | not loaded |
| A repository command (`.claude/commands`) with the same name as yours | the repository's replaced yours | the repository's is dropped, with a notice |
| `/undo` records pointing outside the project | overwrote and deleted files outside | left alone |
| A drive root or home folder listed as trusted | everything below it trusted | ignored |
| More than 1,000 empty rows or columns in a row in an xlsx | filled with empty cells | skipped, and where is noted |
| An MCP server name with `__` or a leading/trailing `_` | its tools could not be called | refused with a reason |
| An auth command reached where no approval hook is attached | Skipped the whole approval block and **ran without asking** | Not run; it returns the reason instead (policy-supplied commands, and ones already approved in this session, still run) |

## Part 3 · How it was found — CHA

Parts 1 and 2 are the result. This is the **method**. None of these fixes came from
reading the code. They came from repeating one procedure eighteen times:
**CHA — Cyclic Hostile Harnessing**.

### Why go this far

One failure kept coming back through all of 1.x: **the place where what is written
and what runs are different.** A comment says "blocked" and it does not block. The
screen says "snapshotted" and nothing was. A test is green and never measures the value.

You cannot find these by **reading**, because a reader believes the comment.
So we stopped reading and switched to a procedure that **collides with the code**.

### One round is nine steps

| Step | What happens | Why |
|---|---|---|
| 1. Hunt | Pick an area and hit it with **real input** — real commands, files, server responses, archives | Invented input gives invented answers |
| 2. Brief | Write it down as "where · what went in · what came out · what was expected" | A claim alone cannot be measured in the next step |
| 3. Second eye | Another model reads — **read-only** — and points at the same places | An author reviewing their own work is a first eye twice |
| 4. Verdict | Decide **by execution**: true · false (with counter-evidence) · cannot measure | Roughly half of what a model points at is false |
| 5. Failing test first | **Before** the fix, add a test for that value and watch it go red | If it does not go red, it does not guard that place |
| 6. Fix | Change the code. **One writer only** | With two writers nobody can tell who changed what |
| 7. Mutate | Revert the fixed line on purpose and check the test turns red | Green can mean "guarded" or just "not hit this time" |
| 8. Gate | Run `npm test`, `npm run check`, `npm run docs` in full | Fixing one place breaks the one next to it |
| 9. Record | **Append only** — what was claimed, how it was adjudicated, why it was fixed that way | A deleted record makes you repeat the mistake |

### What counts as a defect — five classes

We do not use the word "bug". Five fixed classes leave much less room for "well, sort of".

| Class | Meaning | Example from this release |
|---|---|---|
| 1. A rule that never matches | It never fires on input that actually arrives | The cmd switch `/q` in `rd /s /q` was read as "one level under the root", so deleting one folder was blocked |
| 2. Silent failure | It failed but passed as success | The summary failed, history was simply truncated, and it still said "folded into a summary" |
| 3. A test that does not guard | Green, but never measures the value | Two tests had `… \|\| true` attached — green for any input |
| 4. Half-applied fix | The comment or doc was fixed; the code was not | "if we cannot delete it, the sweeper takes it" — nothing ever called the sweeper |
| 5. A leak past a trust boundary | Something escapes the fence | `dd if="../secret.txt"` walked past the fence on one pair of quotes |

**A false warning counts as a defect.** Letting a dangerous thing through and blocking
a legitimate one cost the same. Measuring only one direction makes "block everything"
come out green, so every test measures **both** — what must be blocked and what must still run.

### Three verdicts — especially "cannot measure"

Everything a second or third eye points at gets exactly one of three verdicts.

| Verdict | Meaning | Rule |
|---|---|---|
| True | It really is so | Only after it has been **shown by running it** |
| False | It is not | Counter-evidence written alongside |
| Cannot measure | Not knowable from here | **Never filed as a defect** |

The third one exists for a reason. Without it a model files everything ambiguous as
"true". You then fix places that were not broken, and that becomes a new defect.

It happened here. The second eye raised eight items; six came back "cannot measure"
(the brief had been sent without the code), and one turned out **false** when run.

### One writer only

Exactly one model writes code. The second and third eyes **only read**. The tools
themselves run read-only, and any attempt to edit is printed separately.

Without this the second eye collapses into an author reviewing their own work.

### Mutation — how not to trust a green run

A test being green and a test **guarding that place** are different things.
So we revert the line on purpose and check that the test turns red.

```
✓ stop consulting the alias table when deciding if it is a name   src/commands.js → caught by test/commands.test.js · 1.4s
✗ remove the second pass that strips quotes                        src/safety/guard.js     ← nobody caught it
```

That second line is what the method is worth. In a file with 353 green checks,
**removing that entire pass caught nobody.** So a test for what that pass actually
protects was added (`rm "-rf" /`).

Each mutant attaches by an **anchor** — the exact text of the line it breaks. Edit that
line later and the anchor stops matching, so the mutant is silently skipped: the run is
green while the guarded surface has shrunk. That, too, is caught by a test (`죽은규칙.test.js`).

| | 1.20.13 | 2.0.0 |
|---|---|---|
| Mutants | 300 | **1,656** |
| `src/safety/guard.js` alone | 12 | **46** — all caught, none escaped |

### Three eyes hit the same place three times

The last round looked at one file only: the safety fence (`src/safety/guard.js`).
First (Claude), second (Gemini) and third (codex gpt-5.6-sol) read it in turn, and
**everything all three found was the same kind of thing.**

| | How many | What |
|---|---|---|
| 1st · Claude | 10 | Quotes · `cd..` · a path-spelled shell · the star (`C:\*`) · three false warnings · a leading space · `node -e` |
| 2nd · Gemini | 4 true · 1 false · 2 cannot measure | `\\?\C:\` · `%SystemDrive%` · `\\wsl$\…\bash` · `&del` inside quotes |
| 3rd · codex | 7 true | `${env:SystemDrive}` · `/usr/bin/env bash` · a path with spaces · partial quoting · a newline · a Korean variable name · `C:temp` |

All twenty-one reduce to **one sentence** —

> Not "we blocked it" but **"we blocked whoever spelled it the way our example spelled it."**

The comments in that file had already written that sentence down four times. It still
happened again with every new rule. So this release pairs every rule with a test in
**both directions**.

### What this method does not catch

Stated plainly, not hidden.

| Not caught | Why |
|---|---|
| What happens **inside** a script | The filename in `node -e "…writeFileSync…"` is invisible from outside the shell. Recording the turn is as far as it goes |
| An endpoint we never reached | Only endpoints actually connected to are measured. The rest are written down as "could not measure" |
| Whether the intent is right | We measure "does it do what is written". Not "is what is written correct" |
| Anything slower than one round | A failure that only shows up after several rounds does not surface in this procedure |

### The record is never deleted

Every round **appends** what was claimed, how it was adjudicated, and why it was fixed
that way. In this release that record was once deleted for real — a command that clears
the temp folder was run with the repository as its working directory. 1,445 lines were
recovered from the conversation log; one round (the 7th) is gone for good.

Two things changed because of it. Release content moved to where **git can see it**
(`docs/`), and state-changing commands are no longer run with the repository as the
working directory.
