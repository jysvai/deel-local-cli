## 1.20.10

**Nobody answered, yet an answer had been given**

Six of the twenty-seven fixes in this release are the same shape: **the person
typed nothing, and something answered on their behalf.** The screen then shows
a `✓`.

```
echo "summarize this folder" | deel

  ↗ This connection leaves your machine.
     Going to  api.example.invalid
  › May I go out? ⏎ allow and remember · n stop [y] summarize this folder
  Permission saved — this profile will not ask again.
```

The instruction was eaten **as the answer.** It never reached the model, and
`online: true` was written into the config file, so that profile would never
ask again. This program sells exactly one promise — that nothing leaves your
machine without you knowing — and a single pipe switched it off in silence.

---

## Six places where a non-answer was read as an answer

### Piping into deel made your instruction answer "may I go out?"

| | Before | After |
|---|---|---|
| Screen | `May I go out? [y] summarize this folder` | `⚠ Input is piped, so there is nobody to ask — nothing went out` |
| Config file | `online: true` **written permanently** | untouched |
| Your instruction | consumed as the answer, **never sent** | — (nothing went out, so nothing was sent) |

An empty pipe did the same thing. End-of-input (EOF) and a person pressing
Enter were not told apart, so the default `'y'` became the answer. Each
question now decides for itself what end-of-input means — for this one, it
means **no**.

Pressing Ctrl+D at a real terminal did the same. That is closed too.

### Lines typed before a question appeared were eaten as its answer

Typing ahead while work runs is a supported way to use this program. But that
line came back out as the answer to a prompt that appeared thirty seconds later.

```
Before   ⏺ Edit(src/a.js)
         › Run it? (y/n) [y]
         └ refused                  ← "and run the tests after" became the answer
                                       that instruction vanished from the queue

After    Only a line typed **after** the question counts as its answer.
         What was typed earlier is held and handled when the turn ends.
```

It was worse for the Ask tool — "also fix file 3" had its leading number read
as **choice 3**, and the screen looked exactly as if the person had chosen it.

Feeding answers through a pipe (`echo y | deel`) still works. Where there is
no keyboard, that is the only way to answer.

### A half-written plan was offered for approval

The approval box should only appear after a turn that ended cleanly. Four of
the most common ways a plan ends up half-written were not counted as failures.

| What happened | Before | After |
|---|---|---|
| Cut off at the output cap | `⚠ Reply was cut at 16,384 tokens` then `┌ Plan … ⏎ go ahead` | no approval box |
| Server stopped without saying why | same | no approval box |
| Step ceiling reached | same (and the "continue from where it stopped" prompt never ran at all) | goes to "continue?" |
| Model refused | approval box for a plan that **does not exist** | no approval box |

The window title read "done" in all four. It now reads "failed".

### The plan box showed last turn's leftover to-dos as this turn's plan

The to-do list lives as long as the conversation. Nothing ever cleared it.

```
Turn A   a login task hits the step ceiling; two to-dos stay unfinished
Turn B   "design the payment module and build it" — the model writes prose only

Before   ┌ Plan
         1. Build the login form     ← from turn A
         2. Session cookie           ← from turn A
         └ 2 steps · ⏎ go ahead

After    With no plan written this turn: "no steps were written down"
```

Pressing ⏎ shipped that old list to the model labelled "the plan you just made".

### "Continue?" was offered with zero things left to do

`remaining ?? []` meant an empty array read as "there is something to continue".
One ⏎ called the model again with nowhere to continue from.

### A prompt helper marked "do not use inside the REPL" was used inside the REPL

One place — asking whether to run a corporate login command — was still on the
old path, using a function whose own file says "the REPL holds stdin through
readline, so you cannot use this here". Three things broke at once:

- the typed `y` also reached readline and later answered a different question
- raw mode was switched off on the way out, so ESC and Shift+Tab stopped working
- Ctrl+C there killed the process **without collecting** MCP servers, language
  servers, or background commands

## Twelve places that failed without saying so

### Attaching an external profile always said "the server doesn't tell us"

The context-length probe ran **before** permission was granted. Our own gate
blocked it every time, and the screen blamed the server.

```
Before   ⚠ The server doesn't tell us the context size — using 32,768 for now
         (The server never received the question. And it was never asked again
          after permission was granted, so a 128k model was used as 32,768 for
          the whole session.)

After    The probe runs **after** permission is granted.
         If it still fails, the reason comes with it —
           · no permission to reach this address yet, so we never asked
           · the server answered but does not report a length
           · nothing answered at any of the addresses we tried
```

### `--resume` started a brand-new conversation in silence

```
deel --resume no-such-id

Before   (no line at all → straight to the header → a new file under that id)
After    ⚠ no-such-id — no such conversation, or it is empty.
           Starting a new one. To find one to resume: /sessions
```

When the file could not be read (permissions, another process), the reason is
printed too.

### Declining the permission prompt left spawned programs running

Answering `n` to "may I go out?" skipped the whole cleanup block. MCP servers
are already up by then — deel exited and someone else's process kept running.

### A hook block did not say why it blocked

The screen showed one line: `✗ A hook blocked this (dlp-check)`. You could not
tell whether corporate policy really blocked it or the hook file was missing and
failed to run. The second is something a person can fix. The reason now prints
alongside, up to four lines.

### Things that could not be checked showed as a green ✓

The `✓` in the status bar means "it was run and nothing was wrong".

| Reality | Before | After |
|---|---|---|
| 3 verified · 0 unverified | `✓3` (green) | `✓3` (green) |
| 0 verified · **5 unverified** | `✓0` (green) | `✓0 ?5` (yellow) |
| 1 verified · 2 failed | `✓1 ✗2` (red) | `✓1 ✗2` (red) |

A refused Verify was also counted as "it ran". It no longer is.

### An unreadable undo history still showed the old count

`↩ 3` in the status bar is how much safety net is left. Not being able to read
the history means `/undo` cannot work either — yet the screen said three turns
were still recoverable.

### Failure to prune old conversations was swallowed whole

If it kept failing, the conversation folder grew without limit and nothing ever
appeared on screen.

### A prompt silently threw away stacked continuation lines

Three lines stacked with trailing backticks vanished if a question interrupted.
Cancelling with Ctrl+C prints "discarded what you were continuing" — this path
said nothing.

### `/ctx` and `/out` wrote to the wrong connection

When the current connection was not found, the value went to the **first
profile** and the screen said "saved". With 655,360 written into an 8k server's
profile, the next session starts trusting that number and the server rejects
long conversations.

### An offline lock was reported as the server's fault

Asking `/model` for a list could not tell our own gate blocking the request from
the server declining to list. Now three distinct messages.

### `/export` and `/evidence` threw away the reason

"Could not write the file" alone does not say whether the disk is full or the
folder is read-only. Reasons like `ENOTDIR` and `EACCES` now come with it.

### One slash command could end the whole conversation

If `.deel` was read-only or the disk was full, a single `/memory something` line
ended the process — messages, resume point and all. It now prints one line and
the conversation continues.

## Six places where a name nobody defined read as defined

In JavaScript every table inherits `constructor`, `toString` and `valueOf`. So
asking "is it there?" with `table[value]` returns **true for names nobody ever
defined.**

| Where | Before | After |
|---|---|---|
| `/think profile constructor` | prints `✓ profile Object — undefined`, then stops while drawing the table | shows the list of profiles |
| `/think profile toString` | stops right there | same |
| `deel config explain constructor` | `error: 볼환경.filter is not a function` | `not written down anywhere` |
| Managed-policy view | a field absent from the policy appears as "written in the managed policy" | nothing is invented |
| Model calls a `toString` tool | `t.run is not a function` | `unknown tool: toString` |
| Tool line glyph | `function Object() { [native code] }` | `⏺` |

The first is the worst — it prints the **`✓` first** and then stops. The person
believes the profile changed, and every remaining turn in that session stops
while computing the step budget.

## 1.20.9

**Nothing was missing from the screen — something else was on it**

Almost all forty fixes in this release are the same kind of defect: **not
"it couldn't do it", but "it did something else and said nothing."**

```
couldn't read it   [This page had no extractable text — …]   ← shows up
read the wrong one  plausible text simply appears             ← nowhere to show
```

A PDF you filled in and saved read back the values from **before** you filled it
in. You cleared the context and the office sky stayed at midnight. A guessed
window size was written down as a measured one. Text you typed ahead while the
model worked stopped appearing anywhere from the fourth line on. `/memory 지우기`
("delete") wrote the word "delete" into memory instead of deleting. In all five,
the screen looks perfectly fine — and four of them print a ✓.

## PDF — thirteen places where something else was read

### A form you filled in and saved read back the pre-fill values

A PDF is not rewritten when you edit it. The **changed objects are appended**
and a new table of contents points back at the old one. Filling in a form,
adding a comment, signing — all of them produce exactly this shape, and the old
content is still sitting in the file.

Walking that table newest-first, we let an **older revision overwrite** an entry
that had already been settled.

```
what we read: OLD price 1000
the truth:    NEW price 2000
```

Deleted sentences, corrected amounts and filled-in fields come back to life. And
the text looks perfectly normal.

### A document with "3 0 obj" written inside its body text

There are three ways to find an object in a PDF — scanning the whole file,
reading the cross-reference table, and unpacking object streams. We use all
three because tables in real-world PDFs are wrong so often.

Each of the three had a hole.

| If the file looks like this | What happened |
|---|---|
| header is `4 0` + newline + `obj` | object offsets shift by one, and a file whose table is also wrong became **entirely** unreadable |
| a table row is 19 bytes | everything from the second row on is misaligned, losing the whole table and the trailer with it |
| the body contains the text `3 0 obj` | the scan takes that for an object, and the table that would have corrected it was already lost above |

The second one is the expensive one. Lose the trailer and **an encrypted PDF is
never reported as encrypted** — you get garbage text, or none.

There was code that said it "realigns 19-byte rows". It bailed out the moment it
hit whitespace, so it had never realigned anything.

### "䄀" instead of "A"

A font's table maps glyph numbers back to Unicode. Some files write the target
in two digits (`<41>`) — a spec violation, but they exist.

```
<41>  →  '4100'  →  U+4100  →  「䄀」
wanted   →  U+0041  →  「A」
```

We were padding the missing digits on the right. Faced with a violation, the
choice between inventing a Han character that isn't there and returning "A" is
not a close one.

### Three codes in brackets became another range

```
<0020> <0022> [<0041> <0042> <0043>]
                ↑ these three were read as a range again
```

That invented **mappings that don't exist** for codes 0x41 and 0x42 — "C" and
"D". Korean PDFs almost always use glyph numbers, so 0x41 really is some
character; that character now reads as a different one. A missing character is
visible. A wrong one is not.

### Two bytes inside an image swallowed the rest of the page

Inline images are carried as `BI … ID … EI`. Image data is compressed bytes, so
it can contain the two letters `EI` by accident.

Cutting there starts reading words from the middle of the image, mistakes a `(`
in the data for the start of a string, and **swallows the rest of the page's
text.**

```
what we read: before
the truth:    before / after
```

And because the first part did come through, the page is not listed as
unreadable either.

### One line split into one line per word

Bolding a single word inside a line is commonly typeset by placing that word in
its own run. We were reading those breaks as line breaks.

```
Total          Total 1,000,000 won
1,000,000  →
won
```

Whether the line changed is told by **vertical movement**, not by run
boundaries.

### Also

* An odd-length string in a two-byte font had a zero byte appended to the last
  byte, producing a **glyph number that doesn't exist**. If that number is in the
  table, a character that isn't in the document joins the text. It now counts as
  unread, and the page is reported as partially read.
* The mere **presence** of an image slot in the resources produced "this may be a
  scanned image — OCR required". A header logo inherited from above made truly
  blank pages say that too. Now the actual drawing operation says it.
* `<0000>` was emitted as a character, mixing NUL bytes into the text.
* The catalog-recovery pattern was blocked by a single nested dictionary. In
  Korean documents that inherit resources from the page tree, taking that path
  also loses the fonts, and the screen said **"there is no /ToUnicode table"** —
  the table was right there.
* A `#` inside a name was accepted with only one hex digit following it, eating
  the delimiter that came after.

## The screen — thirteen places where it ate itself

### In a narrow window the screen was eating itself

The input box pins the bottom few rows of the terminal and redraws **only
there**. It never touches the conversation above. For that, the box has to know
exactly how many rows it is — that is how far up it moves the cursor.

If even one row is wider than the terminal, that count is wrong. The terminal
folds that row into two, the box counts it as one, and moves up one row short.
Every keystroke then **eats one row of the conversation above.**

There were five such rows.

| Where | How wide |
|---|---|
| status line | when the window is narrow, a single segment overflows as-is |
| working label | sub-task goals and file paths arrive verbatim |
| `Enter 를 치면 지금 일이 끝난 뒤에 보냅니다` | a fixed 43 columns |
| hint under the box | no length was ever set |
| quota warning | 101 columns at width 80 — the box counted 5 rows, the terminal used 7 |

### Fixing the ruler fixed all five

There is one function that trims an over-wide line. It was **counting colour
codes as characters.**

Colour codes take no space on screen. `\x1b[38;5;245m` is twelve characters and
zero columns wide. Counting them one by one gets two things wrong at once.

```
fitting the status line (66 colour codes) into 70 columns

  before:  ▏[38;5;245…          ← 14 visible columns; colour codes ate the rest
  after:   ▏⌂ Local · 1.20.8 · ⑂ main…   ← 70 columns
```

And if the cut lands inside a colour code, a **command fragment** —
`ESC [ 3 8 ; 5 ;` — is left on screen. The terminal reads it as the start of a
command and eats the characters that follow. Cutting without closing the colour
made that colour **bleed into every line printed below.**

Colour codes are now passed through whole and counted as zero width. If a colour
is open at the cut, it is closed.

### Text typed ahead stopped appearing from the fourth line on

A local model takes minutes per turn. You can type during that time, and we are
in fact receiving it — and showing it. Up to three lines.

But those were the **first** three lines. You type at the end, the screen holds
the beginning, and from the fourth line on nothing you type appears anywhere.
The cursor sits at the end of line three.

```
typing text that folds into five lines

              before        after
visible lines  1,2,3         3,4,5
just typed     not shown     shown
cursor         end of line 3 end of line 5
hidden marker  none (❯)      yes (…)
```

Everything was being received; it just looked like the keyboard was dead.

### Resizing the window produced two boxes

When the width changes the terminal has already refolded the lines itself. So
the box threw away its counts and **swept everything below the cursor** before
redrawing.

The cursor sits in the middle of the box. Sweeping below it leaves **the upper
half in place** — office, status line and top border stranded as a ghost, with
the new box drawn underneath. That ghost then scrolls up with the conversation
and never goes away.

Drawn onto a simulated screen and counted:

```
80 → 100 cols    before: 2 top borders    after: 1
80 →  60 cols    before: 4 ghost rows     after: 2
```

It now moves up to the box's top row and sweeps from there. **No further than
that** — above it is the conversation. (The two rows left when narrowing are what
the terminal refolded. Going further would erase conversation, so we err short.)

### After 45 seconds it was stuck on "still working"

There is a place that swaps the phrase when things take a long time. The point
was: "repeating the same words looks frozen — signal that we're still alive."

Those 45 seconds were measured from **the start of the turn.** A local model
takes minutes per turn, so from 45 seconds on — reading files, writing code,
running commands — the screen just cycled "still working". The phrase became the
frozen thing itself.

```
                        before          after
50s → started writing   still working   writing code
70s → started a command still working   running a command
130s (60s into it)      still working   still working
```

It is now measured from when the activity changed. Elapsed time is still counted
from the start of the turn.

### The office sky stayed dark through `/clear`

The sky in the office view says how full the context is. It was taking that from
the **cumulative token total**, which is a different number from how much is in
the window right now.

```
status line  ▰▰▱▱▱ 18%
sky          midnight
```

`/clear` empties the window but not the total, so the sky stayed at night. It
now reads the same value the status line reads — one fact, one place.

### Guessed numbers were written down as measured

Two places on screen were claiming more than they knew.

```
context  5.5k/32k   ← the server never told us 32k; we guessed it
cost     $0.60      ← /cost was saying "some calls weren't counted"
```

They now read `32k?` and `$0.60?`. One question mark says "this is a guess".

### A typo in `--work` ran in the most permissive mode

`deel --work architcet` — one letter off — silently ignored the unknown name and
ran in the **default mode with no restrictions**: the one that can edit files and
run commands. It now checks the name before starting and, if it is wrong, prints
the available names and stops.

Fixed alongside: putting `constructor` or `__proto__` in as a mode name crashed
the code that lowers a sub-task's privileges. Plan mode told the model to type a
command only a person can type. Three modes had no short prompt for narrow
windows at all — the comment said "these were short to begin with", and one of
them was 761 characters.

## Commands — fourteen places where "delete" did something else

### A command meant to delete added one instead

`/memory 지우기` ("delete") without a number matched no pattern and fell through
to **"remember this"**. So the word "delete" was written into the memory file,
and the screen said "remembered".

```
you typed  /memory 지우기
screen     ✓ Remembered (2 lines)
file       1  Read internal docs as CP949
           2  지우기            ← this line now ships with every request
```

`rm`, `잊어` and `forget` did the same. It now asks for the number and shows you
what there is to delete.

### A command meant to enable turned everything off

`/skills on review` means "enable only the ones matching review". If nothing
matched, **everything was disabled** and then a success mark appeared.

```
✓ enabling only the 0 that match "review".
```

The model then can't use any skill, and you conclude skills are broken. Now, if
nothing matches, nothing is touched and it says so.

### It deleted on a command the screen never showed

`/learned 전선` — the command the screen tells you is `/learned 전선 지우기`,
but the short form alone wiped what had been learned. Typing it to *see* what
had been learned about the wire was the command that destroyed it.

`/undo 다섯` ("five") is the same family. When the number couldn't be read it
**silently undid one turn.** Undo actually restores files, so running on a
misread number costs more here than elsewhere.

### It said "changed" and opened the old model next time

`/model <a model the server has but the config doesn't>` saves a new profile.
But it did not mark that profile as **the one in use.**

| What | Screen | Truth |
|---|---|---|
| right after | ✓ switched to llama-3-8b | correct |
| `/model list` | ● still on the old model | `active` in the config never moved |
| next launch | — | opens the old model |
| `/ctx 655360` meanwhile | ✓ saved to the profile | written to **the wrong profile** |

The last row is the expensive one. Pin 655,360 onto an 8k server's profile and
the next launch starts believing that server holds 655,360.

### It said "off" and kept ringing

`/bell off` only edited the config file. Whether to ring is decided by a value
read once at startup, so it kept ringing for the rest of the session — while the
screen said "applies to this session right away."

`/bell on` was worse: it rang once on the spot as **proof it had been turned
on**, then stayed silent from the next turn.

### You couldn't ask the company gateway

Some profiles fetch their key by running a command (an SSO token). When asking
another model a one-off question (`/consult`) or handing work to a sub-agent
with such a profile, **the key-fetching command was not carried over.**

```
/model company-gw   →  works
/consult company-gw →  401, every time  ← with no reason on screen
```

The path to re-fetch the key is closed off too. `vision` was also missing, so a
sub-agent on a vision-capable model was treated as unable to see images.

### Putting `constructor` in as a mode name

The previous release fixed this for work modes; three more places had it. Looking
a name up in a table also finds **inherited keys.**

```
/mode constructor   the approval mode becomes neither strict nor confirm
                    → nothing is ever asked · screen shows "strict → undefined"
/level constructor  the next command list throws — the conversation ends
/grade constructor  a function becomes the model grade, and it says "set"
```

### Typos that were quietly ignored

`/work` says "no such mode" first. But `/grade 크게` or `/think hgih` printed the
current-status table with no error at all — you read that as "it's set" and carry
on.

`/think auto 켬` did the opposite of what was typed. `켬` was missing from the
list of words meaning "on", so it became an **off** command, and the screen said
"turned off".

`/commit 전부 fix bugs` lost both halves — the folder-wide changes were left out,
and "전부 fix bugs" became the commit title verbatim.

## 1.20.8

**We were writing down "can't" where the truth was "couldn't measure"**

When you first connect an endpoint, deel asks it nine questions. Those answers
go straight into the profile, and from then on the connection **lives by what
was written.** So when this screen is wrong, half the program goes missing.

In three places it wrote *"this model can't"* where the truth was *"we
couldn't measure it."*

```
Basic chat      ✗  response was empty — check the model name
Vision          ⚠  the image went through but the answer was empty — treating as no vision
Effort control  ⚠  no difference (low: 0 chars thought / 0 tokens out · high: 0 / 0)
```

All three are cases where the address, the key and the model name were right
from the start.

| What was actually happening | What got written | The truth |
|---|---|---|
| A reasoning model that returns no visible thinking | check the model name | it spent all 256 tokens thinking |
| The vision question hit its 32-token cap | treating as no vision | the server accepted the image |
| A gateway that returns no `usage` | effort has no effect | there was nothing to measure with |

The first line is the expensive one. Once basic chat is ✗, **all eight
remaining rows become "skipped"**, and that verdict is saved as
`streaming · tools · json · think · vision` **all false**. The person retypes
a correct model name, several times.

Now deel looks at the evidence already in hand — **did it stop at the limit**,
**were reasoning tokens spent** — and asks again with room to answer.

### When you can't measure, which way do you err?

One of the two answers has to be wrong. What's wrong differs:

```
Write "can't"     →  a model that can see never gets an image again.
                     Nothing on screen offers a way back.
Leave it on       →  a server that can't will say so with a 400,
                     and that one 400 puts the reason on screen.
```

Err on the side you can come back from.

### We blamed the model for a cut we made ourselves

The tool-call question is asked with a 512-token cap. When the argument JSON
got cut inside that cap, the report said **"arguments inaccurate — more work
needed on edit reliability."** The model had written the path correctly, and
the raw text was sitting right there in our own hands.

### The screen said "now sending high" while nothing went out

That line in `/think` is a person's **basis for believing a setting took.**
But the code writing it never checked whether there was a field for that rung
to travel in.

```
budget (older Anthropic)   a token count goes out, not a rung
think (ollama)             the card's rung table isn't used at all
no thinking                there is no field to carry it
```

On those three wires, typing `/think high` was accepted on screen and no rung
went out. **Believing a setting took when it didn't is worse than it not
taking.**

Now the three body-building branches and the screen all call **one function**
— fix one side only, and a test breaks.

### Only people who typed a trailing slash got a 404

```
https://…/v1      →  https://…/v1/chat/completions
https://…/v1/     →  https://…/v1//chat/completions   ← 404
```

`//` is **a different path** on many gateways. And that 404 is
indistinguishable on screen from a mistyped model name. The query-string form
was already stripping the slash — so the same URL was normalized differently
depending on whether it had a `?` in it.

### What was learned looked the same as what was guessed

On a 400, deel reads the message, corrects itself, and writes that to disk.
That is **the part that can be wrong.** But the screen showed a guess and a
lesson identically — "this model doesn't think" was indistinguishable from
"three weeks ago we read one 400 that way."

Now the learned fields are named:

```
thinking none · cache key · learned thinking·rungs
```

And the only way back was **"wipe everything you've accumulated."** That takes
weeks of command history and token calibration with it — so people don't do
it, and instead carry a feature that is silently switched off.

```
/learned wire clear      clears only what was learned about the wire
```

`/learned` now shows the wire line too. It is the most consequential thing in
there and it wasn't on that screen at all.

### An MCP server you configured appeared nowhere

Pasting another tool's config into `mcp.json` is the most common way to start,
and such configs contain entries with `"type": "sse"` or only a `url`.

Those were **dropped in silence.** The startup line and the `/mcp` list both
count only what attached, so the list looks complete. This is the very place
where the file's own header promises "what didn't come up is reported — drop
it quietly and nobody can ever tell why that tool is missing."

### A server started eagerly every run, with no config change

deel records the tool list and skips starting the servers next time (four
servers costs over two seconds at startup). But the code that records it
rewrote the file **from scratch.**

```
run 1  A pending · B newly started  →  A's memo is erased
run 2  A started  · B pending       →  B's memo is erased
run 3  …
```

From then on **exactly one server starts eagerly every single run.** The screen
shows one ● and one ◐, so there's no way to tell why someone else's process
keeps starting when you changed nothing.

### "If it differs, fix the record on the spot" wasn't there

After really starting a server, deel compares the tool list and surfaces any
difference. But it **never wrote the correction back.** So the old list went
out to the model again every run — same fingerprint, less than a week old, so
the next run uses the same stale copy.

And the comparison looked at **names only.** The quietest mismatch is the one
where the name is unchanged — when `wiki_search` starts requiring one more
argument, the model calls without it, and if the server falls back to a default
you get **a plausible, wrong result.** That's worse than a 400.

### Kept in the list for a retry, with its output pipe already cut

A process that survives being killed is kept in the list — precisely so it can
be retried. But the pipe was **already cut** before it was kept. The list shows
`running` while nothing it says ever arrives again, and the child takes an
EPIPE on its next write.

### Told to stop, it quietly just read

```
Jobs({ job: 1, action: "stop" })
```

`action` is not an argument deel accepts. But when known and unknown arguments
were **mixed**, it simply discarded `action`, read the output, and returned
**success.** The model believes it stopped the server; the server keeps running.

Now the discarded names are reported back — so if the intent was there, the
next step can correct the call.

### It said the front was truncated when nothing was dropped

Output past 256KB drops from the front. But the dropping loop only ran when
there were **two or more** chunks. One oversized chunk dropped nothing and
still got flagged "front truncated" — sending the model back to re-read a
beginning that was never missing.

### An argument-less tool broke only when streaming

A single space in the arguments field meant "no arguments" on a normal
response and **a broken call** on a streamed one. Same model, same tool,
different answer depending on how it arrived.

### The to-do list was folded only when two tools were called at once

As the conversation fills, old tool results get folded. The fold note says
"read it again if you need it" — but **a to-do list has no file to re-read.**
Fold it and the remaining items exist nowhere. So the most recent list is
exempt.

Except that the exemption looked at **only the first result in a message.**
When the model calls `Read` and `TodoWrite` in one turn — a common pairing —
that format carries both results in a single message, the name reads as
`Read`, and the list loses its exemption.

This was the remaining share of what got reported as "it forgets what I asked
for as the task goes on."

### It waited even when 30,000 tokens were on the table

Folding costs something. Replacing text in the middle of the history makes
everything after it new, and the cache breaks there. So folding is batched.

But the only brake was a **count**, so even with 30,000 tokens to reclaim it
waited for a fourth item. Waiting hands the job to the 80% summarizer, which
replaces the whole conversation with a summary — **far more expensive.** You
wait to save a little and pay a lot.

Now the decision is made on cost:

```
what you save > what gets re-sent after folding   →  fold now
otherwise                                         →  keep batching
```

### "Keeping only the last two images" while keeping four

Images ride in user messages, so they're folded separately. But the count was
over **messages, not images.**

```
a 3-image message + a 1-image message   two slots, so nothing is dropped
                                        (four kept; the setting says two)
```

Three multi-megabyte screenshots stay in the conversation. Now images are
counted — while never splitting a bundle a person attached in one go, and
always keeping the last bundle however large (removing the screenshot someone
just showed you wastes that whole turn).

The count it reported was wrong too — four images removed, reported as "1".

### It warned about a price spike from the very first turn

Folding re-writes the cached prefix, so price and latency spike once. The
screen says so. But that call was made with the **decision** helper, which
deliberately leans toward "a cache exists" when unknown (the right lean for a
decision) — so it was always true on the first turns, including on endpoints
with no caching at all. A warning about losing a cache that was never there.

Decisions may lean. **The screen states only what's known.**

### After falling back, `/context` counted files that were gone

When the summary can't be fetched, deel falls back to plain trimming. That path
cleared the file memory but **not the read-file count.** `/context` reports
"tool results: N" from that count, so it included files no longer in the
conversation.

### Also

* An empty answer with no tool calls went into history as `content: null`,
  which that format rejects from the next request on.
* Anthropic streaming never marked "usage arrived", so the first sign of life
  in a stream didn't count as progress for the stall watcher.
* A job that failed to start had its `-1` exit code overwritten with `null`,
  making it indistinguishable from "killed by a signal."
* `Jobs({ job: "abc" })` reported `(received: undefined)`.

## 1.20.7

**We were learning the opposite of what the server said**

When a gateway rejects a request with 400, deel reads the message to learn
**which field must not go out, and writes what it learned to disk.** That is
how it avoids repeating the mistake.

But the message OpenAI actually returns for o1 / GPT-5 models names **both
fields on one line.**

```
Unsupported parameter: 'max_tokens' is not supported with this model.
Use 'max_completion_tokens' instead.
```

Because the words `max_completion_tokens` appeared, deel read it as **switch
to the old name** — the exact opposite of what the server said. And that value
was written to disk: from then on that endpoint returned **400 every single
turn**, and nothing fixed it until the learning file was deleted.

| What the server sent | What we used to learn | What we learn now |
|---|---|---|
| `'max_tokens' … Use 'max_completion_tokens' instead` | old name ✗ | new name |
| `'max_completion_tokens' … Use 'max_tokens' instead` | old name | old name |
| `max_tokens … must be used instead` | old name ✗ | new name |

Now deel follows **the name the server told it to use.**

### A quota message was read as a field message

```
Adaptive rate limit exceeded: request not allowed
```

That says the quota is full. But `adaptive` and `not allowed` sat side by side,
so deel learned **"this endpoint does not accept the thinking format"** and
saved it. A perfectly good setting froze in the off position.

Now it is not enough for a message to be a rejection — it has to be **about a
field.** And an Anthropic-only format is never learned against an
OpenAI-shaped endpoint.

### One header name turned off conversation naming

```
Unrecognized request argument supplied: user-agent
```

`user_agent` (underscore) was guarded, but **`user-agent` (hyphen) was not** —
a hyphen is a word boundary, not a word character. Once it matched, deel
learned "this endpoint does not accept a conversation name" and wrote it to
disk: a working feature turned off for good on that endpoint, with no visible
way back.

### A model's size was read as its generation

In `custom-gpt-50b-chat`, the `50b` is a parameter count, not a version — but
deel read `gpt-5`. Treated as a reasoning model, it sends `reasoning_effort`,
and that turn is a 400. Another branch in the same file already got this right
— **two branches in one file disagreed about the same model name.**

### A rung Claude does not have was added on top

On Bedrock's OpenAI-compatible endpoint, deel had a comment saying a wide list
would break it — and then **added `minimal` on top anyway.** `minimal` is
OpenAI-only, so on Claude that turn is a 400.

### Thinking strength quietly stopped going out

Learning one thinking format also adjusts the fields that hang off it. But that
adjustment also attached **the mark that says "the server told us no."** So the
first time it learned anything, that mark went on, and from then on the field
that carries the rungs never turned back on. The screen still showed the rungs;
the wire never carried them.

Now what the server actually rejected is counted separately from what we
adjusted ourselves.

### "No thinking" — while advertising four rungs

The `gpt-4o` wire read **"no thinking · rungs minimal, low, medium, high."**
A reader believes a rung can be chosen, but there is no field for it to go out in.

### Behind a proxy, the answer printed and the process hung

Where a proxy answers `CONNECT` with 200 and then goes silent (a proxy with a
dead backend, an inspecting proxy), **the tunnel socket stayed open.** Cancel
lands on time and the screen stops — but the process never exits.

### Only people behind a proxy got the raw English error

A key with Korean characters or a newline in it gets a Korean explanation. But
turning on a proxy takes a different path, and that path did not recognize the
error's wording, so **the raw English came out instead of the explanation.**
Same key, same mistake, different answer depending on the proxy.

### Sent to find an admin while a usable auth sat right there

Corporate proxies commonly offer several schemes at once.

```
Proxy-Authenticate: Negotiate, Basic realm="corp"
```

deel looked only at the first and stopped with **"this scheme is not supported
— contact your administrator"** — with a usable Basic sitting right beside it.
Now it tells you where to put `user:pw@`, and notes separately that Negotiate
is the part it cannot do.

### A model name hid the real cause

Some gateways append the model name to the end of the error sentence.

```
Unrecognized request argument supplied: stream_options
(Received Model Group=qwen3-235b-a22b-thinking-2507)
```

Because the word `thinking` was visible, deel **turned thinking off.** Two
things then happen at once: the real cause, `stream_options`, is still on, so
**the same 400 returns every turn** (while the screen says "learned"), and a
perfectly good thinking feature dies along the way and is written to disk.

Now the trailing name fragment is stripped first, and the loosest rule was
moved to the very bottom of the ladder.

### The most valuable sentence never fired on the most common endpoint

The sentence where a server **enumerates the values it accepts** is the only
one that can turn a guess into a fact. But that rule required a field name
earlier in the sentence, and the wording that actually occurs was not in its list.

```
Invalid value: 'minimal'. Supported values are: 'none', 'low', 'medium', and 'high'.
```

So this sentence rolled down the ladder and became **"the field is not
accepted"** — thinking went off entirely. Now the rule looks at **whether the
enumerated values are rung words**, not at a field name.

### One wrong value turned a whole feature off

Send `medium` to a model that accepts only two words (`low`, `high`), and the
server rejects **one value.** deel read that as "this field is not accepted",
turned the thinking format off, the dependent slot cleared the rungs too, and
all of it went to disk. On that model `/think` did nothing from that day on.


A `#` followed by an identifier character is a private field — after a dot
(`obj.#hidden`) or at the head of a line. Not cutting a line-head `#` costs
nothing: `# API_KEY: value` has no code marker either way, so it is masked either
way.

### When a match spans lines, the value's line is the one read

With the name on one line and the value on another, only the **name's** line was
read. Missing the comma on the value's line, a good object property got masked.

```
const opts = {
  apiKey:
    config.apiKey,     ← this line was being masked
};
```

### The safety doc now describes the masking

Across four releases of fixes there was **nowhere that said what is masked and
what cannot be**. `docs/en/safety.md` now has "Masked before it goes to the model" —
the shapes it knows, how a config line is told from a code line, and a table of
**what cannot be told apart**.

### The three not taken

`tuple.0` is not JavaScript. Quotes inside a template literal turned out to be
counted correctly already. Changing `[^\n]` to `[^\r\n]` inside the pattern would
write the same thing twice — the line is already split on `\r` where it is cut.

## 1.20.0

**A key not written in capitals was going out as it was**

1.19.5 wrote down that this would be measured and shipped on its own. It was
measured. Here it is.

### Only `.env` uses capitals

Secret names were read **in capitals only**. That is the convention in `.env`, so
it sufficed there. Code and JSON/YAML config are not that.

```
API_KEY=sk-real-key-1234       masked
apiKey: 'sk-real-key-1234'     untouched ← went out in plaintext
api_key: "prod.auth.secret"    untouched
accessToken: 'ya29.abcdefgh'   untouched
```

Those middle three are the most common shapes in a config file.

### Only names with a break between the words

camelCase (`apiKey`) and underscore (`api_key`) names count too — but the words
must be **broken apart**: `_key` or `Key`. Accept a plain lowercase `key` ending
and this is what you catch:

```
monkey: 'brown-monkey'      not masked ✓
hotkey: 'ctrl+shift+s'      not masked ✓
turkey: 'roasted12'         not masked ✓
```

**It was measured before it was widened.** Run over the 348 files in this repo, 21
lines are newly masked, and every one of them is a real key (`apiKey: 'sk-…'`).
No line was masked that should not have been.

There is a cost. A camelCase name that is not a secret — `cacheKey`, `rowKey` —
with a quoted value gets masked too; the name alone does not separate `cacheKey`
from `apiKey`. A mangled line is less bad than a secret going out. It is pinned in
a check.

### An identifier is not only Latin letters

When deciding whether a dotted value is a name the code points at, only Latin
letters counted as an identifier. This repo's house style is Korean identifiers,
so **it mangled its own code first.**

```
const API_KEY = 설정.비밀번호;      masked    ← this is code
const API_KEY = config.apiKey;     untouched
```

It now goes by character class. A `#` after a dot counts as part of the
identifier — `obj.#hidden` is JavaScript.

### A `#` inside quotes is not a comment

1.19.4 added "cut the trailing `#` comment before looking". Done as a single
pattern, that forces a choice between two failures. The 16th review found both.

```
API_KEY=prod.v1.secret#(prod)               require a space and this leaks
msg = "a # b"; x.API_KEY = config.apiKey;   don't, and the trailing ; is cut off
```

It now walks the line counting quotes. The first `#` **outside quotes** starts the
comment. Both are right.

### Text that uses only `\r`

Looking for line breaks with `\n` alone makes a CR-only file one single line, and
one `;` somewhere far below then flips that line to "code". Line ends are read as
`[\r\n]`.

### What was not taken

The 16th review raised seven; four were taken. The other three were measured and
declined.

- **`// API_KEY=prod.v1.secret` leaks** — true. But this repo pins that
  **`// API_KEY: config.api_key` must be left alone.** Whether a line inside a
  comment is a secret or is code does not separate on the characters.
- **Everything leaks in a single-line file** — that single line really is code.
  Reading it all as code is correct.
- **Put `\r?$` in the pattern itself** — the line is already split on `\r` where
  it is cut. Writing the same thing in two places is more dangerous when only one
  of them gets fixed.
