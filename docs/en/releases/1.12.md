## 1.12.0

**The same head was going out on every single request**

This started as four reports from running against AWS Bedrock with an API key. They
turned out to be one root: **deel had never caught the cache at all.**

| Report | What was actually happening |
| --- | --- |
| Sessions keep breaking | The gateway was never told "this conversation is that earlier one" |
| The cache is re-read every time | Not a single cache mark was being attached |
| Tools get called twice | `/think max` ran maximum reasoning on "hi" |
| Call limit exceeded | Refused requests were pushed again for every remaining step |

---

### What the dashboard's 5.9K was telling us

Cache reads sat pinned at 5,900 tokens **from the very first request**. The number
never moved as the conversation grew. The hit rate looking like it fell from 30% to
10% was not the cache degrading — **only the denominator was growing.**

5,900 is the system prompt plus the tool schemas: exactly **the head that does not
change by one character between requests**. So nothing beyond the head the gateway
caught on its own was ever being cached. The conversation went out in full every turn.

Across all of `src/`, `cache_control` appeared **zero times**, and so did every
cache-usage field. Nothing was marked, so nothing could be caught; nothing was
measured, so there was no way to know.

### The wire card — what this model actually accepts at this address

Two endpoints can speak the same protocol and still accept different fields. So deel
now settles on one card when the session opens and sends with it for the whole session.

```
  wire       thinking adaptive · rungs low·medium·high·xhigh·max · cache marked
```

The card is settled **without a hardcoded table**. Pin model names to capabilities in a
table and that table goes stale. Instead it reuses how deel already works out context
length — guess, learn from the server's `400`, and keep what it learned per model.

Three things this fixes.

- **`/think max` now actually sends max.** The rung table used to flatten `max` into
  `high`. The screen said max, the wire said high, and nothing happened. An Anthropic
  Messages body now carries `xhigh` and `max` as written. The same Bedrock account's
  OpenAI-compatible endpoint does not get them — whether it accepts those words is not
  confirmed, and an unconfirmed word costs the whole turn.
- **`budget_tokens` is no longer sent to Opus 5.** That model rejects the field with a
  `400`. A valid key getting a `400` is indistinguishable from an auth failure on
  screen. From 4.6 onward thinking is switched on with `adaptive`.
- **The place where one `/plan` killed the turn.** Plan mode climbs into the upper rungs
  on its own, without anyone touching `/think`. That value went out as-is and other
  endpoints answered `400`.

**Nothing extra is sent to an address deel does not recognize.** Corporate gateways
commonly answer `400` to a single unknown field. For an unrecognized vendor, the request
body is **byte-for-byte what it was before this release**.

### Cache marks — two of them

Where marks are accepted (the Anthropic protocol), one goes at the end of the **stable
half of the system prompt** and one on the **last usable block of the conversation**.
The first catches the tool schemas too; the second freezes everything up to this request
for the next one.

Past twenty messages, one more **anchor** is driven into the middle. The lookback window
is twenty positions, so without an anchor the whole head goes out again the moment the
conversation walks past it.

Splitting the system prompt into a stable and a volatile half changes **not one
character** of the text. If the split shifted a single byte, the head would re-link from
scratch — which is the exact failure being fixed. A test holds that line.

`/cost` now shows how much is landing.

```
  Cache      read 48,200 · written 6,100 · 78% hit
```

Writes with zero reads gets called out in the same place — that was the state this
release fixes.

**Input tokens no longer appear to shrink as the cache starts working.** On the
Anthropic protocol `input_tokens` counts **only what follows the last cache
breakpoint**, so a good cache hit makes that number fall. Reported as-is it reads
like the work got smaller. The screen now shows **everything that was sent**,
cache hits included.

This was never only a display concern. That number is what deel compares against
its own estimate to learn a token multiplier — and it **writes that multiplier to
disk**. With half the prompt cached, the multiplier gets dragged down, free context
is over-reported, answers get cut, and folding starts too late. The bad multiplier
then comes back the next time you start. Making the cache work and counting tokens
turned out to be one job, not two.

### Effort follows the request — `/think auto`

With `/think max` set, "hi" ran at maximum reasoning. Turn `auto` on and your setting
becomes a **ceiling**.

| What you typed | What goes out under `/think max` |
|---|---|
| `hi` · `thanks` | `low` |
| `fix src/a.js` | `max` |
| `yes` after a long conversation | `max` |

That last row is the important one. Short is not automatically light — a bare "yes" can
be the turn that picks up everything said before it. **The ceiling is never exceeded.**

On turns that leave the machine, effort is pinned for the whole turn. Effort that moves
between steps is a prefix that moves between steps.

### Call limits — no more wasted requests

Three places that manufactured "call limit exceeded" are closed.

- **A refusal is not pushed again.** A refusal usually carries no tool call, so deel read
  it as "tried to finish after only reading" and pushed once more. The verdict does not
  change, so it refused again, for as many steps as were left. One request that was
  going to be refused went out ten times.
- **A refusal leaves the conversation usable.** "Usually" is not "always" — a refusal
  can land after the tool calls have already opened, leaving calls with no results.
  Send the next message from that state and the server rejects the **whole
  conversation** with a `400`. One refusal used to cost every turn after it.
- **The refusal text is shown.** The OpenAI protocol delivers it in one piece at the
  end rather than streaming it, so the screen carried only "the model declined" and
  no indication of what it declined. People retyped the same request unchanged.
- **One endpoint's limit no longer stalls another.** Remaining quota was held as a
  single value with no owner, so a corporate gateway running dry made the next request
  wait — even one going to a completely different address, such as a local model a
  sub-task had just delegated to.
- **An empty quota waits before sending.** The outcome matches sending and backing off
  from a `429`, except no request is wasted — and each wasted request pushes the limit
  up again.
- **Retries have a total time cap.** Once backoff has accumulated past five minutes it
  stops and says so plainly.

### The session name — the conversation number and nothing else

Endpoints that catch the cache are told this conversation is that earlier one, via
`metadata.user_id` on the Anthropic protocol and `prompt_cache_key` plus `user` on
OpenAI direct.

Everywhere else (Bedrock runtime, Gemini, Azure, unknown gateways) it is **not sent**.
Whether those accept the field is unconfirmed, and even if they do there is nothing to
gain — they cache the head server-side rather than grouping by name.

It carries **the conversation number only**. Anything that is not already a conversation
number is replaced wholesale by a fingerprint rather than filtered. Filtering does not
look at what survives: strip a path and the person's name and folder names are still
sitting there.

```
  C:\Users\<name>\Desktop\<folder>   →   deel-2f3ae766dfb78f6a
```

### AWS Bedrock — the mantle Anthropic endpoint

`bedrock-mantle.{region}.api.aws/anthropic/v1` joins the Bedrock candidate list. It
speaks the Anthropic Messages protocol, so it **accepts cache marks properly**. The
other three are all OpenAI-compatible endpoints, where there is nowhere to put a mark.

It authenticates with a Bedrock API key as `Bearer`, so detection also tries `Bearer` at
that address.

**It goes last.** An install already working through the first three must not move to a
different endpoint because of one added line. To choose it deliberately, enter the
address directly.

**One host, two endpoints.** `/openai/v1` and `/anthropic/v1` sit at the same address
under the same model id. Key the learned wire card by address and model alone and one
endpoint's card lands on the other — which switches thinking and cache marks off
without a word. Both of the things this release fixes would be off before they were
ever on. The card is therefore keyed by **protocol as well**.

And only **learned** fields are kept. A card is mostly guesswork. Store it whole and
today's guess comes back tomorrow wearing the label of something learned, and improving
the guess never takes effect. Only fields the server rejected with a `400` are written
down; the rest is guessed fresh at every start, so a better guess helps the same day.

### One assumption, wired into six places

Fixing the refusal path fixed one tool-pairing site. That site turned out to be
one instance of a **much larger assumption**: "a tool call lives in
`tool_calls`, a tool result lives in `role:'tool'`." That is the OpenAI shape.
The Anthropic shape puts calls in `content` as `tool_use` blocks and results in a
**user** message as `tool_result` blocks.

Five more places believed it, and all five **did nothing while reporting
success**.

| Place | What actually happened on Anthropic connections |
| --- | --- |
| Choosing where to cut | Split a tool pair in half. Every request after that returns `400`, recoverable only with `/clear` — at the longest point of the session |
| Folding tool results | Folded **nothing**. The cheap 55% stage was dead on the wire where the prompt cache matters most |
| Building the summarize text | Labelled tool output as user speech and skipped truncation, so the summarize request grew larger than the conversation it was summarizing |
| Repairing a killed conversation | Reported "fixed 0" and handed resume and `/undo` a history that `400`s on its first request |
| Measuring context | Counted tool output as conversation, so `/context` reported "tool results: 0 tokens" |

**This was not five fixes.** The shape-reading rules now live in one place in
`backend/adapter.js` — right beside the functions that *write* those shapes. A
fourth wire shape means editing one file.

### Learning the wrong lesson, and keeping it

When a server says `thinking.budget_tokens must be greater than or equal to
1024`, it is telling you to **fix the value**. deel read it as "this field is not
supported", changed the card, and **wrote that to disk**. A budget-only model
then returns `400` in every future session, and someone who does not know the
learning file exists has no way to fix it.

Learning the wrong thing is worse than learning nothing. Learn nothing and you
take the same `400` again; learn wrong and something that worked is now broken
permanently. Value complaints now teach nothing — except the one sentence that
enumerates the accepted values.

### `/model` now re-derives the wire card

It used to keep the previous endpoint's card. Switch to Anthropic and thinking
would not turn on and **no cache mark would be attached at all**; switch to an
OpenAI-compatible endpoint and usage would stop arriving, freezing the token
counters. Meanwhile `/status` kept describing the old card — screen and wire
disagreeing, which is the exact failure this release exists to remove.

### `mcp.json` joins the files `@` cannot attach

Found while writing the missing test for "deel's own files cannot be attached
with `@`". `config.json` was blocked; **`mcp.json` was not** — and it stores each
configured MCP server's environment, which is where tokens live. A blocklist
leaks exactly this way: someone adds a file of the same kind and does not add the
row.

---

### What was left out

**A per-turn token or cost cap** — a lock like "this turn gets 50k tokens." Left out.

Token counts are known only **after** they are spent. Before sending there is only an
estimate, and gating on an estimate fails both ways: generous and it stops nothing,
tight and it **cuts a long job that was going fine right down the middle** — usually at
a point where a file is half-edited.

What already exists does the same work with less risk.

- **A step cap** — gates on something that can actually be counted
- **Spin detection** — counts how often the same tool failed the same way
- **`/cost`** — shows what was spent, split into cache reads and writes
- **`/think auto`** — keeps large values off light turns

A numeric lock belongs **after** measurement. Nothing was being measured before; this
release is the first that measures at all.
