## 1.13.0

**Every place deel touches someone else's endpoint, re-examined**

This release is about **compatibility**: every place that handles another
vendor's endpoint, another vendor's wire format, or a file somebody else made.
While widening those, the line deel holds as a local program got *narrower*,
not looser.

This was not one pass. Three reviewers that could not see each other went
through the same repository — Claude (eight angles), GPT, and Gemini. Four
findings came up in more than one of them, and all four were real. Those four
are the first section below.

---

### What more than one reviewer found

#### Three readers that ignored the wire format

The `/export` report, the ACP session replay (Zed and friends), and `/recall`
search all read tool calls and results **as if every wire were OpenAI-shaped**.

In the Anthropic format a call is a `tool_use` block inside `assistant.content`
and a result is a `tool_result` block inside a `role:'user'` message. So
exporting a conversation held over that endpoint produced a document with **the
model's own words and every tool missing.** No error, no warning — indistinguishable
from "it never used a tool."

The reading rules now live in one place, `backend/adapter.js` (`부른것들`,
`결과들`, `도구결과인가`, `본문글`). One more wire format means one place to change.

#### Keys were leaking into child processes

The environment handed to Bash, Jobs, and MCP servers had **exactly one** name
deleted: `DEEL_API_KEY`. There are two key names — the per-profile
`DEEL_KEY_<profile>` went straight through.

And that is the form **our own compliance sheet recommends** — "use an
environment variable and it never touches a file." Only the people who followed
the recommendation leaked. One `Bash({command:'env'})` puts the key on screen,
that screen goes into the conversation, out **to the gateway that owns the key**,
and onto disk in `.deel/sessions/*.jsonl`.

What counts as a key is now known in exactly one place (`config.js`,
`열쇠환경인가`). Add a name there and both the scrubber and the redactor learn it.

#### The output-limit field was chosen **by URL**

Reasoning models (the o-series, GPT-5 family) do not ignore the old
`max_tokens` — they reject it. That branch was `회사 !== 'openai'`, i.e. decided
by the **address**. So anyone running GPT-5 behind a corporate gateway got both
fields on the wire and a 400 on the very first request.

This is exactly why the house rule says never branch on a vendor name: the URL
does not tell you what is behind it. The guess is now made from the **model
name**, and when the guess is wrong one 400 teaches it and the answer is kept
on disk.

#### Korean jamo were counted as English

Token estimation counted only composed Hangul syllables (가–힣). Compatibility
jamo — `ㅋㅋㅋ`, `ㅎㅎ`, `ㅠㅠ` — and decomposed Hangul (NFD, which is what macOS
gives you) were all treated as Latin text and counted at 1/3.6 of their true cost.

Undercounting does not stop at the number on screen. It makes the remaining
context look roomier, so compaction starts late, so the request goes out over
the limit. The characters Korean speakers type most often were the ones in that
gap.

### Ways past the fence

All three leaked at the same place — **choosing which words in a command are
paths.** A word that is never picked up is not blocked; it is never looked at.

| Written like this | Why it slipped through |
| --- | --- |
| `pwsh -Command Get-Content $env:USERPROFILE\.deel\config.json` | a `$` remained, so the whole word was skipped as "unresolved placeholder" |
| `curl.exe file:///C:/Users/…/.deel/config.json` | it had a scheme, so it was treated as a URL and skipped |
| `cmd /c type C:\Windows\System32\drivers\etc\hosts` | `c:/windows` was waived **whole** as "where programs live" |

PowerShell syntax is now expanded, `file:` is turned back into the local path it
is, and the program-directory waiver covers **executable directories only** and
**only one level deep**. Bundle directories (`/Applications`, `Program Files`)
are the exception — those nest by design.

An unresolved placeholder is no longer dropped silently. The fence still cannot
say where it points, but it can still ask **whether it names one of deel's own
files.**

### The home directory was found by spelling

`DEEL_HOME` is a supported setting — portable installs and the test suite both
use it. But the guard looked for the literal string `.deel`, so moving the home
somewhere without that in the name (`DEEL_HOME=D:/agent`) removed the guard
entirely. `config.json` holds the gateway key, and that guard is the one the
tool fence calls.

### WebFetch was only reading the name

The spellings were covered thoroughly — `localhost`, `127.0.0.1`,
`[::ffff:127.0.0.1]`. But an ordinary public domain whose A record points at
`169.254.169.254` (cloud metadata) went straight through. Names are now actually
resolved and **every** returned address is checked — on the first request and on
every redirect hop.

The gap between checking and connecting (TOCTOU) is not closed; `fetch` does not
expose that seam. What is and is not covered is written down in the code.

### One document could kill the process

Entries inside `.docx`/`.xlsx` were **fully inflated and then** size-checked. A
small deflate stream that expands to gigabytes exhausts memory before the check
runs. The size recorded in the archive is now passed as a **ceiling**, so zlib
stops there.

---

### Compaction was corrupting the conversation

Folding a tool result to one line replaced the **whole message**. An Anthropic
result carries its `tool_use_id` inside a `tool_result` block, so overwriting it
destroys that id and orphans the matching call. The next request is a 400, and a
folded conversation cannot be recovered except with `/clear`.

It never fired before, because the folding code **could not find** results in
that format and quietly did nothing. The moment the reader was fixed and folding
started working, a place that did nothing became a place that broke things.

Folded lines also lost the tool name and path. Losing the path means file memory
is never cleared, so re-reading a folded file returns only "unchanged since you
last read it."

### The cache marker switched fields without checking the wire

When `cache_control` is rejected, deel tries the other spelling
(`prompt_cache_breakpoint`) once. It did that **without looking at the wire
format.** An Anthropic endpoint will never accept an OpenAI field, and since the
one learning step was already spent, it could not even fall back to off. Every
turn dies on that endpoint while the screen says "learned" twice.

The same place gave up one more. The list of words meaning "not accepted" was
pinned to `is not permitted`, but what Anthropic actually returns is
**`Extra inputs are not permitted`** — `are`. One letter, and on that endpoint an
unknown field taught us **nothing at all**.

### The cache threshold was not counting tools

On the wire the order is `tools → system → messages`, so the tool schemas sit at
the very front of the cached prefix — about 1,800 tokens for the twenty built-in
tools. The threshold check counted **messages only**. With a system prompt and a
user turn adding up to 500 tokens it answered "below the threshold" and attached
no markers at all — when the real prefix cleared it easily.

### Rate-limit buckets were being mixed

Anthropic counts input and output tokens in **separate** buckets. The comment
said "whichever runs out first"; the code took **the first one present in the
list**. With 100,000 input and 0 output remaining, it recorded 100,000, decided
there was plenty of room, sent the next request immediately, and got a 429.

### "Unknown" was being written as 0

Some endpoints return no `usage` at all. That was filled in with `?? 0`. After a
paid call `/cost` would print "input 0 · $0.00" — and people budget from that
number. Whether usage was **actually measured** is now carried alongside it, and
calls that could not be measured are named on screen and in `--json`.

The pricing help had the same disease: the "I don't know the price" message
offered `"input": 0` as its example, and `0` is **a valid price**. Anyone who
pasted it saw `$0.00` forever after.

### The stream dropped its last chunk

SSE servers conventionally end each event with a newline. That is a convention,
not the spec. On an endpoint that omits the newline after the final JSON, the
**last content, tool call, usage, and stop reason were thrown away.** A server
that answers in one line returned nothing at all. The decoder is now flushed too,
so a multi-byte character straddling the final chunk no longer disappears.

### Diagnostics turned our bug into the server's fault

The streaming check in connection diagnostics swallowed every error in an empty
`catch` and reported "arrives in one piece." A perfectly good endpoint would be
recorded as one that cannot stream. It now reports what actually failed.

### Tests that only looked like they measured

One of the eight review angles went through **the test suite itself**. This
repository has a strong habit of writing down what a test measures — and no
mechanism at all for counting what it **failed** to measure.

**The runner never counted skips.** Several test files honestly report what they
could not measure ("12 skipped"), and that number appeared in neither the table
nor the summary line. From outside, every run looked like "all green," and the
fact that twelve checks never ran on a machine without ripgrep was visible only
by expanding the log. There is now a column for it, and a `::warning` in CI.

**Tests asked the machine and lowered their own bar.** The archive path check was
split by `process.platform === 'win32' ? … : …`, so the drive-letter case **never
ran once** across the three Linux CI legs. Ignore-rule case sensitivity was
pinned on Windows only, so inverting the Linux behaviour stayed green.

**The coverage tool contradicted itself.** It would print "100% line coverage"
and, for the same file, list functions as never called — with line numbers off by
more than twenty. It is the only instrument here for finding code no test ever
reaches, and false positives bury the real gaps.

**The key test measured one key.** It claimed to check "the child cannot see the
key" while actually checking "the child cannot see a variable by that name." It
now dumps the whole environment and asserts that no key-shaped value appears —
a line that does not go stale when a name is added.

**Nothing checked the environment handed to MCP children.** The more dangerous
side.

**`signature_delta` appeared in none of the 116 test files.** Without that one
value a thinking block cannot be sent back, so the turn dies the moment you use
thinking together with tools — the most common way people run Claude.

### "When in doubt, block" was written as "when in doubt, allow"

There is a place that looks at one word on a command line and decides: is this a
path, or a fragment of code? A truncated tag like `</div>` arrives as `/div`, and
no top-level directory has that name — so deel asks the disk, and treats a
missing one as code.

When the ask itself **failed** — no permission, a mount gone away — it also
treated the word as code. Code fragments do not go through the fence. So the one
case where deel did not know fell on the side of letting it through.

The two mistakes are not worth the same. Mistaking code for a path blocks one
harmless command, the person sees it and retypes. Mistaking a path for code is
the same as having no fence at all, and **nothing on screen says so.** When in
doubt, deel now takes the narrow side.

### The audit log knew about exactly one key

The audit log records what was done, when, and how. It exists so you can take it
into a security review — which means people read it, and show it to others.

The `target` it writes is the Bash command line itself, and models pass keys as
environment variables (`DEEL_KEY_WORK=… curl …`). But the list of secrets to mask
held **one** name, `DEEL_API_KEY`. Named keys — `DEEL_KEY_*`, the shape deel
itself recommends — went into the file in the clear.

A leak in the place that promises masking is worse than no masking, because
people trust it. The audit log now asks the same question about "what counts as a
key" that the conversation path asks, from the same single place.

### `/think off` said off on some endpoints without turning anything off

Every wire shape spells "off" differently.

| Shape | How off is expressed | If the field is omitted |
|---|---|---|
| anthropic | drop `thinking` | that *is* off |
| ollama | `think: false` | **the model default** (on) |
| openai-shaped | `reasoning_effort`, using the endpoint's own off word | **the server default** |

The ollama case was missing. `off` is not on the effort ladder, so nothing was
sent — and on that shape sending nothing means "do whatever you like." The screen
said `off` while the model went on thinking. Off is now sent as off.

That leaves the case deel genuinely cannot fix: a reasoning model behind a
gateway that has never told us its off value. `/think detail` now says so
instead of staying quiet: "this endpoint never told us its off value — the field
is omitted, so the server default applies."

### Five copies of the rule for labelling a tool call

The value in the parentheses of `Read(src/a.js)`. Picking which argument stands
for a call is one decision, and it was written out five separate times — screen,
log, editor bridge, report, audit log.

They had drifted.

- The report had no `url`, so a web read showed up as `WebFetch()`.
- The audit log had neither `url` nor `name`, so **what the call was aimed at
  was simply absent.**

Once three surfaces disagree there is no way to tell which one is right. The
list now lives in one place, and a test goes red if it scatters again.

### `npm run check` only looked at JavaScript

House rule 7 is "every file under `src/` is covered by `check`." That rule was
implemented as one line with 136 hand-written `node --check` invocations, which
means **non-JavaScript files could never be on the list.** The seven built-in
skills (`SKILL.md`) were exactly that. The list is now walked, not written. A
file type nothing knows how to check says so out loud.

### Only people with ripgrep saw different results

On Windows, ignore rules are case-insensitive (matching git's `core.ignorecase`
default); ripgrep is case-sensitive everywhere. So with `*.log` in `.gitignore`,
`A.LOG` **was searched** — but only on machines with ripgrep installed, and in
the direction of seeing more of what you asked to hide. Both paths now use the
same rule.

### Two versions reached npm with their tags never pushed

1.10.0 and 1.12.0 are on npm, and **neither tag is in the public repository.**
The tags were created locally and then not pushed, and because those releases went
out through the manual path (`workflow_dispatch`), nothing caught it — the step
that checks the tag against `package.json` only ran when a tag push triggered the
workflow.

For anyone cloning, an unpushed tag is no tag: `git checkout v1.12.0` does not
work. The claim this project makes is that what you install came from this source;
if the name of that source never reaches anyone else's hands, the claim is only
half kept.

The manual path now **requires a `v<version>` tag on the commit being published**.
An unpushed tag is invisible to GitHub, so it stops there and prints how to fix
it. Both tags point at the same commits npm's own provenance records:
`v1.10.0` → `f17088b`, `v1.12.0` → `8d31fef`.

### The marks were only going on the Anthropic wire

1.12.0 said it had fixed "deel was attaching **no cache markers at all**." It
fixed half of it. The marking code went into the Anthropic body only; the
OpenAI body was left on "the server probably handles it."

So nothing changed for anyone calling the same Claude model through an
**OpenAI-shaped** endpoint — which is most people using a gateway.

The dashboard showed it plainly:

| Request | Tokens sent | Cache |
| --- | --- | --- |
| 1 | 6,339 | `0 / 5.9K` — written once |
| 2 | 27,276 | `5.9K / 0` |
| 5 | 42,495 | `5.9K / 0` |
| 8 | 59,698 | `5.9K / 0` — 22% → 10.3% |

Over the 40 seconds the conversation grew from 6k to 59k, the amount **read back
stayed pinned at 5.9k** and nothing new was ever written. The extra 53k was paid
for in full on every step. No 400, no warning — and `/status` said "cache" the
whole time.

### Why the server does not just do it

Claude's cache is **not a growing prefix cache.** It is cut by explicit
breakpoints, so with no breakpoint the cache stops at whatever prefix the server
holds by default. This file's belief — "Bedrock caches the prefix for you" — is
wrong in front of Claude.

### The split is by model, not by endpoint

Splitting by endpoint adds one exception per endpoint, which is the kind of code
this release exists to remove. Whether a field is accepted is decided by **who
ultimately reads the body**, and that is the model. An endpoint fronting Claude
understands this field as its own format even when the body is OpenAI-shaped.
There is not one vendor name in the code.

Nor is the field invented. Both names are documented:

- `cache_control` — the Anthropic format's field
- `prompt_cache_breakpoint` — a field of the **OpenAI schema's** text content part

So a first rejection does not switch caching off. It tries the other name, and
only a second rejection turns it off. Switching off immediately would give up
caching on endpoints that would have accepted it — and that failure gets quietly
more expensive with nothing on screen to show it.

### Marking the tail is the whole point

In a tool-running turn the last position is `role:'tool'`. Without a mark there,
the only marked position is the system prompt at the front — **identical to
before the fix**, with none of the growth captured. Using a content-part array in
that position is the OpenAI schema as written
(`ChatCompletionRequestToolMessageContentPart`). Nothing invented.

In the system prompt the mark goes at the **end of the frozen section**. Putting
it at the very end would rewrite the cache every time the mode changes, making
the mark pointless.

### Caching worked but `/cost` could not show it

`돈셈` took only `{input, output}`, so cache-read tokens were billed at full
price. The better the cache worked, the more the displayed figure inflated —
the fix was not just invisible in deel's own numbers, it read **backwards**.

The multipliers are not hardcoded here, for the same reason prices are not.
Put `캐시읽기` / `캐시쓰기` in the price table and it splits them out; leave them
out and it charges full price, says **"or less"**, and tells you where to write
them. Erring high just startles someone; erring low becomes their budget.

The other half is that "tokens sent" means different things per format —
Anthropic excludes cache from `input_tokens`, OpenAI includes everything in
`prompt_tokens`. That difference is already absorbed in `usage.prompt`, so this
function only subtracts the cache share from the total. Forget to subtract and
cache tokens get counted twice.

### CI had been red for ten releases

Since 1.6.0. Four separate causes; three are reproduced and fixed.

**Windows 8.3 short names.** Windows creates a short alias like `LONGDI~1` for
any name over eight characters. `realpathSync` resolves links but does **not**
expand these. So git answers with the long name while we hold the short one, and
comparing them files the same path as "outside the repository" — not one file,
all of them. The list comes back empty and `/commit` reads that as "nothing
changed", falling back to **the entire working directory**.

Any Windows username over eight characters makes `%TEMP%` short-named
(`C:\Users\RUNNER~1\...`). The CI runner is exactly that case, and it does not
reproduce on a machine with a shorter username — which is why it went unnoticed
for ten releases.

The resolver is now a single one shared with the safety fence
(`safety/guard.js`), using `realpathSync.native`. Two rulers eventually
disagree, and the day they do, `/commit` stages someone else's work.

**Search went deaf on machines without rg.** Calling rg asynchronously was
recorded as the fix, but without rg the code falls through to the JavaScript
path — which was still **one solid block**. A fresh Linux container, a corporate
image, a CI runner: usually no rg. One search over a large folder there freezes
the status line and swallows ESC for seconds. It now yields every few files.

**Plugin archive path checks behaved differently per platform.** `resolve()`
treats a backslash as a separator only on Windows, so an entry named
`..\..\escape.txt` was blocked on Windows and passed through as **an ordinary
filename** on Linux and macOS. Archives travel between machines; blocking on one
platform only is not blocking. Backslashes are now separators everywhere, and a
drive letter (`C:`) is rejected too.

The fourth — a grandchild process surviving a timeout on Unix — is still open.
It does not reproduce on a Windows machine, and process-killing code is not
somewhere to guess. The asymmetry where the Unix branch ignored the caller's
escalation window is fixed.

### Deleted files in a repository opened through a link

`/commit`'s link resolver (`진짜`) **gave up on files that no longer exist** and
returned the name it was given. The root then resolves to its real location while
the file stays on the link path; comparing them yields `..`, and the file is
filtered out as "outside the repository."

Not just that one file. If everything changed this turn was deleted, the list
comes back **completely empty**, and the caller reads that as "nothing changed"
and falls back to **the entire working directory** — the exact `git add -A`
accident `/commit` exists to prevent, with no warning. Deleted files are among
the most common things this command handles.

It now walks up to the deepest path that does resolve.
