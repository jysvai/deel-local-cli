## 1.7.0

**Local stays local. It goes out only when you say so.**

Through 1.6 this tool called itself "fully local." The code enforced half of that.

```
one line in .deel/config.json
  http://127.0.0.1:1234/v1  →  https://api.somewhere.com/v1
```

That one line was enough to send everything out. The screen did show `↗`, but
that is a *notice*, not a lock.

| | 1.6.3 | 1.7.0 |
|---|---|---|
| Point the base URL outside | goes out | blocked — permission is separate |
| Which version and mode am I in | invisible | first line: `deel 1.7.0  ⌂ inside` |
| Keys read from a file, on an external connection | shipped verbatim | masked |
| Model writes a mask back into a file | your real key is destroyed | blocked, with the reason |
| First-time setup | type a URL | pick a target (GPT · Claude · Gemini · Bedrock · custom) |
| Paste a key | nowhere to go | recognized by prefix, sent to that vendor only |
| When it won't connect | `HTTP 401` | what blocked it + where to get a key |
| Claude, directly | not supported | supported (a different wire shape, absorbed) |
| Money | invisible | status bar total · per turn (only when the price is known) |

### Three modes

```
deel            ⌂ inside    asks before an external address (default)
deel online     ↗ outside   does not ask
deel offline    ⛊ sealed    ignores even remembered permission
```

**Both the address and the permission are required.** Changing the address
alone does not get you out.

Say yes once and that connection stops asking — it is stored as `online: true`.
The presence of that field is itself the signal that the connection is
external, so anyone who opens the config file can see it.

Local and intranet ranges (127.x · 10.x · 192.168.x · 172.16–31.x) pass in all
three modes. `offline` does not mean "no internet"; it means "nothing leaves
the company."

### Setup asks where you're connecting

```
1. I only have a key — I'll figure out where it goes    1 blank
2. Enter an address (corporate gateway · local)          2 blanks
3. OpenAI (GPT)                                          1 blank
4. Anthropic (Claude)                                    1 blank
5. Google (Gemini)                                       1 blank
6. AWS Bedrock                                           2 blanks
```

Option 1 is the point. The key prefix decides which single vendor is asked.

```
❯ sk-ant-api03-••••
  ✓ Looks like an Anthropic (Claude) key. (the key starts with sk-ant-)
    It is not thrown at every vendor in turn.
```

Probing vendors one by one would send an Anthropic key to OpenAI's server and
then to Google's. You get a 401 and stop — but **the key has already left.**
So an unrecognized key is never guessed at; you are asked.

Bedrock asks for a region — five, including Seoul (ap-northeast-2), plus
"enter it yourself."

### When it won't connect, it says what blocked it

401, 404 and 403 all used to read "connection failed." Those three are fixed in
completely different places.

```
  ✗ connection failed
    ⚠ The key reached the server, but this model isn't available to it —
      request model access in the console first (Bedrock is per-model).
    Get a key at  https://console.aws.amazon.com/bedrock/
```

### Claude connects directly

Of the five, it is the only one whose **wire shape differs.** Six places —
endpoint, request body, response parsing, history replay, tool results and
streaming — plus images and context size.

Every one of them fails as a bare `400`:

- Without the `anthropic-version` header, a perfectly good key still gets 400
- The system prompt must sit outside `messages`
- Roles must alternate — two tool calls in one turn produce two results, and
  sending them as-is is rejected (**breaks only when there are two**)
- The response is a block array, not one string
- Token fields are named differently (`input_tokens`; `prompt_tokens` is always 0)

What could not be verified is not sent. The thinking field's value shape and
forced output shape are not in the docs we checked, so neither is sent — a
guessed field that produces a 400 is indistinguishable, on screen, from a bad key.

### Going outside masks secrets in file contents too

Masking used to cover command output only. Text read from files was left alone
on purpose: mask it and the model writes the mask back into the file,
destroying your real key.

That trade-off belonged to the local-only era. One `Read` puts your whole
`.env` into someone else's server log, and that cannot be undone.

The other side of the trade is now handled elsewhere: `Write`, `Append` and
`Edit` refuse to write a mask back into a file. That lock landed **first**.

```
✗ The text you're writing contains 2 masked markers («가림»).
  Writing it would overwrite the file's real values with the mask.
  Leave those lines alone to keep the original values.
```

### Money is visible — but no invented prices

```
❯ ─ 12.4s · 3 tools · ↑8.2k ↓1.1k · $0.0271
```

**There is no built-in price table.** Prices change whenever a vendor decides,
and a table baked into source has no one to maintain it. Six months later the
tool would be confidently printing wrong amounts.

So you write them in `.deel/config.json`:

```json
"요금": { "claude-opus-4-6": { "입력": 0, "출력": 0, "기준": "2026-09-01" } }
```

Dollars per million tokens — copy the numbers straight off the price page. The
amount is shown with **where the number came from and as of when**, and after
six months it is marked stale.

Unknown means nothing is printed. A local-only session never sees money at all.

### ↑ no longer eats what you were typing

```
❯ fix this function for me   ← mid-draft
↑                             history
↓                             1.6.3: empty line  ·  1.7.0: "fix this function for me"
```

Node versions disagree here: newer ones restore the draft, older ones return an
empty line. deel now holds it itself instead of depending on the version.
