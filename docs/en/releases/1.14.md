## 1.14.0

**A machine now checks that what we wrote down is true**

This release does not add features. It finds the places where something was
claimed and nobody was watching, and puts each one under a machine.

The way they were found matters. Several reviewers who could not see each
other were pointed at the code, and every finding was then handed to someone
whose job was to **refute it**. Twenty-five came in, ten survived — the other
fifteen were killed with concrete disproofs. The eight items below come out
of those ten.

---

### 1. Folded content was being answered with "you already saw that"

When context fills up, old tool results get folded down to a one-line marker.
The "already read" table (file memory) was cleared alongside the fold.

There was a second table nobody cleared: the **duplicate-call table**. It
suppresses a tool result when the same call with the same arguments returns
the same bytes — and it assumes that earlier result is *still in the
conversation*. Folding breaks that assumption.

In practice:

```
Read(big.txt)          13,037 characters enter the conversation
  … five steps later, context fills, the fold runs …
Read(big.txt)          a 76-character note: "same call, same result as before"
```

What the model receives is **a pointer to text that exists nowhere in the
conversation**. The file never comes back and the task stops there. Not one
error is printed.

All three reduction sites — fold, compact, in-turn reset — now drop the
duplicate table with it (`test/stuck.test.js`, section `1.6`).

### 2. Files written by the shell were invisible to `/undo`

Undo snapshots were taken only when `isMutating(cmd)` was true, and
`echo x > a.js`, `sed -i`, `tee`, `git restore` are not on that list. Files
those commands changed had nothing to restore — and worse, `/undo` would
restore **some other turn's** file instead.

Ten shell-write patterns are now recognised separately (`셸이파일에쓰나`).
Files that do not exist yet are snapshotted too: a file appearing is also
something to undo.

### 3. Only deleting the whole `.deel` folder got through

`rm .deel/config.json` was blocked. `rm -rf .deel/history` was blocked.
`rm -rf .deel` sailed straight through — when path candidates are pulled out
of a command, a word with no slash in it was not treated as a path.

"Clean up the working folder" producing `rm -rf build dist .deel` is not a
rare event. Undo history and the audit log go with it, and you find out when
you type `/undo`.

The name `.deel` is now a path on its own, and the folder as a whole gets its
own explanation (`test/guard.test.js`, section 9 — 113 checks in that file).

### 4. The ACP door was handing out something different

There are three doors in: the chat screen (`repl.js`), batch mode
(`oneshot.js`), and the editor (`acp/serve.js`). The ACP door was missing
`vision` (can this model see images) and `열쇠받기` (fetch the token by
running a command). Same model, but through an editor it went blind to
images — and on a corporate gateway with one-hour tokens, only the editor
died with a 401.

Both are filled in, and **drifting again is now caught**: the connection-object
keys of all three doors are read out of the source and compared, and a key
present in only two of the three turns the run red (`test/doorparity.test.js`).

### 5. The printed exit-code table was missing a row

The table `deel --help` prints had no `6 refusal`. Batch scripts branch on
that table. A check now reconciles the printed table against the program
(`test/exitcode.test.js`).

### 6. `deel run /name` works

If you keep `.claude/commands/preflight.md` around and type `/preflight`
by hand every morning, moving that into a nightly job is now one line.

```bash
deel run /preflight server3
```

Until now `/preflight` reached the model **as literal text**. Handed a single
slash-word, the model usually answers "I don't know what that means" and the
turn ends with **exit 0** — nothing happened and the job is green.

- A command that exists as a file is expanded and run. `$ARGUMENTS` is filled in.
- A chat-only name (`/help`, `/undo`, …) says so and exits **1**.
- Anything else says unknown command and exits **1**.

Built-in names are checked **first**. Reverse that order and the moment a
plugin command like `ralph-loop:help` is installed on the machine,
`deel run /help` alone calls something else — the same characters meaning
different things on different machines is the worst outcome available.

### 7. The coverage floor was not a floor

The `--min` in `npm run coverage --min 90` was used **only to pick a colour**.
Pass 90 or pass 999, the exit code was identical. The README and the docs said
"90%" and nothing anywhere enforced it.

The threshold is now wired to the exit code. Measured coverage is 91%
(20,785/22,951); CI is set at 90, that number rounded down to a multiple of five.

### 8. So: we now re-measure whether the tests guard anything

What the seven items above have in common is that **the tests were green the
whole time**. A green run means "nothing broke", not "breaking it would be
caught". Those two look identical and are worth the opposite.

So it is measured the other way round. The lines that matter are **broken on
purpose**, and the paired test has to turn red.

```
$ npm run mutate

  어긋내기  (7 mutants, checking that the tests catch them)

  · baseline test/guard.test.js → green · 2.0s
  …
  ✓ stop treating the bare name .deel as a path    caught by test/guard.test.js
  ✓ stop clearing the duplicate table on fold      caught by test/stuck.test.js
  ✓ drop shell writes from undo snapshots          caught by test/undo.test.js
  …
  7 killed · 0 survived
```

What gets broken, and what would go wrong if it stayed broken, is written down
in `test/mutants.json`. The source is never edited in place — a copy goes to a
temp folder and only that copy is mutated, so a crash mid-run cannot leave a
mangled working tree behind.

Each paired test is run **unmutated first**. A test that was already red would
look like it caught everything.

CI runs one pass after `npm test`. A single survivor fails the run.

### Also

- The "123 assertions" figure baked into the review sheet is gone. It came
  from nowhere. The real number is 186 (network 70 · web 56 · mcp 60), and the
  document now says **where to look** instead of quoting a number.
- The review sheet has a new section, "What the tests actually guard", in both
  languages.
- Every count in the README's test table was re-measured. `guard 24` was
  actually 113. Twenty-one rows were stale.
- The slash-command name table moved to `src/cmdnames.js`. Batch mode needs to
  read it, and it should not have to drag the whole chat screen in to do that.
- ROADMAP's T2-1 did not match reality — the wire shape shipped in 1.7.0, and
  what is still open is only that the external endpoint has never been reached.

7,095 checks (1.13.1 had 7,046).
