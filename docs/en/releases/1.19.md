## 1.19.0

**Getting one side right broke the other**

1.18.0 added a second review — a different model looking at what this one built.
This release is what came out of running it **eleven rounds**, and of driving the
tool with a real benchmark brief in between. Fifty-eight fixes, and not one new
feature.

Almost all of them are the same family.

- Widen the matcher for instructions and **logs and questions** start matching
- Filter the logs back out and **real instructions** like `Fix errors.` go with them
- Widen the secret masker and **non-secrets** get masked; narrow it and **real keys** go out

**Move a fence and a gap appears where you moved it.** That line was written down
once in 1.18. This release lived it eleven more times. So every check here now
measures **both sides** — what must match, paired with what must not.

### A 3,577-character brief went to "find the root cause first"

The tool reads what you typed and picks a mode, because an editing mode (code) and
a read-only mode (debug · ask · inspect · plan) do very different things. 1.18.0
was driven with a real benchmark brief.

```
"Start from an empty working directory. Design, implement and test a
 request-and-approval web app."   — 3,577 characters of English

  →  debug mode (find the root cause first)
```

The directory is empty. There is no root cause to find.

Two words did it, and both were requirement clauses, not symptoms. But that was
the symptom; the root was lower down. Fourteen English imperatives, measured side
by side: **ten of them scored zero** on the code table.

```
  Fix errors.                        0
  Could you please fix this?         0
  Make a plan for this.              code  (it is a plan)
  Explain user.delete in detail.     code  (it asks for an explanation)
  Review this code.                  no mode at all
```

Korean had been tuned over eight releases. English was still being read through a
handful of leading imperatives. The English scoring table was rewritten here.

### English and Korean were two different programs

Fixing one side and finding the other had fallen behind happened three times. So
**twenty-six pairs of the same request** now run side by side as a check.

```
  "이 코드 검토해 줘"      inspect        "Review this code."       (nothing)
  "이 코드 살펴봐 줘"      0              "Inspect this code."      inspect
  "어떻게 돌리는 거야?"    0              "The tests are failing."  debug
  "계획 세워 줘"           plan           "Make a plan for this."   code
```

Sometimes the left side won, sometimes the right. Either way, **the same request
has to land in the same mode.** A mismatched pair now goes red.

### Pasted text was read as an order

What people paste most is not an instruction — it is **logs and code**. Thirty-eight
lines of paste-shaped text were measured: seven read as instructions, five of them
the same shape.

```
  fix: 값이 아닌 것을 가렸습니다        ← a commit message from this repo
  Change-Id: I8f2c1a
  delete from users where id = 1;
  update accounts set balance = 0 where id = 3
  Delete failed: permission denied
  Rewrite broken with exit code 1
  Update available: 1.2.3
```

Reading it as an order **drops every read-only mode from the running.** You pasted
a query to ask why it behaves that way, and the tool goes off to edit files.

The test is no longer the verb. It is **what follows it**.

```
  delete from users where id = 1;   → SQL          (from + name + where)
  Delete from the list.             → instruction  (no SQL follows)
  Delete the row from users.        → instruction  (from is not right after the verb)
  Modify broken.                    → log          (broken is an adjective)
  Fix broken tests.                 → instruction  (a noun follows)
```

### Non-secrets were masked, and real secrets went out

Masking hides a **value**. It was hiding things that were not values.

```
  const JWT_SECRET = process.env.JWT_SECRET;   → masked  (it is a reference)
  interface Cfg { API_KEY: string }            → masked  (it is a type name)
  const API_KEY = config.apiKey;               → masked  (it is a reference)
  const API_KEY: string = "secret12345";       → the type was masked, the secret stayed
```

That last one is the worst pairing there is — **the line is broken and the secret
is still in it.**

Widening the other way let real keys through.

```
  const API_KEY = "ENV-PROD-SECRET-KEY-12345";   → not masked
  {"API_KEY":"secret12345"}                      → not masked
  const API_KEY: () => string = "secret12345";   → not masked
  const API_KEY: string = ("secret12345");       → not masked
```

This is far worse than a broken line. That value rides out to the model as it is.

Two wrong turns here, both recorded in the source. **Listing what a type looks
like is a losing fight** — the list was widened over eight rounds and every round
found a shape outside it (parentheses, braces, arrows, unions, semicolons). It now
looks only at **where the type ends**. Where a value ends is decided by the quote
pair, not by what character comes next.

### Somebody else's plugins pushed this tool out of its own list

1.19 measured the system prompt of a stock 1.18.0 in an empty directory.

```
  system prompt 9,399 chars
    └ skill list 6,700 chars (71%) · 40 entries
        ├ user skills          11
        ├ plugin skills        29  ← ~/.claude/plugins cache, not deel's
        └ deel's own builtins   0
```

The slot deel built to carry its own methodology was taken by 300 plugins from
somebody else. The priority table said "project > user > builtin > plugin". The
running order was the reverse.

The fix went too far the other way: reserving the cap for builtins **first and
unconditionally** starved project skills (cap 10 · 10 project + 7 builtin →
3 project). Builtins now hold **a quarter of the cap** and the rest follows the
priority table.

The cap value itself was wrong three ways.

```
  maxSkillsListed = -1        → everything but the last one  (should be: none)
  maxSkillsListed = '10'      → 0                            (config gives strings)
  maxSkillsListed = Infinity  → 0
```

### Test files were missed, and housekeeping files were run as tests

This is the part that works out how a project runs its checks. Eight
benchmark-shaped project layouts were measured, and one came back empty — and
**this repo is that shape.**

```
  a project with test/approval.test.js and test/roles.test.js
  and no test entry in package.json    →  found 0
```

Widening it flipped the other way. A dot in the separator of the leading branch
meant **housekeeping files were taken for tests and actually executed.**

```
  check.config.js · test.min.js · qa.bundle.js · spec.d.ts · verify.config.mjs
```

A word in front and a word behind are two different conventions, so they are two
branches now. Only `test` and `spec` are accepted as a bare one-word name —
`check.js`, `bench.js` and `e2e.js` are not.

### Eleven rounds of second review — and the tool had the same disease

The second reviewer built in 1.18 was actually used here. Every finding from all
eleven rounds was **reproduced by hand** first, and only the real ones were fixed.
A little over half were false alarms. The last round raised two "critical" findings
and neither reproduced — both claimed a regex group closed early, and ten sentences
run through it came back clean.

The tool itself was carrying three of the bugs it was built to catch.

```
  node tools/review2.mjs --help      → 40 minutes of real review instead of help
  node tools/review2.mjs --since     → silently became "everything uncommitted"
  node tools/review2.mjs --to HEAD~2 → screen said "uncommitted", it reviewed something else
```

All three **quietly do something else.** Arguments were only ever looked up with
`indexOf`, so anything not on the list simply did not exist. It now stops on an
unknown option and on **an option whose value is missing**.

Four rounds came back empty, and not because there was nothing to report — the
answer hit the **output limit** and was thrown away. Rounds are scoped smaller now,
and a truncated answer is asked again.

### Also

**When no mode was picked, the screen said nothing.** The header of `route.js`
promises that the reason is shown on screen. When nothing was picked, both callers
printed only inside `if (picked.mode)`. "Deliberately did not pick" was unreachable.

**A dropped connection was sent into a 40-minute retry — again.** This is the code
that decides *what* got cut off, and it leaked twice across two releases.
`connection cut off by peer` is not a truncated model answer. Narrowing it to
"only when a noun sits in between" left the shapes with no noun in between, like
`response cut off by peer`.

**Fourteen checks that were green and measuring nothing.** Conditional assertions
whose condition never held, checks measuring less than their name promised, counts
that stayed green while the split behind them broke. Every one of them was reverted
first and **watched go red** before being left green.

**Four comments that said the opposite of the code.** The abbreviation list was
documented as "only words with nothing after them" and held nothing but words with
something after them; a rule documented as "a space before the equals" actually
tests for **a space before the value**. A comment that does not change with the
code becomes a quiet lie.
