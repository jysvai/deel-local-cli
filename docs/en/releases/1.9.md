## 1.9.2

**Guards that said they were blocking were not blocking**

A full security pass. The worst thing it turned up was not a fault — it was
**a fault that stayed green.** Delete the line that does the blocking, and all
6,110 checks still passed.

| What the code claimed | With that line deleted |
| --- | --- |
| Never touches anything outside the working folder (symlink escape) | all 6,110 green |
| Never follows a redirect to an intranet address or `file://` | all 6,110 green |
| Says so when a read was truncated | all 6,110 green |
| Masks `Authorization` values | all 71 green |
| A plugin archive cannot write outside its folder | **it actually could not block it** |

The last row was a hole, not a testing gap. One entry named `../../../..` in a
plugin tarball writes files **outside** the plugin folder, and the extractor
creates the missing directories on the way out. Now a single outside-pointing
name rejects the whole archive — there is no reason to lay down the rest of an
archive built to escape.

Why the `Authorization` rule never fired is just as clear: both samples used a
JWT value, so the JWT rule masked it even with the header rule dead. But the
Bearer tokens corporate gateways hand out are usually not JWTs — **that is
exactly where the header rule is the only net.**

**Found a large part of "it doesn't remember the conversation"**

Take a four-item request, read ten files, then compact. One fold and the
outstanding work is gone.

```
                              before      after
  item 4 of the request       survives    survives
  todo list (item 3 open)   ★ gone        survives
  request on the fallback   ★ not pinned  pinned
```

The reason was written on the fold marker itself — "read it again if you need
it." True for a file. But **a todo list has no file to read again.** Folding it
removes the remaining items from everywhere.

And the code that pins the original request ran **only on the path where
summarizing succeeded.** The path actually taken most often is the fallback,
which keeps just the first two messages — so a four-item request given on the
third turn disappeared entirely.

Fold and trim now pin the **same** thing: the request verbatim, plus the items
that are not yet done. Finished items are left out; the note answers one
question, which is what is left.

**The screen now says what happened**

- **A move that copied but could not delete the original was reported as a
  failure.** Across drives the move is a copy followed by a delete, and the two
  were one block. If an editor holds a file in the source folder, you are told
  the move failed — while **both copies now exist and nobody knows.**
- **A stream that stopped without saying why counted as a complete answer.**
  A relay proxy that truncates the body and closes cleanly leaves no trace.
  It is now reported — and not as a cap problem, so it does not suggest `/out`.
- **A failed audit write was swallowed silently.** Then `/evidence` says
  "nothing changed or ran yet." The one screen built to report what was *not*
  done was making it look like nothing was done at all.
- Aborting still reported falsely **on Unix only**.
- `/undo` counted files it failed to restore, reporting "restored 2 files."
- Tool-name fingerprints produced only 4 distinct values where 5,825 were due.

The suite went from 6,061 to **6,149 checks**. Every one of the 88 added was
confirmed by mutation — and two always-green lines were deleted rather than kept.

## 1.9.1

**MCP tools with Korean names all looked the same to the model**

1.9.0 began fitting tool names to each vendor's rules. But it replaced every
illegal character with its own underscore.

```
mcp__사내문서__검색   (search)  →  mcp__________
mcp__사내문서__열기   (open)    →  mcp__________
mcp__사내문서__지우기 (delete)  →  mcp___________
```

Collisions were avoided with a trailing number, but **the names the model sees
were still indistinguishable.** Ask for a search and the delete tool can be
called — with no error. That is exactly the fault this feature exists to prevent.

Runs of illegal characters now collapse to a single underscore with a short
fingerprint appended. Not readable, but distinct, and stable when the tool list
is reordered. What the tool does is carried by its description (`[사내문서] 검색`),
which is where the meaning belongs once the name cannot hold it.

```
mcp__사내문서__검색   →  mcp_0144c0
mcp__사내문서__열기   →  mcp_00mk0u
mcp__사내문서__지우기 →  mcp_01s4l9
```

Nothing else differs from 1.9.0.

## 1.9.0

**The screen reads, and vendor APIs understand what you set**

Through 1.8 the least readable thing on screen was a **table**. The model answers in
markdown; the screen showed the pipes.

```
| File | Checks | Failed |
|---|---:|---:|
| toolfit.test.js | 49 | 0 |
```

Asking for results as a table is the most common thing there is, and it was the one
place that did not read.

And when you connected a vendor API directly, there were two places where **what you
set never reached the wire**: reasoning effort and tool schemas. In both, the screen
said it was set. That is worse than doing nothing, because you believe it.

| | 1.8.0 | 1.9.0 |
|---|---|---|
| Model answers with a table | Raw pipes | Drawn as a box |
| `/think high` on Claude direct | Nothing sent | Sent as a `thinking` budget |
| MCP tools sent to Gemini | One schema → HTTP 400 | Shaped to spec just before sending |
| Pasting several lines | Only the last line showed | The whole paste shows |
| Reading the same file again | Whole file reloaded | Only what changed |
| `deel audit` under `/lang en` | A Korean document | An English document |

---

### Tables are drawn as tables

Alignment markers in the separator row are honoured — a `---:` column stays right-aligned.

```
┌──────────────────┬────────┬────────┬────────┐
│ File             │ Checks │ Failed │   Time │
├──────────────────┼────────┼────────┼────────┤
│ toolfit.test.js  │     49 │      0 │   0.1s │
├──────────────────┼────────┼────────┼────────┤
│ packlang.test.js │     36 │      0 │   1.9s │
└──────────────────┴────────┴────────┴────────┘
```

Streaming a line at a time cannot align columns — the row above is already printed
before we know how wide the row below will be. So once a table starts, it is **held
until the table ends** and drawn in one go. To avoid looking frozen while holding, a
run that turns out not to be a table is flushed immediately.

In a narrow terminal cells wrap. The box stays square when they do.

---

### Reasoning effort actually applies on Claude and Bedrock

OpenAI-compatible servers take a **word** — `reasoning_effort: 'high'`. The Anthropic
spec takes a **token count**.

```json
"thinking": { "type": "enabled", "budget_tokens": 6144 }
```

That field was never filled in. The body builder accepted an effort argument and never
used it, so connecting Claude directly showed `◇ medium` in the status bar while the
request carried nothing.

Two lines to hold. Break either and the whole request is rejected:

- At least 1,024. Below that the server refuses.
- Below `max_tokens`. Thinking is paid out of the same budget.

So the budget is trimmed with room left for the answer, and if 1,024 still does not
fit, thinking is **not enabled at all**. Enabling it where it cannot fit kills the turn.

---

### Tool schemas are shaped per vendor, just before sending

The place that builds the tool list does not know where it is going — the same list
goes to a local llama.cpp and to Anthropic. So the shaping happens **at the point of
sending**.

| Destination | What is done |
|---|---|
| Gemini | Keys outside the OpenAPI subset are dropped (`$schema`, `$ref`, `oneOf`, `additionalProperties`, unknown `format`) |
| Anthropic · Bedrock | Parameters that are not an object schema are made into one |
| All of them | Names are fitted to `[a-zA-Z0-9_-]{1,64}`, and **restored on the way back** |
| Anywhere else | Nothing is touched |

The destination is decided from the **URL host only**. Not from the model name — with a
gateway like LiteLLM in front, Claude may be behind it, but the thing we are talking to
is the gateway, and it does its own shaping. An unknown host is left completely alone,
and that is where this program most often stands.

deel's own 20 tools pass through unchanged for every vendor. What actually needs the
shaping is **schemas from MCP servers** — third-party schemas commonly carry `$ref` and
`additionalProperties`, and one of those kills the whole turn.

When a name has to be changed, the model calls back with the changed name. Passing that
straight up means the tool silently never runs — no error, the hardest kind of fault to
find. So the mapping is kept and applied to the reply.

---

### The whole paste is visible

Pasting several lines used to print "pasted 4 lines" and keep only the last one. Now the
folded chip and the pasted lines are both shown. Only very long pastes fold — folding
away what you pasted defeats the point.

---

### Files you read are remembered, and only the diff is sent

Edit, then read back to check — the most common step there is. Each read reloaded the
whole file.

```
read → edit → read again      the same 400 lines shipped twice
```

Now the new read is compared against the remembered one and **only the changed region**
is sent. Three lines are held:

- Line numbers are the **new file's** numbers. The model edits by those numbers.
- **A truncated read is never remembered.** Calling a fragment "unchanged" makes the
  model believe it saw a part it never did.
- After a compaction the whole file is sent again. Once the transcript is folded, the
  earlier copy is not there any more.

When shrinking does not pay, nothing is shrunk — for a short file, or one half rewritten,
the whole thing is both shorter and easier to read.

---

### Model size comes from the connection, not from the name

`/grade` read a size out of the model name. Models with no size in the name all landed
on "medium" — `claude-opus` was handed a 400-line plan.

Now, when the name says nothing, the **context length the server reports** is used. A
guess is labelled as a guess.

### Under `/lang en` the artifacts come out in English

`deel audit`, `deel sbom` and `deel pack` never go through the conversation, so they had
no chance to pick a language and were **always Korean**. Someone running the English
screen who generated a review package got a Korean document. That document cannot be
submitted.

The file names move with it. An English document named `반입심사서.txt` tells the
recipient nothing before they open it, and mail attachments mangle the name.

| Korean | English |
|---|---|
| `반입심사서.txt` | `import-review.txt` |
| `심사명세.json` | `audit-spec.json` |
| `읽어주세요.txt` | `READ-ME-FIRST.txt` |
| `deel-반입.zip` | `deel-import.zip` |

`sbom.cdx.json` is named by its spec, so it is the same in both.

Config keys can be written in English too. A config file is **typed by hand**, and no
feature should be locked behind a key that someone without a Korean keyboard cannot type.

```json
"authCommand": { "command": "az account get-access-token …", "ttl": 3600 }
"pricing": { "claude-opus-4-6": { "input": 0, "output": 0, "asOf": "2026-09-01" } }
```

The `/think` screen is in English now as well. It used to be entirely Korean — a table
whose frame is English and whose contents are not reads as nothing at all.

### "Interrupted" now means it actually stopped

Calling `Bash` without `background` cuts the command off at the timeout. On Windows,
**only the screen was cut off.**

```
Bash(npm run dev)  →  timed out (120000ms)
in reality         →  the server is alive, still holding port 3000
```

Node's timeout signals only the immediate child (`cmd.exe`). The grandchild is left
alone — and that leaves exactly the state this program exists to prevent: a port held
by something you cannot find.

The process tree is now cut **while cmd is still alive**. Order is everything here:
once the root is dead, `taskkill /pid` answers "process not found" and cannot be
used again.

One more thing at the same spot. When the machine is busy, `taskkill` hits its own time
limit and is cut off — and that was being treated exactly like "it was already dead".
Those two are now told apart, and when the tree was not fully walked the root is kept
alive for another pass. Three processes leaked per test run before; now it is zero.
