## 1.16.0

**A deep request no longer lands in a shallow mode — and designs and documents open as they are**

The same request went to two tools and the results were put side by side. The
request was "audit the collaboration feature before we ship it." Where the other
one spent 160,000 characters thinking, we spent **zero**.

Not because the model was weaker. The side that received those words read them as
"explain this" and put the request in **ask mode** — thinking `low`, twelve steps.
The depth was decided at the door, before any work began.

---

### A request to look deeply is no longer taken shallowly

**A new inspect mode (`inspect`).** It hunts for defects and changes no files.
It is told to look wide and then narrow, and to record, for every finding:

```
what      where (path:line)      in what order it happens      why      what is lost
```

Nothing without code behind it, and **what it could not look at, it says so**.
Given a count, it spends it worst-first and does not pad.

**A heavy request cannot have its thinking capped by a mode.** Three lines or
more, 200 characters or more, or — even when short — words like "analyse,
review, race condition, inconsistency", and the mode's ceiling does not apply.
An `off` the person chose themselves still stands: that is not a default, it is
a decision.

**The reading rules are now written the same way in all eight modes.**

```
Outline  →  Grep  →  read a range (offset/limit)
Reads that do not depend on each other go out together
```

The English prompts were brought level with the Korean ones. If only one side
improves, people working in the other language do not get the same tool.

**How much a tool prints at once now follows the context.** One fixed number was
still in there — 30,000 characters, pushed at an 8k model too.

| Context | At once |
|---|---|
| 8k | 2,000 chars |
| 32k | 5,120 chars |
| 128k | 20,000 chars |
| 200k | 30,000 chars |

---

### Two things in the router were quietly wrong

Unit tests did not find them. **Running the real instruction through a real
process** did.

- "review" and "add", 800 characters apart, were paired up and the request went
  to **plan mode** — which writes a plan and stops. To someone who had written
  "do not stop to ask." Now the two words count as overlapping only within 60
  characters of each other.
- **The plain Korean imperative form was missing from the edit-verb list.**
  Someone could write "build it", "make only the minimal fix" three times over
  and read-only modes still stayed in the running.

Also fixed: constraint lines like "at most 3" were being counted as deliverables,
so a finished job would still get "why didn't you do this one?" appended.

---

### The gateway did not know who we were

Found by watching the cache on screen drop from 90% to 20%.

The conversation id went out **in the body only** — OpenAI's `user` field,
Anthropic's `metadata.user_id`. So the moment a gateway sat in front, nothing
went out at all, and the gateway opened a new session per request.

```
several deployments behind one model  →  requests split across them
each deployment has its own prompt cache  →  90% becomes 20% on the next step
```

Now `x-litellm-session-id` and `x-deel-session-id` go out in the head. A head a
server does not know is dropped either way, so there is nothing that can 400 and
no per-vendor branch to keep. The body stays clean, and the conversation name
carries **only a number** — no path, no account name.

---

### A document as one Markdown file — `deel doc2md`

```bash
deel doc2md report.pptx            # to stdout
deel doc2md spec.pdf --out spec.md # to a file
```

The reading was already there. What changed is the **shape on the way out**:
tables survive as real `| name | value |` tables, and sheets and pages become
`## Sheet 2` / `## Page 3` headings.

Why Markdown rather than flat text — the reader is not only a person. From a
Markdown table a model simply knows the first row is the header and the third
cell is a note. From glued-together lines it has to guess that every time, and
one empty cell throws the guess off from there on.

Two things it holds to.

- **A page it could not read is never silently skipped.** The reason goes in its
  place. Passed through as an empty page, the document becomes "a document with
  nothing on that page", and the model answers "there is no such content" on
  that basis.
- **Past twelve columns it stops drawing a table.** The rows drop to a CSV fence
  and it says why. Change shape quietly and there is no way to tell whether the
  missing table is the file's doing or ours.

---

### Figma designs (`.fig`) are read

Handing over a `.fig` with "build this" is a real, frequent thing. And the file
ended right here — "binary file, cannot be read." So a person screenshotted the
screen, or copied the strings across one at a time.

What is inside is not only pictures. **Frame names, text, sizes, stacking order**
are all there as characters.

```
## Login

- FRAME · Login screen 375×812
  - TEXT · Title "Welcome back"
  - FRAME · Field 335×48
    - TEXT · Label "Email"
  - RECTANGLE · Underline (hidden)
```

`Read` opens it, and `deel doc2md design.fig` turns it into Markdown. There is no
writing — a design round-tripped through text is no longer a design.

**Nothing new was pulled in here either.** A `.fig` is a zip, and the
`canvas.fig` inside it is a format called Kiwi. In Kiwi **the first chunk of the
file is how to read that file** — so we never have to freeze a copy of Figma's
schema. Nothing frozen means nothing to go stale: if Figma adds a field tomorrow,
the file itself says so.

It also states up front what it does not produce — **no colours, no shadows, no
fonts.** You must not answer as though you had seen those.

Recent `.fig` files are compressed with zstd. Node only shipped zstd in 22.15 and
this program's floor is Node 20, so on a lower version it cannot be unpacked.
When that happens it **does not say "corrupt file"** — the file is fine and this
Node cannot unpack it, and those two call for completely different actions.

---

### Also

- Trying to `Edit` or `Write` a `.fig` gets a real answer — why not, and what to
  do instead — rather than a generic "binary" error. An error with no way forward
  sends the model looking for a detour, and one such detour has overwritten an
  original before.
- The Kiwi reader **does not let someone else's number decide our memory.** An
  array count larger than the bytes remaining is false on its face.
- On an unknown field id it stops rather than guessing onward. A design that is
  half right is worse than one that is wrong.

The suite is 7,346 checks (1.15.1 was 7,152).
